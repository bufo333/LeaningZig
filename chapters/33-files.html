33. Files and directories with std.Io

In this chapter you will create, write, read, append to and delete files, make and list directories, ask for a file's size, handle a missing file gracefully, take paths apart with std.fs.path, and test all of it inside a throw-away directory. Every operation goes through the std.Io interface introduced in Zig 0.16, so this chapter also fixes the habits that older tutorials will try to break.

33.1 The io parameter

In older Zig, std.fs.cwd() was a global you could call from anywhere. In 0.16 the file system, like the clock and the network, is reached through a value of type std.Io that your program receives in main as init.io and passes down explicitly. A directory is std.Io.Dir, a file is std.Io.File, and every method on them takes io as its first argument after the receiver.

The starting point is std.Io.Dir.cwd(), a handle to the current working directory. From it you open, create and delete things by relative path. Absolute paths have their own variants ending in Absolute, such as std.Io.Dir.accessAbsolute(io, "/tmp", .{}). This chapter uses relative paths almost everywhere, because programs that work relative to a directory handle are easier to test.

Do not write these. std.fs.cwd(), std.fs.File, file.writeAll(…) without a writer, std.fs.cwd().readFileAlloc(allocator, path, max) with the old argument order. They are from 0.13 and 0.14 and do not exist now. If a snippet does not mention io, it is not for 0.16.

33.2 Writing a file

There are two ways to write, and you will use both. dir.writeFile(io, .{ .sub_path, .data }) creates (or truncates) a file and writes a slice in one call, ideal for small things that already exist in memory. For anything built up piece by piece, dir.createFile returns a File, file.writer(io, &buf) wraps it in a buffered writer, and you use the familiar print, writeAll and flush on its interface.

write.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    const cwd = std.Io.Dir.cwd();

    // 1. The short way: whole contents in one call.
    try cwd.writeFile(io, .{ .sub_path = "notes.txt", .data = "day 1: founded the company\n" });

    // 2. The streaming way: a file plus a buffered writer.
    var file = try cwd.createFile(io, "ledger.csv", .{});
    defer file.close(io);
    var wbuf: [512]u8 = undefined;
    var fw = file.writer(io, &wbuf);
    const w = &fw.interface;
    try w.writeAll("day,funds\n");
    var funds: i64 = 1000;
    for (1..6) |day| {
        funds -= 120;
        try w.print("{d},{d}\n", .{ day, funds });
    }
    try w.flush();
    std.debug.print("wrote notes.txt and ledger.csv\n", .{});
}
$ zig run write.zig
wrote notes.txt and ledger.csv
$ cat notes.txt ledger.csv
day 1: founded the company
day,funds
1,880
2,760
3,640
4,520
5,400

Three details. The defer file.close(io) line comes immediately after the successful open, before anything can fail; that is the habit this chapter is named for. The writer holds a buffer you own, so nothing reaches the disk until flush, and a missing flush is the most common reason for an empty file. And createFile's options struct is empty here, which means "truncate if it exists, create if not, writable".

33.3 Reading a file

Reading mirrors writing. readFileAlloc loads a whole file into memory you own, with a size limit so a surprise gigabyte cannot exhaust memory. openFile plus file.reader(io, &buf) streams it, and takeDelimiter('\n') hands you one line at a time, exactly as it did for standard input in Chapter 32. And readFile fills a buffer you already have, with no allocator at all.

read.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    const cwd = std.Io.Dir.cwd();

    // 1. Whole file into memory. You own the bytes; free them.
    const notes = try cwd.readFileAlloc(io, "notes.txt", init.gpa, .limited(1 << 20));
    defer init.gpa.free(notes);
    std.debug.print("notes.txt ({d} bytes): {s}", .{ notes.len, notes });

    // 2. Line by line through a buffered reader.
    var file = try cwd.openFile(io, "ledger.csv", .{});
    defer file.close(io);
    var rbuf: [512]u8 = undefined;
    var fr = file.reader(io, &rbuf);
    const r = &fr.interface;
    var total: i64 = 0;
    var rows: u32 = 0;
    _ = try r.takeDelimiter('\n'); // skip the header
    while (try r.takeDelimiter('\n')) |line| {
        var it = std.mem.splitScalar(u8, line, ',');
        _ = it.next();
        const funds = try std.fmt.parseInt(i64, it.next() orelse "0", 10);
        total += funds;
        rows += 1;
    }
    std.debug.print("{d} rows, average funds {d}\n", .{ rows, @divTrunc(total, rows) });

    // 3. Into a fixed buffer, no allocator at all.
    var small: [64]u8 = undefined;
    const got = try cwd.readFile(io, "notes.txt", &small);
    std.debug.print("readFile gave {d} bytes\n", .{got.len});
}
$ zig run read.zig
notes.txt (27 bytes): day 1: founded the company
5 rows, average funds 640
readFile gave 27 bytes

The argument order of readFileAlloc is (io, path, allocator, limit), and the limit is a std.Io.Limit: .limited(n) or .unlimited. Exceeding it is error.StreamTooLong. The line reader's buffer is also a limit: a line longer than the buffer is error.StreamTooLong too, which Exercise 33.2 turns into a friendlier error.

Which to use? Whole-file for configuration and anything under a few megabytes: simplest code, one allocation, one free. Streaming for logs, large data, or when you want to stop early. Fixed buffer when you know the maximum size and want zero allocation, as in a test or an embedded program.

33.4 Appending

To add to the end of an existing file, open it for writing and position the writer at the current length. The file's length(io) method reports its size, and the File.Writer keeps a pos field that you can set before writing.

append.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    const cwd = std.Io.Dir.cwd();
    var file = try cwd.openFile(io, "notes.txt", .{ .mode = .write_only });
    defer file.close(io);
    const end = try file.length(io);
    var wbuf: [256]u8 = undefined;
    var fw = file.writer(io, &wbuf);
    fw.pos = end;
    try fw.interface.print("day 2: hired a tech\n", .{});
    try fw.interface.flush();
    const back = try cwd.readFileAlloc(io, "notes.txt", init.gpa, .limited(4096));
    defer init.gpa.free(back);
    std.debug.print("{s}", .{back});
}
$ zig run append.zig
day 1: founded the company
day 2: hired a tech

openFile's options carry a mode: .read_only is the default, .write_only and .read_write are the others. Opening an existing file for writing does not truncate it; only createFile does.

33.5 When the file is not there

Every open and read returns an error union, and the error you will handle most is error.FileNotFound. A program that loads settings or a save file should treat it as "first run", not as a crash, and a switch on the error makes that policy explicit while letting everything else propagate.

missing.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    const cwd = std.Io.Dir.cwd();
    const data = cwd.readFileAlloc(io, "does-not-exist.txt", init.gpa, .limited(1024)) catch |err| switch (err) {
        error.FileNotFound => {
            std.debug.print("no such file, starting fresh\n", .{});
            return;
        },
        else => return err,
    };
    defer init.gpa.free(data);
    std.debug.print("loaded {d} bytes\n", .{data.len});
}
$ zig run missing.zig
no such file, starting fresh

Other errors you will see: error.AccessDenied (permissions), error.IsDir (you opened a directory as a file), error.PathAlreadyExists (creating a directory that exists, or a file with .exclusive = true), and error.NotDir. All of them are in the error set of the function, so zig build will tell you if a switch is exhaustive.

33.6 Directories

Directories have their own small vocabulary. createDirPath makes a directory and any missing parents (the mkdir -p of Zig; there is no makePath in 0.16). openDir with .iterate = true opens one for listing; without that flag, iteration is illegal. iterate() gives an iterator whose next(io) yields entries with a name and a kind. statFile reports size, kind and timestamps. deleteFile, deleteDir and deleteTree remove things, and access asks whether a path exists.

dirs.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    const cwd = std.Io.Dir.cwd();

    try cwd.createDirPath(io, "saves/campaign-1/backups");
    try cwd.writeFile(io, .{ .sub_path = "saves/campaign-1/day-001.zon", .data = ".{ .day = 1 }\n" });
    try cwd.writeFile(io, .{ .sub_path = "saves/campaign-1/day-002.zon", .data = ".{ .day = 2 }\n" });
    try cwd.writeFile(io, .{ .sub_path = "saves/campaign-1/notes.txt", .data = "hi\n" });

    var dir = try cwd.openDir(io, "saves/campaign-1", .{ .iterate = true });
    defer dir.close(io);
    var it = dir.iterate();
    while (try it.next(io)) |entry| {
        std.debug.print("{s:<10} {s}\n", .{ @tagName(entry.kind), entry.name });
    }

    const st = try dir.statFile(io, "day-002.zon", .{});
    std.debug.print("day-002.zon is {d} bytes, kind {s}\n", .{ st.size, @tagName(st.kind) });

    try dir.deleteFile(io, "notes.txt");
    dir.access(io, "notes.txt", .{}) catch |err| std.debug.print("after delete: {s}\n", .{@errorName(err)});

    // cwd() itself is not iterable; open "." with .iterate to walk it.
    var root = try cwd.openDir(io, ".", .{ .iterate = true });
    defer root.close(io);
    var walker = try root.walk(init.gpa);
    defer walker.deinit();
    var count: u32 = 0;
    while (try walker.next(io)) |e| {
        if (e.kind == .file and std.mem.endsWith(u8, e.basename, ".zon")) count += 1;
    }
    std.debug.print("{d} .zon files below the current directory\n", .{count});
    try cwd.deleteTree(io, "saves");
    std.debug.print("cleaned up\n", .{});
}
$ zig run dirs.zig
file       notes.txt
file       day-001.zon
file       day-002.zon
directory  backups
day-002.zon is 14 bytes, kind file
after delete: FileNotFound
2 .zon files below the current directory
cleaned up

The order of entries is whatever the file system returns, not alphabetical; sort them yourself if it matters (Exercise 33.3). The walk method visits a whole tree recursively, giving each entry's basename, path and kind; it needs an allocator for its stack of open directories, and it must be called on a directory that was opened with .iterate = true. cwd() itself is not iterable, which is why the program opens "." first. Forgetting that produces a confusing failure deep inside the iterator rather than a clear error, so remember: to list or walk, open with .iterate = true.

33.7 Paths

Paths are strings, and std.fs.path has the functions to build and dissect them without hand-written slicing. This namespace is unchanged by the std.Io move because it never touches the disk.

paths.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const p = try std.fs.path.join(init.gpa, &.{ "saves", "campaign-1", "day-002.zon" });
    defer init.gpa.free(p);
    std.debug.print("join:      {s}\n", .{p});
    std.debug.print("basename:  {s}\n", .{std.fs.path.basename(p)});
    std.debug.print("dirname:   {?s}\n", .{std.fs.path.dirname(p)});
    std.debug.print("extension: {s}\n", .{std.fs.path.extension(p)});
    std.debug.print("stem:      {s}\n", .{std.fs.path.stem(p)});
    std.debug.print("absolute?  {}\n", .{std.fs.path.isAbsolute(p)});
    std.debug.print("separator: '{c}'\n", .{std.fs.path.sep});
    std.Io.Dir.accessAbsolute(init.io, "/tmp", .{}) catch |e| std.debug.print("/tmp: {s}\n", .{@errorName(e)});
    std.debug.print("/tmp exists\n", .{});
}
$ zig run paths.zig
join:      saves/campaign-1/day-002.zon
basename:  day-002.zon
dirname:   saves/campaign-1
extension: .zon
stem:      day-002
absolute?  false
separator: '/'
/tmp exists

join allocates, because it builds a new string; everything else returns a slice into the string you passed. dirname is optional (a bare file name has no directory). extension includes the dot, so compare against ".zon". On Windows the separator is a backslash and join uses it; write your paths with join rather than string concatenation and they will work there too.

33.8 Testing file code with tmpDir

File code is easy to test badly: tests that write into the project directory leave litter and fail when run twice. The standard library gives you std.testing.tmpDir(.{}), which creates a uniquely named directory under .zig-cache/tmp, hands you it as tmp.dir, and deletes it in cleanup. Inside tests, the io value is std.testing.io.

tmptest.zig

const std = @import("std");

fn saveScore(dir: std.Io.Dir, io: std.Io, score: u32) !void {
    var buf: [32]u8 = undefined;
    const text = try std.fmt.bufPrint(&buf, "{d}\n", .{score});
    try dir.writeFile(io, .{ .sub_path = "score.txt", .data = text });
}

fn loadScore(dir: std.Io.Dir, io: std.Io) !u32 {
    var buf: [32]u8 = undefined;
    const text = try dir.readFile(io, "score.txt", &buf);
    return std.fmt.parseInt(u32, std.mem.trimEnd(u8, text, "\n"), 10);
}

test "save and load through a temporary directory" {
    const io = std.testing.io;
    var tmp = std.testing.tmpDir(.{});
    defer tmp.cleanup();
    try saveScore(tmp.dir, io, 4242);
    try std.testing.expectEqual(@as(u32, 4242), try loadScore(tmp.dir, io));
}

test "missing file is FileNotFound" {
    var tmp = std.testing.tmpDir(.{});
    defer tmp.cleanup();
    try std.testing.expectError(error.FileNotFound, loadScore(tmp.dir, std.testing.io));
}
$ zig test tmptest.zig
1/2 tmptest.test.save and load through a temporary directory...OK
2/2 tmptest.test.missing file is FileNotFound...OK
All 2 tests passed.

The pattern to copy is in the two helper functions: they take a std.Io.Dir and an io as parameters instead of reaching for cwd(). That one design choice is what makes them testable in a temporary directory and, later, usable against a real save directory with no change. IRON LEDGER's persistence layer is written the same way.

33.9 The rest of the toolbox

You now know the dozen calls that cover almost every program. For completeness, here are the other std.Io.Dir and std.Io.File methods you will meet in real code, all taking io in the positions you have seen. None of them introduces a new idea.

CallWhat it does
dir.rename(old, new_dir, new, io)Moves or renames a file or directory; the basis of atomic saves (Exercise 33.4). Note that io comes last here.
dir.copyFile(src, dest_dir, dest, io, .{})Copies a file, creating the destination.
dir.deleteDir(io, path) / dir.deleteTree(io, path)Removes an empty directory, or a whole tree.
dir.createDirPathOpen(io, path, .{})Makes the path and returns it opened, in one call; tmpDir is built on it.
dir.realPathFileAlloc(io, path, allocator)Resolves a relative path to an absolute one.
file.stat(io), file.length(io)Metadata for an open file. Stat has size, kind, permissions, mtime (an Io.Timestamp) and atime (optional, since some systems do not track it).
file.sync(io)Asks the operating system to push the bytes to the physical disk; call it before you tell the user a save is safe.
file.lock(io, .exclusive) / file.unlock(io)Advisory locking, so two copies of a program do not write the same save at once.
file.setTimestampsNow(io)Touches the file.

Two habits close the chapter. First, keep the functions that touch files small and at the edge of the program, taking a Dir and an io, and keep the logic that decides what to save pure; the game's persistence layer is a thin shell around an in-memory GameState for exactly this reason. Second, when something goes wrong, print @errorName(err) and the path; a message like saves/day-002.zon: FileNotFound is worth more than any stack trace to the person reading it.

In IRON LEDGER. The clearest file-system code in the game is the soundtrack scanner in game/src/tui/music.zig, which lists a directory of audio files in exactly the style of section 33.6: 
var dir = std.Io.Dir.cwd().openDir(self.io, dir_path, .{ .iterate = true }) catch return;
defer dir.close(self.io);
var it = dir.iterate();
while (try it.next(self.io)) |e| {
    if (e.kind == .directory) { /* a soundtrack */ continue; }
    if (e.kind != .file or !isAudio(e.name)) continue;
    // …
}
Note the catch return: a missing music directory simply means no music. The io arrives as a field of the client (self.io), threaded in from main. The build script uses the same API at build time, b.build_root.handle.access(b.graph.io, candidate, .{}), to check whether a mod file exists. And the reason none of this appears in game/src/sim/ is the point the guide makes about purity: the simulation never receives an io, so it cannot touch a file, and its determinism is guaranteed by a parameter that is not there. Chapter 47 shows the SQLite save files that sit on top of all this.

Exercise 33.1 · Save and load records practice

Write save(dir, io, path, pilots) that writes one name,gunnery,piloting line per pilot, and load that reads it back into an owned slice, treating a missing file as an empty roster and a malformed line as error.BadRecord without leaking. File: exercises/33-files/ex1_records.zig.

Solution 
//! Chapter 33, exercise 1: save and load a list of records.
//! Run with:  zig test ex1_records.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

pub const Pilot = struct { name: []const u8, gunnery: u8, piloting: u8 };

/// Write one line per pilot: "name,gunnery,piloting\n".
pub fn save(dir: std.Io.Dir, io: std.Io, path: []const u8, pilots: []const Pilot) !void {
    var file = try dir.createFile(io, path, .{});
    defer file.close(io);
    var buf: [512]u8 = undefined;
    var fw = file.writer(io, &buf);
    const w = &fw.interface;
    for (pilots) |p| try w.print("{s},{d},{d}\n", .{ p.name, p.gunnery, p.piloting });
    try w.flush();
}

/// Read the file back. Names are copied into `gpa`; the caller frees them
/// with `freePilots`. A missing file yields an empty list, not an error.
pub fn load(dir: std.Io.Dir, io: std.Io, gpa: std.mem.Allocator, path: []const u8) ![]Pilot {
    var file = dir.openFile(io, path, .{}) catch |err| switch (err) {
        error.FileNotFound => return try gpa.alloc(Pilot, 0),
        else => return err,
    };
    defer file.close(io);
    var buf: [512]u8 = undefined;
    var fr = file.reader(io, &buf);
    const r = &fr.interface;
    var out: std.ArrayList(Pilot) = .empty;
    errdefer {
        // On any failure below, give back every name we already copied,
        // then the list itself. One block, so the order is explicit.
        for (out.items) |p| gpa.free(p.name);
        out.deinit(gpa);
    }
    while (try r.takeDelimiter('\n')) |line| {
        if (line.len == 0) continue;
        var it = std.mem.splitScalar(u8, line, ',');
        const name = it.next() orelse return error.BadRecord;
        const g = it.next() orelse return error.BadRecord;
        const p = it.next() orelse return error.BadRecord;
        try out.append(gpa, .{
            .name = try gpa.dupe(u8, name),
            .gunnery = try std.fmt.parseInt(u8, g, 10),
            .piloting = try std.fmt.parseInt(u8, p, 10),
        });
    }
    return out.toOwnedSlice(gpa);
}

pub fn freePilots(gpa: std.mem.Allocator, pilots: []Pilot) void {
    for (pilots) |p| gpa.free(p.name);
    gpa.free(pilots);
}

test "round trip" {
    const io = std.testing.io;
    const gpa = std.testing.allocator;
    var tmp = std.testing.tmpDir(.{});
    defer tmp.cleanup();
    const roster = [_]Pilot{
        .{ .name = "Kell", .gunnery = 3, .piloting = 4 },
        .{ .name = "Ana Ruiz", .gunnery = 5, .piloting = 5 },
    };
    try save(tmp.dir, io, "roster.csv", &roster);
    const back = try load(tmp.dir, io, gpa, "roster.csv");
    defer freePilots(gpa, back);
    try std.testing.expectEqual(@as(usize, 2), back.len);
    try std.testing.expectEqualStrings("Ana Ruiz", back[1].name);
    try std.testing.expectEqual(@as(u8, 3), back[0].gunnery);
}

test "missing file is an empty roster" {
    const gpa = std.testing.allocator;
    var tmp = std.testing.tmpDir(.{});
    defer tmp.cleanup();
    const back = try load(tmp.dir, std.testing.io, gpa, "nothing.csv");
    defer freePilots(gpa, back);
    try std.testing.expectEqual(@as(usize, 0), back.len);
}

test "a broken line is an error and leaks nothing" {
    const io = std.testing.io;
    var tmp = std.testing.tmpDir(.{});
    defer tmp.cleanup();
    try tmp.dir.writeFile(io, .{ .sub_path = "bad.csv", .data = "Kell,3,4\nAna,5\n" });
    try std.testing.expectError(error.BadRecord, load(tmp.dir, io, std.testing.allocator, "bad.csv"));
}

The errdefer block is the subtle part: on failure it must free the names already copied and the list, in that order. Two separate errdefers run in reverse order, which would free the list first and then read freed memory; one block makes the order explicit. This is a preview of Chapter 47, where the same records go to SQLite.

Exercise 33.2 · Word count for files warm-up

Stream a file through a deliberately tiny buffer, counting lines, words and bytes, and turn error.StreamTooLong into error.LineTooLong. File: exercises/33-files/ex2_wordcount.zig.

Solution 
//! Chapter 33, exercise 2: count lines, words and bytes of a file.
//! Run with:  zig test ex2_wordcount.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

pub const Counts = struct { lines: u32 = 0, words: u32 = 0, bytes: u64 = 0 };

/// Stream the file through a small buffer; never load it whole.
pub fn count(dir: std.Io.Dir, io: std.Io, path: []const u8) !Counts {
    var file = try dir.openFile(io, path, .{});
    defer file.close(io);
    var buf: [64]u8 = undefined; // tiny on purpose: lines may be longer
    var fr = file.reader(io, &buf);
    const r = &fr.interface;
    var c = Counts{};
    while (true) {
        const maybe = r.takeDelimiter('\n') catch |err| switch (err) {
            error.StreamTooLong => return error.LineTooLong,
            else => return err,
        };
        const line = maybe orelse break;
        c.lines += 1;
        c.bytes += line.len + 1;
        var it = std.mem.tokenizeAny(u8, line, " \t");
        while (it.next()) |_| c.words += 1;
    }
    return c;
}

test "counts" {
    const io = std.testing.io;
    var tmp = std.testing.tmpDir(.{});
    defer tmp.cleanup();
    try tmp.dir.writeFile(io, .{ .sub_path = "t.txt", .data = "alpha beta\ngamma\n\ndelta epsilon zeta\n" });
    const c = try count(tmp.dir, io, "t.txt");
    try std.testing.expectEqual(@as(u32, 4), c.lines);
    try std.testing.expectEqual(@as(u32, 6), c.words);
    try std.testing.expectEqual(@as(u64, 37), c.bytes);
}

test "empty file" {
    const io = std.testing.io;
    var tmp = std.testing.tmpDir(.{});
    defer tmp.cleanup();
    try tmp.dir.writeFile(io, .{ .sub_path = "e.txt", .data = "" });
    try std.testing.expectEqual(Counts{}, try count(tmp.dir, io, "e.txt"));
}

test "a line longer than the buffer is reported" {
    const io = std.testing.io;
    var tmp = std.testing.tmpDir(.{});
    defer tmp.cleanup();
    const long = "x" ** 100 ++ "\n";
    try tmp.dir.writeFile(io, .{ .sub_path = "l.txt", .data = long });
    try std.testing.expectError(error.LineTooLong, count(tmp.dir, io, "l.txt"));
}

takeDelimiter returns null at the end, so the loop reads naturally; the catch on the call itself translates the one error you expect.

Exercise 33.3 · List the save files practice

Write listSaves(dir, io, gpa, sub_path, ext) returning the sorted names of regular files with the given extension directly inside sub_path. File: exercises/33-files/ex3_listing.zig.

Solution 
//! Chapter 33, exercise 3: list save files in a directory.
//! Run with:  zig test ex3_listing.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Names of the regular files directly inside `sub_path` whose extension is
/// `ext` (for example ".zon"), sorted, copied into `gpa`.
pub fn listSaves(dir: std.Io.Dir, io: std.Io, gpa: std.mem.Allocator, sub_path: []const u8, ext: []const u8) ![][]u8 {
    var d = try dir.openDir(io, sub_path, .{ .iterate = true });
    defer d.close(io);
    var names: std.ArrayList([]u8) = .empty;
    errdefer freeNames(gpa, names.items);
    errdefer names.deinit(gpa);
    var it = d.iterate();
    while (try it.next(io)) |e| {
        if (e.kind != .file) continue;
        if (!std.mem.eql(u8, std.fs.path.extension(e.name), ext)) continue;
        try names.append(gpa, try gpa.dupe(u8, e.name));
    }
    std.mem.sort([]u8, names.items, {}, lessThan);
    return names.toOwnedSlice(gpa);
}

fn lessThan(_: void, a: []u8, b: []u8) bool {
    return std.mem.lessThan(u8, a, b);
}

pub fn freeNames(gpa: std.mem.Allocator, names: [][]u8) void {
    for (names) |n| gpa.free(n);
    gpa.free(names);
}

Exercise 33.4 · A config file with a default and an atomic rewrite challenge

load returns defaults when config.zon is missing but propagates a parse error; store writes to config.zon.tmp and renames it over the real name so a crash never leaves a half-written file. File: exercises/33-files/ex4_config.zig.

Solution 
//! Chapter 33, exercise 4: a config file with a default, and a safe rewrite.
//! Run with:  zig test ex4_config.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

pub const Config = struct { seed: u64 = 3025, autosave: bool = true };

/// Load "config.zon" from `dir`. If the file does not exist, return the
/// defaults. Any other error (including a bad file) propagates.
pub fn load(dir: std.Io.Dir, io: std.Io, gpa: std.mem.Allocator) !Config {
    var buf: [256]u8 = undefined;
    const text = dir.readFile(io, "config.zon", &buf) catch |err| switch (err) {
        error.FileNotFound => return Config{},
        else => return err,
    };
    const z = try gpa.dupeZ(u8, text);
    defer gpa.free(z);
    return std.zon.parse.fromSlice(Config, gpa, z, null, .{});
}

/// Write "config.zon" atomically: serialize to "config.zon.tmp", then rename
/// over the real name, so a crash mid-write never leaves a half file.
pub fn store(dir: std.Io.Dir, io: std.Io, cfg: Config) !void {
    var file = try dir.createFile(io, "config.zon.tmp", .{});
    var buf: [256]u8 = undefined;
    var fw = file.writer(io, &buf);
    try std.zon.stringify.serialize(cfg, .{}, &fw.interface);
    try fw.interface.writeByte('\n');
    try fw.interface.flush();
    file.close(io);
    try dir.rename("config.zon.tmp", dir, "config.zon", io);
}

test "defaults when absent" {

The signature of rename in 0.16 is rename(old_dir, old_path, new_dir, new_path, io), with io last. Writing to a temporary name and renaming is the standard way to make a save atomic on every major operating system.

Check your understanding

  1. What replaced std.fs.cwd() in 0.16, and what extra argument do its methods take?
    Answerstd.Io.Dir.cwd(); every operation takes an io: std.Io, which main receives as init.io.
  2. Why might a file you wrote with a writer be empty afterwards?
    AnswerThe writer buffers; without flush() nothing reaches the disk.
  3. What is the argument order of readFileAlloc?
    Answerdir.readFileAlloc(io, path, allocator, limit), where the limit is .limited(n) or .unlimited.
  4. How do you create nested directories in one call?
    Answerdir.createDirPath(io, "a/b/c"). There is no makePath.
  5. What must be true of a directory before you can iterate or walk it?
    AnswerIt must have been opened with .{ .iterate = true }. cwd() is not iterable; open ".".
  6. How should a program react to error.FileNotFound when loading a save?
    AnswerSwitch on the error, treat that case as a fresh start, and propagate everything else.
  7. Where does std.testing.tmpDir put its directory, and which io do tests use?
    AnswerUnder .zig-cache/tmp/ with a random name; tests use std.testing.io. cleanup() deletes it.
  8. Why write file functions to take a Dir parameter instead of calling cwd() inside?
    AnswerSo the same function works in a temporary test directory and in production, and so its signature shows that it touches the file system.
What you learned.
  • All file system access goes through std.Io; start from std.Io.Dir.cwd() and pass io to every call.
  • Write with writeFile for slices, or createFile + file.writer(io, &buf) + flush; always defer file.close(io).
  • Read with readFileAlloc(io, path, allocator, limit), readFile into a buffer, or openFile + reader + takeDelimiter.
  • Append by opening .write_only and setting the writer's pos to file.length(io).
  • Handle error.FileNotFound with a switch; let other errors propagate.
  • createDirPath, openDir(.., .{ .iterate = true }), iterate(), walk(), statFile, deleteFile, deleteTree, access, rename, copyFile, file.sync and file.lock round out the toolbox.
  • std.fs.path.join, basename, dirname, extension, stem, isAbsolute.
  • Test with std.testing.tmpDir(.{}) and std.testing.io; write functions that take a Dir and an io.
