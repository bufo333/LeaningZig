24. A tour of std.mem, std.sort and friends

In this chapter you will take a guided walk through the parts of the standard library you will reach for every day: searching and slicing with std.mem, chopping text with tokenizers and splitters, sorting and binary search with custom orderings, integer and float helpers in std.math, ASCII and Unicode utilities, the debugging aids in std.debug, reflection helpers in std.meta, and the small containers EnumArray, EnumMap and bit sets. Every function shown here was compiled with Zig 0.16; a few old favourites that no longer exist are called out with their replacements.

24.1 How to read the standard library

Zig ships its standard library as source, and it is the documentation. When you wonder whether std.mem.something exists, open lib/zig/std/mem.zig from your Zig install (zig env prints the lib_dir) and search for pub fn something. The naming is regular: functions that take an element type start with comptime T: type; functions that operate on one value end in Scalar; functions that search for any of several values end in Any; functions that search for a sequence end in Sequence. Once you know the pattern, you can guess most names correctly.

24.3 Tokenize and split

The two families look similar and differ in exactly one way, which the transcript makes obvious.

b_split.zig

const std = @import("std");

pub fn main() void {
    // tokenize: runs of delimiters collapse, empty pieces never appear.
    var t = std.mem.tokenizeScalar(u8, "  hire   pilot  Kell ", ' ');
    std.debug.print("tokenizeScalar: ", .{});
    while (t.next()) |tok| std.debug.print("[{s}] ", .{tok});

    // split: every delimiter produces a piece, even empty ones.
    var s = std.mem.splitScalar(u8, "a,,b,", ',');
    std.debug.print("\nsplitScalar:    ", .{});
    while (s.next()) |piece| std.debug.print("[{s}] ", .{piece});

    // tokenizeAny: any of several delimiter characters.
    var ta = std.mem.tokenizeAny(u8, "one, two;three\tfour", ", ;\t");
    std.debug.print("\ntokenizeAny:    ", .{});
    while (ta.next()) |tok| std.debug.print("[{s}] ", .{tok});

    // splitSequence: a multi-character delimiter.
    var ss = std.mem.splitSequence(u8, "alpha--beta--gamma", "--");
    std.debug.print("\nsplitSequence:  ", .{});
    while (ss.next()) |piece| std.debug.print("[{s}] ", .{piece});

    // Iterators are structs; you can peek and rest.
    var cmd = std.mem.tokenizeScalar(u8, "transfer outfit hq 5000", ' ');
    const verb = cmd.next().?;
    std.debug.print("\nverb={s} rest=[{s}]\n", .{ verb, cmd.rest() });
}
tokenizeScalar: [hire] [pilot] [Kell] 
splitScalar:    [a] [] [b] [] 
tokenizeAny:    [one] [two] [three] [four] 
splitSequence:  [alpha] [beta] [gamma] 
verb=transfer rest=[outfit hq 5000]

Tokenize skips empty pieces: runs of delimiters collapse and leading or trailing ones vanish. That is what you want for words on a command line. Split is exact: every delimiter separates two pieces, and "a,,b," has four of them, two empty. That is what you want for CSV, where an empty field means something. Both come in Scalar (one delimiter byte), Any (any of a set) and Sequence (a multi-byte delimiter) forms.

They are iterators: structs with a next() that returns ?[]const u8, so the standard while (it.next()) |tok| loop drives them. The pieces are slices into the original string, so nothing is copied and nothing needs freeing. rest() gives you everything not yet consumed, which the game uses to pass "the rest of the line" to a sub-parser.

24.5 std.mem: bytes and integers

When you write a file format or talk to a network, you need to turn integers into bytes and back, in a byte order you choose rather than whatever the CPU prefers.

d_bytes.zig

const std = @import("std");

pub fn main() void {
    const v: u32 = 0x01020304;

    // The same four bytes, viewed as a byte array (native order; little-endian here).
    const bytes = std.mem.asBytes(&v);
    std.debug.print("asBytes:  {any}\n", .{bytes});
    std.debug.print("toBytes:  {any}\n", .{std.mem.toBytes(v)});

    // Explicit byte order for file formats and network protocols.
    var buf: [4]u8 = undefined;
    std.mem.writeInt(u32, &buf, 258, .big);
    std.debug.print("writeInt big:    {any}\n", .{buf});
    std.mem.writeInt(u32, &buf, 258, .little);
    std.debug.print("writeInt little: {any}\n", .{buf});
    std.debug.print("readInt little:  {d}\n", .{std.mem.readInt(u32, &buf, .little)});
    std.debug.print("readInt big:     {d}\n", .{std.mem.readInt(u32, &buf, .big)});

    // Reinterpret a byte slice as a slice of u16.
    const words = std.mem.bytesAsSlice(u16, &buf);
    std.debug.print("bytesAsSlice u16: {any}\n", .{words});
}
asBytes:  { 4, 3, 2, 1 }
toBytes:  { 4, 3, 2, 1 }
writeInt big:    { 0, 0, 1, 2 }
writeInt little: { 2, 1, 0, 0 }

This machine is little-endian, so asBytes shows the low byte first. writeInt and readInt take an explicit .big or .little and a pointer to an array of exactly the right size (*[4]u8 for a u32), so a size mismatch is a compile error. bytesAsSlice reinterprets a byte slice as a slice of a wider type without copying; use it only for data that was produced on the same kind of machine.

24.6 std.sort: ordering and searching

e_sort.zig

const std = @import("std");

const Unit = struct { name: []const u8, tons: u32, bv: u32 };

fn byTons(_: void, a: Unit, b: Unit) bool {
    return a.tons < b.tons;
}

fn byBvDesc(_: void, a: Unit, b: Unit) bool {
    if (a.bv != b.bv) return a.bv > b.bv;
    return std.mem.lessThan(u8, a.name, b.name); // tie-break by name
}

fn cmpTons(key: u32, item: Unit) std.math.Order {
    return std.math.order(key, item.tons);
}

pub fn main() void {
    var units = [_]Unit{
        .{ .name = "Marauder", .tons = 75, .bv = 1363 },
        .{ .name = "Atlas", .tons = 100, .bv = 1897 },
        .{ .name = "Locust", .tons = 20, .bv = 432 },
        .{ .name = "Warhammer", .tons = 70, .bv = 1363 },
    };

    std.mem.sort(Unit, &units, {}, byTons);
    std.debug.print("by tons:   ", .{});
    for (units) |u| std.debug.print("{s} ", .{u.name});

    std.debug.print("\nbinarySearch tons=70: {?d}\n", .{std.sort.binarySearch(Unit, &units, @as(u32, 70), cmpTons)});
    std.debug.print("binarySearch tons=71: {?d}\n", .{std.sort.binarySearch(Unit, &units, @as(u32, 71), cmpTons)});
    std.debug.print("lowerBound tons=71:   {d}\n", .{std.sort.lowerBound(Unit, &units, @as(u32, 71), cmpTons)});

    std.mem.sort(Unit, &units, {}, byBvDesc);
    std.debug.print("by bv desc: ", .{});
    for (units) |u| std.debug.print("{s} ", .{u.name});
    std.debug.print("\nisSorted: {}\n", .{std.sort.isSorted(Unit, &units, {}, byBvDesc)});

    var small = [_]u8{ 3, 1, 2 };
    std.sort.insertion(u8, &small, {}, std.sort.desc(u8));
    std.debug.print("insertion desc: {any}\n", .{small});
}
by tons:   Locust Warhammer Marauder Atlas 
binarySearch tons=70: 1
binarySearch tons=71: null
lowerBound tons=71:   2
by bv desc: Atlas Marauder Warhammer Locust

std.mem.sort(T, slice, context, lessThan) is a stable sort. lessThan is a plain function fn (context, a: T, b: T) bool; the context is usually {} (void) and only matters when the comparison needs extra data. For the simple cases std.sort.asc(T) and std.sort.desc(T) generate that function for you. Tie-breaking is your job: byBvDesc falls back to name order so the result is fully determined, which matters whenever output must be reproducible.

binarySearch(T, sorted, key, compare) has a shape that changed in 0.16: the key is the context, and compare is fn (key, item) std.math.Order returning .lt, .eq or .gt. It returns ?usize. lowerBound returns the insertion point for a missing key. isSorted is a cheap assertion for tests. std.sort.insertion is the simple algorithm, best for tiny slices; std.mem.sort picks a good general one.

Notes on the ones that trip people up. maxInt and minInt return comptime_int, so they fit anywhere a literal would. The three divisions differ on negative numbers: divTrunc rounds toward zero, divFloor toward negative infinity, divCeil toward positive infinity; all three return an error on division by zero rather than crashing. sqrt works on integers as well as floats. std.math.cast is the safe narrowing cast: null instead of a panic when the value does not fit. std.math.add and mul are checked arithmetic returning error.Overflow, the error-union cousins of the wrapping and saturating operators from Chapter 4.

And the trigonometric and exponential functions are still there (sin, cos, exp, log), but the more common float operations, @sqrt, @floor, @round, @exp, also exist as builtins, which is what the std.math versions call.

24.10 EnumArray, EnumMap, EnumSet and bit sets

i_enums_bits.zig

const std = @import("std");

const Role = enum { pilot, tech, medic };

pub fn main() void {
    // EnumArray: a value for EVERY enum member, indexed by the enum.
    var pay = std.enums.EnumArray(Role, u32).initFill(0);
    pay.set(.pilot, 1500);
    pay.getPtr(.tech).* += 900;
    std.debug.print("EnumArray: pilot={d} tech={d} medic={d}  all={any}\n", .{ pay.get(.pilot), pay.get(.tech), pay.get(.medic), pay.values });

    // EnumMap: optional value per member (absent until put).
    var lead = std.enums.EnumMap(Role, []const u8).init(.{ .pilot = "Kell" });
    lead.put(.medic, "Sato");
    std.debug.print("EnumMap: pilot={?s} tech={?s} count={d}\n", .{ lead.get(.pilot), lead.get(.tech), lead.count() });

    // EnumSet: a set of members, stored as bits.
    var present = std.enums.EnumSet(Role).initEmpty();
    present.insert(.pilot);
    present.insert(.tech);
    std.debug.print("EnumSet: tech? {} medic? {} count={d}\n", .{ present.contains(.tech), present.contains(.medic), present.count() });

    // Bit sets: N bits, set/unset/toggle/count/iterate.
    var slots = std.bit_set.IntegerBitSet(16).initEmpty();
    slots.set(3);
    slots.set(9);
    slots.toggle(0);
    std.debug.print("bits: isSet(3)={} isSet(4)={} count={d} first={?d} set: ", .{ slots.isSet(3), slots.isSet(4), slots.count(), slots.findFirstSet() });
    var it = slots.iterator(.{});
    while (it.next()) |i| std.debug.print("{d} ", .{i});

    var big = std.bit_set.StaticBitSet(200).initFull();
    big.unset(100);
    std.debug.print("\nStaticBitSet(200): count={d}, type={s}\n", .{ big.count(), @typeName(@TypeOf(big)) });
}

EnumArray(E, V) is an array with one slot per enum member, indexed by the enum rather than by an integer. It cannot be out of bounds and it cannot forget a member; adding a variant to Role automatically adds a slot. Use it for "a value for every kind of thing". EnumMap is the same but each slot may be absent, and EnumSet is a set of members packed into bits. Bit sets proper come in IntegerBitSet(N) (fits in one integer) and ArrayBitSet (larger); StaticBitSet(N) picks for you, as the printed type name shows. They support set, unset, toggle, count, find-first and iteration, plus set algebra (setUnion, setIntersection, complement).

24.11 A fixed-capacity list

Older Zig had std.BoundedArray, a list that lived inside a fixed array and needed no allocator. It is gone in 0.16, and its job is done by ArrayList itself, pointed at a buffer you own:

j_bounded.zig

const std = @import("std");

pub fn main() void {
    // A list that lives entirely inside a fixed array: no allocator, cannot exceed 4.
    var storage: [4]u32 = undefined;
    var list: std.ArrayList(u32) = .initBuffer(&storage);

    list.appendBounded(10) catch unreachable;
    list.appendBounded(20) catch unreachable;
    list.appendSliceBounded(&.{ 30, 40 }) catch unreachable;
    std.debug.print("{any} len={d} cap={d}\n", .{ list.items, list.items.len, list.capacity });

    const full = list.appendBounded(50);
    std.debug.print("fifth append: {!}\n", .{full});
    std.debug.print("pop: {?d}\n", .{list.pop()});
}
{ 10, 20, 30, 40 } len=4 cap=4
fifth append: error.OutOfMemory

initBuffer(&storage) makes a list whose capacity is the array's length and which can never grow; the Bounded methods return error.OutOfMemory when it is full instead of allocating. Everything that does not allocate (pop, items, orderedRemove, iteration) works as before.

Exercise 24.1 · Command line warm-up

Write parseCommand(line) that tokenizes on spaces and tabs, matches the first word case-insensitively against an enum of verbs (lower-case it into a small buffer, then stringToEnum), and reports the argument count and the first argument. Name the file: exercises/24-std-tour/ex1_command.zig.

Solution 
//! Chapter 24, exercise 1: chop a command line into a verb and arguments.
//! Run with:  zig test ex1_command.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Verb = enum { hire, fire, transfer, unknown };
const Command = struct { verb: Verb, arg_count: usize, first_arg: ?[]const u8 };

/// "  hire   pilot Kell " -> verb hire, 2 args, first arg "pilot".
/// The verb is matched case-insensitively.
fn parseCommand(line: []const u8) Command {
    var it = std.mem.tokenizeAny(u8, line, " \t");
    const word = it.next() orelse return .{ .verb = .unknown, .arg_count = 0, .first_arg = null };
    var lower_buf: [16]u8 = undefined;
    const verb: Verb = if (word.len > lower_buf.len)
        .unknown
    else
        std.meta.stringToEnum(Verb, std.ascii.lowerString(&lower_buf, word)) orelse .unknown;
    const first = it.next();
    var count: usize = if (first != null) 1 else 0;
    while (it.next()) |_| count += 1;
    return .{ .verb = verb, .arg_count = count, .first_arg = first };
}

test "hire" {
    const c = parseCommand("  hire   pilot Kell ");
    try std.testing.expectEqual(Verb.hire, c.verb);
    try std.testing.expectEqual(@as(usize, 2), c.arg_count);
    try std.testing.expectEqualStrings("pilot", c.first_arg.?);
}

test "case and tabs" {
    const c = parseCommand("TRANSFER\toutfit\thq\t5000");
    try std.testing.expectEqual(Verb.transfer, c.verb);
    try std.testing.expectEqual(@as(usize, 3), c.arg_count);
}

test "unknown and empty" {
    try std.testing.expectEqual(Verb.unknown, parseCommand("dance").verb);
    const e = parseCommand("   ");
    try std.testing.expectEqual(Verb.unknown, e.verb);
    try std.testing.expectEqual(@as(usize, 0), e.arg_count);
    try std.testing.expect(e.first_arg == null);
}

lowerString writes into a buffer you own and returns the slice it used, so a word longer than the buffer has to be rejected first. orelse .unknown turns the optional from stringToEnum into a definite verb.

Exercise 24.2 · CSV of integers practice

Write parseCsvInts(out, line) using splitScalar (not tokenize: an empty field must be an error), trim and parseInt, filling a caller-provided slice, and stats returning sum, min and max using std.mem.minMax. Name the file: exercises/24-std-tour/ex2_csv.zig.

Solution 
//! Chapter 24, exercise 2: a CSV line of numbers.
//! Run with:  zig test ex2_csv.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Parse "12, 7,3" into `out`, trimming spaces around each field.
/// Returns the slice of `out` that was filled. Empty fields are an error.
fn parseCsvInts(out: []i32, line: []const u8) ![]i32 {
    var n: usize = 0;
    var it = std.mem.splitScalar(u8, line, ',');
    while (it.next()) |raw| {
        const field = std.mem.trim(u8, raw, " \t");
        if (field.len == 0) return error.EmptyField;
        if (n == out.len) return error.TooManyFields;
        out[n] = try std.fmt.parseInt(i32, field, 10);
        n += 1;
    }
    return out[0..n];
}

/// Sum, min and max of a slice in one pass, or null if empty.
fn stats(xs: []const i32) ?struct { sum: i64, min: i32, max: i32 } {
    if (xs.len == 0) return null;
    var sum: i64 = 0;
    for (xs) |x| sum += x;
    const mm = std.mem.minMax(i32, xs);
    return .{ .sum = sum, .min = mm[0], .max = mm[1] };
}

test "parse" {
    var buf: [8]i32 = undefined;
    const got = try parseCsvInts(&buf, "12, 7,3 , -1");
    try std.testing.expectEqualSlices(i32, &.{ 12, 7, 3, -1 }, got);
    const s = stats(got).?;
    try std.testing.expectEqual(@as(i64, 21), s.sum);
    try std.testing.expectEqual(@as(i32, -1), s.min);
    try std.testing.expectEqual(@as(i32, 12), s.max);
}

test "errors" {
    var buf: [2]i32 = undefined;
    try std.testing.expectError(error.EmptyField, parseCsvInts(&buf, "1,,2"));
    try std.testing.expectError(error.TooManyFields, parseCsvInts(&buf, "1,2,3"));
    try std.testing.expectError(error.InvalidCharacter, parseCsvInts(&buf, "1,x"));
    try std.testing.expect(stats(&.{}) == null);
}

Because the function fills a slice it was given, it never allocates; the caller decides how many fields are acceptable by the size of out. The inferred error set carries both your errors and parseInt's.

Exercise 24.3 · Sort and search practice

Sort units heaviest first with names as a tie-break, then sort by name and implement findByName with std.sort.binarySearch and a cmpName(key, item) Order function using std.mem.order. Name the file: exercises/24-std-tour/ex3_sort_search.zig.

Solution 
//! Chapter 24, exercise 3: sort by several keys, then binary search.
//! Run with:  zig test ex3_sort_search.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Unit = struct { name: []const u8, tons: u32, bv: u32 };

/// Heaviest first; equal tonnage sorts by name A to Z.
fn byWeightThenName(_: void, a: Unit, b: Unit) bool {
    if (a.tons != b.tons) return a.tons > b.tons;
    return std.mem.lessThan(u8, a.name, b.name);
}

/// Sort by name only (for searching).
fn byName(_: void, a: Unit, b: Unit) bool {
    return std.mem.lessThan(u8, a.name, b.name);
}

fn cmpName(key: []const u8, item: Unit) std.math.Order {
    return std.mem.order(u8, key, item.name);
}

/// Index of the unit called `name` in a name-sorted slice, or null.
fn findByName(units: []const Unit, name: []const u8) ?usize {
    return std.sort.binarySearch(Unit, units, name, cmpName);
}

fn fixture() [5]Unit {
    return .{
        .{ .name = "Marauder", .tons = 75, .bv = 1363 },
        .{ .name = "Atlas", .tons = 100, .bv = 1897 },
        .{ .name = "Locust", .tons = 20, .bv = 432 },
        .{ .name = "Warhammer", .tons = 70, .bv = 1363 },
        .{ .name = "Archer", .tons = 70, .bv = 1300 },
    };
}

test "weight then name" {
    var units = fixture();
    std.mem.sort(Unit, &units, {}, byWeightThenName);
    try std.testing.expectEqualStrings("Atlas", units[0].name);
    try std.testing.expectEqualStrings("Marauder", units[1].name);
    try std.testing.expectEqualStrings("Archer", units[2].name); // 70 tons, A before W
    try std.testing.expectEqualStrings("Warhammer", units[3].name);
    try std.testing.expectEqualStrings("Locust", units[4].name);
}

test "binary search by name" {
    var units = fixture();
    std.mem.sort(Unit, &units, {}, byName);
    try std.testing.expect(std.sort.isSorted(Unit, &units, {}, byName));
    try std.testing.expectEqual(@as(?usize, 0), findByName(&units, "Archer"));
    try std.testing.expectEqual(@as(?usize, 4), findByName(&units, "Warhammer"));
    try std.testing.expectEqual(@as(?usize, null), findByName(&units, "Rifleman"));
}

std.mem.order(u8, a, b) is the three-way comparison for slices, the exact shape binarySearch wants. A binary search on a slice that is not sorted by the same key returns nonsense, which is why the test asserts isSorted first.

Exercise 24.4 · Payroll and days off practice

Use an EnumArray(Role, u64) to total salaries per role, an IntegerBitSet(7) to record which weekdays anyone is off, and set algebra to find the first day everyone is present. Name the file: exercises/24-std-tour/ex4_payroll.zig.

Solution 
//! Chapter 24, exercise 4: EnumArray and a bit set.
//! Run with:  zig test ex4_payroll.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Role = enum { pilot, tech, medic, admin };
const Person = struct { role: Role, salary: u32, day_off: u3 }; // day 0..6

/// Total salary per role.
fn payroll(people: []const Person) std.enums.EnumArray(Role, u64) {
    var totals = std.enums.EnumArray(Role, u64).initFill(0);
    for (people) |p| totals.getPtr(p.role).* += p.salary;
    return totals;
}

/// Which days of the week (0..6) is at least one person off?
fn daysOff(people: []const Person) std.bit_set.IntegerBitSet(7) {
    var days = std.bit_set.IntegerBitSet(7).initEmpty();
    for (people) |p| days.set(p.day_off);
    return days;
}

/// First day nobody is off, or null if every day has someone away.
fn firstFullStrengthDay(people: []const Person) ?u3 {
    const off = daysOff(people);
    var all = std.bit_set.IntegerBitSet(7).initFull();
    all.setIntersection(off.complement());
    const first = all.findFirstSet() orelse return null;
    return @intCast(first);
}

const crew = [_]Person{
    .{ .role = .pilot, .salary = 1500, .day_off = 0 },
    .{ .role = .pilot, .salary = 1200, .day_off = 1 },
    .{ .role = .tech, .salary = 900, .day_off = 1 },
    .{ .role = .medic, .salary = 1100, .day_off = 5 },
};

test "payroll" {
    const t = payroll(&crew);
    try std.testing.expectEqual(@as(u64, 2700), t.get(.pilot));
    try std.testing.expectEqual(@as(u64, 900), t.get(.tech));
    try std.testing.expectEqual(@as(u64, 0), t.get(.admin));
}

test "days" {
    const off = daysOff(&crew);
    try std.testing.expectEqual(@as(usize, 3), off.count());
    try std.testing.expect(off.isSet(5));
    try std.testing.expect(!off.isSet(2));
    try std.testing.expectEqual(@as(?u3, 2), firstFullStrengthDay(&crew));
    const everyone = [_]Person{
        .{ .role = .tech, .salary = 1, .day_off = 0 }, .{ .role = .tech, .salary = 1, .day_off = 1 },
        .{ .role = .tech, .salary = 1, .day_off = 2 }, .{ .role = .tech, .salary = 1, .day_off = 3 },
        .{ .role = .tech, .salary = 1, .day_off = 4 }, .{ .role = .tech, .salary = 1, .day_off = 5 },
        .{ .role = .tech, .salary = 1, .day_off = 6 },
    };
    try std.testing.expectEqual(@as(?u3, null), firstFullStrengthDay(&everyone));
}

complement() flips every bit, setIntersection ands in place, and findFirstSet gives the lowest set bit as ?usize. The u3 for a day index is the compiler enforcing 0 to 7 for you.

Exercise 24.5 · A binary record challenge

Define an 8-byte big-endian wire format (u32 id, u16 armor, u8 flags, one zero pad byte) and write encode and decode with writeInt and readInt. Decoding must reject a non-zero pad byte. Name the file: exercises/24-std-tour/ex5_record.zig.

Solution 
//! Chapter 24, exercise 5: a fixed binary record with explicit byte order.
//! Run with:  zig test ex5_record.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Wire format, 8 bytes, big-endian: id u32, armor u16, flags u8, pad u8 (zero).
const Record = struct { id: u32, armor: u16, flags: u8 };
const size = 8;

fn encode(r: Record, out: *[size]u8) void {
    std.mem.writeInt(u32, out[0..4], r.id, .big);
    std.mem.writeInt(u16, out[4..6], r.armor, .big);
    out[6] = r.flags;
    out[7] = 0;
}

fn decode(in: *const [size]u8) !Record {
    if (in[7] != 0) return error.BadPadding;
    return .{
        .id = std.mem.readInt(u32, in[0..4], .big),
        .armor = std.mem.readInt(u16, in[4..6], .big),
        .flags = in[6],
    };
}

test "known bytes" {
    var buf: [size]u8 = undefined;
    encode(.{ .id = 258, .armor = 0x0102, .flags = 0xAB }, &buf);
    try std.testing.expectEqualSlices(u8, &.{ 0, 0, 1, 2, 1, 2, 0xAB, 0 }, &buf);
}

test "round trip" {
    var buf: [size]u8 = undefined;
    const r: Record = .{ .id = 0xDEADBEEF, .armor = 65535, .flags = 7 };
    encode(r, &buf);
    try std.testing.expectEqual(r, try decode(&buf));
}

test "bad padding" {
    var buf: [size]u8 = .{ 0, 0, 0, 1, 0, 0, 0, 9 };
    try std.testing.expectError(error.BadPadding, decode(&buf));
    buf[7] = 0;
    try std.testing.expectEqual(@as(u32, 1), (try decode(&buf)).id);
}

out[0..4] on a pointer-to-array with comptime bounds is itself a *[4]u8, exactly the type writeInt requires; a wrong slice length is a compile error, not a runtime bug.

Check your understanding

  1. What is the difference between tokenizeScalar and splitScalar on "a,,b"?
    AnswerTokenize yields a, b (empty pieces are skipped). Split yields a, an empty string, b.
  2. Why does every std.mem search function take a type as its first argument?
    AnswerThey are generic over the element type: indexOf(u8, ...) searches bytes, indexOf(u32, ...) searches integers. Text is just the common case.
  3. What does std.mem.sort need from you to sort a slice of structs?
    AnswerA lessThan function fn (context, a: T, b: T) bool (with {} as the context when none is needed), ideally with a tie-break so the order is fully determined.
  4. What is the 0.16 signature of the compare function for std.sort.binarySearch?
    Answerfn (key: K, item: T) std.math.Order; the key is passed as the context argument, and the result is ?usize.
  5. How do divTrunc, divFloor and divCeil differ on -7 / 2?
    Answer-3, -4 and -3 respectively: toward zero, toward negative infinity, toward positive infinity.
  6. What replaced std.math.absCast and std.BoundedArray?
    Answer@abs (which returns the unsigned type) and std.ArrayList(T).initBuffer(&buf) with the appendBounded family.
  7. Why is "héllo".len 6 and not 5?
    Answerlen counts bytes and é is two bytes in UTF-8. Use std.unicode.utf8CountCodepoints for characters.
  8. When would you pick EnumArray over a hash map keyed by the enum?
    AnswerWhenever the key is an exhaustive enum: an EnumArray has a slot for every member, never allocates, cannot miss, and is indexed by the enum directly.
