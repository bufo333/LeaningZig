32. Command-line programs

In this chapter you will write programs that behave well in a terminal: they read arguments and flags, read standard input line by line or all at once, write results to standard output and complaints to standard error, look at environment variables, and exit with a status that scripts can trust. You will finish with a small read-eval-print loop of the kind IRON LEDGER offers behind --repl.

32.1 What main receives

Since Chapter 1 you have seen two shapes of main: pub fn main() void for programs that only print with std.debug.print, and pub fn main(init: std.process.Init) !void for everything else. In 0.16 that init parameter is how a program receives everything the operating system gave it. Its fields, from the standard library:

FieldWhat it is
init.iothe std.Io instance every file, clock and process operation needs
init.gpaa general purpose allocator, leak-checked in Debug
init.arenaa pointer to an arena that lives as long as the process; use init.arena.allocator()
init.minimal.argsthe command-line arguments
init.minimal.environthe raw environment block
init.environ_mapthe environment as a map you can query by name
init.preopensfiles handed over by a parent process (mostly WASI)

Nothing is global. A function that wants to read a file must be handed an io; a function that wants the arguments must be handed them. This is the same discipline as allocators, and it has the same benefit: you can see from a signature what a function is able to do.

32.2 Arguments

init.minimal.args is not a slice; it is an opaque handle that works the same on every platform. You either iterate it with std.process.Args.Iterator, or turn it into a slice with toSlice and an allocator. The first entry is always the program itself.

args.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var it = std.process.Args.Iterator.init(init.minimal.args);
    const prog = it.next().?;
    std.debug.print("program: {s}\n", .{prog});
    var n: usize = 0;
    while (it.next()) |arg| : (n += 1) {
        std.debug.print("arg[{d}] = \"{s}\"\n", .{ n, arg });
    }
    std.debug.print("{d} argument(s)\n", .{n});

    // The same list as a slice, allocated once from the process arena.
    const all = try init.minimal.args.toSlice(init.arena.allocator());
    std.debug.print("as a slice: {d} entries, last = {s}\n", .{ all.len, all[all.len - 1] });
}
$ zig run args.zig -- one "two words" 3
program: /Users/john/.cache/zig/o/0550ef7316e5d2796521459761bbf628/args
arg[0] = "one"
arg[1] = "two words"
arg[2] = "3"
3 argument(s)
as a slice: 4 entries, last = 3

Two habits to note. it.next() returns an optional, so the program name comes out with .? (it always exists) and the loop uses while (it.next()) |arg|. And the shell, not Zig, split the command line: "two words" arrived as one argument because of the quotes. The -- after zig run args.zig separates the compiler's arguments from the program's, exactly as zig build run -- does.

The arena allocator is the right choice for toSlice: the argument list is needed for the whole run and freed automatically at exit.

32.3 Parsing flags by hand

Zig's standard library has no flag-parsing framework, and for most programs you do not want one. A loop, std.mem.eql, std.mem.startsWith and an options struct with defaults handle -v, --days 30, --name=Kell and positional arguments in twenty lines, and the result is a plain struct the rest of the program can use.

flags.zig

const std = @import("std");

const Options = struct {
    verbose: bool = false,
    days: u32 = 1,
    name: []const u8 = "campaign",
    files: std.ArrayList([]const u8) = .empty,
};

const usage =
    \\usage: flags [-v] [--days N] [--name NAME] FILE...
    \\
;

fn parse(gpa: std.mem.Allocator, args: std.process.Args) !Options {
    var opts = Options{};
    var it = std.process.Args.Iterator.init(args);
    _ = it.next();
    while (it.next()) |arg| {
        if (std.mem.eql(u8, arg, "-v") or std.mem.eql(u8, arg, "--verbose")) {
            opts.verbose = true;
        } else if (std.mem.eql(u8, arg, "--days")) {
            const value = it.next() orelse return error.MissingValue;
            opts.days = try std.fmt.parseInt(u32, value, 10);
        } else if (std.mem.startsWith(u8, arg, "--name=")) {
            opts.name = arg["--name=".len..];
        } else if (std.mem.eql(u8, arg, "--help") or std.mem.eql(u8, arg, "-h")) {
            return error.HelpRequested;
        } else if (std.mem.startsWith(u8, arg, "-")) {
            std.debug.print("unknown flag: {s}\n", .{arg});
            return error.UnknownFlag;
        } else {
            try opts.files.append(gpa, arg);
        }
    }
    if (opts.files.items.len == 0) return error.NoFiles;
    return opts;
}

pub fn main(init: std.process.Init) u8 {
    var opts = parse(init.gpa, init.minimal.args) catch |err| switch (err) {
        error.HelpRequested => {
            std.debug.print("{s}", .{usage});
            return 0;
        },
        else => {
            std.debug.print("error: {s}\n{s}", .{ @errorName(err), usage });
            return 2;
        },
    };
    defer opts.files.deinit(init.gpa);
    std.debug.print("verbose={} days={d} name={s} files={d}\n", .{ opts.verbose, opts.days, opts.name, opts.files.items.len });
    for (opts.files.items) |f| std.debug.print("  {s}\n", .{f});
    return 0;
}
$ zig run flags.zig -- -v --days 30 --name=Kell a.txt b.txt
verbose=true days=30 name=Kell files=2
  a.txt
  b.txt
$ zig run flags.zig -- --help
usage: flags [-v] [--days N] [--name NAME] FILE...
$ zig run flags.zig -- --bogus x
unknown flag: --bogus
error: UnknownFlag
usage: flags [-v] [--days N] [--name NAME] FILE...
$ echo $?
2

The structure is worth copying. parse is a pure function from arguments to an Options struct or an error, so it can be tested without a terminal (Exercise 32.3 does exactly that). Values that follow a flag are pulled with another it.next(), and a missing one is an error, not a crash. The usage text is a multi-line string literal with \\, kept in one place. And main is the only function that talks to the user: it maps error.HelpRequested to a clean exit and everything else to a message plus a non-zero status.

32.4 Exit codes

Every process ends with a small integer, and shells, scripts and CI systems read it: zero means success, anything else means failure. Zig gives you three ways to set it.

  • Declare pub fn main(…) u8 and return the code. This is the clearest.
  • Declare main as returning an error union and let an error escape: the runtime prints error: Name with a stack trace and exits with 1.
  • Call std.process.exit(code) from anywhere. It never returns and runs no defers, so use it only for "stop right now" situations.

exit.zig

const std = @import("std");

pub fn main(init: std.process.Init) u8 {
    var it = std.process.Args.Iterator.init(init.minimal.args);
    _ = it.next();
    const arg = it.next() orelse {
        std.debug.print("usage: exit <code>\n", .{});
        return 64;
    };
    if (std.mem.eql(u8, arg, "now")) {
        std.debug.print("leaving immediately\n", .{});
        std.process.exit(3);
    }
    const code = std.fmt.parseInt(u8, arg, 10) catch {
        std.debug.print("not a number: {s}\n", .{arg});
        return 1;
    };
    std.debug.print("returning {d}\n", .{code});
    return code;
}
$ zig build-exe exit.zig
$ ./exit; echo "status $?"
usage: exit <code>
status 64
$ ./exit 7; echo "status $?"
returning 7
status 7
$ ./exit now; echo "status $?"
leaving immediately
status 3
$ ./exit zzz; echo "status $?"
not a number: zzz
status 1

And the error-union version, which is what most of your programs have used so far:

exit_err.zig

const std = @import("std");

fn risky() !void {
    return error.DiskFull;
}

pub fn main() !void {
    try risky();
}
$ ./exit_err; echo "status $?"
error: DiskFull
/…/exit_err.zig:4:5: 0x100b8594b in risky (exit_err)
    return error.DiskFull;
    ^
…
status 1

The stack trace is wonderful while developing and unpleasant for users. Programs meant for other people catch errors in main, print one line, and return a code. The traditional values from sysexits.h are a good vocabulary: 0 success, 1 general failure, 2 bad usage (many tools), 64 usage error, 65 bad input data, 70 internal error, 74 I/O error. Exercise 32.5 uses them.

std.process.exit skips cleanup. Buffered output that has not been flushed is lost, files are not closed by your defers, and the leak checker does not run. Prefer return code; from main, which unwinds normally.

32.5 Reading standard input line by line

Standard input is a file, std.Io.File.stdin(), and like every file in 0.16 you read it through a reader with a buffer you provide. The reader's interface is a *std.Io.Reader, and its takeDelimiter('\n') method returns the next line without the newline, or null at end of input. A line longer than your buffer is error.StreamTooLong, so the buffer size is a real decision.

lines.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var rbuf: [4096]u8 = undefined;
    var stdin = std.Io.File.stdin().reader(init.io, &rbuf);
    const in = &stdin.interface;

    var wbuf: [4096]u8 = undefined;
    var stdout = std.Io.File.stdout().writer(init.io, &wbuf);
    const out = &stdout.interface;

    var lines: u32 = 0;
    var words: u32 = 0;
    var bytes: u64 = 0;
    while (try in.takeDelimiter('\n')) |line| {
        lines += 1;
        bytes += line.len + 1;
        var it = std.mem.tokenizeAny(u8, line, " \t");
        while (it.next()) |_| words += 1;
        try out.print("{d:>4}: {s}\n", .{ lines, line });
    }
    try out.print("{d} lines, {d} words, {d} bytes\n", .{ lines, words, bytes });
    try out.flush();
}
$ printf 'alpha beta\ngamma\n\ndelta epsilon zeta\n' | zig run lines.zig
   1: alpha beta
   2: gamma
   3:
   4: delta epsilon zeta
4 lines, 6 words, 37 bytes
$ printf 'one\ntwo' | zig run lines.zig
   1: one
   2: two
2 lines, 2 words, 8 bytes

Two things to check against your intuition. An empty line comes back as an empty slice, not as null; only the true end of input is null. And a final line with no trailing newline is still returned, so "one\ntwo" counts as two lines. The slice you get points into the reader's buffer and is only valid until the next call, so copy it if you need to keep it.

Notice also that the program never blocks waiting for a terminal when its input is a pipe or a file; it simply reads until the end. Run it with no pipe and it waits for you to type, line by line, until you press Ctrl-D.

32.6 Reading all of standard input

When the input is small and you want it whole, allocRemaining reads everything into one allocated slice. The Limit argument is a ceiling that turns a runaway input into error.StreamTooLong rather than an out-of-memory condition.

readall.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var rbuf: [1024]u8 = undefined;
    var stdin = std.Io.File.stdin().reader(init.io, &rbuf);
    const text = try stdin.interface.allocRemaining(init.gpa, .limited(1 << 20));
    defer init.gpa.free(text);
    var upper: u32 = 0;
    for (text) |c| if (std.ascii.isUpper(c)) {
        upper += 1;
    };
    std.debug.print("read {d} bytes, {d} upper-case letters\n", .{ text.len, upper });
}
$ printf 'Hello World\nBig Mek\n' | zig run readall.zig
read 20 bytes, 4 upper-case letters

.limited(1 << 20) is one megabyte; .unlimited exists but think twice before using it on input you do not control. The result belongs to you: defer init.gpa.free(text).

32.7 stdout for results, stderr for everything else

A terminal program has two output streams, and the distinction matters as soon as someone pipes your output into another program. Standard output is for the result; standard error is for diagnostics, progress, warnings. Both are files with buffered writers, and both must be flushed. std.debug.print writes to standard error, unbuffered, which is why it has been fine for teaching and is wrong for the main output of a real tool.

streams.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var obuf: [256]u8 = undefined;
    var stdout = std.Io.File.stdout().writer(init.io, &obuf);
    const out = &stdout.interface;
    var ebuf: [256]u8 = undefined;
    var stderr = std.Io.File.stderr().writer(init.io, &ebuf);
    const err = &stderr.interface;

    try out.print("day,funds\n", .{});
    var funds: i64 = 1000;
    for (1..4) |day| {
        funds -= 150;
        try out.print("{d},{d}\n", .{ day, funds });
        if (funds < 700) try err.print("warning: day {d} funds low ({d})\n", .{ day, funds });
    }
    try out.flush();
    try err.flush();
}
$ zig run streams.zig 2>/dev/null
day,funds
1,850
2,700
3,550
$ zig run streams.zig >/dev/null
warning: day 3 funds low (550)

The CSV goes to stdout and survives 2>/dev/null; the warning goes to stderr and survives >/dev/null. Someone can now write streams > report.csv and still see the warning on their screen.

Flush before you block. Output sits in your buffer until flush(). If you print a prompt and then wait for input, flush the prompt first or the user will stare at a blank line. The REPL in section 32.9 does this on every turn.

32.8 Environment variables

init.environ_map is a pointer to a map from names to values, built from the process environment. get returns an optional slice; contains and count do what they say.

env.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const env = init.environ_map;
    const home = env.get("HOME") orelse "(unset)";
    std.debug.print("HOME = {s}\n", .{home});
    const seed_text = env.get("LEDGER_SEED") orelse "3025";
    const seed = try std.fmt.parseInt(u64, seed_text, 10);
    std.debug.print("seed = {d}\n", .{seed});
    std.debug.print("has PATH? {}\n", .{env.contains("PATH")});
    std.debug.print("{d} variables in the environment\n", .{env.count()});
}
$ LEDGER_SEED=99 zig run env.zig
HOME = /Users/john
seed = 99
has PATH? true
59 variables in the environment

The value is a plain []const u8 owned by the map, so it is valid for the life of the program and you do not free it. Parse it as you would any string. The orelse "3025" idiom gives a default without a branch, and is the usual way to let an environment variable override a built-in setting.

32.9 A read-eval-print loop

Everything so far combines into a small interactive shell: print a prompt, flush, read a line, split off the command word, act, repeat, until quit or end of input. This is a miniature of the game's --repl mode, which drives the whole simulation from typed commands.

repl.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var rbuf: [1024]u8 = undefined;
    var stdin = std.Io.File.stdin().reader(init.io, &rbuf);
    const in = &stdin.interface;
    var wbuf: [1024]u8 = undefined;
    var stdout = std.Io.File.stdout().writer(init.io, &wbuf);
    const out = &stdout.interface;

    var funds: i64 = 1000;
    var day: u32 = 1;
    try out.print("ledger repl. commands: day, pay N, earn N, status, quit\n", .{});
    while (true) {
        try out.print("day {d}> ", .{day});
        try out.flush();
        const raw = try in.takeDelimiter('\n') orelse break;
        const line = std.mem.trim(u8, raw, " \t\r");
        if (line.len == 0) continue;
        var it = std.mem.tokenizeScalar(u8, line, ' ');
        const cmd = it.next().?;
        if (std.mem.eql(u8, cmd, "quit")) break;
        if (std.mem.eql(u8, cmd, "day")) {
            day += 1;
            funds -= 50;
        } else if (std.mem.eql(u8, cmd, "pay") or std.mem.eql(u8, cmd, "earn")) {
            const n = std.fmt.parseInt(i64, it.next() orelse "", 10) catch {
                try out.print("  usage: {s} N\n", .{cmd});
                continue;
            };
            funds += if (cmd[0] == 'p') -n else n;
        } else if (std.mem.eql(u8, cmd, "status")) {
            try out.print("  day {d}, {d} C-bills\n", .{ day, funds });
        } else {
            try out.print("  unknown command: {s}\n", .{cmd});
        }
    }
    try out.print("\nbye. final balance {d}\n", .{funds});
    try out.flush();
}
$ printf 'status\nearn 500\nday\nday\npay abc\nfly\nstatus\nquit\n' | zig run repl.zig
ledger repl. commands: day, pay N, earn N, status, quit
day 1>   day 1, 1000 C-bills
day 1> day 1> day 2> day 3>   usage: pay N
day 3>   unknown command: fly
day 3>   day 3, 1400 C-bills
day 3>
bye. final balance 1400

Piping input in shows the prompts jammed together, because the input is not echoed; type the same commands by hand and it reads naturally. The shape to remember: trim the raw line, skip empty lines, tokenizeScalar to get the command and its arguments, parseInt with a catch that prints usage and continues, and orelse break on the read so end of input ends the loop cleanly.

In IRON LEDGER. The executable's entry point, game/src/main.zig, is the flag loop from section 32.3 in the real world:

The --repl mode in game/src/sim/cli.zig is the loop from section 32.9 with the game's command set behind it.

Exercise 32.1 · echo warm-up

Print the arguments separated by spaces to stdout, with -n suppressing the newline and -u upper-casing. File: exercises/32-cli/ex1_echo.zig.

Solution 
//! Chapter 32, exercise 1: echo with options.
//! Run with:  zig run ex1_echo.zig -- -n hello world
//! Expected output (for the command above, on stdout):
//!   hello world
//! With no arguments it prints an empty line. `-n` suppresses the newline,
//! `-u` upper-cases every word.
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buf: [1024]u8 = undefined;
    var stdout = std.Io.File.stdout().writer(init.io, &buf);
    const out = &stdout.interface;

    var newline = true;
    var upper = false;
    var first = true;
    var it = std.process.Args.Iterator.init(init.minimal.args);
    _ = it.next();
    while (it.next()) |arg| {
        if (std.mem.eql(u8, arg, "-n")) {
            newline = false;
            continue;
        }
        if (std.mem.eql(u8, arg, "-u")) {
            upper = true;
            continue;
        }
        if (!first) try out.writeByte(' ');
        first = false;
        if (upper) {
            for (arg) |c| try out.writeByte(std.ascii.toUpper(c));
        } else {
            try out.writeAll(arg);
        }
    }
    if (newline) try out.writeByte('\n');
    try out.flush();
}

Flags are consumed with continue so they never reach the printing code. writeByte and writeAll on the buffered writer avoid formatting when there is nothing to format.

Exercise 32.3 · A testable flag parser practice

Write parse(gpa, args: []const []const u8) !Options supporting -v, --days N, --name NAME, --name=NAME, -h, and a bare -- after which everything is positional. Positionals are returned as an owned slice. File: exercises/32-cli/ex3_flags.zig.

Solution 
//! Chapter 32, exercise 3: a flag parser you can test.
//! Run with:  zig test ex3_flags.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

pub const Options = struct {
    verbose: bool = false,
    days: u32 = 1,
    name: []const u8 = "campaign",
    /// Positional arguments, in order.
    files: []const []const u8 = &.{},
};

pub const ParseError = error{ MissingValue, BadNumber, UnknownFlag, HelpRequested };

/// Parse `args` (WITHOUT the program name). Positionals are copied into a
/// slice allocated from `gpa`; the caller frees `options.files`.
/// Supported: -v / --verbose, --days N, --name NAME, --name=NAME, -h / --help.
/// Everything after a bare "--" is positional even if it starts with "-".
pub fn parse(gpa: std.mem.Allocator, args: []const []const u8) (ParseError || std.mem.Allocator.Error)!Options {
    var opts = Options{};
    var files: std.ArrayList([]const u8) = .empty;
    errdefer files.deinit(gpa);
    var i: usize = 0;
    var only_positional = false;
    while (i < args.len) : (i += 1) {
        const arg = args[i];
        if (only_positional or !std.mem.startsWith(u8, arg, "-")) {
            try files.append(gpa, arg);
        } else if (std.mem.eql(u8, arg, "--")) {
            only_positional = true;
        } else if (std.mem.eql(u8, arg, "-v") or std.mem.eql(u8, arg, "--verbose")) {
            opts.verbose = true;
        } else if (std.mem.eql(u8, arg, "-h") or std.mem.eql(u8, arg, "--help")) {
            return error.HelpRequested;
        } else if (std.mem.eql(u8, arg, "--days")) {
            i += 1;
            if (i >= args.len) return error.MissingValue;
            opts.days = std.fmt.parseInt(u32, args[i], 10) catch return error.BadNumber;
        } else if (std.mem.eql(u8, arg, "--name")) {
            i += 1;
            if (i >= args.len) return error.MissingValue;
            opts.name = args[i];
        } else if (std.mem.startsWith(u8, arg, "--name=")) {
            opts.name = arg["--name=".len..];
        } else {
            return error.UnknownFlag;
        }
    }
    opts.files = try files.toOwnedSlice(gpa);
    return opts;
}

test "flags and positionals" {
    const gpa = std.testing.allocator;
    const o = try parse(gpa, &.{ "-v", "--days", "30", "--name=Kell", "a.txt", "b.txt" });
    defer gpa.free(o.files);
    try std.testing.expect(o.verbose);
    try std.testing.expectEqual(@as(u32, 30), o.days);
    try std.testing.expectEqualStrings("Kell", o.name);
    try std.testing.expectEqual(@as(usize, 2), o.files.len);
    try std.testing.expectEqualStrings("b.txt", o.files[1]);
}

    try std.testing.expectEqualStrings("campaign", o.name);
    try std.testing.expectEqual(@as(usize, 0), o.files.len);

test "separate --name value and the -- separator" {
    const gpa = std.testing.allocator;

Exercise 32.4 · A calculator REPL practice

Prompt with > , read A op B lines, print the result or error: Name, stop on quit or end of input. Keep eval pure and test it. File: exercises/32-cli/ex4_repl.zig.

Solution 
//! Chapter 32, exercise 4: a calculator REPL.
//! Run with:  zig run ex4_repl.zig
//! Then type lines such as  2 + 3  or  10 * 4 , and  quit  to leave.
//! Expected output for  printf '2 + 3\n10 / 4\n7 % 0\nquit\n' | zig run ex4_repl.zig
//!   > 5
//!   > 2
//!   > error: DivisionByZero
//!   > bye
//! Prompt goes to stdout and is flushed before each read. EOF ends the loop
//! exactly like "quit".
const std = @import("std");

const Error = error{ BadSyntax, BadNumber, DivisionByZero, UnknownOperator };

fn eval(line: []const u8) Error!i64 {
    var it = std.mem.tokenizeScalar(u8, line, ' ');
    const a_text = it.next() orelse return error.BadSyntax;
    const op = it.next() orelse return error.BadSyntax;
    const b_text = it.next() orelse return error.BadSyntax;
    if (it.next() != null) return error.BadSyntax;
    const a = std.fmt.parseInt(i64, a_text, 10) catch return error.BadNumber;
    const b = std.fmt.parseInt(i64, b_text, 10) catch return error.BadNumber;
    if (op.len != 1) return error.UnknownOperator;
    return switch (op[0]) {
        '+' => a + b,
        '-' => a - b,
        '*' => a * b,
        '/' => if (b == 0) error.DivisionByZero else @divTrunc(a, b),
        '%' => if (b == 0) error.DivisionByZero else @rem(a, b),
        else => error.UnknownOperator,
    };
}

pub fn main(init: std.process.Init) !void {
    var rbuf: [1024]u8 = undefined;
    var stdin = std.Io.File.stdin().reader(init.io, &rbuf);
    const in = &stdin.interface;
    var wbuf: [1024]u8 = undefined;
    var stdout = std.Io.File.stdout().writer(init.io, &wbuf);
    const out = &stdout.interface;

    while (true) {
        try out.writeAll("> ");
        try out.flush();
        const raw = try in.takeDelimiter('\n') orelse break;
        const line = std.mem.trim(u8, raw, " \t\r");
        if (line.len == 0) continue;
        if (std.mem.eql(u8, line, "quit")) break;
        if (eval(line)) |v| {
            try out.print("{d}\n", .{v});
        } else |err| {
            try out.print("error: {s}\n", .{@errorName(err)});
        }
    }
    try out.writeAll("bye\n");
    try out.flush();
}

test "eval" {
    try std.testing.expectEqual(@as(i64, 5), try eval("2 + 3"));
    try std.testing.expectEqual(@as(i64, -8), try eval("2 * -4"));
    try std.testing.expectError(error.DivisionByZero, eval("1 / 0"));
    try std.testing.expectError(error.BadSyntax, eval("1 +"));
    try std.testing.expectError(error.UnknownOperator, eval("1 ^ 2"));
}

The file both runs and tests: zig run uses main, zig test runs the eval test and ignores main. Division uses @divTrunc because / on signed integers is a compile error unless the sign is known.

Exercise 32.5 · Exit codes challenge

Sum the arguments and print the total (no arguments prints 0). --help: usage on stderr, status 0. Any other --flag: usage, status 64. A non-number: message, status 65. The word abort: std.process.exit(70) immediately. Output failures: 74. File: exercises/32-cli/ex5_exitcodes.zig.

Solution 
//! Chapter 32, exercise 5: exit codes that scripts can trust.
//! Run with:  zig run ex5_exitcodes.zig -- 12 30
//! Expected output (stdout): "42" and exit status 0. With no arguments: "0".
//! Rules: --help          -> usage on stderr, status 0;
//!        any other --flag -> usage on stderr, status 64 (EX_USAGE);
//!        a non-number     -> message on stderr, status 65 (EX_DATAERR);
//!        the word "abort" anywhere -> std.process.exit(70) immediately.
const std = @import("std");

pub fn main(init: std.process.Init) u8 {
    var obuf: [128]u8 = undefined;
    var stdout = std.Io.File.stdout().writer(init.io, &obuf);
    const out = &stdout.interface;

    var it = std.process.Args.Iterator.init(init.minimal.args);
    _ = it.next();
    var sum: i64 = 0;
    while (it.next()) |arg| {
        if (std.mem.eql(u8, arg, "--help")) {
            std.debug.print("usage: exitcodes [--help] N [N...]\n", .{});
            return 0;
        }
        if (std.mem.startsWith(u8, arg, "--")) {
            std.debug.print("unknown flag {s}\nusage: exitcodes [--help] N [N...]\n", .{arg});
            return 64;
        }
        if (std.mem.eql(u8, arg, "abort")) {
            std.debug.print("aborting on request\n", .{});
            std.process.exit(70);
        }
        const n = std.fmt.parseInt(i64, arg, 10) catch {
            std.debug.print("not a number: {s}\n", .{arg});
            return 65;
        };
        sum += n;
    }
    out.print("{d}\n", .{sum}) catch return 74;
    out.flush() catch return 74;
    return 0;
}
$ ./ex5_exitcodes 12 30; echo "status $?"
42
status 0
$ ./ex5_exitcodes --bogus; echo "status $?"
unknown flag --bogus
usage: exitcodes [--help] N [N...]
status 64
$ ./ex5_exitcodes 1 x; echo "status $?"
not a number: x
status 65
$ ./ex5_exitcodes 1 abort; echo "status $?"
aborting on request
status 70

Because main returns u8 it cannot use try; every failing call gets an explicit catch return code. That is the price of precise exit codes, and it is a small one.

Check your understanding

  1. How do you get the command-line arguments in 0.16?
    AnswerFrom init.minimal.args, iterated with std.process.Args.Iterator.init(…) or converted with toSlice(allocator). The first entry is the program name.
  2. What are the three ways to set the exit status, and which one skips defer?
    AnswerReturn a u8 from main, let an error escape from main (status 1 with a trace), or call std.process.exit(code), which never returns and runs no defers.
  3. What does takeDelimiter('\n') return for an empty line, and at the end of input?
    AnswerAn empty slice for an empty line; null at end of input. A last line without a newline is still returned.
  4. Why should a program's result go to stdout and its warnings to stderr?
    AnswerSo the result can be piped or redirected into a file without the warnings, and the warnings still reach the terminal.
  5. What happens if you print a prompt and read a line without flushing?
    AnswerThe prompt stays in the buffer; the user sees nothing and the program appears to hang while waiting for input.
  6. How do you read an environment variable with a default?
    Answerinit.environ_map.get("NAME") orelse "default". The returned slice is owned by the map and is not freed by you.
  7. Why is parse in the flag examples written to take a slice of strings instead of reading init directly?
    AnswerSo it can be called from tests with literal argument lists, and so the only code that touches the process is main.
What you learned.
  • std.process.Init carries io, gpa, arena, minimal.args, environ_map; nothing is global.
  • Iterate arguments with std.process.Args.Iterator; parse flags with a loop, std.mem.eql/startsWith, and an options struct.
  • Return u8 from main for exit codes; escaping errors give status 1; std.process.exit is immediate and skips cleanup.
  • Read stdin with std.Io.File.stdin().reader(io, &buf) and takeDelimiter('\n'), or all at once with allocRemaining and a limit.
  • Write results to a buffered stdout writer and diagnostics to stderr; flush both, and flush prompts before reading.
  • Environment variables come from init.environ_map.get.
  • A REPL is prompt, flush, read, trim, tokenize, dispatch, repeat; end of input ends it.
