Appendix A5. Glossary

This appendix defines the terms the course uses, in alphabetical order, with a link to the chapter that introduces each. Zig terms come first in a definition; where IRON LEDGER gives a term a specific meaning, that follows.

allocator
A value of type std.mem.Allocator that hands out and takes back memory. Nothing in Zig allocates without being given one. Chapter 19.
anonymous struct literal
.{ .x = 1 }: a struct value whose type is inferred from where it is used. Also the syntax of ZON files. Chapter 12, Chapter 28.
anytype
A parameter type meaning "whatever the caller passes"; the function is specialised per argument type at compile time. Chapter 26.
arena
std.heap.ArenaAllocator: an allocator that never frees individually and releases everything in one deinit. IRON LEDGER gives each campaign one and each frame another. Chapter 20, Chapter 41.
array
A fixed number of elements known at compile time: [3]u8. Copied by value. Chapter 9.
ArrayList
The standard growable list. In 0.16 it is unmanaged: it starts as .empty and every growing call takes an allocator. Chapter 21.
basis points
Hundredths of a percent; 10,000 is a multiplier of one. IRON LEDGER's Bp type, applied by applyBp in integer arithmetic. Chapter 45.
builtin
A function whose name starts with @, provided by the language rather than the standard library. A1.
build.zig
The build script: an ordinary Zig program that describes modules, executables, tests and options as a graph of steps. Chapter 31.
C-bill
The BattleTech currency. In IRON LEDGER, CBills = i64; there are no floats in money. Chapter 45.
capture
The |x| after if, while, for, catch or a switch arm that binds the unwrapped value, the payload or the error. Chapter 6, Chapter 14.
catch
Handle an error in place: f() catch default, catch |err| { … }, catch unreachable. Chapter 16.
coercion
An implicit conversion the compiler allows because it cannot lose information: u8 to u32, *[3]u8 to []u8, a literal to a typed value. Everything else needs a cast. Chapter 4, Chapter 10.
command
In IRON LEDGER, a value of the Command tagged union; the only way to change a campaign is to pass one to commands.execute. Chapter 42.
comptime
Code and values evaluated while compiling. A comptime parameter must be known at compile time; types are values only at compile time. Chapter 25.
defer
Run a statement when the enclosing block exits by any path. errdefer runs only when it exits with an error. Chapter 17.
determinism
The property that the same inputs produce the same outputs. IRON LEDGER's core is a pure function of a seed and a command history, tested by the golden master. Chapter 39, Chapter 49.
doc comment
/// documents the next declaration; //! documents the file. // is an ordinary comment. Chapter 30.
enum
A closed set of named values, optionally with an integer representation and methods. A non-exhaustive enum (enum(u32) { none = 0, _ }) also accepts every other integer; IRON LEDGER's typed IDs are these. Chapter 13.
error set
A set of error names, error{ A, B }. Sets merge with ||; anyerror is the set of all of them. Chapter 16.
error union
E!T: either an error from E or a T. !T lets the compiler infer E. Chapter 16.
exhaustive switch
A switch that names every case of an enum, union or error set and therefore fails to compile when a case is added. IRON LEDGER uses this as a checklist. Chapter 14, Chapter 46.
extern fn
A declaration of a function defined elsewhere, usually in a C library, with C-shaped parameter types. Chapter 35, Chapter 47.
format string
The first argument of print: literal text with {…} placeholders, checked against the argument tuple at compile time. Chapter 23, A2.
frame arena
In IRON LEDGER's client, the arena reset before each draw and each key; query results live in it. Chapter 44, Chapter 48.
generic
A function that takes a comptime T: type and returns a value or type built from it, such as std.ArrayList(u32). Chapter 26.
golden master
A test that runs a fixed script from a fixed seed twice and compares a hash of the results. Chapter 49.
hash map
std.AutoHashMapUnmanaged(K, V) and relatives. The ArrayHashMap variants keep insertion order, which IRON LEDGER needs for determinism. Chapter 22, Chapter 41.
inline for
A loop unrolled at compile time, one copy of the body per element; required to iterate a tuple or a type's fields. Chapter 27.
io
A value of type std.Io, received in main as init.io, that every file, clock, process and sleep operation takes. Code without one cannot do I/O. Chapter 33, Chapter 39.
labeled block
blk: { … break :blk value; }: a block that yields a value. Chapter 6.
ledger
In IRON LEDGER, the append-only list of tagged transactions from which every balance and report is computed. Chapter 45.
many-item pointer
[*]T: a pointer to an unknown number of elements, with no length. [*:0]const u8 is a C string. Chapter 10, Chapter 35.
markup
In IRON LEDGER's query text, {g}…{/} tokens naming a style, rendered by the terminal client and stripped by the REPL. Chapter 44.
migration
A guarded schema change applied when an old save file is opened; in IRON LEDGER a row in store.migrations. Chapter 47.
module
A tree of source files with one root, declared in build.zig and imported by name. IRON LEDGER has a library module game and an executable module. Chapter 30, Chapter 31.
opaque
opaque {}: a type with unknown contents that can only be pointed to; the type of a C handle. Chapter 35.
optional
?T: a T or null. Unwrapped with orelse, if (x) |v|, or .?. Chapter 15.
orelse
Supply a fallback for a null optional, or exit early: x orelse return error.Missing. Chapter 15.
packed struct
A struct with a specified bit layout, packed struct(u8) { lo: u4, hi: u4 }, convertible to its integer with @bitCast. Chapter 29.
payload
The value carried by a union variant, an optional or an error union; bound by a capture. Chapter 14.
phase
In IRON LEDGER, one function of the daily tick, called in a fixed order from advanceDay. Chapter 43.
pointer
*T is the address of one T; *const T cannot write through; &x takes an address; p.* dereferences. Field access through a pointer needs no arrow. Chapter 18.
PRNG
A pseudo-random number generator: std.Random.DefaultPrng, seeded so its sequence is repeatable. IRON LEDGER keeps eight in a bag with named streams. Chapter 34, Chapter 41.
pub
Makes a declaration visible to importers. Without it, a declaration is private to its file. Chapter 30.
pure
Of a function or module: its result depends only on its inputs, with no I/O, wall clock or global state. IRON LEDGER's src/domain, sim, econ and gen are pure. Chapter 39.
query
In IRON LEDGER, a function in queries.zig that takes an allocator and the state and returns formatted rows with IDs; the only way a frontend reads the simulation. Chapter 44.
refAllDecls
std.testing.refAllDecls(@This()) in a test: references every public declaration so that unreferenced code is still compiled. Chapter 8, Chapter 49.
reflection
Inspecting types at compile time with @typeInfo, @field, @hasDecl and friends. Chapter 27.
REPL
IRON LEDGER's line-oriented console (--repl): reads verbs, parses them with cli.parseCommand, executes, prints. Chapter 39.
result type
The type the compiler infers for an expression from its surroundings; casts like @intCast rely on it. A1.
saturating arithmetic
+|, -|: clamp at the type's bounds instead of overflowing. need -| have is never negative. Chapter 4.
seed
The integer a PRNG starts from; the same seed gives the same sequence. IRON LEDGER's campaign seed is part of Config. Chapter 34.
sentinel
A terminating value in a pointer or slice type: [:0]const u8 is guaranteed to end with a zero byte. Chapter 10, Chapter 35.
shadowing
Reusing an outer name for an inner declaration. A compile error in Zig. Chapter 7, A4.
slice
[]T: a pointer plus a length. Strings are []const u8. Made by slicing an array, arr[a..b]. Chapter 10.
stream (RNG)
In IRON LEDGER, one of eight named generators (.battle, .market, …) so that adding rolls to one subsystem does not disturb another. Chapter 41.
struct
A record of named fields, optionally with defaults and with functions declared inside. Every Zig file is one. Chapter 12, Chapter 30.
tagged union
union(enum) { a: u32, b }: a value that is exactly one of several alternatives and knows which. Consumed by switch with payload captures. Chapter 14.
test block
test "name" { … }, run by zig test or zig build test, using std.testing's assertions and leak-checking allocator. Chapter 8.
tick
In IRON LEDGER, one call of tick.advanceDay: the clock moves one day and every phase runs. Chapter 43.
treasury
In IRON LEDGER, a tagged union naming which balance money moves in: the outfit, an HQ, or a deployed company. Chapter 45.
try
Evaluate an error union; on an error, return it from the current function. Chapter 16.
tuple
An anonymous struct with positional fields, .{ 1, "x" }; the argument list of print. Iterated with inline for. Chapter 23, Chapter 27.
typed ID
In IRON LEDGER, a non-exhaustive enum over u32 (PersonId, UnitId…) so that IDs of different kinds cannot be mixed up at no runtime cost. Chapter 13, Chapter 41.
undefined
A value you promise to write before reading; var buf: [64]u8 = undefined;. Debug builds fill it with 0xAA. Chapter 3.
unmanaged
Of a container: it does not store an allocator, so you pass one to every call that may allocate. The 0.16 default for lists and maps. Chapter 21.
unreachable
An expression asserting that control never gets here; a panic in safe builds, undefined behaviour in fast ones. Chapter 6.
wrapping arithmetic
+%, *%: overflow wraps around instead of panicking. Used where the wrap is intended, as in seeding RNG streams. Chapter 4.
writer
*std.Io.Writer: the interface print, writeAll and flush are called on; obtained from a file with a buffer, from a fixed buffer, or from an allocator. Chapter 2, Chapter 33.
ZON
Zig Object Notation: a data file that is a single Zig literal, imported with @import and type-checked against the declaration that receives it. Chapter 28, Chapter 40.
