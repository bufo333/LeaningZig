25. comptime

In this chapter you will learn the idea that makes Zig different from every language you have used so far: the compiler can run your code. You will see what "known at compile time" means, the comptime keyword on values, blocks and parameters, the special types comptime_int and comptime_float, types as ordinary values, inline for and inline while, compile-time string concatenation, tables computed while compiling, @compileError, @compileLog, the evaluation quota, and why Zig has no macros and no preprocessor.

25.1 Two worlds

Every value in a Zig program lives in one of two worlds. Either the compiler knows it while it is compiling, or it will only exist when the program runs. The literal 12 is in the first world; a number typed by the user is in the second. Most languages keep these worlds far apart: constants on one side, everything else on the other, and a separate macro or template language for anything in between. Zig instead lets ordinary functions run in either world, and gives you one keyword, comptime, to insist on the first.

a_two_worlds.zig

const std = @import("std");

fn square(x: u32) u32 {
    return x * x;
}

pub fn main() void {
    const a = square(12); // the compiler knows 12, so it can run square now
    const b = comptime square(12); // ...and this insists that it does

    var input: u32 = 12;
    input += 1; // now the compiler cannot know the value
    const c = square(input); // so this runs when the program runs

    std.debug.print("{d} {d} {d}\n", .{ a, b, c });
    std.debug.print("{s} {s} {s}\n", .{ @typeName(@TypeOf(a)), @typeName(@TypeOf(b)), @typeName(@TypeOf(c)) });
}
144 144 169
u32 u32 u32

square is a normal function; nothing about it says "compile time". The first call has a constant argument, so the compiler may evaluate it early (and in practice does). The second call is marked comptime, so the compiler must evaluate it, and it would be an error if it could not. The third call has an argument that depends on a mutated variable, so it necessarily happens at run time. All three produce a u32; the world a value comes from does not change its type, only when it was computed.

The rule that decides the world is simple. A value is comptime-known if it is a literal, a const initialised from comptime-known values, the result of calling a function with comptime-known arguments, or anything marked comptime. A var is never comptime-known once it has been mutated at run time, and anything read from outside the program (arguments, files, the clock) is runtime by nature.

25.2 comptime_int and comptime_float

What type does the literal 12 have before you assign it anywhere? Not i32, not u8; in Zig it is comptime_int, an integer of unlimited size that exists only in the compiler.

b_literal_types.zig

const std = @import("std");

pub fn main() void {
    const n = 1 << 40; // no annotation: comptime_int, any size
    const big = 1 << 100; // far bigger than u64; fine, it is not a machine integer
    const f = 2.5; // comptime_float

    std.debug.print("{s} {s} {s}\n", .{ @typeName(@TypeOf(n)), @typeName(@TypeOf(big)), @typeName(@TypeOf(f)) });
    std.debug.print("{d}\n", .{big});

    const fits: u8 = 200; // comptime_int coerces when it fits
    std.debug.print("{d}\n", .{fits});
}
comptime_int comptime_int comptime_float
1267650600228229401496703205376
200

1 << 100 is a perfectly good comptime_int: it never has to fit in a register because it never reaches the CPU. When a comptime value is stored into a typed location, it coerces to that type if it fits, which is why const fits: u8 = 200 works with no cast. If it does not fit, the compiler says so:

b_overflow.zig

const std = @import("std");
pub fn main() void {
    const x: u8 = 200 + 100; // both sides known: checked at compile time
    std.debug.print("{d}\n", .{x});
}
b_overflow.zig:3:23: error: type 'u8' cannot represent integer value '300'
    const x: u8 = 200 + 100; // both sides known: checked at compile time
                  ~~~~^~~~~

This is the same overflow check you met in Chapter 4, but caught before the program exists. The rule to remember: arithmetic on comptime-known values is checked by the compiler; arithmetic on runtime values is checked by the safety mode. Both refuse to let 300 into a u8; they just complain at different moments.

25.3 comptime blocks, comptime var and the quota

c_comptime_var.zig

const std = @import("std");

fn fib(n: u32) u64 {
    return if (n < 2) n else fib(n - 1) + fib(n - 2);
}

pub fn main() void {
    // A comptime block: everything in it runs in the compiler.
    const fib15 = comptime blk: {
        @setEvalBranchQuota(100_000); // recursion needs more than the default 1000 branches
        break :blk fib(15);
    };

    // comptime var: a variable that exists only during compilation.
    comptime var total = 0;
    inline for (.{ 1, 2, 3, 4 }) |v| total += v;

    std.debug.print("fib(15) = {d}, total = {d}\n", .{ fib15, total });
    std.debug.print("{s}\n", .{@typeName(@TypeOf(total))});
}
fib(15) = 610, total = 10
comptime_int

A comptime block (or a labelled block with break :blk, as here) runs entirely in the compiler; the result is baked into the binary as a constant, so fib(15) costs nothing at run time. A comptime var is a variable that only the compiler can see and change; the loop that adds to total is unrolled and the final value, 10, is what the program contains. Its type stays comptime_int.

The compiler is not an infinitely patient interpreter. To stop a mistaken infinite loop from hanging your build, each compile-time evaluation gets a budget of one thousand "backward branches" (loop iterations and recursive calls). Exceed it and you get this:

c_quota.zig

fn slow() u32 {
    var s: u32 = 0;
    for (0..5000) |i| s +%= @intCast(i);
    return s;
}
pub fn main() void {
    const v = comptime slow();
    @import("std").debug.print("{d}\n", .{v});
}
c_quota.zig:3:5: error: evaluation exceeded 1000 backwards branches
    for (0..5000) |i| s +%= @intCast(i);
    ^~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
c_quota.zig:3:5: note: use @setEvalBranchQuota() to raise the branch limit from 1000
c_quota.zig:7:28: note: called at comptime here
    const v = comptime slow();
                       ~~~~^~

The fix is what the note says: call @setEvalBranchQuota(n) inside the scope being evaluated, with a number comfortably above what you need. In c_comptime_var.zig the call sits inside the block, before the recursive fib starts. It is not a global setting; it applies to the evaluation it appears in.

25.4 Types are values

At compile time, a type is just another value. It has a type of its own, type, and you can store it in a constant, pick it with an if, put it in an array, or pass it to a function. This single fact is the whole foundation of generics in Zig, which Chapter 26 builds on.

d_types_are_values.zig

const std = @import("std");

pub fn main() void {
    const T = u16; // a type stored in a constant
    const x: T = 65535;

    const Wide = if (@sizeOf(usize) == 8) u64 else u32; // chosen by an if, at compile time
    const y: Wide = 1;

    const types = [_]type{ u8, i32, f64, bool }; // an array of types
    inline for (types) |Ty| std.debug.print("{s}: {d} bytes\n", .{ @typeName(Ty), @sizeOf(Ty) });

    std.debug.print("{d} {d} {s}\n", .{ x, y, @typeName(Wide) });
}
u8: 1 bytes
i32: 4 bytes
f64: 8 bytes
bool: 1 bytes
65535 1 u64

The one restriction is that a type value only exists at compile time. You cannot make a runtime if choose between two types, and you cannot use a runtime integer as an array length, because the compiler has to lay out memory before the program runs:

d_runtime_type.zig

pub fn main() void {
    var n: u32 = 3;
    n += 1;
    const a = [n]u8{ 0, 0, 0, 0 }; // an array length must be known at compile time
    _ = a;
}
d_runtime_type.zig:4:16: error: unable to resolve comptime value
    const a = [n]u8{ 0, 0, 0, 0 }; // an array length must be known at compile time
               ^
d_runtime_type.zig:4:16: note: types must be comptime-known

The message "types must be comptime-known" is one you will see often while learning. It always means the same thing: something that shapes memory or code (an array length, a type, a field name) depended on a runtime value. The fix is either to make the value comptime (a constant, a comptime parameter) or to use a runtime structure (a slice, an ArrayList) instead.

25.5 inline for and inline while

A normal for loop is one piece of code that runs many times. An inline for is many pieces of code, one per iteration, generated by the compiler; the loop variable is a compile-time constant inside each copy. That is what lets each copy have a different type.

e_inline.zig

const std = @import("std");

const Difficulty = enum { easy, hard };
const Config = struct { seed: u64, days: u32, difficulty: Difficulty, ironman: bool };

pub fn main() void {
    const cfg: Config = .{ .seed = 42, .days = 30, .difficulty = .hard, .ironman = true };

    // Walk the fields of a struct. The loop body is copied once per field,
    // and in each copy `f.name` and `f.type` are constants.
    inline for (@typeInfo(Config).@"struct".fields) |f| {
        std.debug.print("{s: <5} : {s: <12} = {any}\n", .{ f.name, @typeName(f.type), @field(cfg, f.name) });
    }

    // A tuple of mixed types: only an inline loop can handle each element by its own type.
    const mixed = .{ 1, 2.5, "three", false };
    inline for (mixed, 0..) |v, i| std.debug.print("{d}: {s}\n", .{ i, @typeName(@TypeOf(v)) });

    // inline while, with a comptime counter.
    comptime var i = 0;
    inline while (i < 3) : (i += 1) std.debug.print("unrolled {d}\n", .{i});
}
seed  : u64          = 42
days  : u32          = 30
difficulty : e_inline.Difficulty = .hard
ironman : bool         = true
0: comptime_int
1: comptime_float
2: *const [5:0]u8
3: bool
unrolled 0
unrolled 1
unrolled 2

The first loop is the most useful pattern in this chapter. @typeInfo(Config).@"struct".fields is a compile-time array describing the fields; f.name is a string, f.type is a type, and @field(cfg, f.name) reads the field by name. Because the loop is inline, @field gets a constant name each time and the whole thing compiles to four plain field reads. A runtime for could not do this: there is no such thing as a runtime field name. Chapter 27 is entirely about this kind of reflection.

The second loop walks a tuple whose elements have four different types. Only inline for can do that, because each iteration is compiled separately with its own @TypeOf(v). The third shows inline while with a comptime var counter, which is how you unroll a fixed count of iterations.

Use inline loops when you need to, not for speed. Each iteration is a separate copy of the code, so an inline for over a thousand elements produces a thousand copies of the body. The compiler is also perfectly capable of unrolling ordinary loops when that is faster. Reach for inline when the loop variable has to be comptime: field names, types, tuple elements.

25.6 Building strings in the compiler

++ concatenates arrays and slices, and ** repeats them. Both need the operands' lengths to be known at compile time, because the result is a fixed-size array.

f_concat.zig

const std = @import("std");

const prefix = "IRON";
const name = prefix ++ " " ++ "LEDGER"; // concatenation happens in the compiler
const banner = "=" ** name.len; // repetition too

fn withUnit(comptime label: []const u8) []const u8 {
    return label ++ " (tons)"; // label must be comptime for ++ to work
}

pub fn main() void {
    std.debug.print("{s}\n{s}\n", .{ name, banner });
    std.debug.print("{s}\n", .{withUnit("weight")});
    std.debug.print("{s}\n", .{@typeName(@TypeOf(name))});
}
IRON LEDGER
===========
weight (tons)
*const [11:0]u8

The result type, *const [11:0]u8, tells the story: a pointer to an eleven-byte, zero-terminated array that the compiler wrote into the binary. Nothing happens at run time. The withUnit function only works because its parameter is comptime; drop that keyword and label ++ " (tons)" fails because the compiler no longer knows how long label is. This is the exact device the tuning checker in IRON LEDGER uses to build dotted field paths.

The precise rule is about lengths, not contents. An array with runtime contents can still be concatenated, because its length is part of its type:

f_concat_array.zig

const std = @import("std");
pub fn main() void {
    var user: [8]u8 = "runtime!".*; // an array: its LENGTH is part of the type
    user[0] = 'R'; // its contents are decided at runtime
    const s = "value: " ++ user; // allowed: 7 + 8 bytes, the compiler knows the size
    std.debug.print("{s} ({s})\n", .{ s, @typeName(@TypeOf(s)) });
}
value: Runtime! (*const [15:0]u8)

A slice with a runtime length cannot:

f_concat_bad.zig

const std = @import("std");
pub fn main() void {
    var len: usize = 3;
    len += 1;
    const user: []const u8 = "runtime"[0..len]; // a slice whose length is a runtime value
    const s = "value: " ++ user;
    std.debug.print("{s}\n", .{s});
}
f_concat_bad.zig:6:28: error: unable to resolve comptime value
    const s = "value: " ++ user;
                           ^~~~
f_concat_bad.zig:6:28: note: slice being concatenated must be comptime-known

For runtime strings you use the tools of Chapter 21 and Chapter 23: an ArrayList(u8), allocPrint or bufPrint. For compile-time strings you use ++ and std.fmt.comptimePrint.

25.7 Tables computed at compile time

Whenever you find yourself writing a table of magic numbers by hand, ask whether the compiler could write it for you. It can, with an ordinary loop inside a block that initialises a constant.

g_table.zig

const std = @import("std");

/// The 2d6 probability table, in tenths of a percent, computed by the compiler.
const two_d6_permille: [13]u16 = blk: {
    var t: [13]u16 = @splat(0);
    for (1..7) |a| {
        for (1..7) |b| t[a + b] += 1;
    }
    for (&t) |*e| e.* = @intCast(@as(u32, e.*) * 1000 / 36);
    break :blk t;
};

/// A CRC-8 lookup table: 256 entries, each needing 8 inner steps.
fn crc8Table() [256]u8 {
    @setEvalBranchQuota(10_000); // 256 * 8 loop iterations exceed the default
    var t: [256]u8 = undefined;
    for (&t, 0..) |*e, i| {
        var c: u8 = @intCast(i);
        for (0..8) |_| c = if (c & 0x80 != 0) (c << 1) ^ 0x07 else c << 1;
        e.* = c;
    }
    return t;
}
const crc_table = crc8Table();

fn crc8(bytes: []const u8) u8 {
    var c: u8 = 0;
    for (bytes) |b| c = crc_table[c ^ b];
    return c;
}

comptime {
    // Sanity checks that run in the compiler. A failure is a build error.
    std.debug.assert(two_d6_permille[7] == 166);
    std.debug.assert(two_d6_permille[2] == two_d6_permille[12]);
    std.debug.assert(crc_table[0] == 0);
}

pub fn main() void {
    std.debug.print("P(7) = {d}.{d}%  P(12) = {d}.{d}%\n", .{
        two_d6_permille[7] / 10, two_d6_permille[7] % 10,
        two_d6_permille[12] / 10, two_d6_permille[12] % 10,
    });
    std.debug.print("crc8(\"123456789\") = 0x{x}\n", .{crc8("123456789")});
}
P(7) = 16.6%  P(12) = 2.7%
crc8("123456789") = 0xf4

Both tables are written into the executable as data; crc8 at run time is a loop with one table lookup per byte. Notice the ordinary for loops and an ordinary var inside the initialiser: because the whole block is evaluated by the compiler, they are compile-time loops and variables without any special keyword. The @setEvalBranchQuota in crc8Table is needed because 256 times 8 iterations is more than a thousand.

The top-level comptime { ... } block is a container-level assertion. Its std.debug.assert calls run during compilation, and a false one is a build error with a location, which is a cheap way to check that a table came out right, that a struct is the size you expect, or that two constants agree.

25.8 @compileError and @compileLog

@compileError("message") stops the build with your message, if the compiler ever reaches it. Put it behind a comptime condition and you have a custom compile-time check with a readable diagnostic.

h_compile_error.zig

const std = @import("std");

const Tuning = struct { max_lance: u8 = 4, repair_hours: u32 = 20 };
const t: Tuning = .{};

comptime {
    if (t.max_lance > 12) @compileError("a lance cannot have more than 12 units");
    if (@sizeOf(Tuning) > 64) @compileError("Tuning grew past a cache line");
}

fn checkedShift(comptime bits: u8, value: u32) u32 {
    if (bits >= 32) @compileError("shift amount " ++ std.fmt.comptimePrint("{d}", .{bits}) ++ " is too large for u32");
    return value << bits;
}

pub fn main() void {
    std.debug.print("{d}\n", .{checkedShift(4, 1)});
}
16

25.9 Why there are no macros

C has a preprocessor; C++ has templates; Rust has two macro systems; Lisp has real macros. Zig has none of these, and the reason is everything above. A macro is a program that writes program text. Zig lets you run the language itself while compiling, with the same syntax, the same functions, the same debugger-visible values. There is no second language to learn, no text substitution to reason about, and every error is reported in terms of real code with real types. Conditional compilation is an if on a comptime value. Generics are functions that take types. Lookup tables are loops. Type-dependent behaviour is a switch on @typeInfo. The cost of this design is that comptime code must be pure and finite (hence the quota) and cannot do I/O; the benefit is that "what does this expand to?" is never a question you have to ask.

In IRON LEDGER. The RNG module sizes an array by the number of enum members, so that adding a stream to the enum grows the array (game/src/sim/rng.zig): 
pub const Stream = enum(u8) {
    generation, market, maintenance, acquisition, battle, events, medical, travel,
    const count = @typeInfo(Stream).@"enum".fields.len;
};

pub const Rng = struct {
    prngs: [Stream.count]std.Random.DefaultPrng,
    ...
};
The tuning sanity test in game/src/domain/tuning.zig is 25.5 and 25.6 together: a recursive function with comptime T: type and comptime name: []const u8 parameters walks a nested struct with inline for, building the dotted path of each field with name ++ "." ++ f.name, so that a bad knob is reported as t.person.share_profit_default_bp. Because the type and the name are comptime, the recursion is entirely resolved during compilation; only the integer comparisons survive into the test binary. And the SQLite binding's else => @compileError("unsupported bind type " ++ @typeName(T)) is 25.8: try to bind a type it does not understand and the build stops with the type's name.

Exercise 25.1 · Powers of two warm-up

Fill a [64]u64 table of powers of two in a compile-time block, add a container-level comptime assertion on it, and write ceilLog2(n) ?u6 that searches the table at run time. Name the file: exercises/25-comptime/ex1_powers.zig.

Solution 
//! Chapter 25, exercise 1: a table computed by the compiler.
//! Run with:  zig test ex1_powers.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// powers[i] == 2^i for i in 0..64, filled in at compile time.
const powers: [64]u64 = blk: {
    var t: [64]u64 = undefined;
    for (&t, 0..) |*e, i| e.* = @as(u64, 1) << @intCast(i);
    break :blk t;
};

// Checks that run while compiling; a failure is a build error, not a test failure.
comptime {
    std.debug.assert(powers[0] == 1);
    std.debug.assert(powers[63] == 1 << 63);
}

/// The smallest i such that 2^i >= n, or null if n is 0 or too large.
fn ceilLog2(n: u64) ?u6 {
    if (n == 0) return null;
    for (powers, 0..) |p, i| {
        if (p >= n) return @intCast(i);
    }
    return null;
}

test "table" {
    try std.testing.expectEqual(@as(u64, 1024), powers[10]);
    try std.testing.expectEqual(@as(u64, 1 << 40), powers[40]);
}

test "ceilLog2" {
    try std.testing.expectEqual(@as(?u6, 0), ceilLog2(1));
    try std.testing.expectEqual(@as(?u6, 3), ceilLog2(8));
    try std.testing.expectEqual(@as(?u6, 4), ceilLog2(9));
    try std.testing.expectEqual(@as(?u6, null), ceilLog2(0));
    try std.testing.expectEqual(@as(?u6, null), ceilLog2(std.math.maxInt(u64)));
}

test "the table is a compile-time constant" {
    // If this were not comptime-known, the array length below would not compile.
    const n = comptime powers[3];
    const arr: [n]u8 = @splat(7);
    try std.testing.expectEqual(@as(usize, 8), arr.len);
}

The last test proves the table is a true constant: only a comptime-known value can be an array length. Note that a doc comment (///) may not sit on a comptime block; use a plain // comment.

Exercise 25.2 · Sieve practice

Compute is_prime: [1000]bool with a sieve of Eratosthenes at compile time (you will need @setEvalBranchQuota), write primesBelow(n), and make prime_count a compile-time constant usable as an array length. Name the file: exercises/25-comptime/ex2_sieve.zig.

Solution 
//! Chapter 25, exercise 2: a sieve of Eratosthenes at compile time.
//! Run with:  zig test ex2_sieve.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const limit = 1000;

/// is_prime[n] is true when n is prime, for n < limit. Built by the compiler.
const is_prime: [limit]bool = blk: {
    @setEvalBranchQuota(20_000); // the nested loops need more than the default
    var t: [limit]bool = @splat(true);
    t[0] = false;
    t[1] = false;
    var i: usize = 2;
    while (i * i < limit) : (i += 1) {
        if (!t[i]) continue;
        var j = i * i;
        while (j < limit) : (j += i) t[j] = false;
    }
    break :blk t;
};

/// How many primes are below `n` (n <= limit)?
fn primesBelow(n: usize) usize {
    var count: usize = 0;
    for (is_prime[0..n]) |p| {
        if (p) count += 1;
    }
    return count;
}

/// Computed once, at compile time, from the table. The loop runs `limit` times,
/// which is over the default quota, so raise it for this evaluation.
const prime_count = blk: {
    @setEvalBranchQuota(2000);
    break :blk primesBelow(limit);
};

test "small primes" {
    try std.testing.expect(is_prime[2]);
    try std.testing.expect(is_prime[97]);
    try std.testing.expect(!is_prime[1]);
    try std.testing.expect(!is_prime[91]); // 7 * 13
}

test "counts" {
    try std.testing.expectEqual(@as(usize, 25), primesBelow(100));
    try std.testing.expectEqual(@as(usize, 168), prime_count);
}

test "prime_count is usable as an array length" {
    const arr: [prime_count]u8 = undefined;
    try std.testing.expectEqual(@as(usize, 168), arr.len);
}

Two quotas: one for the sieve itself and one for the thousand-iteration count. Each is set inside the evaluation it serves. The same primesBelow function runs in the compiler for prime_count and at run time in the first test.

const std = @import("std");

/// Sum every integer field of a struct; skip fields of other types.
/// Fields of an anonymous literal like .{ .a = 1 } have type comptime_int, so accept that too.
fn sumIntFields(value: anytype) i64 {
    const T = @TypeOf(value);
    var total: i64 = 0;
    inline for (@typeInfo(T).@"struct".fields) |f| {
        switch (@typeInfo(f.type)) {
            .int, .comptime_int => total += @field(value, f.name),
            else => {},
        }
    }
    return total;
}

/// How many fields of type `bool` does the struct type T have? Computed at compile time.
fn boolFieldCount(comptime T: type) usize {
    comptime var n: usize = 0;
    inline for (@typeInfo(T).@"struct".fields) |f| {
        if (f.type == bool) n += 1;
    }
    return n;
}

/// The name of the first field whose type is `Wanted`, or null.
fn firstFieldOfType(comptime T: type, comptime Wanted: type) ?[]const u8 {
    inline for (@typeInfo(T).@"struct".fields) |f| {
        if (f.type == Wanted) return f.name;
    }
    return null;
}

const Unit = struct { tons: u32, armor: u16, name: []const u8, destroyed: bool, salvage: bool, bv: i32 };

test "sum" {
    const u: Unit = .{ .tons = 100, .armor = 300, .name = "Atlas", .destroyed = false, .salvage = true, .bv = -5 };
    try std.testing.expectEqual(@as(i64, 395), sumIntFields(u));
    try std.testing.expectEqual(@as(i64, 3), sumIntFields(.{ .a = 1, .b = 2 }));
}

test "counts at compile time" {
    const n = comptime boolFieldCount(Unit);
    const flags: [n]bool = @splat(false);
    try std.testing.expectEqual(@as(usize, 2), flags.len);
}

test "first field of type" {
    try std.testing.expectEqualStrings("armor", (comptime firstFieldOfType(Unit, u16)).?);
    try std.testing.expectEqualStrings("destroyed", (comptime firstFieldOfType(Unit, bool)).?);
    try std.testing.expect(comptime firstFieldOfType(Unit, f64) == null);
}

Everything that depends on a field's type or name happens inside inline for, where f is a constant. f.type == bool is a comparison of two type values, which is legal exactly because types are values.

Exercise 25.4 · Labels practice

Write three functions that return compile-time strings: label(name, unit) using ++ and a @compileError for an empty name, header(text, width) that pads with " " ** n, and version(major, minor, patch) using comptimePrint. Name the file: exercises/25-comptime/ex4_labels.zig.

Solution 
//! Chapter 25, exercise 4: strings built by the compiler.
//! Run with:  zig test ex4_labels.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// "weight (tons)" from ("weight", "tons"); "weight" alone when unit is empty.
/// An empty name is a compile error.
fn label(comptime name: []const u8, comptime unit: []const u8) []const u8 {
    if (name.len == 0) @compileError("label needs a name");
    if (unit.len == 0) return name;
    return name ++ " (" ++ unit ++ ")";
}

/// A column header: the label left-aligned and padded with spaces to `width`,
/// all decided at compile time.
fn header(comptime text: []const u8, comptime width: usize) []const u8 {
    if (text.len >= width) return text;
    return text ++ (" " ** (width - text.len));
}

/// "v0.16.0" from three numbers.
fn version(comptime major: u32, comptime minor: u32, comptime patch: u32) []const u8 {
    return std.fmt.comptimePrint("v{d}.{d}.{d}", .{ major, minor, patch });
}

test "label" {
    try std.testing.expectEqualStrings("weight (tons)", label("weight", "tons"));
    try std.testing.expectEqualStrings("name", label("name", ""));
}

test "header" {
    try std.testing.expectEqualStrings("tons      ", header("tons", 10));
    try std.testing.expectEqualStrings("battle value", header("battle value", 5));
    try std.testing.expectEqual(@as(usize, 10), header("tons", 10).len);
}

test "version" {
    try std.testing.expectEqualStrings("v0.16.0", version(0, 16, 0));
    // The result is a compile-time constant, so it can size an array.
    const n = comptime version(1, 2, 3).len;
    const arr: [n]u8 = @splat('x');
    try std.testing.expectEqual(@as(usize, 6), arr.len);
}

All parameters are comptime, so the functions cannot be called with runtime strings, which is the point: the results are constants. In the last test the call is prefixed with comptime so that .len can size an array.

Exercise 25.5 · Enum tables challenge

Write names(comptime E: type) returning an array of every tag name, values(E) returning the matching enum values, longestName(E) for column sizing, and fromName(E, text) that does a runtime lookup through the compile-time tables (it must work for enums with explicit values). Name the file: exercises/25-comptime/ex5_enum_names.zig.

Solution 
//! Chapter 25, exercise 5: tables derived from an enum at compile time.
//! Run with:  zig test ex5_enum_names.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// An array of every tag name of enum E, in declaration order.
fn names(comptime E: type) [@typeInfo(E).@"enum".fields.len][]const u8 {
    const fields = @typeInfo(E).@"enum".fields;
    var out: [fields.len][]const u8 = undefined;
    inline for (fields, 0..) |f, i| out[i] = f.name;
    return out;
}

/// Every value of E, in declaration order, matching names(E) index for index.
fn values(comptime E: type) [@typeInfo(E).@"enum".fields.len]E {
    const fields = @typeInfo(E).@"enum".fields;
    var out: [fields.len]E = undefined;
    inline for (fields, 0..) |f, i| out[i] = @enumFromInt(f.value);
    return out;
}

/// The length of the longest tag name, for sizing a column.
fn longestName(comptime E: type) usize {
    comptime var best: usize = 0;
    inline for (@typeInfo(E).@"enum".fields) |f| best = @max(best, f.name.len);
    return best;
}

/// Look a value up by name at runtime, using the compile-time table.
fn fromName(comptime E: type, text: []const u8) ?E {
    const table = comptime names(E);
    const vals = comptime values(E);
    for (table, vals) |n, v| {
        if (std.mem.eql(u8, n, text)) return v;
    }
    return null;
}

const Role = enum { pilot, tech, medic, quartermaster };
const Weather = enum(u8) { clear = 1, rain = 5, storm = 9 };

test "names" {
    const n = names(Role);
    try std.testing.expectEqual(@as(usize, 4), n.len);
    try std.testing.expectEqualStrings("pilot", n[0]);
    try std.testing.expectEqualStrings("quartermaster", n[3]);
}

test "longest" {
    const w = comptime longestName(Role);
    const col: [w]u8 = @splat(' ');
    try std.testing.expectEqual(@as(usize, 13), col.len);
    try std.testing.expectEqual(@as(usize, 5), comptime longestName(Weather));
}

test "fromName with explicit values" {
    try std.testing.expectEqual(@as(?Weather, .storm), fromName(Weather, "storm"));
    try std.testing.expectEqual(@as(?Weather, null), fromName(Weather, "snow"));
    try std.testing.expectEqual(@as(?Role, .medic), fromName(Role, "medic"));
}

The array length in the return type, [@typeInfo(E).@"enum".fields.len][]const u8, is itself a compile-time expression. fromName builds both tables with comptime and then does an ordinary runtime loop over them; you cannot index fields[i] with a runtime i because fields only exists in the compiler. (The standard library has std.meta.stringToEnum for this job.)

Check your understanding

  1. What is the type of the literal 42 before it is assigned anywhere?
    Answercomptime_int: an unbounded integer that exists only in the compiler and coerces to any integer type it fits in.
  2. What does the comptime keyword in front of an expression guarantee?
    AnswerThat the expression is evaluated by the compiler; if it cannot be, compilation fails. The result is a constant baked into the binary.
  3. Why must an array length be comptime-known?
    AnswerThe length is part of the array's type, and the compiler lays out memory and generates code from types before the program runs. For runtime lengths use a slice or an ArrayList.
  4. When do you need inline for rather than for?
    AnswerWhen the loop variable must be comptime-known inside the body: iterating struct fields, types, or tuple elements of different types. Not for performance.
  5. What does "evaluation exceeded 1000 backwards branches" mean and how do you fix it?
    AnswerA compile-time evaluation looped or recursed more than the default quota. Call @setEvalBranchQuota(n) inside that evaluation with a larger n.
  6. Can ++ join a string literal to a slice read from a file at run time?
    AnswerNo; its operands need comptime-known lengths. Use an ArrayList(u8), allocPrint or bufPrint for runtime strings.
  7. What is the difference between @compileError and @compileLog?
    Answer@compileError fails the build with your message when reached; @compileLog prints values during compilation for debugging and also fails the build so it cannot be left in.
  8. Why does Zig not need a preprocessor or a template language?
    AnswerBecause ordinary Zig code can run at compile time, with types as values: conditional compilation is an if, generics are functions returning types, and tables are loops.
What you learned.
  • Values are either comptime-known or runtime; comptime forces the first world, and literals, constants and pure calls on constants already live there.
  • comptime_int and comptime_float are unbounded literal types that coerce when they fit; overflow is a compile error.
  • comptime blocks, comptime var, and @setEvalBranchQuota for evaluations beyond a thousand branches.
  • Types are values of type type; array lengths, types and field names must be comptime-known.
  • inline for and inline while unroll with a comptime loop variable, which is what field walking and mixed tuples need.
  • ++ and ** build strings in the compiler from operands with known lengths; comptimePrint formats there.
  • Tables are loops inside constant initialisers; container-level comptime {} blocks hold build-time assertions.
  • @compileError gives custom diagnostics; @compileLog prints while compiling.
