23. Formatting and parsing text

In this chapter you will learn the whole of Zig's format-string grammar: every specifier, width, alignment, fill and precision, positional and named arguments, and how to escape braces. You will see where formatted text can go (the heap, a buffer, a writer, or the compiler itself), how to turn text back into numbers with parseInt and parseFloat and handle their errors, and how to give your own types a format method.

23.1 The grammar

You have been writing {d} and {s} since Chapter 2. Here is the full shape of a placeholder:

{[argument]specifier:[fill][alignment][width][.precision]}

Everything except the braces is optional. argument is a position (0, 1) or a field name in square brackets. specifier is a short letter code saying how to render the value. After a colon come the layout options: a fill character, an alignment (< left, ^ centre, > right), a width in characters and a .precision for floats. Format strings are checked at compile time against the argument tuple: a missing argument, an extra one, or a specifier that does not fit the type is a compile error, never a runtime surprise.

23.2 Every specifier

a_specs.zig

const std = @import("std");

pub fn main() void {
    const n: u32 = 42;
    const neg: i32 = -7;
    const f: f64 = 3.14159;
    const s: []const u8 = "Atlas";
    const c: u8 = 'K';
    const opt: ?u32 = null;
    const eu: anyerror!u32 = error.NoFuel;

    std.debug.print("{{d}}   -> {d}  {d}\n", .{ n, neg });
    std.debug.print("{{x}}   -> {x}    {{X}} -> {X}\n", .{ n, n });
    std.debug.print("{{b}}   -> {b}  {{o}} -> {o}\n", .{ n, n });
    std.debug.print("{{c}}   -> {c}   {{u}} -> {u}\n", .{ c, @as(u21, 0x2694) });
    std.debug.print("{{s}}   -> {s}\n", .{s});
    std.debug.print("{{d}}   -> {d}   {{e}} -> {e}\n", .{ f, f });
    std.debug.print("{{?}}   -> {?}  {{?d}} -> {?d}\n", .{ opt, @as(?u32, 5) });
    std.debug.print("{{!}}   -> {!}  {{!d}} -> {!d}\n", .{ eu, @as(anyerror!u32, 9) });
    std.debug.print("{{any}} -> {any}\n", .{[_]u8{ 1, 2, 3 }});
    std.debug.print("{{*}}   -> {*}\n", .{&n});
    std.debug.print("{{}}    -> {}  {}\n", .{ true, n });
}

The ? and ! prefixes compose: {?d} is "an optional integer, print the integer in decimal if present". They save you an if when debugging. Slices are the one place Zig refuses a bare {}: a []const u8 might be text or bytes, so you have to say which with {s} or {x}.

23.3 Width, alignment, fill and precision

b_width.zig

const std = @import("std");

pub fn main() void {
    const name: []const u8 = "Locust";
    const tons: u32 = 20;
    const f: f64 = 2.0 / 3.0;

    std.debug.print("[{s: <10}] left in 10\n", .{name});
    std.debug.print("[{s: >10}] right in 10\n", .{name});
    std.debug.print("[{s:^10}] centred in 10\n", .{name});
    std.debug.print("[{s:.^10}] centred, fill '.'\n", .{name});
    std.debug.print("[{d: >6}] right in 6\n", .{tons});
    std.debug.print("[{d:0>6}] zero-padded to 6\n", .{tons});
    std.debug.print("[{d:<6}] left in 6 (default fill is space)\n", .{tons});
    std.debug.print("[{d:.2}] two decimals\n", .{f});
    std.debug.print("[{d:8.3}] width 8, three decimals\n", .{f});
    std.debug.print("[{x:0>8}] hex, zero-padded to 8\n", .{@as(u32, 0xBEEF)});

    // A table: the format string is the layout.
    const rows = [_]struct { n: []const u8, t: u32, bv: u32 }{
        .{ .n = "Atlas", .t = 100, .bv = 1897 },
        .{ .n = "Marauder", .t = 75, .bv = 1363 },
        .{ .n = "Locust", .t = 20, .bv = 432 },
    };
    std.debug.print("{s: <10} {s: >5} {s: >6}\n", .{ "name", "tons", "bv" });
    for (rows) |r| std.debug.print("{s: <10} {d: >5} {d: >6}\n", .{ r.n, r.t, r.bv });
}

Read {s: <10} as: specifier s, then after the colon a fill character (space), an alignment (<), a width (10). The fill is any single character, and it is only recognised if an alignment character follows it, which is why {d:0>6} means "fill with zeros, right-align, width 6" and not "width 06". Numbers align right by default and text aligns... also right, which surprises people; put an explicit < on string columns. Precision for floats is .N and rounds; width and precision combine as {d:8.3}.

The table at the end is the whole trick of text user interfaces: pick a format string once, use it for the header and every row, and the columns line up. IRON LEDGER's screens are hundreds of lines exactly like it.

A 0.16 surprise: signed integers grow a plus sign when given a width.

c_sign.zig

const std = @import("std");

pub fn main() void {
    const unsigned: u32 = 42;
    const signed: i32 = 42;
    std.debug.print("[{d}] [{d}]      no width: same\n", .{ unsigned, signed });
    std.debug.print("[{d: >5}] [{d: >5}]  with width: signed gets a '+'\n", .{ unsigned, signed });
    std.debug.print("[{d: >5}]          negative is what you expect\n", .{@as(i32, -42)});
}
[42] [42]      no width: same
[   42] [  +42]  with width: signed gets a '+'
[  -42]          negative is what you expect
The rule inside the standard library is: for a signed type with a non-zero width, print the sign always. With no width, positive numbers print bare. If you want 42 from an i32, cast to unsigned first when you know it is not negative (@as(u32, @intCast(v))), or format the number into a small buffer with {d} and then align that string with {s: >5}.

23.4 Positional and named arguments, and literal braces

d_positional.zig

const std = @import("std");

pub fn main() void {
    // Positional: {0} is the first argument, {1} the second.
    std.debug.print("{1s} weighs {0d} tons; yes, {0d}.\n", .{ 100, "Atlas" });

    // Named: the argument is a struct, and {[field]} picks a field.
    std.debug.print("{[name]s}: gunnery {[gun]d}, piloting {[pil]d}\n", .{
        .name = "Natasha", .gun = 1, .pil = 2,
    });

    // Literal braces are doubled.
    std.debug.print("markup looks like {{g}}{s}{{/}}\n", .{"active"});
}
Atlas weighs 100 tons; yes, 100.
Natasha: gunnery 1, piloting 2
markup looks like {g}active{/}

Positional indices let you reuse an argument or reorder them. Named placeholders take a struct instead of a tuple, and {[name]s} reads the field name. Both are rare in everyday code but useful for message templates. The doubled brace is essential: {{ prints {. You will see this constantly in the game, because its colour markup uses braces.

23.5 Where the text goes

std.debug.print sends formatted text to stderr. The same format engine can send it to the heap, to a buffer you own, to any writer, or run at compile time.

e_targets.zig

const std = @import("std");

pub fn main() !void {
    var gpa_state: std.heap.DebugAllocator(.{}) = .init;
    defer _ = gpa_state.deinit();
    const gpa = gpa_state.allocator();

    // 1. allocPrint: heap string, caller frees.
    const heap = try std.fmt.allocPrint(gpa, "unit-{d:0>3}", .{7});
    defer gpa.free(heap);
    std.debug.print("allocPrint: {s}\n", .{heap});

    // 2. bufPrint: into a buffer you provide; returns the slice actually used.
    var buf: [16]u8 = undefined;
    const fixed = try std.fmt.bufPrint(&buf, "{d}%", .{95});
    std.debug.print("bufPrint:   {s} ({d} of {d} bytes)\n", .{ fixed, fixed.len, buf.len });

    // 3. bufPrint fails, it does not truncate.
    const too_long = std.fmt.bufPrint(buf[0..4], "{d}", .{123456});
    std.debug.print("too long:   {!s}\n", .{too_long});

    // 4. bufPrintZ: same, with a trailing zero byte for C.
    const z = try std.fmt.bufPrintZ(&buf, "{s}", .{"cstr"});
    std.debug.print("bufPrintZ:  {s} len {d}, byte after is {d}\n", .{ z, z.len, z[z.len] });

    // 5. A fixed Writer: many prints into one buffer.
    var w = std.Io.Writer.fixed(&buf);
    try w.print("{d}", .{1});
    try w.print("+{d}", .{2});
    try w.writeAll("=3");
    std.debug.print("fixed:      {s}\n", .{w.buffered()});

    // 6. comptimePrint: the string is built by the compiler.
    const version = std.fmt.comptimePrint("zig {d}.{d}", .{ 0, 16 });
    std.debug.print("comptime:   {s} ({s})\n", .{ version, @typeName(@TypeOf(version)) });

    // 7. count: how many bytes would it take?
    std.debug.print("count:      {d}\n", .{std.fmt.count("{d}-{s}", .{ 12, "ab" })});
}
allocPrint: unit-007
bufPrint:   95% (3 of 16 bytes)
too long:   error.NoSpaceLeft
bufPrintZ:  cstr len 4, byte after is 0
fixed:      1+2=3
comptime:   zig 0.16 (*const [8:0]u8)
count:      5
  • allocPrint(gpa, fmt, args) returns a []u8 you must free. It is the most common in IRON LEDGER (over five hundred calls), always with an arena so the frees are one deinit.
  • bufPrint(buf, fmt, args) writes into your buffer and returns the slice that was written. If the result does not fit, it returns error.NoSpaceLeft and writes nothing useful. It never truncates silently, which is a deliberate contrast with C's snprintf.
  • bufPrintZ is the same with a zero byte appended, returning [:0]u8, for handing to C (Chapter 35).
  • std.Io.Writer.fixed(&buf) makes a writer backed by your buffer; you can print to it repeatedly and read back buffered(). This is how you build a line from several pieces without an allocator. The growable version is std.Io.Writer.Allocating from Chapter 21.
  • comptimePrint produces the string at compile time. The result's type, *const [8:0]u8, tells you it is a pointer to a constant array baked into the binary. Use it for building names, error messages and @compileError text in generic code.
  • count tells you how long the output would be, useful to size a buffer.

23.6 Parsing numbers

Going the other way, from text to a value, is std.fmt.parseInt(T, text, base), parseUnsigned and parseFloat. They return error unions, and the errors are specific.

f_parse.zig

const std = @import("std");

pub fn main() void {
    std.debug.print("{!d}\n", .{std.fmt.parseInt(i32, "-12", 10)});
    std.debug.print("{!d}\n", .{std.fmt.parseInt(u8, "ff", 16)});
    std.debug.print("{!d}\n", .{std.fmt.parseInt(u8, "1010", 2)});

    std.debug.print("{!d}  (256 does not fit u8)\n", .{std.fmt.parseInt(u8, "256", 10)});
    std.debug.print("{!d}  (trailing junk)\n", .{std.fmt.parseInt(u8, "12a", 10)});

The rules: the whole string must be a number (no leading or trailing spaces, no trailing junk); an optional sign is accepted by parseInt but not parseUnsigned; underscores between digits are fine; base 0 means "look at the prefix" (0x, 0o, 0b, or decimal). The value must fit in T or you get error.Overflow. Everything else is error.InvalidCharacter. parseFloat understands exponents, inf and nan.

Because the error set of parseInt is exactly { Overflow, InvalidCharacter }, you can switch on it exhaustively and give the user a precise message:

g_handle.zig

const std = @import("std");

/// Parse "name=value" into a number, explaining any problem.
fn readSetting(line: []const u8) ?i32 {
    const eq = std.mem.indexOfScalar(u8, line, '=') orelse {
        std.debug.print("  no '=' in {s}\n", .{line});
        return null;
    };
    const text = std.mem.trim(u8, line[eq + 1 ..], " ");
    return std.fmt.parseInt(i32, text, 10) catch |err| switch (err) {
        error.InvalidCharacter => {
            std.debug.print("  '{s}' is not a number\n", .{text});
            return null;
        },
        error.Overflow => {
            std.debug.print("  '{s}' does not fit in an i32\n", .{text});
            return null;
        },
    };
}

pub fn main() void {
    const lines = [_][]const u8{ "seed = 42", "seed=-1", "seed", "seed = forty", "seed = 99999999999" };
    for (lines) |l| {
        std.debug.print("{s}:\n", .{l});
        if (readSetting(l)) |v| std.debug.print("  -> {d}\n", .{v});
    }
}

Notice the trim before the parse. Users type spaces; parseInt does not forgive them; so you strip them. This pairs with the tokenizers of Chapter 24, which is how command lines are chopped into words before each word is parsed.

23.7 Bytes as hex

Older Zig had std.fmt.fmtSliceHexLower. In 0.16 it is gone, and the job is done by the plain {x} specifier applied to a byte slice, or by bytesToHex when you want an array back:

i_hex.zig

const std = @import("std");

pub fn main() void {
    const bytes = [_]u8{ 0xDE, 0xAD, 0xBE, 0xEF };
    std.debug.print("{x}\n", .{&bytes}); // a byte slice with {x}: hex, no separators
    std.debug.print("{X}\n", .{&bytes});
    std.debug.print("{s}\n", .{&std.fmt.bytesToHex(bytes, .lower)}); // comptime-sized array
    std.debug.print("{any}\n", .{&bytes}); // {any} prints decimal elements
    var out: [4]u8 = undefined;
    const back = std.fmt.hexToBytes(&out, "deadbeef") catch unreachable;
    std.debug.print("{any}\n", .{back});
}

DEADBEEF

bytesToHex takes an array (not a slice) so it can size its result at compile time; hexToBytes reverses it into a buffer you provide.

23.8 Giving your type a format method

Any struct, union or enum can declare a public format method, and the {f} specifier calls it. The 0.16 signature is small: the value, and a pointer to the writer.

h_custom.zig

const std = @import("std");

const CBills = struct {
    amount: i64,

    /// Called for the {f} specifier. Writes to any writer.
    pub fn format(self: CBills, w: *std.Io.Writer) std.Io.Writer.Error!void {
        if (self.amount < 0) try w.writeByte('-');
        var digits: [24]u8 = undefined;
        const raw = std.fmt.bufPrint(&digits, "{d}", .{@abs(self.amount)}) catch unreachable;
        for (raw, 0..) |ch, i| {
            if (i > 0 and (raw.len - i) % 3 == 0) try w.writeByte(',');
            try w.writeByte(ch);
        }
        try w.writeAll(" C-bills");
    }
};

const Hex = struct { q: i16, r: i16 };

pub fn main() !void {
    const pay: CBills = .{ .amount = 1234567 };
    const debt: CBills = .{ .amount = -950 };
    std.debug.print("{f}\n{f}\n", .{ pay, debt });
    std.debug.print("{any}\n", .{pay}); // {any} ignores format(): prints the fields

    const h: Hex = .{ .q = 2, .r = -1 };
    std.debug.print("{any}\n", .{h});

    var buf: [64]u8 = undefined;
    const line = try std.fmt.bufPrint(&buf, "balance: {f}", .{pay});
    std.debug.print("{s}\n", .{line});
}
1,234,567 C-bills
-950 C-bills
.{ .amount = 1234567 }
.{ .q = 2, .r = -1 }
balance: 1,234,567 C-bills

Inside format you have a full *std.Io.Writer: print, writeAll, writeByte. The error type is fixed as std.Io.Writer.Error, so anything that can fail for other reasons (here, bufPrint into a buffer we know is big enough) is handled locally, with catch unreachable. Once written, the type works everywhere the format engine does: debug.print, allocPrint, bufPrint, file writers.

You must write {f}. In 0.16 the plain {} and {any} do not call format; they print the fields:

h_nof.zig

const std = @import("std");
const CBills = struct { amount: i64,
    pub fn format(self: CBills, w: *std.Io.Writer) std.Io.Writer.Error!void { try w.print("{d} C-bills", .{self.amount}); } };
pub fn main() void { std.debug.print("{}\n", .{CBills{ .amount = 5 }}); }
.{ .amount = 5 }
Older code relied on {} calling format with a four-argument signature (fmt, options, writer). That signature is gone. If you port such code, change the method to format(self, w: *std.Io.Writer) std.Io.Writer.Error!void and the call sites to {f}.
In IRON LEDGER. Every screen is a format string. The People query in game/src/sim/queries.zig lays out a row with widths alone: 
"{d: <4} {s: <20} {s: <15} {s: <7} {s: <5} {d: >3} {s} {s} {s: <11} {d: >3} {d: >3} {s: >7}"
The colour markup that the terminal renders, {g}active{/}, has to be written {{g}}active{{/}} inside format strings, which is where most brace confusion in the code base comes from. The money function is Exercise 23.5 almost verbatim: bufPrint the magnitude with {d}, then walk the digits inserting commas. And the console parser in game/src/sim/cli.zig wraps parseInt in a tiny generic helper that turns both of its errors into the command layer's own error.BadNumber: 
pub fn num(comptime T: type, tok: ?[]const u8) ParseError!T {
    return std.fmt.parseInt(T, tok orelse return error.BadArguments, 10) catch return error.BadNumber;
}
The terminal's status line uses bufPrint into a fixed buffer and falls back to the whole buffer on NoSpaceLeft rather than failing a frame (tui/app.zig, say).

Exercise 23.1 · Table row and clock warm-up

Write formatRow(buf, name, tons, bv) producing name left in 10, tons right in 5, bv right in 6 with single spaces between, and formatClock(buf, h, m) producing 07:05. Both use bufPrint. Name the file: exercises/23-formatting/ex1_table.zig.

Solution 
//! Chapter 23, exercise 1: fixed-width table rows.
//! Run with:  zig test ex1_table.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// name left-aligned in 10, tons right-aligned in 5, bv right-aligned in 6, single spaces between.
fn formatRow(buf: []u8, name: []const u8, tons: u32, bv: u32) ![]u8 {
    return std.fmt.bufPrint(buf, "{s: <10} {d: >5} {d: >6}", .{ name, tons, bv });
}

/// "07:05" style, zero padded.
fn formatClock(buf: []u8, hours: u8, minutes: u8) ![]u8 {
    return std.fmt.bufPrint(buf, "{d:0>2}:{d:0>2}", .{ hours, minutes });
}

test "row" {
    var buf: [64]u8 = undefined;
    try std.testing.expectEqualStrings("Atlas        100   1897", try formatRow(&buf, "Atlas", 100, 1897));
    try std.testing.expectEqualStrings("Locust        20    432", try formatRow(&buf, "Locust", 20, 432));
}

test "clock" {
    var buf: [8]u8 = undefined;
    try std.testing.expectEqualStrings("07:05", try formatClock(&buf, 7, 5));
    try std.testing.expectEqualStrings("23:59", try formatClock(&buf, 23, 59));
}

test "a buffer that is too small is an error, not a truncation" {
    var tiny: [4]u8 = undefined;
    try std.testing.expectError(error.NoSpaceLeft, formatClock(&tiny, 7, 5));
}

Exercise 23.2 · Coordinates practice

Parse "3,-2" (spaces allowed around the numbers) into a Hex{ q, r } of i16, with your own error set { MissingComma, BadNumber }. Name the file: exercises/23-formatting/ex2_coords.zig.

Solution 
//! Chapter 23, exercise 2: parse "q,r" hex coordinates.
//! Run with:  zig test ex2_coords.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Hex = struct { q: i16, r: i16 };
const ParseError = error{ MissingComma, BadNumber };

/// "3,-2" -> Hex{ .q = 3, .r = -2 }. Spaces around the numbers are allowed.
fn parseHex(text: []const u8) ParseError!Hex {
    const comma = std.mem.indexOfScalar(u8, text, ',') orelse return error.MissingComma;
    const q_text = std.mem.trim(u8, text[0..comma], " ");
    const r_text = std.mem.trim(u8, text[comma + 1 ..], " ");
    const q = std.fmt.parseInt(i16, q_text, 10) catch return error.BadNumber;
    const r = std.fmt.parseInt(i16, r_text, 10) catch return error.BadNumber;
    return .{ .q = q, .r = r };
}

test "good input" {
    try std.testing.expectEqual(Hex{ .q = 3, .r = -2 }, try parseHex("3,-2"));
    try std.testing.expectEqual(Hex{ .q = 0, .r = 7 }, try parseHex(" 0 , 7 "));
}

test "bad input" {
    try std.testing.expectError(error.MissingComma, parseHex("3 -2"));
    try std.testing.expectError(error.BadNumber, parseHex("3,x"));
    try std.testing.expectError(error.BadNumber, parseHex(",2"));
    try std.testing.expectError(error.BadNumber, parseHex("40000,0")); // overflow of i16
}

indexOfScalar finds the comma, trim removes spaces, and catch return error.BadNumber folds both parse errors into one domain error, the way the game's num helper does.

//! Chapter 23, exercise 3: parse and print hex colours.
//! Run with:  zig test ex3_color.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Rgb = struct { r: u8, g: u8, b: u8 };

/// "#ff8800" or "ff8800" -> Rgb. Case-insensitive.
fn parseColor(text: []const u8) !Rgb {
    const hex = if (text.len > 0 and text[0] == '#') text[1..] else text;
    if (hex.len != 6) return error.WrongLength;
    return .{
        .r = try std.fmt.parseUnsigned(u8, hex[0..2], 16),
        .g = try std.fmt.parseUnsigned(u8, hex[2..4], 16),
        .b = try std.fmt.parseUnsigned(u8, hex[4..6], 16),
    };
}

/// Rgb -> "#ff8800", lower case, always six digits.
fn formatColor(buf: []u8, c: Rgb) ![]u8 {
    return std.fmt.bufPrint(buf, "#{x:0>2}{x:0>2}{x:0>2}", .{ c.r, c.g, c.b });
}

test "parse" {
    try std.testing.expectEqual(Rgb{ .r = 255, .g = 136, .b = 0 }, try parseColor("#ff8800"));
    try std.testing.expectEqual(Rgb{ .r = 255, .g = 136, .b = 0 }, try parseColor("FF8800"));
    try std.testing.expectError(error.WrongLength, parseColor("#fff"));
    try std.testing.expectError(error.InvalidCharacter, parseColor("#gg0000"));
}

test "format round trip" {
    var buf: [8]u8 = undefined;
    try std.testing.expectEqualStrings("#0a0b0c", try formatColor(&buf, .{ .r = 10, .g = 11, .b = 12 }));
    const c = try parseColor("#12abEF");
    try std.testing.expectEqualStrings("#12abef", try formatColor(&buf, c));
}

{x:0>2} is fill 0, right-aligned, width 2. The parse error set is inferred (!Rgb) and includes both your WrongLength and parseUnsigned's errors.

Exercise 23.4 · Duration challenge

Give a Duration { seconds: u64 } a format method that renders 2d 3h 4m 5s, dropping leading zero units (2m 5s, 45s, and 0s for zero, but 1h 0m 0s for exactly an hour). Test it through bufPrint and allocPrint with {f}. Name the file: exercises/23-formatting/ex4_duration.zig.

Solution 
//! Chapter 23, exercise 4: a custom format method.
//! Run with:  zig test ex4_duration.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Duration = struct {
    seconds: u64,

    /// "2d 3h 4m 5s", omitting any leading zero units; "0s" for zero.
    pub fn format(self: Duration, w: *std.Io.Writer) std.Io.Writer.Error!void {
        var rest = self.seconds;
        const days = rest / 86_400;
        rest %= 86_400;
        const hours = rest / 3_600;
        rest %= 3_600;
        const mins = rest / 60;
        rest %= 60;
        var started = false;
        if (days > 0) {
            try w.print("{d}d", .{days});
            started = true;
        }
        if (started or hours > 0) {
            if (started) try w.writeByte(' ');
            try w.print("{d}h", .{hours});
            started = true;
        }
        if (started or mins > 0) {
            if (started) try w.writeByte(' ');
            try w.print("{d}m", .{mins});
            started = true;
        }
        if (started) try w.writeByte(' ');
        try w.print("{d}s", .{rest});
    }
};

fn render(buf: []u8, d: Duration) ![]u8 {
    return std.fmt.bufPrint(buf, "{f}", .{d});
}

test "format" {
    var buf: [32]u8 = undefined;
    try std.testing.expectEqualStrings("0s", try render(&buf, .{ .seconds = 0 }));
    try std.testing.expectEqualStrings("45s", try render(&buf, .{ .seconds = 45 }));
    try std.testing.expectEqualStrings("2m 5s", try render(&buf, .{ .seconds = 125 }));
    try std.testing.expectEqualStrings("1h 0m 0s", try render(&buf, .{ .seconds = 3600 }));
    try std.testing.expectEqualStrings("2d 3h 4m 5s", try render(&buf, .{ .seconds = 2 * 86400 + 3 * 3600 + 4 * 60 + 5 }));
}

test "works with allocPrint too" {
    const s = try std.fmt.allocPrint(std.testing.allocator, "eta {f}", .{Duration{ .seconds = 90 }});
    defer std.testing.allocator.free(s);
    try std.testing.expectEqualStrings("eta 1m 30s", s);
}

The started flag does the "once a bigger unit has printed, print all the smaller ones" logic. The method takes self by value because the struct is tiny and it does not mutate.

Exercise 23.5 · Money challenge

Write money(gpa, v: i64) ![]u8 that prints thousands separators and a leading minus (-1,234,567), and parseMoney(text) !i64 that accepts the same form (commas optional). The tests round-trip. Name the file: exercises/23-formatting/ex5_money.zig.

Solution 
//! Chapter 23, exercise 5: money with thousands separators, like IRON LEDGER's.
//! Run with:  zig test ex5_money.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// -1234567 -> "-1,234,567". The caller owns the result.
fn money(gpa: std.mem.Allocator, v: i64) ![]u8 {
    var digits: [24]u8 = undefined;
    const raw = try std.fmt.bufPrint(&digits, "{d}", .{@abs(v)});
    var out: std.ArrayList(u8) = .empty;
    errdefer out.deinit(gpa);
    if (v < 0) try out.append(gpa, '-');
    for (raw, 0..) |c, i| {
        if (i > 0 and (raw.len - i) % 3 == 0) try out.append(gpa, ',');
        try out.append(gpa, c);
    }
    return out.toOwnedSlice(gpa);
}

/// "1,234,567" or "-1,234,567" -> i64. Commas are optional; anything else is an error.
fn parseMoney(text: []const u8) !i64 {
    var clean: [32]u8 = undefined;
    var n: usize = 0;
    for (text) |c| {
        if (c == ',') continue;
        if (n == clean.len) return error.Overflow;
        clean[n] = c;
        n += 1;
    }
    return std.fmt.parseInt(i64, clean[0..n], 10);
}

fn check(expected: []const u8, v: i64) !void {
    const s = try money(std.testing.allocator, v);
    defer std.testing.allocator.free(s);
    try std.testing.expectEqualStrings(expected, s);
    try std.testing.expectEqual(v, try parseMoney(s));
}

test "money" {
    try check("0", 0);
    try check("999", 999);
    try check("1,000", 1000);
    try check("1,234,567", 1234567);
    try check("-950", -950);
    try check("-1,234,567", -1234567);
}

test "parse rejects junk" {
    try std.testing.expectError(error.InvalidCharacter, parseMoney("1,2x3"));
    try std.testing.expectEqual(@as(i64, 5000), try parseMoney("5000"));
}

The comma goes before digit i whenever the number of digits remaining, raw.len - i, is a multiple of three. @abs on an i64 gives a u64, which sidesteps the "minus the most negative value" overflow. This is the game's money function.

Check your understanding

  1. What does {d:0>6} mean, character by character?
    AnswerSpecifier d; fill character 0; alignment > (right); width 6. The value 20 prints as 000020.
  2. How do you print a literal {?
    AnswerDouble it: {{. Likewise }} for }.
  3. Why does bufPrint return an error union?
    AnswerThe buffer may be too small; it returns error.NoSpaceLeft rather than truncating.
  4. What is the difference between parseInt(u8, "-1", 10) and parseUnsigned(u8, "-1", 10)?
    AnswerBoth fail, but for different reasons: parseInt reads the minus sign and then finds -1 does not fit u8 (Overflow); parseUnsigned does not accept a sign at all (InvalidCharacter).
  5. What are the two errors parseInt can return?
    Answererror.Overflow (does not fit the type) and error.InvalidCharacter (anything else: junk, empty string, spaces, bad sign).
  6. You gave a struct a format method but {} still prints the fields. Why?
    AnswerIn 0.16 only {f} calls a format method. {} and {any} use the built-in rendering.
  7. Why does {d: >5} print +42 for an i32 but 42 for a u32?
    AnswerThe integer printer adds an explicit sign to signed values whenever a width is given. Unsigned values have no sign to show. Cast, or format then align the string.
  8. What replaced std.fmt.fmtSliceHexLower?
    AnswerThe {x} specifier on a byte slice (and {X} for upper case), or std.fmt.bytesToHex for an array result.
What you learned.
  • A placeholder is {[arg]spec:[fill][align][width][.prec]}; format strings are checked at compile time.
  • Specifiers: d x X b o c u s e any * f t, with ? and ! prefixes for optionals and error unions.
  • Width and alignment build tables; signed integers with a width print a +.
  • {{ escapes a brace; {0} and {[name]} select arguments.
  • Targets: allocPrint (heap), bufPrint/bufPrintZ (buffer, errors rather than truncates), Writer.fixed, comptimePrint.
  • parseInt(T, text, base), parseUnsigned, parseFloat: whole-string, specific errors, base 0 reads prefixes.
  • A pub fn format(self, w: *std.Io.Writer) std.Io.Writer.Error!void method is invoked by {f}.
