6. Control flow: if, while, for, switch

In this chapter you will learn Zig's four control-flow constructs and the ways they differ from what you know: if and switch are expressions that produce values, while has a continue expression, for walks ranges and arrays without an index variable, loops can be labeled and can produce values with else, and switch must be exhaustive. You will also meet unreachable.

6.1 if as a statement

An if tests a bool and runs a block. else if and else chain on as in C or JavaScript. The parentheses around the condition are required; the braces can be dropped when the body is a single statement.

if_stmt.zig
const std = @import("std");

pub fn main() void {
    const funds: i64 = -25_000;
    if (funds < 0) {
        std.debug.print("the company is in debt\n", .{});
    } else if (funds == 0) {
        std.debug.print("the company is broke\n", .{});
    } else {
        std.debug.print("the company is solvent\n", .{});
    }
    if (funds < 0) std.debug.print("(one-line form works too)\n", .{});
}
$ zig run if_stmt.zig
the company is in debt
(one-line form works too)

As Chapter 5 said, the condition must be a bool. There is no truthiness, so if (funds) is an error and if (funds != 0) is what you write.

6.2 if as an expression

In Zig, if can also be a value. Each branch is an expression, and the whole thing evaluates to whichever branch ran. This replaces the cond ? a : b operator of C and JavaScript.

if_expr.zig
const std = @import("std");

pub fn main() void {
    const tonnage: u32 = 75;
    const class = if (tonnage <= 35) "light" else if (tonnage <= 55) "medium" else "heavy";
    std.debug.print("{d} tons: {s}\n", .{ tonnage, class });
    const bonus: u32 = if (tonnage > 50) 10 else 0;
    std.debug.print("bonus {d}\n", .{bonus});
}
$ zig run if_expr.zig
75 tons: heavy
bonus 10

An if expression must have an else, because it has to produce a value on every path, and both branches must have compatible types (peer type resolution again). The bonus line shows that a literal in a branch takes the annotated type. This form is used constantly in real code for small decisions inline, and it pairs with const: instead of declaring a var and assigning it in each branch, you declare a const and let the if produce it.

6.3 while

while repeats a block as long as a condition holds.

while_basic.zig
const std = @import("std");

pub fn main() void {
    var day: u32 = 1;
    while (day <= 3) {
        std.debug.print("day {d}\n", .{day});
        day += 1;
    }
    std.debug.print("after the loop, day = {d}\n", .{day});
}
$ zig run while_basic.zig
day 1
day 2
day 3
after the loop, day = 4

Zig has no do … while and, as you will see, no C-style three-part for. Instead while takes an optional continue expression after a colon, which runs at the end of every iteration, including after a continue:

while_cont.zig
const std = @import("std");

pub fn main() void {
    var day: u32 = 1;
    while (day <= 3) : (day += 1) {
        std.debug.print("day {d}\n", .{day});
    }

    var i: u32 = 0;
    var total: u32 = 0;
    while (i < 10) : (i += 1) {
        if (i % 2 == 1) continue; // skip odd numbers; the continue expression still runs
        total += i;
    }
    std.debug.print("sum of even numbers below 10: {d}\n", .{total});
}
$ zig run while_cont.zig
day 1
day 2
day 3
sum of even numbers below 10: 20

while (day <= 3) : (day += 1) reads: while this holds, run the body, then do this. The increment lives in the loop header, where it cannot be forgotten and where a continue in the body cannot skip it. That second point is the reason the form exists: in the second loop, continue jumps past total += i but the i += 1 still runs, so the loop cannot get stuck.

break leaves the loop immediately. A while (true) with a break inside is the idiom for "loop until something happens in the middle":

while_break.zig
const std = @import("std");

pub fn main() void {
    var funds: i64 = 100_000;
    var day: u32 = 0;
    while (true) {
        day += 1;
        funds -= 35_000;
        if (funds < 0) break;
    }
    std.debug.print("ran out of money on day {d}\n", .{day});
}
$ zig run while_break.zig
ran out of money on day 3

6.4 for over ranges and arrays

Zig's for does not count; it iterates. Give it something to walk, and a name in pipes for each element.

for_range.zig
const std = @import("std");

pub fn main() void {
    for (0..3) |i| {
        std.debug.print("i = {d}\n", .{i});
    }
    for (1..4) |n| std.debug.print("n = {d} ", .{n});
    std.debug.print("\n", .{});
    for (0..3) |_| std.debug.print("tick ", .{});
    std.debug.print("\n", .{});
}
$ zig run for_range.zig
i = 0
i = 1
i = 2
n = 1 n = 2 n = 3 
tick tick tick

0..3 is a range: 0, 1, 2. The end is exclusive, so 0..n runs n times and 1..4 gives 1, 2, 3. The name between the pipes, |i|, is the capture: a fresh const for each iteration. If you do not need the value, capture |_|, since an unused capture is an error like any unused name.

The type of a range capture is usize. That matters as soon as you try to store it somewhere narrower:

$ zig run for_index_type.zig
for_index_type.zig:6:23: error: expected type 'u8', found 'usize'
        const x: u8 = i;
                      ^
for_index_type.zig:6:23: note: unsigned 8-bit int cannot represent all possible unsigned 64-bit values

Use @intCast(i) when you need the index as a smaller type.

The same syntax walks an array. Arrays are Chapter 9, but you can read [_]u32{ 20, 55, 75, 100 } as "an array of four u32, count them for me":

for_array.zig
const std = @import("std");

pub fn main() void {
    const tonnages = [_]u32{ 20, 55, 75, 100 };
    var total: u32 = 0;
    for (tonnages) |t| {
        total += t;
    }
    std.debug.print("total {d}\n", .{total});

    for (tonnages, 0..) |t, i| {
        std.debug.print("slot {d}: {d} tons\n", .{ i, t });
    }

    const names = [_][]const u8{ "Locust", "Shadow Hawk", "Marauder", "Atlas" };
    for (names, tonnages) |name, t| {
        std.debug.print("{s} ({d}t)\n", .{ name, t });
    }
}
$ zig run for_array.zig
total 250
slot 0: 20 tons
slot 1: 55 tons
slot 2: 75 tons
slot 3: 100 tons
Locust (20t)
Shadow Hawk (55t)
Marauder (75t)
Atlas (100t)

Three forms appear. for (tonnages) |t| gives each element. for (tonnages, 0..) |t, i| gives each element and its index, by iterating the array and an open-ended range together. for (names, tonnages) |name, t| walks two arrays in step; they must have the same length, and Zig checks that in Debug builds. There is no separate "enumerate" or "zip"; you just list more things to iterate.

The capture is a copy. To change the elements you iterate the array's address and capture a pointer, which is Chapter 18's topic, but the shape is worth seeing now:

for_mut.zig
const std = @import("std");

pub fn main() void {
    var armor = [_]u8{ 10, 20, 30 };
    for (&armor) |*a| {
        a.* += 5;
    }
    std.debug.print("{any}\n", .{armor});
}
$ zig run for_mut.zig
{ 15, 25, 35 }

&armor lends the array itself, |*a| captures a pointer to each slot, and a.* is the value behind that pointer. Without the & and the *, a += 5 would be an error, because the capture is a const.

6.5 Labeled loops

A break or continue normally applies to the innermost loop. To reach an outer one, give it a label:

labeled.zig
const std = @import("std");

pub fn main() void {
    const grid = [_][3]u8{
        .{ 1, 5, 3 },
        .{ 4, 9, 6 },
        .{ 7, 8, 9 },
    };
    outer: for (grid, 0..) |row, r| {
        for (row, 0..) |cell, c| {
            if (cell == 9) {
                std.debug.print("found 9 at row {d}, col {d}\n", .{ r, c });
                break :outer;
            }
        }
    }
    var lines: u32 = 0;
    rows: for (grid) |row| {
        for (row) |cell| {
            if (cell % 2 == 0) continue :rows; // skip rows with any even cell
        }
        lines += 1;
    }
    std.debug.print("rows with only odd cells: {d}\n", .{lines});
}
$ zig run labeled.zig
found 9 at row 1, col 1
rows with only odd cells: 1

outer: for … names the loop, and break :outer leaves it from inside the inner loop. continue :rows abandons the rest of the current row and moves to the next one. Without labels, the first search would need a flag variable checked after the inner loop, and the second would need to remember whether it had already seen an even cell. Labels are the same mechanism as the labeled blocks of Chapter 3; a loop is just a block that repeats.

6.6 Loops as expressions: else

Because loops are blocks, they can produce values too. A break can carry a value, and the loop can have an else clause that supplies the value when the loop finishes without breaking.

loop_else.zig
const std = @import("std");

pub fn main() void {
    const roster = [_]u32{ 3, 8, 12, 27 };
    const wanted: u32 = 12;
    const found = for (roster, 0..) |id, i| {
        if (id == wanted) break i;
    } else null;
    std.debug.print("found at: {?}\n", .{found});

    var n: u32 = 91;
    var divisor: u32 = 2;
    const factor = while (divisor * divisor <= n) : (divisor += 1) {
        if (n % divisor == 0) break divisor;
    } else 0;
    n += 0;
    std.debug.print("smallest factor of 91: {d}\n", .{factor});
}
$ zig run loop_else.zig
found at: 2
smallest factor of 91: 7

The first loop is a search. If it finds the id, break i makes the loop's value the index; if it runs out of elements, the else null makes it null. The result type is ?usize, "an index or nothing", and {?} prints an optional; Chapter 15 is all about these. The second loop uses while … else the same way, with a continue expression, to find the smallest factor of a number.

The else of a loop runs only when the condition ends the loop naturally. It is the "not found" branch, and it removes the need for a "found" flag. This is a Zig habit worth acquiring early: compute the value with the loop, rather than declaring a variable and mutating it from inside the loop.

6.7 switch

switch compares one value against a list of cases and runs the matching arm. Unlike C's switch there is no fall-through and no break; exactly one arm runs. Like if, it is an expression.

switch_basic.zig
const std = @import("std");

pub fn main() void {
    const month: u8 = 2;
    const days: u8 = switch (month) {
        1, 3, 5, 7, 8, 10, 12 => 31,
        4, 6, 9, 11 => 30,
        2 => 28,
        else => 0,
    };
    std.debug.print("month {d} has {d} days\n", .{ month, days });

    const roll: u8 = 9;
    const outcome = switch (roll) {
        2...4 => "disaster",
        5...8 => "setback",
        9...11 => "success",
        12 => "triumph",
        else => "impossible",
    };
    std.debug.print("rolled {d}: {s}\n", .{ roll, outcome });
}
$ zig run switch_basic.zig
month 2 has 28 days
rolled 9: success

Cases are written to the left of =>. A single value: 12. A list: 1, 3, 5, 7, 8, 10, 12. An inclusive range: 2...4, with three dots (a range in a for has two dots and an exclusive end; a range in a switch has three and an inclusive end; this is confusing for a week). else catches anything not listed. Arms are separated by commas, and each arm is an expression; when an arm needs several statements, make it a block:

switch_stmt.zig
const std = @import("std");

pub fn main() void {
    const key: u8 = 'q';
    switch (key) {
        'q' => std.debug.print("quit\n", .{}),
        'h', '?' => std.debug.print("help\n", .{}),
        '0'...'9' => |digit| std.debug.print("digit {c}\n", .{digit}),
        else => {
            std.debug.print("unknown key ", .{});
            std.debug.print("{d}\n", .{key});
        },
    }
}
$ zig run switch_stmt.zig
quit

This one is a statement, so its arms produce nothing; the block arm ends with a comma after its closing brace. The '0'...'9' => |digit| arm shows that an arm can capture the matched value, which is useful when the case is a range.

Two rules make switch safer than its relatives in other languages. First, it must be exhaustive: every possible value of the type must match some arm, or there must be an else.

switch_missing.zig
const std = @import("std");

pub fn main() void {
    const d: u2 = 3;
    const name = switch (d) {
        0 => "north",
        1 => "east",
        2 => "south",
    };
    std.debug.print("{s}\n", .{name});
}
$ zig run switch_missing.zig
switch_missing.zig:5:18: error: switch must handle all possibilities
    const name = switch (d) {
                 ^~~~~~

A u2 has four values and only three are handled, so the compiler refuses. Add the fourth arm and it builds; with a small type like u2 or bool you can list every case and leave out else entirely, which means that if the type ever grows, the compiler will find every switch that needs updating. This is a big part of why the game uses enums so heavily (Chapter 13).

$ zig run switch_full.zig
west
yes

Second, cases may not overlap. Two ranges that share a value are an error, so a value can never match two arms:

$ zig run switch_dup.zig
switch_dup.zig:7:10: error: duplicate switch value
        6...12 => "high",
        ~^~~~~
switch_dup.zig:6:10: note: previous value here
        1...6 => "low",
        ~^~~~

6.8 unreachable

Sometimes a case is impossible by construction, and you want to say so instead of inventing a default value. unreachable is a statement that asserts control never gets here.

unreach.zig
const std = @import("std");

fn daysInMonth(month: u8) u8 {
    return switch (month) {
        1, 3, 5, 7, 8, 10, 12 => 31,
        4, 6, 9, 11 => 30,
        2 => 28,
        else => unreachable, // months are always 1..12 here
    };
}

pub fn main() void {
    std.debug.print("{d}\n", .{daysInMonth(4)});
    var bad: u8 = 12;
    bad += 1;
    std.debug.print("{d}\n", .{daysInMonth(bad)});
}
$ zig run unreach.zig
30
thread 12345 panic: reached unreachable code
unreach.zig:8:17: 0x10000abcd in daysInMonth (unreach)
        else => unreachable, // months are always 1..12 here
                ^
unreach.zig:16:43: 0x10000abcd in main (unreach)
    std.debug.print("{d}\n", .{daysInMonth(bad)});
                                          ^

The first call works. The second passes 13, hits the else, and panics with "reached unreachable code", naming the line. In a Debug build unreachable is a check; in ReleaseFast it is a promise the optimiser may rely on, and breaking it is undefined behaviour. So use it for cases that truly cannot happen given how the function is called, not for cases you have not thought about yet. unreachable also satisfies the exhaustiveness rule, because an arm that never returns has no type to disagree with the others.

6.9 Putting it together

Here is a small simulation of a month's cash flow using several constructs at once, so you can see them cooperate.

nested.zig
const std = @import("std");

pub fn main() void {
    var day: u32 = 1;
    var funds: i64 = 120_000;
    const daily_cost: i64 = 45_000;
    while (day <= 30) : (day += 1) {
        funds -= daily_cost;
        if (day % 7 == 0) funds += 200_000; // weekly contract pay
        const status = if (funds < 0) "DEBT" else "ok";
        if (day <= 8) std.debug.print("day {d:>2}: {d:>8} {s}\n", .{ day, funds, status });
    }
    std.debug.print("month end: {d}\n", .{funds});
}
$ zig run nested.zig
day  1:   +75000 ok
day  2:   +30000 ok
day  3:   -15000 DEBT
day  4:   -60000 DEBT
day  5:  -105000 DEBT
day  6:  -150000 DEBT
day  7:    +5000 ok
day  8:   -40000 DEBT
month end: -430000

A while with a continue expression drives the days. An if statement adds the weekly pay. An if expression picks a status word into a const. Another one-line if limits the printing. The {d:>8} on the signed funds shows the plus sign that Chapter 2 warned about.

Try it. Make the loop stop on the first day the company goes into debt, using break, and print the day number after the loop. Then rewrite it so the loop itself produces the day number with break day and else 0.
In IRON LEDGER. The calendar in game/src/sim/clock.zig is a switch on the month with list cases, an if expression in one arm, and an unreachable for the months that do not exist: 
pub fn daysInMonth(year: u16, month: u8) u8 {
    return switch (month) {
        1, 3, 5, 7, 8, 10, 12 => 31,
        4, 6, 9, 11 => 30,
        2 => if (isLeapYear(year)) @as(u8, 29) else 28,
        else => unreachable,
    };
}
The @as(u8, 29) is there because both branches of the inner if are literals and the outer switch needs one of them to have a concrete type. In game/src/main.zig the demo's contract hunt is a while with a continue expression: while (pick == null and hunts < 8) : (hunts += 1) { … }. And the simulation's "is this person in this company" check walks up the force tree with a while … else expression that yields a bool, which you will read in Part 5.

Exercise 6.1 · Countdown and fizzbuzz warm-up

Print a countdown from 5 with a while loop and a continue expression, then a fizzbuzz line for 1 to 15 with a for over a range, formatted exactly as the header shows. Name the file: exercises/06-control-flow/ex1_countdown.zig.

Solution 
//! Chapter 06, exercise 1: while, for and if together.
//! Run with:  zig run ex1_countdown.zig
//! Expected output (on stderr):
//!   T-5 T-4 T-3 T-2 T-1 launch
//!   1 2 fizz 4 buzz fizz 7 8 fizz buzz 11 fizz 13 14 fizzbuzz
const std = @import("std");

pub fn main() void {
    var t: u32 = 5;
    while (t > 0) : (t -= 1) {
        std.debug.print("T-{d} ", .{t});
    }
    std.debug.print("launch\n", .{});

    for (1..16) |n| {
        if (n % 15 == 0) {
            std.debug.print("fizzbuzz", .{});
        } else if (n % 3 == 0) {
            std.debug.print("fizz", .{});
        } else if (n % 5 == 0) {
            std.debug.print("buzz", .{});
        } else {
            std.debug.print("{d}", .{n});
        }
        if (n == 15) {
            std.debug.print("\n", .{});
        } else {
            std.debug.print(" ", .{});
        }
    }
}

The separator is printed by an if statement rather than an if expression inside print, because the format string must be known at compile time and the choice depends on a runtime n. That is a rule you will meet again in Chapter 23.

Exercise 6.2 · Dice, months and keys practice

Write three switch expressions: the outcome of a 2d6 roll from four ranges, the days in a month from two lists and a single case, and the action for a keypress including a character range. The last returns an enum value; write those as .quit, .help and so on. Name the file: exercises/06-control-flow/ex2_dice.zig.

Solution 
//! Chapter 06, exercise 2: switch on ranges and lists.
//! Run with:  zig test ex2_dice.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Outcome of a 2d6 roll: 2..4 "disaster", 5..8 "setback", 9..11 "success",
/// 12 "triumph". Anything else cannot happen with two dice.
fn outcome(roll: u8) []const u8 {
    return switch (roll) {
        2...4 => "disaster",
        5...8 => "setback",
        9...11 => "success",
        12 => "triumph",
        else => unreachable,
    };
}

/// Days in a month of the year 3025 (not a leap year).
fn daysInMonth(month: u8) u8 {
    return switch (month) {
        1, 3, 5, 7, 8, 10, 12 => 31,
        4, 6, 9, 11 => 30,
        2 => 28,
        else => 0,
    };
}

/// A single keypress in the terminal client: 'q' quits, 'h' or '?' shows
/// help, a digit selects that slot (0..9), anything else is ignored.
const Action = enum { quit, help, select, ignore };

fn keyAction(key: u8) Action {
    return switch (key) {
        'q' => .quit,
        'h', '?' => .help,
        '0'...'9' => .select,
        else => .ignore,
    };
}

test "outcome" {
    try std.testing.expectEqualStrings("disaster", outcome(2));
    try std.testing.expectEqualStrings("disaster", outcome(4));
    try std.testing.expectEqualStrings("setback", outcome(5));
    try std.testing.expectEqualStrings("success", outcome(11));
    try std.testing.expectEqualStrings("triumph", outcome(12));
}

test "daysInMonth" {
    try std.testing.expectEqual(@as(u8, 31), daysInMonth(1));
    try std.testing.expectEqual(@as(u8, 28), daysInMonth(2));
    try std.testing.expectEqual(@as(u8, 30), daysInMonth(4));
    try std.testing.expectEqual(@as(u8, 0), daysInMonth(13));
}

test "keyAction" {
    try std.testing.expectEqual(Action.quit, keyAction('q'));
    try std.testing.expectEqual(Action.help, keyAction('?'));
    try std.testing.expectEqual(Action.select, keyAction('7'));
    try std.testing.expectEqual(Action.ignore, keyAction('x'));
}

In outcome, the else => unreachable documents that two dice cannot produce 1 or 13; if you preferred a safe default you could return a string instead, and both satisfy exhaustiveness. Character literals are integers, so '0'...'9' is an ordinary range.

Exercise 6.3 · Loops that produce values practice

Write indexOf with a for … else expression, everyRowHasZero with a labeled outer loop and continue :label, and smallestDivisor with a while … else and a continue expression. No flag variables in the first and third. Name the file: exercises/06-control-flow/ex3_search.zig.

Solution 
//! Chapter 06, exercise 3: loops that produce values, and labeled loops.
//! Run with:  zig test ex3_search.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Index of the first element equal to `wanted`, or null if absent.
/// Use a `for ... else` expression, not a separate flag variable.
fn indexOf(items: []const u32, wanted: u32) ?usize {
    return for (items, 0..) |item, i| {
        if (item == wanted) break i;
    } else null;
}

/// True when every row of the grid contains at least one zero.
/// Use a labeled outer loop with `continue :label`.
fn everyRowHasZero(grid: []const [3]u8) bool {
    var rows_with_zero: usize = 0;
    rows: for (grid) |row| {
        for (row) |cell| {
            if (cell == 0) {
                rows_with_zero += 1;
                continue :rows;
            }
        }
    }
    return rows_with_zero == grid.len;
}

/// Smallest divisor of n greater than 1 (n itself when n is prime).
/// Use a `while ... else` expression with a continue expression.
fn smallestDivisor(n: u32) u32 {
    var d: u32 = 2;
    return while (d * d <= n) : (d += 1) {
        if (n % d == 0) break d;
    } else n;
}

test "indexOf" {
    const roster = [_]u32{ 3, 8, 12, 27 };
    try std.testing.expectEqual(@as(?usize, 2), indexOf(&roster, 12));
    try std.testing.expectEqual(@as(?usize, 0), indexOf(&roster, 3));
    try std.testing.expectEqual(@as(?usize, null), indexOf(&roster, 99));
}

test "everyRowHasZero" {
    const yes = [_][3]u8{ .{ 1, 0, 2 }, .{ 0, 5, 5 }, .{ 7, 7, 0 } };
    const no = [_][3]u8{ .{ 1, 0, 2 }, .{ 4, 5, 5 } };
    try std.testing.expect(everyRowHasZero(&yes));
    try std.testing.expect(!everyRowHasZero(&no));
}

test "smallestDivisor" {
    try std.testing.expectEqual(@as(u32, 7), smallestDivisor(91));
    try std.testing.expectEqual(@as(u32, 2), smallestDivisor(100));
    try std.testing.expectEqual(@as(u32, 13), smallestDivisor(13));
}

The parameters are slices, []const u32, which Chapter 10 explains; for now they behave like arrays under for. Each function's shape matches one construct from this chapter, and the point of the exercise is to feel where each one is the natural fit.

Exercise 6.4 · A month of payroll challenge

Simulate thirty days of costs and weekly pay following the rules in the starter's header, printing a line each payday and stopping with a DEBT line the moment funds go negative. The expected output is given exactly. Name the file: exercises/06-control-flow/ex4_payroll.zig.

Solution 
//! Chapter 06, exercise 4: a month of payroll, day by day.
//! Run with:  zig run ex4_payroll.zig
//! Expected output (on stderr):
//!   day 7: paid 200000, funds 385000
//!   day 14: paid 200000, funds 270000
//!   day 21: paid 200000, funds 155000
//!   day 25: DEBT (-25000), stopping
const std = @import("std");

pub fn main() void {
    var funds: i64 = 500_000;
    const daily_cost: i64 = 45_000;
    const weekly_pay: i64 = 200_000;
    var day: u32 = 1;
    while (day <= 30) : (day += 1) {
        funds -= daily_cost;
        if (day % 7 == 0) {
            funds += weekly_pay;
            std.debug.print("day {d}: paid {d}, funds {d}\n", .{ day, weekly_pay, funds });
        }
        if (funds < 0) {
            std.debug.print("day {d}: DEBT ({d}), stopping\n", .{ day, funds });
            break;
        }
    }
}

Order matters: the day's cost is subtracted, then pay is added and printed if it is a payday, then the debt check runs. Getting day 25 rather than day 26 depends on doing the check after the cost on the same day. The break leaves the while even though the continue expression has not run, which is exactly right.

Check your understanding

  1. What is the difference between 0..n in a for and 0...n in a switch?
    AnswerTwo dots is an exclusive-end range for iteration (0 to n-1); three dots is an inclusive range for a switch case (0 to n).
  2. When does a while loop's continue expression run?
    AnswerAt the end of every iteration, including after a continue statement; it does not run after a break.
  3. What type does |i| have in for (0..10) |i|?
    Answerusize. Use @intCast to store it in a narrower type.
  4. How do you get both the element and its index from a for?
    AnswerIterate the array together with an open range: for (items, 0..) |item, i|.
  5. When does the else of a loop run?
    AnswerWhen the loop ends because its condition became false or its items ran out, not when it ends by break. It supplies the loop's value in that case.
  6. Why does switch (x) { 0 => "a", 1 => "b" } fail for x: u2?
    AnswerA u2 has values 0 to 3; the switch is not exhaustive. Add arms for 2 and 3 or an else.
  7. What happens if execution reaches unreachable in a Debug build? And in ReleaseFast?
    AnswerDebug: a panic, "reached unreachable code". ReleaseFast: undefined behaviour; the optimiser assumed it could not happen.
What you learned.
  • if takes a bool and can be an expression with a mandatory else.
  • while (cond) : (step) runs step after every iteration; break and continue work as expected.
  • for iterates ranges a..b and arrays, captures with |x|, gets an index from 0.., and walks several things in step.
  • Labels let break :outer and continue :outer reach an enclosing loop; loops can yield values with break v and else.
  • switch has values, lists, and inclusive a...b ranges, must be exhaustive, allows no overlap, and is an expression.
  • unreachable asserts a path cannot happen: a panic in Debug, a promise in release.
