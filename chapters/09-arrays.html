9. Arrays

In this chapter you will meet Zig's simplest collection: the fixed-length array. You will learn how its length is part of its type, how indexing is checked, how to loop over it, build it with repetition and concatenation, nest it, copy it, compare it, and pass it to functions. Arrays are the ground that slices (Chapter 10) and strings (Chapter 11) stand on, so this chapter is slow on purpose.

9.1 A fixed number of things

An array is a block of values of one type, sitting next to each other in memory, whose count is fixed when the program is compiled. A lance in BattleTech is four meks; their tonnages fit in a four-element array of bytes.

basics.zig

const std = @import("std");

pub fn main() void {
    const lance: [4]u8 = .{ 55, 65, 70, 50 }; // tonnage of four meks
    std.debug.print("first: {d}\n", .{lance[0]});
    std.debug.print("last: {d}\n", .{lance[3]});
    std.debug.print("length: {d}\n", .{lance.len});
}
first: 55
last: 50
length: 4

Read the type [4]u8 as "four u8". The number is part of the type: [4]u8 and [5]u8 are different types, as different as u8 and i32. That is the single most important fact about arrays in Zig, and most of this chapter follows from it.

Elements are numbered from zero. lance[0] is the first, lance[3] the last. lance.len is the count, and because the count is in the type, the compiler knows it without looking at the data.

The initialiser .{ 55, 65, 70, 50 } is an anonymous list literal; it takes the type [4]u8 from the declaration. When the type is not written anywhere, spell the element type and let Zig count for you with [_]:

infer.zig

const std = @import("std");

pub fn main() void {
    const a = [_]u8{ 55, 65, 70, 50 }; // type is [4]u8, length counted for you
    const b = [4]u8{ 55, 65, 70, 50 }; // same thing, spelled out
    std.debug.print("{any}\n", .{@TypeOf(a)});
    std.debug.print("{any}\n", .{@TypeOf(b)});
    std.debug.print("{any}\n", .{a});
}
[4]u8
[4]u8
{ 55, 65, 70, 50 }

[_]u8{ ... } is what you will write most of the time. It is the same array; you have only asked the compiler to count the elements. @TypeOf confirms both are [4]u8. Printing an array with {any} gives you the braces-and-commas form, which is handy while learning.

Coming from Python or JavaScript? A Python list or JS array grows and shrinks and can hold mixed types. A Zig array is closer to a C array or a NumPy fixed-shape buffer: one type, one size, chosen up front. The growable kind exists too, it is called ArrayList and needs an allocator (Chapter 21). Zig makes you choose, because the growable one costs heap memory and the fixed one costs nothing.

9.2 Indexing is checked

What happens if you ask for lance[4] in a four-element array? In C you get whatever bytes happen to sit after the array, silently. In Zig you get stopped. When the index is a plain number the compiler catches it before the program exists:

Four lines print, then the program panics: it stops with a message and a stack trace instead of reading memory that is not yours. index 4, len 4 says exactly what went wrong, and the first trace line names your file and column. This runtime check is on in the default Debug build and in ReleaseSafe; ReleaseFast turns it off for speed. While learning, leave it on.

Index type is usize. The variable i above is declared usize, an unsigned integer as wide as a memory address. Array indexes must be usize; if you try to index with an i32 or a u8 the compiler asks you to cast it with @intCast. Declare loop counters that index arrays as usize from the start and you avoid the whole conversation.

9.3 Looping over an array

You met for in Chapter 6. Its most common job is walking an array, and it never goes out of bounds because it reads the length from the type:

iter.zig

const std = @import("std");

pub fn main() void {
    const lance = [_]u8{ 55, 65, 70, 50 };

    var total: u32 = 0;
    for (lance) |tons| {
        total += tons;
    }
    std.debug.print("total tonnage: {d}\n", .{total});

    for (lance, 0..) |tons, i| {
        std.debug.print("slot {d}: {d} tons\n", .{ i, tons });
    }
}
total tonnage: 240
slot 0: 55 tons
slot 1: 65 tons
slot 2: 70 tons
slot 3: 50 tons

The first loop captures each element as tons. The second adds 0.. as a second thing to iterate, which yields the index alongside the element; i is a usize here without you saying so. Note that total is a u32, not a u8: four bytes can add up past 255, and Zig would panic on the overflow rather than wrap (Chapter 4). Choose the accumulator type with the sum in mind, not the elements.

To change elements as you go, you need two things: a var array, and a loop over &array that captures a pointer to each element:

mutate.zig

const std = @import("std");

pub fn main() void {
    var armor = [_]u8{ 10, 10, 10 };
    armor[1] = 3; // one element
    for (&armor) |*a| { // every element, through a pointer
        a.* += 1;
    }
    std.debug.print("{any}\n", .{armor});
}
{ 11, 4, 11 }

for (&armor) |*a| reads: for each element of the array behind this pointer, give me a pointer a to it. a.* is the element itself; a.* += 1 changes it in place. Without the & and the *, a would be a copy of each element and changing it would do nothing to the array. Pointers get their own chapter (Chapter 18); for now, memorise this shape.

And if the array is a const, nothing can change it:

const std = @import("std");

}

9.4 Arrays of arrays

An array's element type can itself be an array. That gives you grids, boards and tables with no extra machinery.

multi.zig

const std = @import("std");

pub fn main() void {
    // A 3-by-3 board: three rows, each a row of three bytes.
    var board: [3][3]u8 = .{
        .{ '.', '.', '.' },
        .{ '.', 'X', '.' },
        .{ '.', '.', '.' },
    };
    board[0][2] = 'O';

    for (board) |row| {
        for (row) |cell| std.debug.print("{c}", .{cell});
        std.debug.print("\n", .{});
    }
    std.debug.print("rows: {d}, cols: {d}\n", .{ board.len, board[0].len });
}
..O
.X.
...
rows: 3, cols: 3

Read [3][3]u8 from the outside in: three of (three u8). board[1] is a whole row, itself a [3]u8; board[1][1] is the byte in the middle. The nested literal mirrors the type, one .{ ... } per row. The outer for hands you each row and the inner one each cell.

The {c} format prints a u8 as a character rather than a number, which is why the board looks like a board.

9.5 Building arrays: ** and ++

Two operators work on arrays when their contents are known at compile time. ** repeats an array, and ++ joins two arrays end to end.

repeat.zig

const std = @import("std");

pub fn main() void {
    const zeros = [_]u32{0} ** 6; // six zeros
    const ab = [_]u8{ 'a', 'b' } ** 3; // a b a b a b
    const joined = [_]u8{ 1, 2 } ++ [_]u8{ 3, 4, 5 };
    std.debug.print("{any}\n", .{zeros});
    std.debug.print("{s}\n", .{&ab});
    std.debug.print("{any} len {d}\n", .{ joined, joined.len });
    const line = "-" ** 20;
    std.debug.print("{s}\n", .{line});
}
{ 0, 0, 0, 0, 0, 0 }
ababab
{ 1, 2, 3, 4, 5 } len 5
--------------------

[_]u32{0} ** 6 is the idiom for "an array of six zeros", and you will see it in IRON LEDGER for counters. ++ produces a new array whose length is the sum. Both need the operands to be compile-time known; you cannot ++ two arrays that were filled in at runtime (for that you copy into a buffer, which Chapter 10 shows).

The last line shows that string literals are arrays too, so "-" ** 20 builds a twenty-dash line at compile time. This is a favourite for drawing borders.

9.6 undefined: reserve now, fill later

Sometimes you want the space for an array but do not have the values yet, because a later loop or a formatting call will write them. Initialise with undefined:

undef.zig

const std = @import("std");

pub fn main() void {
    var buf: [8]u8 = undefined; // reserved, but holds garbage until written
    for (&buf, 0..) |*b, i| {
        b.* = @intCast('a' + i);
    }
    std.debug.print("{s}\n", .{&buf});
}
abcdefgh

undefined means "I promise to write this before I read it". Zig does not zero the memory for you; in Debug builds it fills it with the byte 0xAA so that a forgotten write shows up as obvious garbage rather than a lucky zero. You will use var buf: [N]u8 = undefined; constantly as scratch space for building text.

The @intCast on 'a' + i is needed because i is a usize, so the sum is a usize, and the element type is u8. The cast says "I know this fits"; in Debug it checks.

Reading undefined is a bug, not an error. The compiler cannot always tell that you read before writing. If your output contains repeated 170 (that is 0xAA) where you expected real values, look for an undefined array that a code path forgot to fill.

9.7 Assignment copies

An array is a value, like an integer. Assigning it, or passing it to a function, copies all of it.

copy.zig

const std = @import("std");

pub fn main() void {
    const original = [_]u8{ 1, 2, 3 };
    var copy = original; // a full copy, not a reference
    copy[0] = 99;
    std.debug.print("original: {any}\n", .{original});
    std.debug.print("copy:     {any}\n", .{copy});
}
original: { 1, 2, 3 }
copy:     { 99, 2, 3 }

If you are used to Python, where b = a makes two names for one list, this is the opposite. There is no sharing unless you ask for it with a pointer or a slice. For small arrays this is exactly what you want; for a [1_000_000]u8 it is a million bytes moved, and you would pass a pointer instead (next section).

9.8 Comparing arrays

There is no == for arrays:

const std = @import("std");

pub fn main() void {
    const a = [_]u8{ 1, 2, 3 };
    const b = [_]u8{ 1, 2, 3 };
    std.debug.print("{}\n", .{a == b});
}

Zig keeps operators for things that are one machine instruction, or close to it; comparing a hundred elements is a loop, so it is a function. The function is std.mem.eql, and it takes the element type first, then two arrays by reference:

eql.zig

const std = @import("std");

pub fn main() void {
    const a = [_]u8{ 1, 2, 3 };
    const b = [_]u8{ 1, 2, 3 };
    const c = [_]u8{ 1, 2, 4 };
    std.debug.print("a == b: {}\n", .{std.mem.eql(u8, &a, &b)});
    std.debug.print("a == c: {}\n", .{std.mem.eql(u8, &a, &c)});
    // Arrays of the same type can also be compared with == directly? Let's see.
}
a == b: true
a == c: false

The & matters: std.mem.eql takes slices, and &array turns an array into a slice of the whole thing. That coercion is the bridge to the next chapter. In tests, std.testing.expectEqual compares two arrays element by element, so expectEqual([3]u8{ 1, 2, 3 }, arr) works there without eql.

9.9 Passing arrays to functions

Because the length is part of the type, a function parameter of type [4]u8 accepts exactly four-element arrays and nothing else. And because arrays are values, the function receives a copy.

pass.zig

const std = @import("std");

fn sumByValue(xs: [4]u8) u32 {
    var t: u32 = 0;
    for (xs) |x| t += x;
    return t;
}

fn bumpByValue(xs: [4]u8) void {
    var local = xs;
    local[0] += 1; // changes the copy only
}

fn bumpByPointer(xs: *[4]u8) void {
    xs[0] += 1; // changes the caller's array
}

pub fn main() void {
    var lance = [_]u8{ 55, 65, 70, 50 };
    std.debug.print("sum: {d}\n", .{sumByValue(lance)});
    bumpByValue(lance);
    std.debug.print("after by value:   {any}\n", .{lance});
    bumpByPointer(&lance);
    std.debug.print("after by pointer: {any}\n", .{lance});
}
sum: 240
after by value:   { 55, 65, 70, 50 }
after by pointer: { 56, 65, 70, 50 }

Three things to notice. sumByValue reads its copy; that is fine and cheap for four bytes. bumpByValue changes its copy and the caller sees nothing: parameters are immutable in Zig, so it had to copy into a var first, and that var dies at the closing brace. bumpByPointer takes *[4]u8, a pointer to a four-byte array, and the caller passes &lance; writing through the pointer changes the original.

The rule of thumb: take arrays by value when the function only reads and the array is small; take *[N]T when the function must modify the caller's array; and, most of the time, take a slice so the length is not baked into the signature at all. Here is the wall you hit otherwise:

const std = @import("std");

fn sum(xs: [4]u8) u32 {
    var t: u32 = 0;
    for (xs) |x| t += x;
    return t;
}

pub fn main() void {
    const three = [_]u8{ 1, 2, 3 };
    std.debug.print("{d}\n", .{sum(three)});
}
pass_wrong_len.zig:11:36: error: expected type '[4]u8', found '[3]u8'
    std.debug.print("{d}\n", .{sum(three)});
                                   ^~~~~
pass_wrong_len.zig:11:36: note: destination has length 4
pass_wrong_len.zig:11:36: note: source has length 3
referenced by:
    callMain [inlined]: <zig>/lib/std/start.zig:698:59
    callMainWithArgs [inlined]: <zig>/lib/std/start.zig:638:20
    main: <zig>/lib/std/start.zig:663:28

A sum that works on four elements but not three is not much of a sum. The fix is to declare the parameter as []const u8, a slice, and that is the subject of Chapter 10.

In IRON LEDGER. Fixed arrays show up wherever the count is a rule of the game rather than a fact about the data. The hangar report counts units by quality with six counters, one per quality grade, built with ** and indexed by an enum's integer value: 
// src/main.zig
var quality_counts = [_]u32{0} ** 6;
var broken_slots: u32 = 0;
var uit = gs.units.iterator();
while (uit.next()) |entry| {
    quality_counts[@intFromEnum(entry.value_ptr.quality)] += 1;
    for (entry.value_ptr.slots.items) |s| {
        if (s.condition != .ok) broken_slots += 1;

The terminal client keeps its tab names and the year picker as arrays of compile-time constants (src/tui/app.zig): const start_years = [_]u16{ 3015, 3020, 3025, 3028, 3030 }; and a [_][]const u8 of ten tab labels. An emblem editor holds a 3-by-8 character grid as [3][8]u8, filled with spaces by @splat, exactly the array-of-arrays shape from 9.4. None of these can ever have the wrong length, because the length is the type.

Exercise 9.1 · Array statistics warm-up

Implement heaviest, total and indexOf over a [4]u8. Pay attention to the result type of total. Name the file: exercises/09-arrays/ex1_stats.zig.

Solution 
//! Chapter 09, exercise 1: array statistics.
//! Run with:  zig test ex1_stats.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// The heaviest value in the array.
fn heaviest(tons: [4]u8) u8 {
    var best: u8 = 0;
    for (tons) |t| {
        if (t > best) best = t;
    }
    return best;
}

/// The sum of all values. Note the wider result type: four u8 can exceed 255.
fn total(tons: [4]u8) u32 {
    var sum: u32 = 0;
    for (tons) |t| sum += t;
    return sum;
}

/// Index of the first element equal to `needle`, or the array length if absent.
fn indexOf(tons: [4]u8, needle: u8) usize {
    for (tons, 0..) |t, i| {
        if (t == needle) return i;
    }
    return tons.len;
}

test "heaviest" {
    try std.testing.expectEqual(@as(u8, 70), heaviest(.{ 55, 65, 70, 50 }));
    try std.testing.expectEqual(@as(u8, 100), heaviest(.{ 100, 20, 20, 20 }));
}

test "total does not overflow" {
    try std.testing.expectEqual(@as(u32, 240), total(.{ 55, 65, 70, 50 }));
    try std.testing.expectEqual(@as(u32, 1020), total(.{ 255, 255, 255, 255 }));
}

test "indexOf" {
    const lance = [_]u8{ 55, 65, 70, 50 };
    try std.testing.expectEqual(@as(usize, 2), indexOf(lance, 70));
    try std.testing.expectEqual(@as(usize, 4), indexOf(lance, 99));
}

total accumulates into a u32; the second test adds four 255s, which would panic with integer overflow in a u8. indexOf returns tons.len as a "not found" marker; Chapter 15 will replace that with an optional.

Exercise 9.2 · Reverse in place practice

Write reverse, which takes a pointer to a five-element array and reverses it in place, and reversed, which takes the array by value and returns a reversed copy without touching the original. Name the file: exercises/09-arrays/ex2_reverse.zig.

Solution 
//! Chapter 09, exercise 2: reverse in place, through a pointer.
//! Run with:  zig test ex2_reverse.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Reverse the array the pointer refers to. The caller sees the change.
fn reverse(xs: *[5]i32) void {
    var i: usize = 0;
    var j: usize = xs.len - 1;
    while (i < j) : ({
        i += 1;
        j -= 1;
    }) {
        const tmp = xs[i];
        xs[i] = xs[j];
        xs[j] = tmp;
    }
}

/// Return a reversed copy; the caller's array is untouched.
fn reversed(xs: [5]i32) [5]i32 {
    var out = xs;
    reverse(&out);
    return out;
}

test "reverse mutates through the pointer" {
    var xs = [_]i32{ 1, 2, 3, 4, 5 };
    reverse(&xs);
    try std.testing.expectEqual([5]i32{ 5, 4, 3, 2, 1 }, xs);
}

test "reversed leaves the original alone" {
    const xs = [_]i32{ 1, 2, 3, 4, 5 };
    const ys = reversed(xs);
    try std.testing.expectEqual([5]i32{ 1, 2, 3, 4, 5 }, xs);
    try std.testing.expectEqual([5]i32{ 5, 4, 3, 2, 1 }, ys);
}

test "reversing twice is the identity" {
    var xs = [_]i32{ 9, -1, 0, 7, 3 };
    reverse(&xs);
    reverse(&xs);
    try std.testing.expect(std.mem.eql(i32, &xs, &[_]i32{ 9, -1, 0, 7, 3 }));
}

Through a *[5]i32 you can index directly, xs[i], without dereferencing first; Zig does that for you on pointers to arrays. reversed reuses reverse on its local copy, which is the usual way to get a by-value version of an in-place function.

Exercise 9.3 · A battle grid practice

Build a [4][6]u8 grid of '.' characters, place markers into it through a pointer, count markers, and render one row as text into a caller-supplied buffer. Name the file: exercises/09-arrays/ex3_grid.zig.

Solution 
//! Chapter 09, exercise 3: a hex-less battle grid.
//! Run with:  zig test ex3_grid.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const rows = 4;
const cols = 6;
const Grid = [rows][cols]u8;

/// A grid full of '.' characters.
fn emptyGrid() Grid {
    return [_][cols]u8{[_]u8{'.'} ** cols} ** rows;
}

/// Place marker `m` at (r, c). Out-of-range coordinates are a bug; let Zig panic.
fn place(g: *Grid, r: usize, c: usize, m: u8) void {
    g[r][c] = m;
}

/// Count how many cells hold marker `m`.
fn count(g: Grid, m: u8) usize {
    var n: usize = 0;
    for (g) |row| {
        for (row) |cell| {
            if (cell == m) n += 1;
        }
    }
    return n;
}

/// Write row `r` into `buf` and return it as text (for printing).
fn rowText(g: Grid, r: usize, buf: *[cols]u8) []const u8 {
    buf.* = g[r];
    return buf;
}

test "empty grid is all dots" {
    const g = emptyGrid();
    try std.testing.expectEqual(@as(usize, rows * cols), count(g, '.'));
    try std.testing.expectEqual(@as(usize, 0), count(g, 'M'));
}

test "placing markers" {
    var g = emptyGrid();
    place(&g, 0, 0, 'M');
    place(&g, 3, 5, 'M');
    place(&g, 1, 2, 'T');
    try std.testing.expectEqual(@as(usize, 2), count(g, 'M'));
    try std.testing.expectEqual(@as(usize, 1), count(g, 'T'));
    try std.testing.expectEqual(@as(usize, rows * cols - 3), count(g, '.'));
}

test "row as text" {
    var g = emptyGrid();
    place(&g, 2, 1, 'M');
    var buf: [cols]u8 = undefined;
    try std.testing.expectEqualStrings(".M....", rowText(g, 2, &buf));
    try std.testing.expectEqualStrings("......", rowText(g, 0, &buf));
}

[_][cols]u8{[_]u8{'.'} ** cols} ** rows repeats a row of dots rows times. rowText copies the row into the buffer with a plain assignment (buf.* = g[r], arrays copy) and returns the buffer, which coerces to []const u8.

Exercise 9.4 · A dice histogram challenge

Given 2d6 results, count how often each total appeared into a [13]u32 (indexes 0 and 1 stay zero), find the most frequent total, and draw a text bar for one total using std.fmt.bufPrint for the prefix. Name the file: exercises/09-arrays/ex4_histogram.zig.

Solution 
//! Chapter 09, exercise 4: a dice histogram (challenge).
//! Run with:  zig test ex4_histogram.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Given a list of 2d6 results (each 2..12), count how many times each total
/// appeared. Index 0 and 1 of the result are always zero.
fn histogram(rolls: []const u8) [13]u32 {
    var counts = [_]u32{0} ** 13;
    for (rolls) |r| {
        counts[r] += 1;
    }
    return counts;
}

/// The most frequent total. Ties go to the smaller total.
fn mode(counts: [13]u32) u8 {
    var best: u8 = 2;
    for (counts, 0..) |c, i| {
        if (c > counts[best]) best = @intCast(i);
    }
    return best;
}

/// Build a one-line text bar for a total: "7: ####" style, into buf.
fn bar(buf: []u8, total: u8, n: u32) []const u8 {
    const prefix = std.fmt.bufPrint(buf, "{d:>2}: ", .{total}) catch unreachable;
    var i: usize = 0;
    while (i < n) : (i += 1) buf[prefix.len + i] = '#';
    return buf[0 .. prefix.len + n];
}

test "histogram counts every total" {
    const h = histogram(&[_]u8{ 7, 7, 2, 12, 7, 6 });
    try std.testing.expectEqual(@as(u32, 3), h[7]);
    try std.testing.expectEqual(@as(u32, 1), h[2]);
    try std.testing.expectEqual(@as(u32, 1), h[12]);
    try std.testing.expectEqual(@as(u32, 0), h[3]);
    try std.testing.expectEqual(@as(u32, 0), h[0]);
}

test "empty input gives all zeros" {
    const h = histogram(&[_]u8{});
    try std.testing.expectEqual([_]u32{0} ** 13, h);
}

test "mode" {
    try std.testing.expectEqual(@as(u8, 7), mode(histogram(&[_]u8{ 7, 7, 2, 12, 7, 6 })));
    try std.testing.expectEqual(@as(u8, 3), mode(histogram(&[_]u8{ 9, 3, 3, 9 })));
}

test "bar" {
    var buf: [32]u8 = undefined;
    try std.testing.expectEqualStrings(" 7: ###", bar(&buf, 7, 3));
    try std.testing.expectEqualStrings("12: ", bar(&buf, 12, 0));
}

The histogram indexes the array directly by the roll value, which is why it has 13 slots for values up to 12. mode starts at 2 and only moves on a strictly larger count, so ties go to the smaller total. bar takes a slice rather than an array so it works with any buffer size; the next chapter explains why that is the better signature.

Check your understanding

  1. Are [3]u8 and [4]u8 the same type?
    AnswerNo. The length is part of an array type, so they are different types and cannot be assigned to each other or passed where the other is expected.
  2. What does [_] mean in [_]u8{ 1, 2, 3 }?
    Answer"Count the elements for me." The type is still a fixed [3]u8; the underscore only saves you writing the number.
  3. What happens when you index past the end with a runtime index in a Debug build?
    AnswerThe program panics with index out of bounds: index N, len M and a stack trace. With a compile-time index it is a compile error instead.
  4. How do you modify each element in a for loop?
    AnswerLoop over &array and capture with |*item|, then assign through item.*. The array must be a var.
  5. What does var b = a; do when a is an array?
    AnswerCopies every element. b is an independent array; changing it does not affect a.
  6. Why does a == b not compile for arrays, and what do you use instead?
    AnswerZig reserves operators for cheap operations; element-wise comparison is a loop, so it is the function std.mem.eql(T, &a, &b). In tests, expectEqual also compares arrays element by element.
  7. When should a parameter be *[4]u8 instead of [4]u8?
    AnswerWhen the function must modify the caller's array, or when the array is large enough that copying it is wasteful. For read-only access to arrays of any length, a slice []const u8 is better still.
What you learned.
  • An array type [N]T includes its length; [_]T{...} lets the compiler count.
  • Indexes are usize, start at 0, and are bounds-checked: a compile error for constant indexes, a panic for runtime ones.
  • for (arr) |x| reads, for (arr, 0..) |x, i| adds the index, for (&arr) |*x| lets you write.
  • [N][M]T is an array of arrays; index with a[r][c].
  • ** repeats and ++ concatenates compile-time arrays; undefined reserves space you promise to fill.
  • Arrays are values: assignment and by-value parameters copy. Compare with std.mem.eql, not ==.
  • Pass *[N]T to modify in place; pass a slice to accept any length.
