27. Reflection with @typeInfo

In this chapter you will ask the compiler questions about types: what kind of thing a type is, what fields a struct has, what tags an enum has, and whether a name exists. You will use the answers, at compile time, to write one function that handles many types. By the end you will understand the tuning-table validator that IRON LEDGER runs on every build.

27.1 Types are values, and values have types

In Chapter 26 you passed types into functions as comptime T: type. Reflection is the other direction: given a value or a type, ask the compiler what it is. The first tool is @TypeOf, which takes any expression and returns its type without evaluating it at run time. The second is @typeName, which turns a type into a string you can print.

typeof.zig

const std = @import("std");

pub fn main() void {
    const a = 42;
    const b: u8 = 42;
    const c = 2.5;
    const name = "Shadow Hawk";
    const list = [_]u16{ 1, 2, 3 };

    std.debug.print("a is {s}\n", .{@typeName(@TypeOf(a))});
    std.debug.print("b is {s}\n", .{@typeName(@TypeOf(b))});
    std.debug.print("c is {s}\n", .{@typeName(@TypeOf(c))});
    std.debug.print("name is {s}\n", .{@typeName(@TypeOf(name))});
    std.debug.print("list is {s}\n", .{@typeName(@TypeOf(list))});
    std.debug.print("list[0..] is {s}\n", .{@typeName(@TypeOf(list[0..]))});
    std.debug.print("a + b is {s}\n", .{@typeName(@TypeOf(a + b))});
}
a is comptime_int
b is u8
c is comptime_float
name is *const [11:0]u8
list is [3]u16
list[0..] is *const [3]u16
a + b is u8

Every line here teaches something you already half knew. A bare literal like 42 is a comptime_int, not a u8 or an i32: it has no width until it meets a typed variable. A string literal is a pointer to a constant, sentinel-terminated array of bytes, which is why "Shadow Hawk" shows as *const [11:0]u8. Slicing an array with [0..] gives a pointer to the whole array, not a slice, because the length is still known. And a + b is a u8: the untyped literal adopted the concrete type next to it.

Why this matters. Zig has no auto keyword and no type inference across function boundaries, but inside an expression the compiler always knows the type. @TypeOf lets you name that type in places where you would otherwise repeat it, such as var copy: @TypeOf(original) = original;. It is also how generic functions with anytype parameters discover what they were given.

27.2 @typeInfo: a description of a type

@typeInfo(T) returns a value of type std.builtin.Type, which is a tagged union (Chapter 14). Each tag names a kind of type, and most tags carry a payload struct with the details. Because it is a tagged union, you inspect it with switch, and because the argument is a type, the whole switch happens at compile time.

describe.zig

const std = @import("std");

fn describe(comptime T: type) []const u8 {
    return switch (@typeInfo(T)) {
        .int => |info| if (info.signedness == .signed) "a signed integer" else "an unsigned integer",
        .float => "a float",
        .bool => "a boolean",
        .pointer => "a pointer",
        .array => "an array",
        .optional => "an optional",
        .error_union => "an error union",
        .@"struct" => "a struct",
        .@"enum" => "an enum",
        .@"union" => "a union",
        .@"fn" => "a function",
        else => "something else",
    };
}

const Role = enum { pilot, tech, medic };
const Pilot = struct { name: []const u8, gunnery: u8 };

pub fn main() void {
    std.debug.print("u32:       {s}\n", .{describe(u32)});
    std.debug.print("i8:        {s}\n", .{describe(i8)});
    std.debug.print("f64:       {s}\n", .{describe(f64)});
    std.debug.print("bool:      {s}\n", .{describe(bool)});
    std.debug.print("*u8:       {s}\n", .{describe(*u8)});
    std.debug.print("[]u8:      {s}\n", .{describe([]const u8)});
    std.debug.print("[4]u8:     {s}\n", .{describe([4]u8)});
    std.debug.print("?u8:       {s}\n", .{describe(?u8)});
    std.debug.print("!u8:       {s}\n", .{describe(anyerror!u8)});
    std.debug.print("Pilot:     {s}\n", .{describe(Pilot)});
    std.debug.print("Role:      {s}\n", .{describe(Role)});
    std.debug.print("fn:        {s}\n", .{describe(@TypeOf(describe))});
}

f64:       a float

[4]u8:     an array

Two details of the spelling deserve a pause. The tags for struct, enum, union and function are .@"struct", .@"enum", .@"union" and .@"fn": those words are keywords in Zig, and the @"…" syntax lets an identifier be spelled with a keyword. The other tags are plain lower-case words: .int, .float, .bool, .pointer, .array, .optional, .error_union, .vector, .void, .type.

Old tutorials will mislead you. Before 0.14 the tags were capitalised: .Int, .Struct, .Enum. In 0.16 those do not exist. If a snippet on the web writes @typeInfo(T).Struct.fields, translate it to @typeInfo(T).@"struct".fields.

Notice also that a slice ([]const u8) reports as .pointer. A slice is a pointer with a length, and the pointer payload tells you which flavour it is through a size field: .one, .many, .slice or .c.

27.3 Reading the payload

The tag tells you the kind; the payload tells you the details. You capture it in a switch arm with |info|, or reach for it directly with field syntax when you already know the kind: @typeInfo(i16).int is the Int payload, and it is a compile error if i16 were not an integer.

intinfo.zig

const std = @import("std");

fn bitsOf(comptime T: type) u16 {
    return switch (@typeInfo(T)) {
        .int => |i| i.bits,
        .float => |f| f.bits,
        else => @compileError("bitsOf wants a number type, got " ++ @typeName(T)),
    };
}

pub fn main() void {
    std.debug.print("u8 has {d} bits\n", .{bitsOf(u8)});
    std.debug.print("i64 has {d} bits\n", .{bitsOf(i64)});
    std.debug.print("u3 has {d} bits\n", .{bitsOf(u3)});
    std.debug.print("f32 has {d} bits\n", .{bitsOf(f32)});
    const info = @typeInfo(i16).int;
    std.debug.print("i16: signedness={s} bits={d}\n", .{ @tagName(info.signedness), info.bits });
    const opt = @typeInfo(?u32).optional;
    std.debug.print("?u32 wraps {s}\n", .{@typeName(opt.child)});
    const arr = @typeInfo([5]f32).array;
    std.debug.print("[5]f32: {d} of {s}\n", .{ arr.len, @typeName(arr.child) });
    const ptr = @typeInfo([]const u8).pointer;
    std.debug.print("[]const u8: size={s} const={} child={s}\n", .{ @tagName(ptr.size), ptr.is_const, @typeName(ptr.child) });
}
u8 has 8 bits
i64 has 64 bits
u3 has 3 bits
f32 has 32 bits
i16: signedness=signed bits=16
?u32 wraps u32
[5]f32: 5 of f32
[]const u8: size=slice const=true child=u8

bitsOf shows the standard shape of a reflective function: switch on the info, use the payload in the arms you support, and turn every other kind into a @compileError with a helpful message. The message is built with ++, which concatenates strings at compile time, so it can include @typeName(T). Try calling bitsOf(bool) and read the error: it names your function, your message and the offending type.

Compile errors are the point. A reflective function that quietly does the wrong thing for an unexpected type is worse than one that refuses. Always end the switch with else => @compileError(…) unless "do nothing" is genuinely the right behaviour, as it is in the validator later in this chapter.

27.4 Walking the fields of a struct

The most useful payload is .@"struct".fields: a slice of StructField, each with a name, a type, and whether it has a default. Combined with inline for, which unrolls the loop at compile time, and @field(value, name), which reads a field by a compile-time known name, you can visit every field of any struct without knowing the struct in advance.

walk.zig

const std = @import("std");

const Pilot = struct {
    name: []const u8,
    gunnery: u8,
    piloting: u8,
    salary: u32,
    active: bool,
};

fn printFields(value: anytype) void {
    const T = @TypeOf(value);
    const info = @typeInfo(T).@"struct";
    std.debug.print("{s} has {d} fields:\n", .{ @typeName(T), info.fields.len });
    inline for (info.fields) |f| {
        std.debug.print("  {s}: {s} = {any}\n", .{ f.name, @typeName(f.type), @field(value, f.name) });
    }
}

pub fn main() void {
    const p = Pilot{ .name = "Kell", .gunnery = 3, .piloting = 4, .salary = 1500, .active = true };
    printFields(p);
}
walk.Pilot has 5 fields:
  name: []const u8 = { 75, 101, 108, 108 }
  gunnery: u8 = 3
  piloting: u8 = 4
  salary: u32 = 1500
  active: bool = true

Read printFields slowly. It takes anytype, so it is specialised per argument type. @TypeOf(value) recovers the type. @typeInfo(T).@"struct" would be a compile error for a non-struct, which is fine: that is the contract. Then inline for runs the body once per field, at compile time, with f a different constant each time. Inside, f.name is a string, f.type is a type, and @field(value, f.name) is the actual field value, with its own concrete type.

The one blemish is the name: {any} printed the string as a list of byte values, because to the formatter a []const u8 is just a slice of integers. You already know the fix from Chapter 23: pick the format by type. Reflection lets you do that inside the loop.

walk2.zig

fn printFields(value: anytype) void {
    const T = @TypeOf(value);
    inline for (@typeInfo(T).@"struct".fields) |f| {
        const v = @field(value, f.name);
        switch (@typeInfo(f.type)) {
            .int => std.debug.print("  {s} = {d}\n", .{ f.name, v }),
            .bool => std.debug.print("  {s} = {}\n", .{ f.name, v }),
            .pointer => std.debug.print("  {s} = \"{s}\"\n", .{ f.name, v }),
            else => std.debug.print("  {s} = ?\n", .{f.name}),
        }
    }
}

  name = "Kell"
  gunnery = 3
  piloting = 4
  salary = 1500
  active = true

The inner switch (@typeInfo(f.type)) is resolved at compile time for each field, so the compiled program contains five straight-line print calls and no switch at all. This pattern, an outer inline for over fields and an inner switch on each field's kind, is the heart of every serializer, pretty-printer and validator written in Zig. Exercise 27.2 asks you to grow it into a general toString.

27.5 Writing fields by name

@field works on the left of an assignment too, provided you have a pointer to the struct. This is how a settings screen or a command parser can map a run-time string like "turnover" onto a field, without a hand-written table that goes stale.

setfield.zig

const std = @import("std");

const Tuning = struct { fatigue_tired: u8 = 30, exhausted: u8 = 70, turnover: u8 = 3 };

fn setByName(t: *Tuning, name: []const u8, value: u8) bool {
    inline for (@typeInfo(Tuning).@"struct".fields) |f| {
        if (std.mem.eql(u8, f.name, name)) {
            @field(t, f.name) = value;
            return true;
        }
    }
    return false;
}

pub fn main() void {
    var t = Tuning{};
    _ = setByName(&t, "turnover", 5);
    const ok = setByName(&t, "nonsense", 1);
    std.debug.print("turnover={d} nonsense-accepted={}\n", .{ t.turnover, ok });
}
turnover=5 nonsense-accepted=false

The inline for is unrolled at compile time, but the std.mem.eql inside runs at run time, once per field, because name is a run-time value. So this compiles to three string comparisons. That is the usual division of labour: the shape is fixed at compile time, the data flows at run time.

All fields must accept the value. The line @field(t, f.name) = value is compiled once per field, so it must type-check for every field. Here every field is a u8, so a u8 value works. If one field were a u32 and another a bool, you would need an inner switch on f.type to convert or skip, exactly as in walk2.zig.

27.6 @hasField, @hasDecl and the decls list

Sometimes you do not need to walk everything; you just want to know whether a name exists. @hasField(T, "name") answers for fields, @hasDecl(T, "name") for declarations (functions and constants inside the struct). Both return a compile-time bool, so they combine naturally with if to select code paths per type.

has.zig

const std = @import("std");

const Mek = struct {
    tonnage: u32,
    pub fn describe(self: Mek) u32 {
        return self.tonnage;
    }
    pub const max_tonnage = 100;
};
const Rock = struct { mass: u32 };

fn weightOf(thing: anytype) u32 {
    const T = @TypeOf(thing);
    if (@hasField(T, "tonnage")) return thing.tonnage;
    if (@hasField(T, "mass")) return thing.mass;
    @compileError(@typeName(T) ++ " has neither tonnage nor mass");
}

pub fn main() void {
    std.debug.print("mek: {d}\n", .{weightOf(Mek{ .tonnage = 55 })});
    std.debug.print("rock: {d}\n", .{weightOf(Rock{ .mass = 3 })});
    std.debug.print("Mek has describe: {}\n", .{@hasDecl(Mek, "describe")});
    std.debug.print("Rock has describe: {}\n", .{@hasDecl(Rock, "describe")});
    inline for (@typeInfo(Mek).@"struct".decls) |d| {
        std.debug.print("Mek decl: {s}\n", .{d.name});
    }
}
mek: 55
rock: 3
Mek has describe: true
Rock has describe: false
Mek decl: describe
Mek decl: max_tonnage

weightOf is a small example of what other languages call duck typing, except that it is checked when the program is compiled rather than when the line runs. Pass a type with neither field and the @compileError fires with the type's name in the message. Note that the if statements are not comptime if in any special syntax: because the condition is a compile-time constant, the compiler simply drops the branches that cannot be taken, including the @compileError when it is unreachable.

The decls list only contains public declarations. Private functions are invisible to reflection from outside, which keeps @hasDecl honest as an interface check: "does this type provide a public describe?"

27.7 Enums under the microscope

Enums (Chapter 13) expose their tags through .@"enum".fields, each an EnumField with a name and an integer value. The payload also tells you the tag integer type and whether the enum is exhaustive. The length of the field list is a compile-time integer, so it can size an array.

enuminfo.zig

const std = @import("std");

const Stream = enum { combat, market, weather, names };

pub fn main() void {
    const info = @typeInfo(Stream).@"enum";
    std.debug.print("tag type {s}, exhaustive={}\n", .{ @typeName(info.tag_type), info.is_exhaustive });
    inline for (info.fields) |f| {
        std.debug.print("  {s} = {d}\n", .{ f.name, f.value });
    }
    var counters = [_]u32{0} ** info.fields.len;
    counters[@intFromEnum(Stream.weather)] += 1;
    std.debug.print("counters has {d} slots\n", .{counters.len});
    const parsed = std.meta.stringToEnum(Stream, "market");
    std.debug.print("parsed: {?}\n", .{parsed});
}
tag type u2, exhaustive=true
  combat = 0
  market = 1
  weather = 2
  names = 3
counters has 4 slots
parsed: .market

Notice the tag type: the compiler picked u2, the smallest integer that holds four values. The array counters has exactly one slot per tag, and if someone adds a fifth stream to the enum, the array grows with it and no test needs to change. This is precisely how IRON LEDGER sizes its array of random number generators, one per Stream.

std.meta.stringToEnum is the standard library's version of the loop you would write yourself with inline for over the fields and std.mem.eql. Exercise 27.5 has you write it, so you can see there is no magic.

27.8 Making types: @Int and @Enum

Reflection also runs in reverse: you can construct a type from a description. Older Zig had one builtin, @Type, that took a std.builtin.Type value. Zig 0.16 removed it and replaced it with one builtin per kind: @Int(signedness, bits), @Enum(tag_type, mode, names, values), @Struct(…) and so on. You will rarely need these; the standard library wraps the common ones as std.meta.Int. But they are worth seeing once.

attype.zig

const std = @import("std");

const U12 = @Int(.unsigned, 12);

fn Unsigned(comptime bits: u16) type {
    return @Int(.unsigned, bits);
}

const Color = @Enum(u8, .exhaustive, &.{ "red", "green", "blue" }, &.{ 0, 1, 2 });

pub fn main() void {
    const x: U12 = 4095;
    std.debug.print("{s} max = {d}\n", .{ @typeName(U12), x });
    const y: Unsigned(20) = 1_000_000;
    std.debug.print("{s} holds {d}\n", .{ @typeName(@TypeOf(y)), y });
    std.debug.print("Unsigned(12) == u12: {}\n", .{Unsigned(12) == u12});
    std.debug.print("std.meta.Int(.signed, 7) == i7: {}\n", .{std.meta.Int(.signed, 7) == i7});
    const c: Color = .green;
    std.debug.print("Color.green = {d}\n", .{@intFromEnum(c)});
}
u12 max = 4095
u20 holds 1000000
Unsigned(12) == u12: true
std.meta.Int(.signed, 7) == i7: true
Color.green = 1

Two things to take from this. First, types are compared with == and a constructed u12 is the same type as the one you would write by hand; there is only one u12. Second, the arguments to @Enum are ordinary compile-time values (a slice of names, a slice of values), which means a program can compute an enum from a table. That is a deep rabbit hole; for this course, knowing that @Type is gone and @Int exists is enough.

Trap. If you paste code that calls @Type(.{ .int = … }), 0.16 says error: invalid builtin function: '@Type'. Replace it with @Int(.unsigned, bits) or std.meta.Int(.unsigned, bits).

27.9 Worked example: validating a tuning table

Now the pieces come together. IRON LEDGER keeps every balance constant in one nested struct, Tuning, loaded from a data file (the next chapter explains how). The designers wanted a test that checks every unsigned knob is positive and every basis-point knob (a field whose name ends in _bp) is at most 100,000, and they wanted the test to cover new knobs automatically. Here is the whole thing, with a small stand-in table so the file runs on its own.

tuning.zig

const std = @import("std");

const Tuning = struct {
    person: struct { fatigue_tired: u8, exhausted_fatigue: u8, turnover_target: u8 },
    market: struct { fab_cost_bp: u32, fab_days: u32, morale_delta: i8 },
};

const t = Tuning{
    .person = .{ .fatigue_tired = 30, .exhausted_fatigue = 70, .turnover_target = 3 },
    .market = .{ .fab_cost_bp = 12_000, .fab_days = 14, .morale_delta = -2 },
};

fn checkPositive(comptime T: type, value: T, comptime name: []const u8) !void {
    switch (@typeInfo(T)) {
        .int => |info| {
            if (info.signedness == .signed) return;
            if (value <= 0) {
                std.debug.print("tuning field {s} must be positive\n", .{name});
                return error.BadTuning;
            }
            if (std.mem.endsWith(u8, name, "_bp") and value > 100_000) {
                std.debug.print("tuning field {s} is over 100000 basis points\n", .{name});
                return error.BadTuning;
            }
        },
        .@"struct" => |info| inline for (info.fields) |f|
            try checkPositive(f.type, @field(value, f.name), name ++ "." ++ f.name),
        else => {},
    }
}

test "every tuning value is positive and every basis-point knob is sane" {
    try checkPositive(Tuning, t, "t");
}

test "a zero knob is caught" {
    var bad = t;
    bad.market.fab_days = 0;
    try std.testing.expectError(error.BadTuning, checkPositive(Tuning, bad, "bad"));
}

test "a silly basis-point knob is caught" {
    var bad = t;
    bad.market.fab_cost_bp = 5_000_000;
    try std.testing.expectError(error.BadTuning, checkPositive(Tuning, bad, "bad"));
}
$ zig test tuning.zig
1/3 tuning.test.every tuning value is positive and every basis-point knob is sane...OK
2/3 tuning.test.a zero knob is caught...tuning field bad.market.fab_days must be positive
OK
3/3 tuning.test.a silly basis-point knob is caught...tuning field bad.market.fab_cost_bp is over 100000 basis points
OK
All 3 tests passed.

Walk through checkPositive one arm at a time.

  • The .int arm is the only one that does run-time work. Signed integers are skipped entirely (deltas may be negative by design). Unsigned ones are compared against zero, and if the dotted name ends in _bp, against the basis-point ceiling. std.mem.endsWith runs on a comptime string here, so the compiler evaluates it and drops the whole if for fields whose names do not qualify.
  • The .@"struct" arm is pure compile-time recursion. For each field it calls checkPositive again with three arguments: the field's type, the field's value read with @field, and a longer name made with ++. Because T and name are comptime parameters, each call is a distinct specialisation, and by the time the program runs there is no recursion left, only a flat list of integer checks with their names baked into the error messages.
  • The else => {} arm is deliberate. Floats, enums, booleans and strings are not knobs this test cares about, so it passes over them rather than refusing. This is the one place where a silent else is the right design, because the test is about a specific property, not about supporting every type.

The payoff is in the last sentence of the guide's description: add a knob to the table and it is covered by this test with no change to the test. Exercise 27.4 asks you to extend the validator with arrays, optionals and floats.

In IRON LEDGER. The validator above is lifted almost line for line from game/src/domain/tuning.zig, where the real Tuning struct has seven sections and well over a hundred knobs; the test at the bottom of that file is simply try checkPositive(Tuning, t, "t");. The other big use of reflection is the SQLite binding in game/src/persist/sqlite.zig, which binds any value to a prepared statement by switching on its type: 
pub fn bind(self: Stmt, idx: c_int, value: anytype) Error!void {
    const T = @TypeOf(value);
    const rc = switch (@typeInfo(T)) {
        .int, .comptime_int => sqlite3_bind_int64(self.h, idx, @intCast(value)),
        .bool => sqlite3_bind_int64(self.h, idx, @intFromBool(value)),
        .@"enum" => blk: {
            if (@typeInfo(T).@"enum".is_exhaustive) {
                const name = @tagName(value);
                break :blk sqlite3_bind_text(self.h, idx, name.ptr, @intCast(name.len), transient);
            }
            break :blk sqlite3_bind_int64(self.h, idx, @intCast(@intFromEnum(value)));
        },
        .optional => if (value) |v| return self.bind(idx, v) else sqlite3_bind_null(self.h, idx),
        .pointer => blk: {
            const s: []const u8 = value;
            break :blk sqlite3_bind_text(self.h, idx, s.ptr, @intCast(s.len), transient);
        },
        else => @compileError("unsupported bind type " ++ @typeName(T)),
    };
    // …
}
Read the enum arm: exhaustive enums are stored by name so a save file stays readable, while non-exhaustive typed IDs are stored as integers. That policy lives in one place because reflection let it.

Exercise 27.1 · Describe a type warm-up

Write describe(comptime T: type) []const u8 returning a short kind name (distinguish slices from other pointers), bitsOf for ints and floats with a compile error otherwise, and fits(T, n) using std.math.minInt / maxInt. File: exercises/27-reflection/ex1_describe.zig.

Solution 
//! Chapter 27, exercise 1: describe a type.
//! Run with:  zig test ex1_describe.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Return a short human description of T, built only from @typeInfo.
pub fn describe(comptime T: type) []const u8 {
    return switch (@typeInfo(T)) {
        .int => |i| if (i.signedness == .signed) "signed int" else "unsigned int",
        .float => "float",
        .bool => "bool",
        .pointer => |p| if (p.size == .slice) "slice" else "pointer",
        .array => "array",
        .optional => "optional",
        .error_union => "error union",
        .@"struct" => "struct",
        .@"enum" => "enum",
        .@"union" => "union",
        .@"fn" => "function",
        else => "other",
    };
}

/// How many bits an int or float occupies. Compile error for anything else.
pub fn bitsOf(comptime T: type) u16 {
    return switch (@typeInfo(T)) {
        .int => |i| i.bits,
        .float => |f| f.bits,
        else => @compileError("bitsOf: not a number: " ++ @typeName(T)),
    };
}

pub fn fits(comptime T: type, n: comptime_int) bool {
    return n >= std.math.minInt(T) and n <= std.math.maxInt(T);
}

Exercise 27.2 · A generic toString practice

Write toString(w: *std.Io.Writer, value: anytype) that prints ints, floats, bools, enum tag names, optionals (null or the payload), []const u8 in quotes, arrays as [a, b] and structs as {field=value, …}, recursively. File: exercises/27-reflection/ex2_tostring.zig.

Solution 
//! Chapter 27, exercise 2: a generic toString.
//! Run with:  zig test ex2_tostring.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Write a readable form of `value` into `w`, choosing the format by type.
/// Structs print as {field=value, ...}, enums as their tag name, optionals
/// as "null" or the payload, []const u8 as quoted text.
pub fn toString(w: *std.Io.Writer, value: anytype) std.Io.Writer.Error!void {
    const T = @TypeOf(value);
    switch (@typeInfo(T)) {
        .int, .comptime_int => try w.print("{d}", .{value}),
        .float, .comptime_float => try w.print("{d:.2}", .{value}),
        .bool => try w.print("{}", .{value}),
        .@"enum" => try w.print("{s}", .{@tagName(value)}),
        .optional => if (value) |v| try toString(w, v) else try w.writeAll("null"),
        .pointer => |p| {
            if (p.size == .slice and p.child == u8) {
                try w.print("\"{s}\"", .{value});
            } else if (p.size == .one) {
                try toString(w, value.*);
            } else {
                @compileError("toString: unsupported pointer " ++ @typeName(T));
            }
        },
        .array => {
            try w.writeAll("[");
            for (value, 0..) |item, i| {
                if (i != 0) try w.writeAll(", ");
                try toString(w, item);
            }
            try w.writeAll("]");
        },
        .@"struct" => |info| {
            try w.writeAll("{");
            inline for (info.fields, 0..) |f, i| {
                if (i != 0) try w.writeAll(", ");
                try w.print("{s}=", .{f.name});
                try toString(w, @field(value, f.name));
            }
            try w.writeAll("}");
        },
        else => @compileError("toString: unsupported type " ++ @typeName(T)),
    }
}

/// Convenience: render into a fixed buffer and return the written slice.
pub fn toBuf(buf: []u8, value: anytype) ![]u8 {
    var w = std.Io.Writer.fixed(buf);
    try toString(&w, value);
    return w.buffered();
}

const Role = enum { pilot, tech };
const Pilot = struct { name: []const u8, role: Role, gunnery: u8, callsign: ?[]const u8 };

Exercise 27.3 · Generic deep equality practice

Write eql(a: anytype, b: @TypeOf(a)) bool that compares scalars with ==, optionals, arrays and slices element by element (slices by content, not address), structs field by field and tagged unions by tag then payload. File: exercises/27-reflection/ex3_equal.zig.

Solution 
//! Chapter 27, exercise 3: a generic deep equality.
//! Run with:  zig test ex3_equal.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Deep structural equality. Slices compare by content, not by address.
pub fn eql(a: anytype, b: @TypeOf(a)) bool {
    const T = @TypeOf(a);
    switch (@typeInfo(T)) {
        .void => return true,
        .int, .comptime_int, .float, .comptime_float, .bool, .@"enum" => return a == b,
        .optional => {
            if (a == null and b == null) return true;
            if (a == null or b == null) return false;
            return eql(a.?, b.?);
        },
        .array => {
            for (a, b) |x, y| if (!eql(x, y)) return false;
            return true;
        },
        .pointer => |p| switch (p.size) {
            .one => return eql(a.*, b.*),
            .slice => {
                if (a.len != b.len) return false;
                for (a, b) |x, y| if (!eql(x, y)) return false;
                return true;
            },
            else => @compileError("eql: unsupported pointer " ++ @typeName(T)),
        },
        .@"struct" => |info| {
            inline for (info.fields) |f| {
                if (!eql(@field(a, f.name), @field(b, f.name))) return false;
            }
            return true;
        },
        .@"union" => |info| {
            if (info.tag_type == null) @compileError("eql: untagged union " ++ @typeName(T));
            const Tag = info.tag_type.?;
            const ta: Tag = a;
            const tb: Tag = b;
            if (ta != tb) return false;
            inline for (info.fields) |f| {
                if (ta == @field(Tag, f.name)) {
                    return eql(@field(a, f.name), @field(b, f.name));
                }
            }
            unreachable;
        },
        else => @compileError("eql: unsupported type " ++ @typeName(T)),
    }
}

const Pilot = struct { name: []const u8, gunnery: u8, callsign: ?[]const u8 };
const Event = union(enum) { none, wound: u8, promoted: []const u8 };

test "scalars and optionals" {
    try std.testing.expect(eql(@as(u8, 3), 3));
    try std.testing.expect(!eql(@as(u8, 3), 4));
    try std.testing.expect(eql(@as(?u8, null), null));
    try std.testing.expect(!eql(@as(?u8, 1), null));
}

test "slices compare by content" {
    const a: []const u8 = "Kell";
    var storage = [_]u8{ 'K', 'e', 'l', 'l' };
    const b: []const u8 = storage[0..];
    try std.testing.expect(a.ptr != b.ptr);
    try std.testing.expect(eql(a, b));
    try std.testing.expect(!eql(a, @as([]const u8, "Kel")));
}

test "structs with slices and optionals" {
    const p = Pilot{ .name = "Kell", .gunnery = 3, .callsign = "Ace" };
    var q = Pilot{ .name = "Kell", .gunnery = 3, .callsign = "Ace" };
    try std.testing.expect(eql(p, q));
    q.callsign = null;
    try std.testing.expect(!eql(p, q));
    q.callsign = "Ace";
    q.gunnery = 4;
    try std.testing.expect(!eql(p, q));
}

test "tagged unions" {
    try std.testing.expect(eql(Event{ .wound = 2 }, Event{ .wound = 2 }));
    try std.testing.expect(!eql(Event{ .wound = 2 }, Event{ .wound = 3 }));
    try std.testing.expect(!eql(Event{ .wound = 2 }, Event.none));
    try std.testing.expect(eql(Event{ .promoted = "Sgt" }, Event{ .promoted = "Sgt" }));
}

test "arrays of structs" {
    const a = [_]Pilot{ .{ .name = "A", .gunnery = 1, .callsign = null } };
    const b = [_]Pilot{ .{ .name = "A", .gunnery = 1, .callsign = null } };
    try std.testing.expect(eql(a, b));
}

The union arm is the subtle one: coerce both values to the tag type to compare tags, then inline for over the union fields and compare the payload of the matching one. A void payload (like .none) needs its own arm returning true, since == is not defined on void.

Exercise 27.4 · A stronger tuning validator challenge

Extend the worked example: unsigned ints must be positive, _bp names at most 100,000, floats within 0 and 1, optionals checked when present, arrays element by element, structs recursively. Report the dotted path of the bad knob. File: exercises/27-reflection/ex4_validator.zig.

Solution 
//! Chapter 27, exercise 4: a tuning-table validator.
//! Run with:  zig test ex4_validator.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

pub const Tuning = struct {
    person: struct { fatigue_tired: u8, exhausted_fatigue: u8, morale_delta: i8 },
    market: struct { fab_cost_bp: u32, fab_days: u32, rarity_target: [3]u8 },
    battle: struct { salvage_bp: u32, retreat_chance: ?f32 },
};

pub const stock = Tuning{
    .person = .{ .fatigue_tired = 30, .exhausted_fatigue = 70, .morale_delta = -2 },
    .market = .{ .fab_cost_bp = 12_000, .fab_days = 14, .rarity_target = .{ 5, 3, 1 } },
    .battle = .{ .salvage_bp = 2_500, .retreat_chance = 0.25 },
};

pub const Problem = error{ Zero, TooManyBasisPoints, BadFraction };

/// Walk `value` recursively. Rules:
///  - unsigned ints must be > 0                     (error.Zero)
///  - names ending in _bp must be <= 100_000        (error.TooManyBasisPoints)
///  - floats must be within 0.0 ... 1.0 inclusive   (error.BadFraction)
///  - signed ints are free, optionals check the payload when present,
///    arrays check every element, structs recurse into every field.
/// On failure, print "bad knob: <dotted.path>" to stderr before returning.
pub fn validate(comptime T: type, value: T, comptime path: []const u8) Problem!void {
    switch (@typeInfo(T)) {
        .int => |info| {
            if (info.signedness == .signed) return;
            if (value == 0) return fail(path, error.Zero);
            const is_bp = comptime std.mem.endsWith(u8, path, "_bp");
            if (is_bp and value > 100_000) return fail(path, error.TooManyBasisPoints);
        },
        .float => if (value < 0.0 or value > 1.0) return fail(path, error.BadFraction),
        .optional => |o| if (value) |v| try validate(o.child, v, path),
        .array => |a| for (value) |item| try validate(a.child, item, path ++ "[]"),
        .@"struct" => |info| inline for (info.fields) |f|
            try validate(f.type, @field(value, f.name), path ++ "." ++ f.name),
        else => {},
    }
}

fn fail(path: []const u8, err: Problem) Problem!void {
    std.debug.print("bad knob: {s}\n", .{path});
    return err;
}

test "stock tuning passes" {
    try validate(Tuning, stock, "t");
}

test "zero in a nested struct" {
    var t = stock;
    t.market.fab_days = 0;
    try std.testing.expectError(error.Zero, validate(Tuning, t, "t"));
}

test "basis points too large" {
    var t = stock;
    t.battle.salvage_bp = 200_000;
    try std.testing.expectError(error.TooManyBasisPoints, validate(Tuning, t, "t"));
}

test "zero inside an array element" {
    var t = stock;
    t.market.rarity_target[2] = 0;
    try std.testing.expectError(error.Zero, validate(Tuning, t, "t"));
}

test "optional float out of range, and null is fine" {
    var t = stock;
    t.battle.retreat_chance = 1.5;
    try std.testing.expectError(error.BadFraction, validate(Tuning, t, "t"));
    t.battle.retreat_chance = null;
    try validate(Tuning, t, "t");
}

test "signed ints may be negative" {
    var t = stock;
    t.person.morale_delta = -100;
    try validate(Tuning, t, "t");
}

One trap worth remembering: comptime std.mem.endsWith(…) and value > 100_000 makes the comptime keyword apply to the whole and expression, which fails because value is a run-time value. Bind the compile-time part to a constant first.

Exercise 27.5 · Enum tables without std.meta practice

Write parseEnum(E, text) using only @typeInfo(E).@"enum".fields, names(E) returning a fixed-size array of tag names, and Counter(E), a struct with one u32 per tag. File: exercises/27-reflection/ex5_enumtable.zig.

Solution 
//! Chapter 27, exercise 5: enum tables from reflection.
//! Run with:  zig test ex5_enumtable.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Parse a tag name into an enum value, using only @typeInfo (no std.meta).
pub fn parseEnum(comptime E: type, text: []const u8) ?E {
    inline for (@typeInfo(E).@"enum".fields) |f| {
        if (std.mem.eql(u8, f.name, text)) return @enumFromInt(f.value);
    }
    return null;
}

/// All tag names of E, as a comptime array of strings, in declaration order.
pub fn names(comptime E: type) [@typeInfo(E).@"enum".fields.len][]const u8 {
    const fields = @typeInfo(E).@"enum".fields;
    var out: [fields.len][]const u8 = undefined;
    inline for (fields, 0..) |f, i| out[i] = f.name;
    return out;
}

/// A fixed array with one slot per enum tag, indexed by @intFromEnum.
pub fn Counter(comptime E: type) type {
    return struct {
        counts: [@typeInfo(E).@"enum".fields.len]u32 = @splat(0),
        const Self = @This();
        pub fn bump(self: *Self, e: E) void {
            self.counts[@intFromEnum(e)] += 1;
        }
        pub fn get(self: Self, e: E) u32 {
            return self.counts[@intFromEnum(e)];
        }
    };
}

const Role = enum { pilot, tech, medic, admin };

test "parseEnum" {
    try std.testing.expectEqual(@as(?Role, .medic), parseEnum(Role, "medic"));
    try std.testing.expectEqual(@as(?Role, null), parseEnum(Role, "cook"));
}

test "names" {
    const n = names(Role);
    try std.testing.expectEqual(@as(usize, 4), n.len);
    try std.testing.expectEqualStrings("pilot", n[0]);
    try std.testing.expectEqualStrings("admin", n[3]);
}

test "Counter" {
    var c = Counter(Role){};
    c.bump(.tech);
    c.bump(.tech);
    c.bump(.admin);
    try std.testing.expectEqual(@as(u32, 2), c.get(.tech));
    try std.testing.expectEqual(@as(u32, 0), c.get(.pilot));
    try std.testing.expectEqual(@as(usize, 4), c.counts.len);
}

The return type of names uses the field count directly in an array type, which is legal because @typeInfo is evaluated at compile time. @splat(0) fills the counter array whatever its length.

Check your understanding

  1. What is @TypeOf(1 + @as(u16, 2))?
    Answeru16. The untyped literal adopts the concrete type of the other operand.
  2. How do you spell the struct tag of @typeInfo in 0.16, and why?
    Answer.@"struct". struct is a keyword, so the identifier must be quoted with @"…". The same applies to .@"enum", .@"union", .@"fn" and .@"opaque".
  3. Which kind does []const u8 report, and how do you tell it apart from *u8?
    AnswerBoth are .pointer. The payload's size field is .slice for the first and .one for the second.
  4. Why must a loop over @typeInfo(T).@"struct".fields be an inline for?
    AnswerEach field has a different type, so the loop body must be compiled separately per field. inline for unrolls the loop at compile time so each iteration sees a constant field descriptor.
  5. What does @field(value, "x") require of its second argument?
    AnswerIt must be known at compile time. A run-time string cannot be used directly; you loop over the fields and compare with std.mem.eql, as setByName does.
  6. Does @hasDecl(T, "helper") see a private fn helper from another file?
    AnswerNo. Reflection over declarations only sees pub declarations, so @hasDecl is effectively an interface check.
  7. What replaced @Type in Zig 0.16?
    AnswerPer-kind builtins: @Int, @Enum, @Struct and friends, wrapped by helpers such as std.meta.Int.
  8. In the tuning validator, how much of the recursion survives into the compiled program?
    AnswerNone. Because the type and the name are comptime, every recursive call is a separate specialisation resolved during compilation; only the integer comparisons remain at run time.
What you learned.
  • @TypeOf gives the type of any expression; @typeName prints it.
  • @typeInfo(T) is a tagged union; switch on it at compile time. Tags are lower-case, with .@"struct", .@"enum", .@"union", .@"fn" quoted.
  • Payloads carry the details: bits and signedness for ints, child for optionals and pointers, fields and decls for structs and enums.
  • inline for over fields plus @field lets one function walk any struct, reading or writing fields by name.
  • @hasField and @hasDecl answer yes-or-no questions; end reflective switches with @compileError unless skipping is intended.
  • Enum field lists size arrays automatically and let you write your own stringToEnum.
  • @Type is gone in 0.16; @Int, @Enum and std.meta.Int build types.
  • Compile-time recursion over a nested struct gives you a validator that covers new fields for free.
