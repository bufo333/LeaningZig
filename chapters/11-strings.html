11. Strings

In this chapter you will learn that Zig has no string type, and why that turns out to be fine. A string is a slice of bytes, []const u8, and everything you want to do with one (compare, search, trim, split, change case, build, parse) is a function in std.mem, std.ascii or std.fmt. You will also learn where bytes and characters part ways, and how to build text into a buffer you own.

11.1 A string is a slice of bytes

Start with a literal and ask Zig what it is:

literal.zig

const std = @import("std");

pub fn main() void {
    const name = "Kai Allard";
    std.debug.print("{s}\n", .{name});
    std.debug.print("type: {any}\n", .{@TypeOf(name)});
    std.debug.print("len: {d}\n", .{name.len});
    std.debug.print("first byte: {d} ('{c}')\n", .{ name[0], name[0] });
    const s: []const u8 = name; // the everyday string type
    std.debug.print("as slice: {any}\n", .{@TypeOf(s)});
}
Kai Allard
type: *const [10:0]u8
len: 10
first byte: 75 ('K')
as slice: []const u8

*const [10:0]u8: a pointer to a constant array of ten bytes with a zero after them (Chapter 10 covered the sentinel). Ten bytes, not ten characters; for plain ASCII text those are the same, and 11.8 covers when they are not. name[0] is the byte 75, which {c} shows as the letter K.

The literal's pointer-to-array type coerces to []const u8, and that is the type you will write on every string parameter and most string variables. When people say "a Zig string" they mean []const u8: a read-only slice of bytes, with a length, and no promise about what the bytes mean.

There is no String class with methods. Instead, there are free functions that take slices. Because every one of them takes the element type as its first argument, you will type u8 a lot: std.mem.eql(u8, a, b). Those functions also work on slices of u32 or of structs, which is the reason for the parameter; strings are just the common case.

11.2 Comparing

The first thing every newcomer tries is ==:

nostring.zig

const std = @import("std");

pub fn main() void {
    var buf: [5]u8 = undefined;
    @memcpy(&buf, "lance");
    const typed: []const u8 = &buf;
    std.debug.print("{}\n", .{typed == "lance"});
}
nostring.zig:7:37: error: cannot compare strings with ==
    std.debug.print("{}\n", .{typed == "lance"});
                              ~~~~~~^~~~~~~~~~

The compiler has a special message for it. The reason is the same as for arrays in Chapter 9: comparing contents is a loop, and Zig does not hide loops behind operators. Use std.mem.eql:

compare.zig

const std = @import("std");

fn isQuit(cmd: []const u8) bool {
    return std.mem.eql(u8, cmd, "quit") or std.mem.eql(u8, cmd, "q");
}

pub fn main() void {
    std.debug.print("{} {} {}\n", .{ isQuit("quit"), isQuit("q"), isQuit("quit ") });
    std.debug.print("{}\n", .{std.ascii.eqlIgnoreCase("QUIT", "quit")});
    std.debug.print("{any}\n", .{std.mem.order(u8, "alpha", "bravo")});
}
true true false
true
.lt

eql is exact: "quit " with a trailing space is not "quit". For a case-blind comparison use std.ascii.eqlIgnoreCase. For ordering (sorting names, say) std.mem.order returns .lt, .eq or .gt, comparing byte by byte.

11.3 Searching

Prefixes, suffixes and substrings all live in std.mem. The functions that search for a position return an optional ?usize: an index, or null for not found. You will meet optionals properly in Chapter 15; for now, {?} prints one, and if (x) |k| ... else ... unwraps one.

search.zig

const std = @import("std");

pub fn main() void {
    const path = "data/units/atlas.zon";
    std.debug.print("{}\n", .{std.mem.startsWith(u8, path, "data/")});
    std.debug.print("{}\n", .{std.mem.endsWith(u8, path, ".zon")});
    std.debug.print("{?}\n", .{std.mem.indexOf(u8, path, "units")});
    std.debug.print("{?}\n", .{std.mem.indexOf(u8, path, "mek")});
    std.debug.print("{?}\n", .{std.mem.indexOfScalar(u8, path, '/')});
    std.debug.print("{?}\n", .{std.mem.lastIndexOfScalar(u8, path, '/')});
    // The classic: the file name after the last slash.
    const base = if (std.mem.lastIndexOfScalar(u8, path, '/')) |k| path[k + 1 ..] else path;
    std.debug.print("{s}\n", .{base});
    std.debug.print("{d}\n", .{std.mem.count(u8, path, "/")});
}

indexOf finds a substring; indexOfScalar and lastIndexOfScalar find a single byte from the front or from the back. The base line is the guide's own idiom for a file name: find the last slash, and slice from one past it. If there is no slash the whole path is the name. count tells you how many times a needle appears.

11.4 Trimming and splitting

User input arrives with spaces and newlines around it. std.mem.trim takes the set of bytes to strip as its third argument:

trim.zig

const std = @import("std");

pub fn main() void {
    const raw = "   hire Kai mekwarrior  \n";
    const t = std.mem.trim(u8, raw, " \n");
    std.debug.print("[{s}]\n", .{t});
    std.debug.print("[{s}]\n", .{std.mem.trimStart(u8, raw, " ")});
    std.debug.print("[{s}]\n", .{std.mem.trimEnd(u8, raw, " \n")});
}
[hire Kai mekwarrior]
[hire Kai mekwarrior  
]
[   hire Kai mekwarrior]

Trimming returns a smaller slice of the same memory; nothing is copied. trimStart and trimEnd do one side only.

To take a line apart into words there are two iterators, and the difference between them matters:

tokenize.zig

const std = @import("std");

pub fn main() void {
    const line = "hire   Kai  mekwarrior";

    var it = std.mem.tokenizeScalar(u8, line, ' ');
    while (it.next()) |word| {
        std.debug.print("[{s}] ", .{word});
    }
    std.debug.print("\n", .{});

    var sp = std.mem.splitScalar(u8, line, ' ');
    while (sp.next()) |piece| {
        std.debug.print("[{s}] ", .{piece});
    }
    std.debug.print("\n", .{});

    // A fixed record: two commas, so always three fields.
    var csv = std.mem.splitScalar(u8, "3025,7,14", ',');
    const year = csv.next().?;
    const month = csv.next().?;
    const day = csv.next().?;
    std.debug.print("year={s} month={s} day={s}\n", .{ year, month, day });

    // The same record with the month left blank. The field is still there.
    var blank = std.mem.splitScalar(u8, "3025,,14", ',');
    const b_year = blank.next().?;
    const b_month = blank.next().?;
    const b_day = blank.next().?;
    std.debug.print("year={s} month=[{s}] day={s}\n", .{ b_year, b_month, b_day });
}
[hire] [Kai] [mekwarrior] 
[hire] [] [] [Kai] [] [mekwarrior] 
year=3025 month=7 day=14
year=3025 month=[] day=14

tokenizeScalar treats any run of the delimiter as a single break and never yields an empty piece, so "hire Kai mekwarrior" gives three words however many spaces sit between them.

splitScalar breaks at every delimiter separately. Count the delimiters in that line. There are five spaces, and the second output row has six pieces. The empty ones are the gaps between two adjacent spaces, which are real pieces with no bytes in them. The rule is that n delimiters always produce n+1 pieces, empties included, so a three-field record split on commas gives you three fields whatever they contain.

That rule is what tells you which of the two to reach for. Use tokenizeScalar when a person typed the line, where a run of spaces is just loose typing and only the words matter. Use splitScalar when the format is fixed and a field's position carries its meaning. In the last output row above the month is blank, and splitScalar still reports three fields with the day in its proper place. tokenizeScalar on "3025,,14" would hand back only [3025] and [14], sliding the day silently into the month.

Both are driven by while (it.next()) |piece|, the same loop shape you will use for every iterator in the standard library.

The .? needs an explanation of its own, because it is the first thing on this page that is not about strings. next() does not return a slice. It returns ?[]const u8, an optional slice, meaning either a slice or nothing at all. That is how an iterator reports that it has run out, and it is what while (it.next()) |piece| has been quietly doing in every loop above: the capture |piece| runs the body only while there is a value, and ends the loop the first time there is not.

Calling next() outside a loop hands you that "or nothing" to deal with yourself. The .? operator is the blunt way to do that. It unwraps the optional and asserts that a value is there. When the assertion is wrong the program stops and says so.

unwrap.zig

const std = @import("std");

pub fn main() void {
    var csv = std.mem.splitScalar(u8, "3025", ',');
    _ = csv.next().?; // fine, there is one field
    const second = csv.next().?; // nothing left
    std.debug.print("never reached: {s}\n", .{second});
}
thread 7484770 panic: attempt to use null value
ch11/unwrap.zig:6:30: in main (unwrap)
    const second = csv.next().?; // nothing left
                             ^

That is a safety check, not undefined behaviour: you get the file, line and column of the .? that was wrong. Use it where the value is guaranteed by something you already know, as with the three fields of a record your own code just built. When the text comes from outside the program, handle the nothing instead:

unwrap2.zig

const std = @import("std");

pub fn main() void {
    const input = "3025";  // a record that is missing its month and day
    var csv = std.mem.splitScalar(u8, input, ',');

    const year = csv.next() orelse "????";
    const month = csv.next() orelse "??";
    std.debug.print("year={s} month={s}\n", .{ year, month });

    if (csv.next()) |day| {
        std.debug.print("day={s}\n", .{day});
    } else {
        std.debug.print("no day field in \"{s}\"\n", .{input});
    }
}
year=3025 month=??
no day field in "3025"

orelse supplies a value to use when there is none; if (opt) |v| takes its branch only when there is a value and binds it to v. Chapter 15 covers optionals properly. This is the minimum you need to read the rest of this chapter.

Two more useful methods:

tokenize2.zig

const std = @import("std");

pub fn main() void {
    var it = std.mem.tokenizeScalar(u8, "newlance 1st Recon Lance", ' ');
    const verb = it.next().?;
    const rest = it.rest();
    std.debug.print("verb=[{s}] rest=[{s}]\n", .{ verb, rest });
    var seq = std.mem.tokenizeSequence(u8, "a, b, c", ", ");
    while (seq.next()) |p| std.debug.print("<{s}>", .{p});
    std.debug.print("\n", .{});
}
verb=[newlance] rest=[1st Recon Lance]
<a><b><c>

it.rest() hands you everything not yet consumed, which is how a command parser takes one verb and leaves the rest of the line as a free-form name. tokenizeSequence splits on a multi-byte separator.

11.5 Characters: std.ascii

Because a byte is just a u8, single-character questions are functions on u8, gathered in std.ascii:

11.6 Building strings into a buffer

Everything so far returned slices of existing text. To make new text you need memory to put it in, and in Zig you say where. The simplest place is an array on the stack, and the simplest tool is std.fmt.bufPrint, which is print aimed at a buffer:

bufprint.zig

const std = @import("std");

pub fn main() !void {
    var buf: [64]u8 = undefined;
    const s = try std.fmt.bufPrint(&buf, "order {s} hq:{d}", .{ "advance", 3 });
    std.debug.print("{s} (len {d})\n", .{ s, s.len });
    std.debug.print("{any} {any}\n", .{ @TypeOf(s), @TypeOf(&buf) });

    // Build in steps with a fixed writer.
    var w = std.Io.Writer.fixed(&buf);
    try w.print("{d}", .{3025});
    try w.writeByte('-');
    try w.print("{d:0>2}", .{1});
    try w.writeAll("-01");
    std.debug.print("{s}\n", .{w.buffered()});
}
order advance hq:3 (len 18)
[]u8 *[64]u8
3025-01-01

bufPrint returns a []u8 slice of the buffer holding exactly what it wrote. The buffer is [64]u8; the result is eighteen bytes long. Keep the buffer alive as long as you use the slice, and remember it is the same rule as in Chapter 10: a slice of a local buffer cannot be returned from the function that owns the buffer. The usual design is for the caller to pass the buffer in, exactly as bufPrint itself does.

For building in several steps, wrap the buffer in a fixed writer. print, writeByte and writeAll append; buffered() gives back the slice written so far. This is the same std.Io.Writer interface as stdout in Chapter 2, pointed at memory instead of a file.

What if the buffer is too small? bufPrint returns an error, which is why the function above is !void and the call has try:

const std = @import("std");

pub fn main() !void {
    var buf: [8]u8 = undefined;
    const s = try std.fmt.bufPrint(&buf, "{s} {s}", .{ "hello", "world" });
    std.debug.print("{s}\n", .{s});
}
error: NoSpaceLeft
<zig>/lib/std/Io/Writer.zig:2321:50: in fixedDrain (bufprint_small)

error: NoSpaceLeft. No overflow, no truncation you did not ask for. When you cannot know the size in advance, the answer is an allocator and std.fmt.allocPrint, which returns a string of exactly the right length that you later free. That arrives in Chapter 21 and Chapter 23; until then, buffers.

Replacing a substring uses an output buffer in the same way, but it differs from bufPrint in one way that matters. Ask how large the result will be before you write it:

replace.zig

const std = @import("std");

pub fn main() void {
    const src = "1st Lance / 2nd Lance";
    var out: [64]u8 = undefined;

    const size = std.mem.replacementSize(u8, src, "Lance", "Company");
    if (size > out.len) {
        std.debug.print("need {d} bytes, the buffer has {d}\n", .{ size, out.len });
        return;
    }
    const n = std.mem.replace(u8, src, "Lance", "Company", &out);
    std.debug.print("{d} replacements, {d} bytes: {s}\n", .{ n, size, out[0..size] });
}
2 replacements, 25 bytes: 1st Company / 2nd Company

Nothing in the program computed that 64. It is a round number chosen to sit comfortably above what this input needs, which is an honest description of most fixed buffers. std.mem.replacementSize is how you stop guessing, because it reports the exact length the result will occupy. Here that is 25 bytes: each "Lance" is five bytes and each "Company" is seven, so two replacements grow the 21-byte source by four. Call it before replace rather than after, since its purpose is to tell you whether the buffer can hold the answer.

That check is yours to make. bufPrint returns error.NoSpaceLeft when the text will not fit, so the mistake reaches you as a value you can handle. replace returns only a count and verifies nothing, so a buffer that is too small sends it past the end of your array:

replace_small.zig

const std = @import("std");

pub fn main() void {
    const src = "1st Lance / 2nd Lance";
    var out: [16]u8 = undefined; // too small, and nothing says so
    _ = std.mem.replace(u8, src, "Lance", "Company", &out);
    std.debug.print("{s}\n", .{out});
}

Safety caught it, so nothing was corrupted, but the trace starts inside std/mem.zig instead of in your own file, which is an awkward place to begin reading. The if in the first program is what keeps you out of it.

11.7 Literals are read-only; copies are not

A literal lives in the program's read-only data. You cannot write into it:

const std = @import("std");

pub fn main() void {
    const lit = "atlas";
    lit[0] = 'A';
    std.debug.print("{s}\n", .{lit});
}
mutate_lit.zig:5:8: error: cannot assign to constant
    lit[0] = 'A';
    ~~~^~~
referenced by:
    callMain [inlined]: <zig>/lib/std/start.zig:698:59
    callMainWithArgs [inlined]: <zig>/lib/std/start.zig:638:20
    main: <zig>/lib/std/start.zig:663:28
    1 reference(s) hidden; use '-freference-trace=4' to see all references

To change text, copy it into an array that you own. That takes one line, but three separate things happen in it:

mutate.zig

const std = @import("std");

pub fn main() void {
    const lit = "atlas";
    var copy: [5]u8 = lit.*; // copy the bytes out of the literal
    copy[0] = 'A';
    std.debug.print("{s} {s}\n", .{ lit, &copy });
}
atlas Atlas

First, lit is not the text. A string literal is a pointer, and @TypeOf(lit) reports *const [5:0]u8, a pointer to a constant array of five bytes with a zero after them. The pointer occupies eight bytes on a 64-bit machine, and the letters themselves live elsewhere, in the program's read-only data.

Second, .* is the dereference operator, and it means the value that the pointer refers to. So lit.* is the array itself, of type [5:0]u8, rather than its address. Leave the .* off and the line tries to put a pointer into an array variable, which the compiler refuses:

mutate.zig:5:23: error: expected type '[5]u8', found '*const [5:0]u8'
    var copy: [5]u8 = lit;
                      ^~~

Third, an array in Zig is a value rather than a reference, so assigning one copies every byte. copy is a new array on the stack at its own address, and writing to it cannot reach the literal. That is why the program prints the original and the altered copy side by side.

One detail is easy to miss. The type changes from [5:0]u8 to [5]u8 across the assignment, because the destination does not ask for a sentinel and the trailing zero is dropped. Write var copy: [5:0]u8 = lit.*; instead if you want to keep it, which matters when you pass the result to C (Chapter 35).

This is the same const rule as for slices: a []const u8 may look at bytes, a []u8 may change them, and a literal only ever gives you the former.

11.8 Multi-line literals

Long text uses a line-comment-like syntax. Each line starts with \\, and the newlines between lines are part of the string; the final line has no trailing newline.

multiline.zig

const std = @import("std");

const banner =
    \\IRON LEDGER
    \\  a mercenary company simulator
    \\  "no floats in the ledger"
;

pub fn main() void {
    std.debug.print("{s}\n", .{banner});
    std.debug.print("{d} bytes, {d} newlines\n", .{ banner.len, std.mem.count(u8, banner, "\n") });
}
IRON LEDGER
  a mercenary company simulator
  "no floats in the ledger"
71 bytes, 2 newlines

Nothing inside a \\ line is escaped, so quotes and backslashes can appear as they are. IRON LEDGER's splash screen and its ASCII-art mek are multi-line literals in src/tui/splash.zig.

11.9 Bytes are not characters

All of the above treats a string as bytes. Text is stored in UTF-8, where ASCII characters are one byte each and everything else is two to four. Zig does not hide this:

utf8.zig

const std = @import("std");

pub fn main() !void {
    const word = "Mëk";
    std.debug.print("{s}: {d} bytes\n", .{ word, word.len });
    for (word) |b| std.debug.print("{x} ", .{b});
    std.debug.print("\n", .{});

    const n = try std.unicode.utf8CountCodepoints(word);
    std.debug.print("{d} code points\n", .{n});

    var it = (try std.unicode.Utf8View.init(word)).iterator();
    while (it.nextCodepoint()) |cp| std.debug.print("U+{X:0>4} ", .{cp});
    std.debug.print("\n", .{});

    const cp = try std.unicode.utf8Decode(word[1..3]); // the two bytes of ë
    std.debug.print("{d}\n", .{cp});
}
Mëk: 4 bytes
4d c3 ab 6b 
3 code points
U+004D U+00EB U+006B 
235

"Mëk" is four bytes and three code points. len counts bytes, always. The ë is the pair c3 ab. To count or walk characters, use std.unicode: utf8CountCodepoints counts, Utf8View iterates one code point at a time, and utf8Decode turns the bytes of one character into its number (235 is U+00EB).

The rule that keeps you safe: byte functions like indexOf and eql are fine on UTF-8, because a valid UTF-8 sequence never appears by accident inside another. What is not fine is slicing at an arbitrary byte offset (you may cut a character in half) and calling std.ascii.toUpper on non-ASCII bytes (it leaves them alone, which is correct but not what you meant). The terminal client in IRON LEDGER reads keys as u21 code points for exactly this reason.

11.10 Parsing numbers

The last everyday string job is turning text into a number, and it can fail:

parse.zig

const std = @import("std");

pub fn main() !void {
    const n = try std.fmt.parseInt(u32, "3025", 10);
    const f = try std.fmt.parseFloat(f64, "1.5");
    std.debug.print("{d} {d}\n", .{ n + 1, f * 2 });
    const bad = std.fmt.parseInt(u32, "30x5", 10);
    std.debug.print("{!}\n", .{bad});
}
3026 3
error.InvalidCharacter

parseInt takes the target type, the text and the base. Invalid text is an error, not zero and not a crash; {!} prints either the value or the error name. Chapter 16 shows how to handle these errors properly; Chapter 23 covers the rest of std.fmt.

In IRON LEDGER. The command-line parser is nothing but this chapter's functions applied in order. A line becomes a token iterator, the first token is compared against known verbs with std.mem.eql, the rest is parsed or trimmed: 
// src/sim/cli.zig
pub fn parseCommand(verb: []const u8, tokens: *std.mem.TokenIterator(u8, .scalar)) ParseError!?Command {
    const eq = std.mem.eql;
    if (eq(u8, verb, "admit")) return .{ .admit = @enumFromInt(try num(u32, tokens.next())) };
    if (eq(u8, verb, "shares")) return .{ .set_shares_pct = try num(u8, tokens.next()) };
    if (eq(u8, verb, "newlance")) {
        const site = try parseSite(try need(tokens.next()));
        var name = std.mem.trim(u8, tokens.rest(), " ");
        // ...
    }
    return null; // not a verb we know
}

Three things in that signature belong to later chapters, and you can read past them for now. The * makes tokens a pointer, so that parseCommand advances the caller's iterator instead of a copy of it, which is what lets it consume the arguments the caller has not read yet (Chapter 18). The .scalar names the kind of delimiter the iterator splits on, and it is part of the type rather than a value in a field, so an iterator from tokenizeAny would not fit this parameter (Chapter 26). The return type ParseError!?Command stacks two wrappers on Command and gives the function three outcomes: a command, null for a word that is not a verb at all, or a parse error for a known verb with bad arguments (Chapter 15 and Chapter 16). Keeping the unknown word separate from the error is deliberate, because the caller can offer help for one and must report the other.

const eq = std.mem.eql; is a small trick to shorten a function you call twenty times in a row. Elsewhere, std.mem.startsWith(u8, token, "hq:") recognises references like hq:3 (src/main.zig), and the terminal-detection code uses std.ascii.indexOfIgnoreCase to spot "iterm" in an environment variable regardless of case (src/tui/emblem.zig). Every one of those functions takes a []const u8 and returns a slice or an optional index; there is no string object anywhere in the 31,000 lines.

Exercise 11.1 · String predicates warm-up

Write isQuit (trim, then case-insensitive match against three words), isNumber (all digits, at least one) and isHqRef (the form hq:<digits>). Name the file: exercises/11-strings/ex1_predicates.zig.

Solution 
//! Chapter 11, exercise 1: string predicates.
//! Run with:  zig test ex1_predicates.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// True when the command is one of the quit words, ignoring case and
/// surrounding whitespace.
fn isQuit(cmd: []const u8) bool {
    const t = std.mem.trim(u8, cmd, " \t\r\n");
    return std.ascii.eqlIgnoreCase(t, "quit") or std.ascii.eqlIgnoreCase(t, "q") or
        std.ascii.eqlIgnoreCase(t, "exit");
}

/// True when every byte is a decimal digit and there is at least one.
fn isNumber(s: []const u8) bool {
    if (s.len == 0) return false;
    for (s) |c| {
        if (!std.ascii.isDigit(c)) return false;
    }
    return true;
}

/// True when `s` looks like "hq:<digits>".
fn isHqRef(s: []const u8) bool {
    return std.mem.startsWith(u8, s, "hq:") and isNumber(s["hq:".len..]);
}

test "isQuit" {
    try std.testing.expect(isQuit("quit"));
    try std.testing.expect(isQuit("  Q\n"));
    try std.testing.expect(isQuit("EXIT"));
    try std.testing.expect(!isQuit("quit now"));
    try std.testing.expect(!isQuit(""));
}

test "isNumber" {
    try std.testing.expect(isNumber("3025"));
    try std.testing.expect(isNumber("0"));
    try std.testing.expect(!isNumber(""));
    try std.testing.expect(!isNumber("30x5"));
    try std.testing.expect(!isNumber("-1"));
}

test "isHqRef" {
    try std.testing.expect(isHqRef("hq:1"));
    try std.testing.expect(isHqRef("hq:42"));
    try std.testing.expect(!isHqRef("hq:"));
    try std.testing.expect(!isHqRef("co:1"));
    try std.testing.expect(!isHqRef("hq"));

s["hq:".len..] slices past the prefix using the literal's own length, so the two cannot drift apart. isNumber rejects the empty string explicitly; without that check an empty input would loop zero times and return true.

Exercise 11.2 · Taking a command line apart practice

Using the tokenizer and splitter, write verb, wordCount, args (the rest of the line after the verb, trimmed) and parseDate, which turns "3025-1-1" into three numbers and rejects the wrong number of pieces. Name the file: exercises/11-strings/ex2_tokens.zig.

Solution 
//! Chapter 11, exercise 2: taking a command line apart.
//! Run with:  zig test ex2_tokens.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// The first whitespace-separated word, or "" when there is none.
fn verb(line: []const u8) []const u8 {
    var it = std.mem.tokenizeScalar(u8, line, ' ');
    return it.next() orelse "";
}

/// Number of whitespace-separated words.
fn wordCount(line: []const u8) usize {
    var it = std.mem.tokenizeScalar(u8, line, ' ');
    var n: usize = 0;
    while (it.next()) |_| n += 1;
    return n;
}

/// Everything after the first word, trimmed. "" if there is nothing.
fn args(line: []const u8) []const u8 {
    var it = std.mem.tokenizeScalar(u8, line, ' ');
    _ = it.next();
    return std.mem.trim(u8, it.rest(), " ");
}

/// Parse "YYYY-MM-DD" into three numbers. Any other shape is an error.
fn parseDate(s: []const u8) ![3]u16 {
    var it = std.mem.splitScalar(u8, s, '-');
    var out: [3]u16 = undefined;
    for (&out) |*slot| {
        const piece = it.next() orelse return error.BadDate;
        slot.* = try std.fmt.parseInt(u16, piece, 10);
    }
    if (it.next() != null) return error.BadDate;
    return out;
}

test "verb" {
    try std.testing.expectEqualStrings("hire", verb("hire Kai mekwarrior"));
    try std.testing.expectEqualStrings("day", verb("   day"));
    try std.testing.expectEqualStrings("", verb("   "));
}

test "wordCount" {
    try std.testing.expectEqual(@as(usize, 3), wordCount("hire Kai mekwarrior"));
    try std.testing.expectEqual(@as(usize, 3), wordCount("  hire   Kai  mekwarrior "));
    try std.testing.expectEqual(@as(usize, 0), wordCount(""));
}

test "args" {
    try std.testing.expectEqualStrings("Kai mekwarrior", args("hire Kai mekwarrior"));
    try std.testing.expectEqualStrings("1st Recon Lance", args("newlance   1st Recon Lance  "));
    try std.testing.expectEqualStrings("", args("day"));
}

test "parseDate" {
    try std.testing.expectEqual([3]u16{ 3025, 1, 1 }, try parseDate("3025-1-1"));
    try std.testing.expectEqual([3]u16{ 3026, 12, 31 }, try parseDate("3026-12-31"));
    try std.testing.expectError(error.BadDate, parseDate("3025-1"));
    try std.testing.expectError(error.BadDate, parseDate("3025-1-1-1"));
    try std.testing.expectError(error.InvalidCharacter, parseDate("3025-x-1"));
}

it.next() orelse "" turns "no token" into the empty string. parseDate uses splitScalar, not tokenizeScalar, because a missing field should be an error rather than silently skipped; after three pieces it checks that nothing is left.

Exercise 11.3 · Building strings into a buffer practice

Write fullName with one bufPrint, shoutWords with a fixed writer (normalising spaces and upper-casing), and money, which inserts thousands separators. Every function takes the output buffer as a parameter and returns a slice of it. Name the file: exercises/11-strings/ex3_build.zig.

Solution 
//! Chapter 11, exercise 3: building strings into a buffer.
//! Run with:  zig test ex3_build.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// "Last, First" into buf.
fn fullName(buf: []u8, first: []const u8, last: []const u8) ![]const u8 {
    return std.fmt.bufPrint(buf, "{s}, {s}", .{ last, first });
}

/// The words of `line` joined by a single space, upper-cased, into buf.
fn shoutWords(buf: []u8, line: []const u8) ![]const u8 {
    var w = std.Io.Writer.fixed(buf);
    var it = std.mem.tokenizeScalar(u8, line, ' ');
    var first = true;
    while (it.next()) |word| {
        if (!first) try w.writeByte(' ');
        first = false;
        for (word) |c| try w.writeByte(std.ascii.toUpper(c));
    }
    return w.buffered();
}

/// A C-bills amount with thousands separators: 1234567 -> "1,234,567".
fn money(buf: []u8, amount: u64) ![]const u8 {
    var digits: [20]u8 = undefined;
    const d = try std.fmt.bufPrint(&digits, "{d}", .{amount});
    var w = std.Io.Writer.fixed(buf);
    for (d, 0..) |c, i| {
        const remaining = d.len - i;
        if (i != 0 and remaining % 3 == 0) try w.writeByte(',');
        try w.writeByte(c);
    }
    return w.buffered();
}

test "fullName" {
    var buf: [32]u8 = undefined;
    try std.testing.expectEqualStrings("Allard, Kai", try fullName(&buf, "Kai", "Allard"));
}

test "fullName refuses a too-small buffer" {
    var buf: [4]u8 = undefined;
    try std.testing.expectError(error.NoSpaceLeft, fullName(&buf, "Kai", "Allard"));
}

test "shoutWords" {
    var buf: [64]u8 = undefined;
    try std.testing.expectEqualStrings("HIRE KAI NOW", try shoutWords(&buf, "  hire   kai now "));
    try std.testing.expectEqualStrings("", try shoutWords(&buf, ""));
}

test "money" {
    var buf: [32]u8 = undefined;
    try std.testing.expectEqualStrings("0", try money(&buf, 0));
    try std.testing.expectEqualStrings("999", try money(&buf, 999));
    try std.testing.expectEqualStrings("1,000", try money(&buf, 1000));
    try std.testing.expectEqualStrings("1,234,567", try money(&buf, 1234567));
}

money first prints the digits into a small scratch array, then copies them out one at a time, inserting a comma whenever the number of digits still to come is a multiple of three. The second fullName test shows the buffer-too-small case turning into error.NoSpaceLeft, which expectError checks for.

Exercise 11.4 · Bytes are not characters challenge

Write charCount (code points, not bytes), takeChars (the first n code points as a slice, never cutting a character), and reverseAscii, which refuses non-ASCII input rather than scrambling it. Name the file: exercises/11-strings/ex4_utf8.zig.

Solution 
//! Chapter 11, exercise 4: bytes are not characters (challenge).
//! Run with:  zig test ex4_utf8.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// Number of code points, or error.Utf8InvalidStartByte for malformed input.
fn charCount(s: []const u8) !usize {
    return std.unicode.utf8CountCodepoints(s);
}

/// The first `n` code points of `s` (fewer if s is shorter), as a slice of s.
/// Never cuts a multi-byte character in half.
fn takeChars(s: []const u8, n: usize) ![]const u8 {
    var view = try std.unicode.Utf8View.init(s);
    var it = view.iterator();
    var taken: usize = 0;
    while (taken < n) : (taken += 1) {
        if (it.nextCodepointSlice() == null) break;
    }
    return s[0..it.i];
}

/// Reverse a string byte-by-byte into buf. Only valid for ASCII input,
/// so refuse anything with a byte >= 0x80.
fn reverseAscii(buf: []u8, s: []const u8) ![]const u8 {
    for (s) |c| {
        if (c >= 0x80) return error.NotAscii;
    }
    for (s, 0..) |c, i| buf[s.len - 1 - i] = c;
    return buf[0..s.len];
}

test "charCount" {
    try std.testing.expectEqual(@as(usize, 3), try charCount("Mëk"));
    try std.testing.expectEqual(@as(usize, 4), "Mëk".len);
    try std.testing.expectEqual(@as(usize, 0), try charCount(""));
    try std.testing.expectError(error.Utf8InvalidStartByte, charCount("\xff"));
}

test "takeChars" {
    try std.testing.expectEqualStrings("Më", try takeChars("Mëk", 2));
    try std.testing.expectEqualStrings("Mëk", try takeChars("Mëk", 10));
    try std.testing.expectEqualStrings("", try takeChars("Mëk", 0));
}

test "reverseAscii" {
    var buf: [16]u8 = undefined;
    try std.testing.expectEqualStrings("salta", try reverseAscii(&buf, "atlas"));
    try std.testing.expectError(error.NotAscii, reverseAscii(&buf, "Mëk"));
}

Utf8View.iterator() keeps a byte offset in its i field; after stepping n code points, s[0..it.i] is a slice that ends on a character boundary. The test also documents that "Mëk".len is 4 while the character count is 3.

Check your understanding

  1. What is the type of a string literal, and what does it coerce to?
    Answer*const [N:0]u8, a pointer to a zero-terminated constant byte array. It coerces to []const u8, and to [:0]const u8 if you want to keep the sentinel.
  2. How do you compare two strings for equality?
    Answerstd.mem.eql(u8, a, b). == is a compile error ("cannot compare strings with ==").
  3. What is the difference between tokenizeScalar and splitScalar on "a,,b" with ','?
    AnswertokenizeScalar yields a and b; splitScalar yields a, an empty string, and b.
  4. What does std.mem.indexOf return when the needle is absent?
    Answernull. Its return type is ?usize, an optional index.
  5. Why can a function not return the result of bufPrint into a local buffer?
    AnswerThe result is a slice of the local array, which ceases to exist when the function returns. Let the caller pass the buffer in, or allocate.
  6. What is "Mëk".len?
    Answer4. len counts bytes; ë takes two bytes in UTF-8. std.unicode.utf8CountCodepoints gives 3.
  7. Does std.mem.trim copy the string?
    AnswerNo. It returns a shorter slice into the same bytes.
What you learned.
  • There is no string type. A string is []const u8; a literal is *const [N:0]u8 and coerces to it.
  • Compare with std.mem.eql or std.ascii.eqlIgnoreCase; order with std.mem.order.
  • Search with startsWith, endsWith, indexOf, indexOfScalar, lastIndexOfScalar, count; positions come back as ?usize.
  • Trim with std.mem.trim; split with tokenizeScalar (collapses runs) or splitScalar (exact fields); rest() gives the remainder.
  • std.ascii has the per-byte helpers; upperString and friends write into a buffer you provide.
  • Build new text with std.fmt.bufPrint or a fixed std.Io.Writer into a caller-owned buffer; too small is error.NoSpaceLeft. allocPrint comes with allocators.
  • Literals are read-only; copy with lit.* to modify. Multi-line literals use \\.
  • len counts bytes. Use std.unicode when characters matter.
