Appendix A4. Common compile errors, decoded

This appendix collects the compiler messages a beginner meets most often, each reproduced by compiling a tiny file with Zig 0.16.0 while this page was written. For each: the code that triggers it, the message exactly as printed (file names and line numbers will differ), what it means, and the fix. The last section covers the three runtime panics that look like compile errors to a newcomer. Chapter 37 explains how to read a message; this is the lookup table.

Reading a message. The first line is file:line:column: error: … and points at the exact token. Lines beginning note: add context (where a type was declared, which value is unhandled). Lines after referenced by: show the call chain that made the compiler look at this code, which is how a message inside the standard library (as in A4.24) leads back to your own line. Fix the first error and rebuild; later ones are often consequences of it.

A4.1 Unused and misused names

A4.1 unused local constant

pub fn main() void {
    const x: u32 = 5;
}
e01.zig:2:11: error: unused local constant

Meaning. Every local must be used. Fix. Use it, delete it, or discard it on purpose with _ = x;. The same message reads "unused local variable" for a var. (Chapter 3)

A4.2 unused function parameter

fn f(a: u32, b: u32) u32 {
    return a;
}
e02.zig:1:14: error: unused function parameter

Meaning. b is never read. Fix. _ = b; as the first line of the body, or name the parameter _ if it exists only to match a signature. (Chapter 7)

A4.3 local variable is never mutated

pub fn main() void {
    var x: u32 = 5;
    _ = x;
}
e03.zig:2:9: error: local variable is never mutated
e03.zig:2:9: note: consider using 'const'

Meaning. A var that is never assigned after initialisation must be a const. Fix. Do what the note says. This is the error you get most often after deleting code. (Chapter 3)

A4.4 pointless discard of local variable

var x: u8 = 200;
x += 100;
_ = x;
e24.zig:4:9: error: pointless discard of local variable
e24.zig:3:5: note: used here

Meaning. You wrote _ = x; but x is already used. Fix. Remove the discard. (Chapter 3)

A4.5 local constant shadows declaration

const std = @import("std");
pub fn main() void {
    const std = 1;
    _ = std;
}
e04.zig:3:11: error: local constant shadows declaration of 'std'
e04.zig:1:1: note: declared here

Meaning. Zig forbids shadowing entirely; an inner name may not reuse an outer one. Fix. Rename the local. IRON LEDGER's slightly fussy names (uit2, pit2) exist because of this rule. (Chapter 7)

A4.6 unused capture

const items = [_]u8{ 1, 2 };
for (items) |item| {}
e31.zig:3:18: error: unused capture

Meaning. The loop captures item and never reads it. Fix. Write |_| if you only want the iteration count, or use the value. (Chapter 6)

A4.2 Types and coercion

A4.7 expected type 'X', found 'Y'

pub fn main() void {
    const s: []const u8 = 42;
    _ = s;
}
e11.zig:2:27: error: expected type '[]const u8', found 'comptime_int'

Meaning. The value's type cannot coerce to the declared type. Fix. Supply a value of the right type, or convert explicitly. This message has a hundred variants; read both type names carefully, because the difference is often a const, a ?, or a pointer versus a value (see A4.8, A4.9, A4.14). (Chapter 3)

A4.8 unsigned 8-bit int cannot represent all possible signed 64-bit values

pub fn main() void {
    var big: i64 = 300;
    big += 1;
    const small: u8 = big;
    _ = small;
}
e15.zig:4:23: error: expected type 'u8', found 'i64'
e15.zig:4:23: note: unsigned 8-bit int cannot represent all possible signed 64-bit values

Meaning. Integers only coerce implicitly when every value of the source fits the destination. Fix. const small: u8 = @intCast(big);, which checks at runtime, or @truncate if you mean to keep the low bits. (Chapter 4)

A4.9 type 'u8' cannot represent integer value '256'

const x: u8 = 255 + 1;
e08.zig:2:23: error: type 'u8' cannot represent integer value '256'

Meaning. The value is known at compile time and does not fit. Fix. Use a wider type, or if the wrap is intended, wrapping arithmetic (+%) on a runtime value. (Chapter 4)

A4.10 division with 'i32' and 'i32': signed integers must use @divTrunc, @divFloor, or @divExact

var a: i32 = -7;
a -= 1;
const b: i32 = 2;
std.debug.print("{d}\n", .{a / b});
e26.zig:6:34: error: division with 'i32' and 'i32': signed integers must use @divTrunc, @divFloor, or @divExact

Meaning. Truncation and flooring differ on negatives, so Zig makes you choose. Fix. @divTrunc(a, b) for C-style rounding toward zero, as IRON LEDGER's applyBp does. (Chapter 4, Chapter 45)

A4.11 cannot compare strings with ==

const a: []const u8 = "x";
if (a == "x") std.debug.print("same\n", .{});
e16.zig:4:11: error: cannot compare strings with ==

Meaning. Slices compare by pointer and length, not by contents, and the compiler refuses the obvious mistake. Fix. std.mem.eql(u8, a, "x"). (Chapter 11)

A4.12 invalid operands to binary expression: 'optional' and 'comptime_int'

const m: ?u32 = 5;
const n: u32 = m + 1;
e12.zig:3:22: error: invalid operands to binary expression: 'optional' and 'comptime_int'

Meaning. An optional must be unwrapped before use. Fix. (m orelse 0) + 1, if (m) |v| v + 1 else …, or m.? + 1 if you are sure it is not null. (Chapter 15)

A4.13 no field or member function named 'double' in '?P'

const p: ?P = .{ .x = 1 };
_ = p.double();
e30.zig:7:10: error: no field or member function named 'double' in '?e30.P'

Meaning. The same optional trap with a method call: the type is ?P, not P. Fix. Unwrap first. The message also appears, without the ?, when you misspell a method or field name. (Chapter 15)

A4.14 expected type '*u32', found 'u32'

fn bump(n: *u32) void { n.* += 1; }
pub fn main() void {
    var n: u32 = 1;
    bump(n);
}
e34.zig:4:10: error: expected type '*u32', found 'u32'
e34.zig:1:12: note: parameter type declared here

Meaning. The function wants a pointer and you passed a value. Fix. bump(&n);. Method calls take the address for you (gs.deinit()), plain calls do not (execute(&gs, …)). (Chapter 18)

A4.15 cannot assign to constant

const x: u32 = 1;
x = 2;
e14.zig:3:5: error: cannot assign to constant

Meaning. Exactly what it says. The same message appears for p.* = 2 through a *const u32 obtained by &x when x is const. Fix. Declare with var, or take a mutable pointer to a var. (Chapter 3, Chapter 18)

A4.16 slice of non-array type 'u32'

const n: u32 = 5;
const s = n[0..1];
e27.zig:3:16: error: slice of non-array type 'u32'

Meaning. Only arrays, slices and many-item pointers can be sliced. Fix. Slice the container, not the element; if you meant bytes of an integer, use std.mem.asBytes(&n). (Chapter 10)

A4.3 Control flow and completeness

A4.17 switch must handle all possibilities

const Color = enum { red, green, blue };
const n: u8 = switch (c) {
    .red => 1,
    .green => 2,
};
e07.zig:4:19: error: switch must handle all possibilities
e07.zig:1:34: note: unhandled enumeration value: 'blue'
e07.zig:1:15: note: enum 'e07.Color' declared here

Meaning. A switch on an enum, union or error set must name every case or have an else. Fix. Add the arm. This is the error IRON LEDGER relies on when a Command or Effect variant is added (Chapter 42, Chapter 46). For an integer switch the message is the same but with no note listing values; add else. (Chapter 6, Chapter 14)

A4.18 function with non-void return type 'u32' implicitly returns

fn f(a: u32) u32 {
    if (a > 1) return 1;
}
e18.zig:1:14: error: function with non-void return type 'u32' implicitly returns
e18.zig:3:1: note: control flow reaches end of body here

Meaning. Some path reaches the closing brace without returning. Fix. Add the missing return, or make the if an expression with an else. (Chapter 7)

A4.19 unreachable code

pub fn main() void {
    return;
    const x = 1;
    _ = x;
}
e23.zig:3:5: error: unreachable code
e23.zig:2:5: note: control flow is diverted here

Meaning. Code after a return, break, continue or unreachable is an error, not a warning. Fix. Delete it or move the return. (Chapter 6)

A4.20 cannot return from defer expression

defer {
    return;
}
e25.zig:3:9: error: cannot return from defer expression
e25.zig:2:5: note: defer expression here

Meaning. A defer block runs on the way out and may not change where the function returns to or what it returns. Fix. Do the cleanup and nothing else in the block; if the cleanup can fail, catch {} it. (Chapter 17)

A4.4 Errors and try

A4.21 expected type 'void', found '…error_set' / function cannot return an error

fn parse() !u32 { return std.fmt.parseInt(u32, "12", 10); }
pub fn main() void {
    const n = try parse();
    _ = n;
}
e05.zig:4:15: error: expected type 'void', found '@typeInfo(@typeInfo(@TypeOf(e05.parse)).@"fn".return_type.?).error_union.error_set'
e05.zig:3:15: note: function cannot return an error

Meaning. try returns the error from the current function, so the current function must be able to return one; main here returns void. The long type in the message is just "parse's error set". Fix. Change the return type to !void, or handle the error with catch. (Chapter 16)

A4.22 error union is ignored

pub fn main() void {
    parse();
}
e13.zig:4:10: error: error union is ignored
e13.zig:4:10: note: consider using 'try', 'catch', or 'if'

Meaning. A call that can fail must have its result handled. Fix. One of the three in the note, or _ = parse() catch {}; if you truly do not care. (Chapter 16)

A4.23 expectEqual: expected type 'u32', found 'i32'

fn add(a: i32, b: i32) i32 { return a + b; }
test "t" { try std.testing.expectEqual(@as(u32, 5), add(2, 3)); }
…/std/testing.zig:83:42: error: expected type 'u32', found 'i32'
…/std/testing.zig:83:42: note: unsigned 32-bit int cannot represent all possible signed 32-bit values
…/std/testing.zig:86:60: note: parameter type declared here
e06.zig:3:39: note: called inline here

Meaning. The expected and actual values have different types and the actual cannot coerce to the expected. The message points into the standard library; the last note is your line. Fix. Make the expected value's type match the function's return type: @as(i32, 5). (An untyped literal, expectEqual(5, add(2, 3)), compiles in 0.16 because the literal coerces.) (Chapter 8)

A4.5 Compile-time and formatting

A4.24 too few arguments (inside Writer.zig)

std.debug.print("{d} {d}\n", .{1});
…/std/Io/Writer.zig:717:13: error: too few arguments
referenced by:
    print__anon_27067: …/std/debug.zig:311:39
    main: e28.zig:3:20

Meaning. Two placeholders, one argument. Format strings are checked at compile time, so the error is inside the formatter with your line in the referenced by chain. Fix. Match the tuple to the placeholders. The sibling message "invalid format string 'd' for type '[]const u8'" means a placeholder does not suit the argument's type; see A2. (Chapter 2, Chapter 23)

A4.25 unable to resolve comptime value / types must be comptime-known

var n: usize = 3;
n += 1;
const arr: [n]u8 = undefined;
e22.zig:5:17: error: unable to resolve comptime value
e22.zig:5:17: note: types must be comptime-known

Meaning. An array length is part of a type, and types are fixed at compile time; n is a runtime value. Fix. Use a slice allocated at runtime (try alloc.alloc(u8, n)), or make n a comptime constant. (Chapter 9, Chapter 25)

A4.26 no field named 'Struct' in union 'builtin.Type'

const n = @typeInfo(P).Struct.fields.len;
e19.zig:4:28: error: no field named 'Struct' in union 'builtin.Type'
…/std/builtin.zig:550:18: note: union declared here

Meaning. The @typeInfo tags were renamed to lower case (.@"struct", .@"enum", .int…). The tutorial you copied from is pre-0.14. Fix. See A3. (Chapter 27)

A4.27 root source file struct 'std' has no member named 'io'

const out = std.io.getStdOut().writer();
e20.zig:3:21: error: root source file struct 'std' has no member named 'io'
…/std/std.zig:1:1: note: struct declared here

Meaning. std.io (lower case) is gone; I/O lives in std.Io and takes an io value. Any "has no member named" against std is a sign of a pre-0.16 tutorial. Fix. A3, first table. (Chapter 2)

A4.28 struct 'array_list.Aligned(u32,null)' has no member named 'init'

var list = std.ArrayList(u32).init(std.heap.page_allocator);
e21.zig:3:34: error: struct 'array_list.Aligned(u32,null)' has no member named 'init'

Meaning. Managed lists are gone; there is no init(alloc). Fix. var list: std.ArrayList(u32) = .empty; and pass the allocator to append, deinit and friends. (Chapter 21)

A4.6 Three runtime panics that are not compile errors

These compile fine and stop the program with a stack trace in Debug and ReleaseSafe builds. The trace names the line; read it the same way.

A4.29 integer overflow

var x: u8 = 200;
x += 100;
thread 6004466 panic: integer overflow
e24.zig:4:7: 0x10109dc53 in main (e24)
    x += 100;
      ^

Meaning. Plain + is checked. Fix. A wider type, +% to wrap, +| to saturate, or @addWithOverflow to inspect. (Chapter 4)

A4.30 index out of bounds

thread 6003567 panic: index out of bounds: index 3, len 3
e32.zig:6:37: 0x104341cd3 in main (e32)

Meaning. Every index into an array or slice is checked against its length. Fix. Check the index, or use if (i < items.len); note that the message gives you both numbers. (Chapter 9)

A4.31 attempt to use null value

thread 6003651 panic: attempt to use null value
e33.zig:5:33: 0x1028d1c97 in main (e33)
    std.debug.print("{d}\n", .{m.?});
                                ^

Meaning. .? asserted an optional was non-null and it was null. Fix. orelse or if (m) |v|. IRON LEDGER uses .? only where the code just created the value it unwraps (Chapter 42). (Chapter 15)
