34. Time and randomness

In this chapter you will read the wall clock and the monotonic clock through std.Io, measure how long code takes, sleep, and do calendar arithmetic by hand the way IRON LEDGER does. Then you will meet std.Random: seeding a generator, rolling dice, shuffling, and, most importantly, understanding why a simulation wants its randomness to be reproducible.

34.1 Two clocks

Every operating system offers at least two clocks, and it matters which one you ask.

The wall clock tells you what time it is in the world: seconds since midnight on the first of January 1970, UTC, the "Unix epoch". It can jump. A user changes the time zone, NTP corrects a drift, a laptop wakes from sleep; the wall clock moves accordingly, sometimes backwards.

The monotonic clock tells you how long the machine has been running since some arbitrary moment. It never goes backwards. Its absolute value means nothing, but the difference between two readings is a trustworthy duration. That is the clock for "how long did this take".

In Zig 0.16 both live behind std.Io, because reading a clock is talking to the outside world. Just as with files in Chapter 33, you need the io value that main receives. The clock is an enum, std.Io.Clock, and now is a method on it:

s1_wall.zig
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    const now = std.Io.Clock.now(.real, io);
    std.debug.print("nanoseconds since 1970: {d}\n", .{now.nanoseconds});
    std.debug.print("seconds since 1970:     {d}\n", .{now.toSeconds()});
    const days = @divFloor(now.toSeconds(), std.time.s_per_day);
    std.debug.print("days since 1970:        {d}\n", .{days});
}
$ zig run s1_wall.zig
nanoseconds since 1970: 1788964937601115000
seconds since 1970:     1788964937
days since 1970:        20705

Three things to notice. Clock.now returns a plain std.Io.Timestamp, not an error union: reading the clock cannot fail, so there is no try. The timestamp has one field, nanoseconds, of type i96 (wide enough that it will never overflow), and helper methods toSeconds, toMilliseconds and toMicroseconds. And the constants for converting between units live in std.time: ns_per_s, ns_per_ms, s_per_day, ms_per_min and so on. They are comptime integers, so @divFloor(secs, std.time.s_per_day) is ordinary integer arithmetic.

The clock names. The variants of std.Io.Clock in 0.16 are .real (the wall clock), .awake (monotonic, not counting time the machine was suspended), .boot (monotonic, including suspend), .cpu_process and .cpu_thread (CPU time consumed). There is no variant literally called monotonic; when this book says "the monotonic clock" it means .awake. On macOS .awake is CLOCK_UPTIME_RAW, on Linux it is CLOCK_MONOTONIC.
Gone in 0.16. std.time.timestamp(), std.time.milliTimestamp(), std.time.nanoTimestamp() and std.time.Timer no longer exist. Tutorials that use them will not compile. The replacement for all of them is std.Io.Clock.now plus the duration arithmetic below.

34.2 Measuring elapsed time

To time something, read the monotonic clock before and after, and subtract. Zig gives you a method for the subtraction, durationTo, which returns an std.Io.Duration with the same shape as a timestamp: a nanoseconds field and the same toMilliseconds family of helpers.

s2_elapsed.zig
const std = @import("std");

fn slowSum(n: u64) u64 {
    var total: u64 = 0;
    var i: u64 = 0;
    while (i < n) : (i += 1) total +%= i;
    return total;
}

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    const start = std.Io.Clock.now(.awake, io);
    const result = slowSum(50_000_000);
    const stop = std.Io.Clock.now(.awake, io);
    const took = start.durationTo(stop);
    std.debug.print("result {d}\n", .{result});
    std.debug.print("took {d} ns\n", .{took.nanoseconds});
    std.debug.print("took {d} ms\n", .{took.toMilliseconds()});
}
$ zig run s2_elapsed.zig
result 1249999975000000
took 99296500 ns
took 99 ms

This is the whole of what std.time.Timer used to do. If you find yourself timing things often, wrap it in a two-line helper struct that stores the start timestamp and has a read method; that is exactly what the old Timer was.

Two habits make timings honest. First, run the program with -O ReleaseFast when you care about the number; the Debug build above spends much of its 99 ms on overflow checks (the +%= avoids one, but the loop counter still has them). Second, do something with the result (here we print it) so the optimiser cannot delete the work you are measuring.

34.3 Sleeping

Sleeping also goes through io, for the same reason: it is a request to the operating system. The method is io.sleep(duration, clock). The duration is an std.Io.Duration, which you build with .fromMilliseconds, .fromSeconds, or .fromNanoseconds. Because the argument type is known, you can write the shorthand .fromMilliseconds(200) without naming the type.

s3_sleep.zig
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    const before = std.Io.Clock.now(.awake, io);
    try io.sleep(.fromMilliseconds(200), .awake);
    const after = std.Io.Clock.now(.awake, io);
    std.debug.print("asked for 200 ms, slept {d} ms\n", .{before.durationTo(after).toMilliseconds()});
}
$ zig run s3_sleep.zig
asked for 200 ms, slept 206 ms

Sleep can return an error, error.Canceled, because 0.16's I/O layer supports cancelling a blocked operation from another task. In a plain program that never happens, but the type is honest about the possibility, so you write try. And note the 206: sleep promises "at least this long", never "exactly this long". Never build a clock out of repeated sleeps.

34.4 Calendars by hand

The standard library will turn a Unix timestamp into a civil date for you (std.time.epoch has EpochSeconds, getEpochDay, calculateYearDay and calculateMonthDay), and that is the right tool when you need today's real date:

s7_epoch.zig
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const secs = std.Io.Clock.now(.real, init.io).toSeconds();
    const es = std.time.epoch.EpochSeconds{ .secs = @intCast(secs) };
    const yd = es.getEpochDay().calculateYearDay();
    const md = yd.calculateMonthDay();
    const ds = es.getDaySeconds();
    std.debug.print("UTC now: {d}-{d:0>2}-{d:0>2} {d:0>2}:{d:0>2}\n", .{
        yd.year, md.month.numeric(), md.day_index + 1, ds.getHoursIntoDay(), ds.getMinutesIntoHour(),
    });
}
$ zig run s7_epoch.zig
UTC now: 2026-09-09 14:42

But a simulation set in the year 3025 does not want the real date; it wants its own calendar, one it can advance a day at a time, forever, and render as "3025-02-01" when the player asks. This is a small and pleasant piece of code to write yourself, and IRON LEDGER does. There are two representations to keep straight:

  • A day counter: an integer holding the days since the campaign began, which makes arithmetic easy. "Was this person hired more than 90 days ago?" is a subtraction. Every transaction in the game's ledger is stamped with this integer.
  • A civil date: year, month, day. Perfect for humans and for rules that care about the calendar ("payday is the first of the month").

The trick is to store both and advance both together, so you never convert. Advancing a civil date by one day needs only the length of the current month, and that needs only the leap year rule: divisible by 4, except years divisible by 100, except years divisible by 400.

s6_date.zig
const std = @import("std");

const Date = struct {
    year: u16,
    month: u8,
    day: u8,

    fn isLeapYear(year: u16) bool {
        return (year % 4 == 0 and year % 100 != 0) or year % 400 == 0;
    }

    fn daysInMonth(year: u16, month: u8) u8 {
        return switch (month) {
            1, 3, 5, 7, 8, 10, 12 => 31,
            4, 6, 9, 11 => 30,
            2 => if (isLeapYear(year)) @as(u8, 29) else 28,
            else => unreachable,
        };
    }

    fn next(self: Date) Date {
        var d = self;
        d.day += 1;
        if (d.day > daysInMonth(d.year, d.month)) {
            d.day = 1;
            d.month += 1;
            if (d.month > 12) {
                d.month = 1;
                d.year += 1;
            }
        }
        return d;
    }
};

pub fn main() void {
    var d: Date = .{ .year = 3024, .month = 2, .day = 27 };
    var day_index: u32 = 0;
    for (0..4) |_| {
        std.debug.print("day {d} = {d}-{d:0>2}-{d:0>2}\n", .{ day_index, d.year, d.month, d.day });
        d = d.next();
        day_index += 1;
    }
}
$ zig run s6_date.zig
day 0 = 3024-02-27
day 1 = 3024-02-28
day 2 = 3024-02-29
day 3 = 3024-03-01

Three details are worth a second look. daysInMonth uses else => unreachable because a month outside 1 to 12 is a bug in the caller, not a runtime condition; in Debug builds the program will stop there with a stack trace if you ever break the rule (Chapter 37 has more on this choice). The @as(u8, 29) in the February arm forces both branches of the if to the same type, because 29 and 28 on their own are comptime_int. And next takes self by value and returns a new Date: no mutation, easy to test.

The format specifier {d:0>2} means "decimal, pad with zeros on the left to width 2", which is how 2 becomes 02. Chapter 23 has the full table.

34.5 Random numbers

Randomness in Zig is a small interface, std.Random, and a handful of generators that implement it. You create a generator with a seed, ask it for a std.Random value, and call methods on that. The generator you want by default is std.Random.DefaultPrng, which is Xoshiro256++: fast, good statistical quality, and 64-bit seeded.

s4_dice.zig
const std = @import("std");

pub fn main() void {
    var prng = std.Random.DefaultPrng.init(42);
    const r = prng.random();

    std.debug.print("d6:      {d}\n", .{r.intRangeAtMost(u8, 1, 6)});
    std.debug.print("d6:      {d}\n", .{r.intRangeAtMost(u8, 1, 6)});
    std.debug.print("0..99:   {d}\n", .{r.intRangeLessThan(u32, 0, 100)});
    std.debug.print("any u16: {d}\n", .{r.int(u16)});
    std.debug.print("float:   {d:.3}\n", .{r.float(f64)});
    std.debug.print("coin:    {}\n", .{r.boolean()});

    var deck = [_]u8{ 1, 2, 3, 4, 5, 6, 7, 8 };
    r.shuffle(u8, &deck);
    std.debug.print("shuffle: {any}\n", .{deck});

    const weights = [_]u32{ 70, 20, 10 }; // common, uncommon, rare
    std.debug.print("rarity:  {d}\n", .{r.weightedIndex(u32, &weights)});

    const Weather = enum { clear, rain, storm };
    std.debug.print("weather: {s}\n", .{@tagName(r.enumValue(Weather))});
}
$ zig run s4_dice.zig
d6:      4
d6:      4
0..99:   4
any u16: 13752
float:   0.597
coin:    true
shuffle: { 2, 6, 4, 8, 7, 3, 1, 5 }
rarity:  0
weather: rain

The methods you will use most:

CallGives
r.intRangeAtMost(T, lo, hi)an integer in lo..hi, both ends included: a die is (u8, 1, 6)
r.intRangeLessThan(T, lo, hi)an integer in lo..hi, upper end excluded: an index is (usize, 0, len)
r.uintLessThan(T, n)same, starting at 0, unsigned only
r.int(T)any value of the integer type, all bits random
r.float(T)a float in [0, 1)
r.boolean()a fair coin
r.shuffle(T, slice)rearranges the slice in place, every order equally likely
r.weightedIndex(T, weights)an index into weights, chosen proportionally: 70/20/10 above
r.enumValue(E)a random tag of an enum
r.bytes(buf)fills a byte slice

Notice that prng is declared with var: every draw advances the generator's internal state, so random() needs a mutable pointer to it. The std.Random value you get back is a small struct holding that pointer plus a function pointer; it is cheap to pass around by value and you can call prng.random() as often as you like.

Not for secrets. DefaultPrng is predictable by design. For anything security-related (tokens, keys, salts) use the operating system's generator instead: io.random(&buf) fills a buffer from the OS, and std.Random.DefaultCsprng is a cryptographic generator you can seed from it.

34.6 Seeds, and why determinism matters

A pseudo-random generator is a pure function of its seed. Same seed, same sequence, on every machine, forever. That is not a weakness to work around; it is the most useful property a simulation's randomness can have.

s5_seed.zig
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    // Fixed seed: the same three numbers every run.
    var fixed = std.Random.DefaultPrng.init(3025);
    std.debug.print("fixed: {d} {d} {d}\n", .{
        fixed.random().intRangeAtMost(u8, 1, 6),
        fixed.random().intRangeAtMost(u8, 1, 6),
        fixed.random().intRangeAtMost(u8, 1, 6),
    });

    // Seed from the operating system: different every run.
    var seed_bytes: [8]u8 = undefined;
    init.io.random(&seed_bytes);
    const seed = std.mem.readInt(u64, &seed_bytes, .little);
    var fresh = std.Random.DefaultPrng.init(seed);
    std.debug.print("fresh: {d} {d} {d} (seed {d})\n", .{
        fresh.random().intRangeAtMost(u8, 1, 6),
        fresh.random().intRangeAtMost(u8, 1, 6),
        fresh.random().intRangeAtMost(u8, 1, 6),
        seed,
    });
}
$ zig run s5_seed.zig
fixed: 4 1 1
fresh: 2 4 5 (seed 13483122203582859263)
$ zig run s5_seed.zig
fixed: 4 1 1
fresh: 4 1 5 (seed 10071616139519654204)

The fixed line never changes. The fresh line does, because the seed came from the OS. (You could also seed from the wall clock, @bitCast-ing the nanoseconds into a u64; the OS generator is simpler and better.) The pattern to copy from this program is: print the seed. A game that shows "seed 13483122203582859263" on its title screen can reproduce any bug report exactly.

Determinism buys you three things:

  1. Reproducible bugs. "It crashed on day 212 with seed 42" is a test case. "It crashed sometimes" is a mystery.
  2. Testable rules. A test can seed a generator with 7, run a thousand days, and assert on the exact outcome, because the outcome is a fact about the code and the seed, not about luck.
  3. Save files that replay. If the state after 90 days is a function of (seed, commands), then a save file need not store every dice roll, only the seed and the state.

There is a subtle trap, and IRON LEDGER's answer to it is one of the nicest small designs in the game. Suppose every subsystem shares one generator: the market draws, then a battle draws, then a medical check draws. Now you add one extra weather roll to battles. Every market roll after the first battle shifts by one position; a saved game replays differently after your update; every golden-master test breaks. The fix is to give each subsystem its own stream: a separate generator, derived from the master seed in a stable way. Adding a draw to the battle stream leaves the market stream untouched. Exercise 34.5 has you build exactly this.

In IRON LEDGER. The game's clock is src/sim/clock.zig: a Date struct with isLeapYear, daysInMonth, next and isPayday (the first of the month), wrapped in a Clock that carries both the civil date and day_index, "the canonical timestamp". Everything that records when stores the integer; everything that displays a date renders the struct. Randomness is src/sim/rng.zig: an enum of eight streams (generation, market, maintenance, acquisition, battle, events, medical, travel) and an Rng holding one DefaultPrng per stream, each seeded with seed ^ (0x9E3779B97F4A7C15 *% (i + 1)). Every die in the game is gs.rng.roll2d6(.some_stream). The simulation core never receives an io, so it cannot read the real clock even by accident, and the golden-master test in src/sim/commands.zig (same seed, same script, same hash, twice) guards the whole property on every build. 
pub fn roll2d6(self: *Rng, stream: Stream) u8 {
    const r = self.random(stream);
    return r.intRangeAtMost(u8, 1, 6) + r.intRangeAtMost(u8, 1, 6);
}

Exercise 34.1 · Elapsed time warm-up

Time a busy loop at three sizes (one million, ten million, one hundred million iterations) with the monotonic clock, and print each result in milliseconds to stdout. Then run it again with -O ReleaseFast and compare. Name the file: exercises/34-time-random/ex1_elapsed.zig.

Solution 
//! Chapter 34, exercise 1: measuring elapsed time.
//! Run with:  zig run ex1_elapsed.zig
//! Goal: time three sizes of a busy loop with the monotonic clock and print
//! each duration in milliseconds. Your numbers will differ; the shape
//! (each line roughly ten times the last) should not.
//!
//! Example output:
//!   n=1000000     sum=499999500000        took 1 ms
//!   n=10000000    sum=49999995000000      took 12 ms
//!   n=100000000   sum=4999999950000000    took 121 ms

const std = @import("std");

fn busyLoop(n: u64) u64 {
    var sum: u64 = 0;
    var i: u64 = 0;
    while (i < n) : (i += 1) sum +%= i;
    return sum;
}

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    var buf: [256]u8 = undefined;
    var w = std.Io.File.stdout().writer(io, &buf);
    const out = &w.interface;

    const sizes = [_]u64{ 1_000_000, 10_000_000, 100_000_000 };
    for (sizes) |n| {
        const t0 = std.Io.Clock.now(.awake, io);
        const sum = busyLoop(n);
        const t1 = std.Io.Clock.now(.awake, io);
        const took = t0.durationTo(t1);
        try out.print("n={d:<12} sum={d:<20} took {d} ms\n", .{ n, sum, took.toMilliseconds() });
    }
    try out.flush();
}

Two readings of .awake bracket the work, durationTo subtracts them, and toMilliseconds scales. The {d:<12} specifier left-aligns in a 12-character field so the columns line up. In ReleaseFast the compiler may compute the closed-form sum and every line becomes 0 ms, which is a lesson in its own right.

Exercise 34.2 · A dice roller practice

Write roll(r, count, sides) that returns the total of count dice with sides faces, and roll2d6(r) on top of it. The tests check the range, that 2 and 12 both appear over enough rolls, that the average is near 7, and that two generators with the same seed agree roll for roll. Name the file: exercises/34-time-random/ex2_dice.zig.

Solution 
//! Chapter 34, exercise 2: a dice roller.
//! Run with:  zig test ex2_dice.zig
//! Goal: implement `roll` and `roll2d6`, then make every test pass
//! without changing the tests.

const std = @import("std");

/// Roll `count` dice with `sides` sides each and return the total.
pub fn roll(r: std.Random, count: u8, sides: u8) u32 {
    std.debug.assert(sides >= 1);
    var total: u32 = 0;
    for (0..count) |_| total += r.intRangeAtMost(u8, 1, sides);
    return total;
}

/// The BattleTech die roll.
pub fn roll2d6(r: std.Random) u32 {
    return roll(r, 2, 6);
}

test "one die stays in range" {
    var prng = std.Random.DefaultPrng.init(1);
    const r = prng.random();
    for (0..1000) |_| {
        const v = roll(r, 1, 6);
        try std.testing.expect(v >= 1 and v <= 6);
    }
}

test "2d6 stays in range and hits both ends" {
    var prng = std.Random.DefaultPrng.init(2);
    const r = prng.random();
    var seen_2 = false;
    var seen_12 = false;
    for (0..5000) |_| {
        const v = roll2d6(r);
        try std.testing.expect(v >= 2 and v <= 12);
        if (v == 2) seen_2 = true;
        if (v == 12) seen_12 = true;
    }
    try std.testing.expect(seen_2 and seen_12);
}

test "2d6 averages close to 7" {
    var prng = std.Random.DefaultPrng.init(3);
    const r = prng.random();
    var total: u64 = 0;
    const n = 20_000;
    for (0..n) |_| total += roll2d6(r);
    const avg: f64 = @as(f64, @floatFromInt(total)) / n;
    try std.testing.expect(avg > 6.8 and avg < 7.2);
}

test "same seed, same rolls" {
    var a = std.Random.DefaultPrng.init(99);
    var b = std.Random.DefaultPrng.init(99);
    for (0..100) |_| {
        try std.testing.expectEqual(roll2d6(a.random()), roll2d6(b.random()));
    }
}

Each die is one intRangeAtMost(u8, 1, sides), summed into a u32 so many dice cannot overflow. The average test converts with @floatFromInt and allows a small tolerance; with 20,000 rolls the sample mean of 2d6 is within 0.2 of 7 essentially always, and because the seed is fixed the test is not flaky at all.

Exercise 34.3 · A seeded shuffle practice

Given a fixed array of six names, write shuffledCopy(seed) that returns a shuffled copy. Tests check that every name survives, that the same seed gives the same order, and that two different seeds give different orders. Name the file: exercises/34-time-random/ex3_shuffle.zig.

Solution 
//! Chapter 34, exercise 3: a seeded shuffle.
//! Run with:  zig test ex3_shuffle.zig
//! Goal: implement `shuffledCopy` so the tests pass. A shuffle must keep
//! every element exactly once, and the same seed must give the same order.

const std = @import("std");

const names = [_][]const u8{ "Grayson", "Lori", "Clay", "Delmar", "Ricol", "Yorinaga" };

/// Return a shuffled copy of `names`, driven by `seed`.
pub fn shuffledCopy(seed: u64) [names.len][]const u8 {
    var copy = names;
    var prng = std.Random.DefaultPrng.init(seed);
    prng.random().shuffle([]const u8, &copy);
    return copy;
}

fn contains(haystack: []const []const u8, needle: []const u8) bool {
    for (haystack) |h| if (std.mem.eql(u8, h, needle)) return true;
    return false;
}

test "every name survives the shuffle" {
    const s = shuffledCopy(1);
    for (names) |n| try std.testing.expect(contains(&s, n));
    try std.testing.expectEqual(names.len, s.len);
}

test "same seed gives same order" {
    const a = shuffledCopy(2024);
    const b = shuffledCopy(2024);
    for (a, b) |x, y| try std.testing.expectEqualStrings(x, y);
}

test "different seeds usually differ" {
    const a = shuffledCopy(1);
    const b = shuffledCopy(2);
    var same = true;
    for (a, b) |x, y| if (!std.mem.eql(u8, x, y)) {
        same = false;
    };
    try std.testing.expect(!same);
}

Copying the array (var copy = names;) is what makes the function pure: the original is never touched. shuffle takes the element type and a slice, and &copy is a pointer to the array, which coerces to that slice. Returning the array by value is fine; it is six slices, 96 bytes.

Exercise 34.4 · Calendar arithmetic practice

Complete a Date struct with isLeapYear, daysInMonth, next, addDays(n) and dayOfYear. Tests include the century rules (1900 is not a leap year, 2000 is), month and year rollover, a 45-day jump, and day 366 of 3024. Name the file: exercises/34-time-random/ex4_calendar.zig.

Solution 
//! Chapter 34, exercise 4: civil calendar arithmetic by hand.
//! Run with:  zig test ex4_calendar.zig
//! Goal: implement `daysInMonth`, `next`, `addDays` and `dayOfYear` so
//! the tests pass. Leap years: divisible by 4, except centuries, except
//! every 400th year.

const std = @import("std");

pub const Date = struct {
    year: u16,
    month: u8, // 1..12
    day: u8, // 1..31

    pub fn isLeapYear(year: u16) bool {
        return (year % 4 == 0 and year % 100 != 0) or year % 400 == 0;
    }

    pub fn daysInMonth(year: u16, month: u8) u8 {
        return switch (month) {
            1, 3, 5, 7, 8, 10, 12 => 31,
            4, 6, 9, 11 => 30,
            2 => if (isLeapYear(year)) @as(u8, 29) else 28,
            else => unreachable,
        };
    }

    pub fn next(self: Date) Date {
        var d = self;
        d.day += 1;
        if (d.day > daysInMonth(d.year, d.month)) {
            d.day = 1;
            d.month += 1;
            if (d.month > 12) {
                d.month = 1;
                d.year += 1;
            }
        }
        return d;
    }

    pub fn addDays(self: Date, n: u32) Date {
        var d = self;
        for (0..n) |_| d = d.next();
        return d;
    }

    /// 1 for January 1st, 365 or 366 for December 31st.
    pub fn dayOfYear(self: Date) u16 {
        var total: u16 = self.day;
        var m: u8 = 1;
        while (m < self.month) : (m += 1) total += daysInMonth(self.year, m);
        return total;
    }
};

test "leap year rules" {
    try std.testing.expect(Date.isLeapYear(2024));
    try std.testing.expect(!Date.isLeapYear(2023));
    try std.testing.expect(!Date.isLeapYear(1900));
    try std.testing.expect(Date.isLeapYear(2000));
    try std.testing.expect(Date.isLeapYear(3024));
}

test "february length" {
    try std.testing.expectEqual(@as(u8, 29), Date.daysInMonth(3024, 2));
    try std.testing.expectEqual(@as(u8, 28), Date.daysInMonth(3025, 2));
}

test "month and year rollover" {
    const d: Date = .{ .year = 3025, .month = 12, .day = 31 };
    try std.testing.expectEqual(Date{ .year = 3026, .month = 1, .day = 1 }, d.next());
    const f: Date = .{ .year = 3024, .month = 2, .day = 28 };
    try std.testing.expectEqual(Date{ .year = 3024, .month = 2, .day = 29 }, f.next());
}

test "addDays crosses months" {
    const d: Date = .{ .year = 3025, .month = 1, .day = 1 };
    try std.testing.expectEqual(Date{ .year = 3025, .month = 2, .day = 15 }, d.addDays(45));
    try std.testing.expectEqual(Date{ .year = 3026, .month = 1, .day = 1 }, d.addDays(365));
}

test "dayOfYear" {
    try std.testing.expectEqual(@as(u16, 1), (Date{ .year = 3025, .month = 1, .day = 1 }).dayOfYear());
    try std.testing.expectEqual(@as(u16, 365), (Date{ .year = 3025, .month = 12, .day = 31 }).dayOfYear());
    try std.testing.expectEqual(@as(u16, 366), (Date{ .year = 3024, .month = 12, .day = 31 }).dayOfYear());
}

addDays simply calls next in a loop, which is plenty fast for a game that advances a day at a time and avoids a page of tricky arithmetic. dayOfYear adds up the lengths of the months before this one. Notice that expectEqual compares two Date structs field by field.

Exercise 34.5 · Named streams challenge

Build a miniature of IRON LEDGER's Rng: an enum Stream { market, battle, events } and a struct holding one DefaultPrng per stream, all derived from one seed. Write init(seed), random(stream) and roll2d6(stream). The key test draws a thousand times from .market in one instance and then checks that .battle still matches an untouched twin. Name the file: exercises/34-time-random/ex5_streams.zig.

Solution 
//! Chapter 34, exercise 5: named random streams.
//! Run with:  zig test ex5_streams.zig
//! Goal: implement `Rng.init` so every stream gets its own generator
//! derived from the seed, and make the tests pass.

const std = @import("std");

pub const Stream = enum(u8) {
    market,
    battle,
    events,

    const count = @typeInfo(Stream).@"enum".fields.len;
};

pub const Rng = struct {
    prngs: [Stream.count]std.Random.DefaultPrng,

    pub fn init(seed: u64) Rng {
        var self: Rng = undefined;
        for (&self.prngs, 0..) |*prng, i| {
            prng.* = std.Random.DefaultPrng.init(seed ^ (0x9E3779B97F4A7C15 *% (i + 1)));
        }
        return self;
    }

    pub fn random(self: *Rng, stream: Stream) std.Random {
        return self.prngs[@intFromEnum(stream)].random();
    }

    pub fn roll2d6(self: *Rng, stream: Stream) u8 {
        const r = self.random(stream);
        return r.intRangeAtMost(u8, 1, 6) + r.intRangeAtMost(u8, 1, 6);
    }
};

test "streams are independent" {
    var a = Rng.init(42);
    var b = Rng.init(42);
    for (0..1000) |_| _ = a.roll2d6(.market);
    for (0..10) |_| try std.testing.expectEqual(b.roll2d6(.battle), a.roll2d6(.battle));
}

test "streams differ from each other" {
    var r = Rng.init(7);
    var same: usize = 0;
    for (0..50) |_| {
        if (r.roll2d6(.market) == r.roll2d6(.events)) same += 1;
    }
    try std.testing.expect(same < 50);
}

test "2d6 stays in range" {
    var r = Rng.init(7);
    for (0..1000) |_| {
        const v = r.roll2d6(.events);
        try std.testing.expect(v >= 2 and v <= 12);
    }
}

Stream.count is computed by reflection so adding a stream to the enum grows the array automatically. The seed for stream i is the master seed XORed with a large odd constant times i + 1 (wrapping multiply, *%), which spreads the seeds far apart; any stable, distinct derivation would do. The struct starts as undefined and every slot is filled in the loop, which is the idiomatic way to build an array of non-default values.

Check your understanding

  1. Which clock do you use to measure how long a function took, and why not the other one?
    AnswerThe monotonic clock, .awake. The wall clock (.real) can jump forwards or backwards when the system time is adjusted, so a difference of two wall-clock readings is not a reliable duration.
  2. Why does std.Io.Clock.now(.real, io) not need try?
    AnswerIt returns a plain Timestamp, not an error union. Reading a clock cannot fail in a way the program could handle. Sleeping, by contrast, returns Cancelable!void because it blocks and can be cancelled.
  3. What happened to std.time.Timer and std.time.timestamp()?
    AnswerThey are gone in 0.16. Use std.Io.Clock.now for both, with durationTo for elapsed time. The unit constants in std.time (ns_per_s and friends) remain.
  4. Is 3000 a leap year? Is 3024?
    Answer3000 is divisible by 100 but not by 400, so it is not a leap year. 3024 is divisible by 4 and not by 100, so it is.
  5. Why does IRON LEDGER store both a day counter and a civil date?
    AnswerThe integer is for arithmetic and for stamping records (a subtraction answers "how many days ago"); the struct is for display and for calendar rules like payday on the 1st. Advancing both together avoids ever converting between them.
  6. What does r.intRangeAtMost(u8, 1, 6) return, and how would you write "a random index into a slice of length n"?
    AnswerAn integer from 1 to 6 inclusive. For an index use r.intRangeLessThan(usize, 0, n) or r.uintLessThan(usize, n), since the upper bound is excluded.
  7. Two runs with the same seed produce different results. Name three possible causes.
    AnswerSomething read the wall clock; a hash map with unordered iteration decided an order; a second generator was created somewhere with a different seed (or a thread interleaved draws). The golden-master test exists to catch all of these.
  8. Why give each subsystem its own random stream?
    AnswerSo that adding or removing a draw in one subsystem does not shift the sequence every other subsystem sees. Saved games and tests stay stable across updates that touch only one area.
What you learned.
  • std.Io.Clock.now(.real, io) gives Unix time; .awake is the monotonic clock. Both return a Timestamp with a nanoseconds field and toSeconds-style helpers.
  • Elapsed time is start.durationTo(stop); sleeping is try io.sleep(.fromMilliseconds(n), .awake). std.time.Timer and std.time.timestamp() are gone.
  • Unit constants live in std.time: ns_per_s, s_per_day, and so on. Real-date conversion is in std.time.epoch.
  • A simulation calendar is a small struct: leap years, days in month, next(). Keep an integer day counter alongside it.
  • std.Random.DefaultPrng.init(seed) then .random() gives an std.Random with intRangeAtMost, float, boolean, shuffle, weightedIndex, enumValue.
  • Seed from io.random for variety, from a constant for reproducibility, and always print the seed. One generator per subsystem keeps saves and tests stable.
