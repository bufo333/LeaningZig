29. Packed structs, bit casting and vectors

In this chapter you go below the byte. You will use integers of any width, flip individual bits with the bit operators and the counting builtins, lay out a struct so it occupies exactly one byte, reinterpret memory with @bitCast, read big-endian numbers out of a file header, keep a set of flags in std.bit_set, and do arithmetic on several numbers at once with @Vector. Each tool is small; together they are how Zig talks to file formats, hardware and C.

29.1 Integers of any width

You have used u8, i32 and u64. Zig also has u3, u7, i5, u24, in fact uN and iN for any N from 1 to 65535. A u3 holds 0 to 7 and nothing else; overflowing it is the same error as overflowing a u8. In memory it still takes a whole byte (there is no such thing as a 3-bit load), but inside a packed struct it takes exactly three bits.

widths.zig

const std = @import("std");

pub fn main() void {
    const a: u3 = 7;
    const b: u7 = 127;
    const c: i5 = -16;
    std.debug.print("u3 max {d}, u7 max {d}, i5 min {d}\n", .{ a, b, c });
    std.debug.print("u3: size {d} bytes, {d} bits, align {d}\n", .{ @sizeOf(u3), @bitSizeOf(u3), @alignOf(u3) });
    std.debug.print("u7: size {d} bytes, {d} bits\n", .{ @sizeOf(u7), @bitSizeOf(u7) });
    std.debug.print("u24: size {d} bytes, {d} bits, align {d}\n", .{ @sizeOf(u24), @bitSizeOf(u24), @alignOf(u24) });
    std.debug.print("u64: size {d} bytes, align {d}\n", .{ @sizeOf(u64), @alignOf(u64) });
    std.debug.print("bool: size {d} bytes, {d} bits\n", .{ @sizeOf(bool), @bitSizeOf(bool) });
    std.debug.print("maxInt(u3) = {d}, maxInt(u12) = {d}\n", .{ std.math.maxInt(u3), std.math.maxInt(u12) });
}
u3 max 7, u7 max 127, i5 min -16

Three builtins measure a type. @sizeOf(T) is the number of bytes a value occupies in memory, rounded up to something the CPU can address, which is why u24 reports 4. @bitSizeOf(T) is the number of bits that carry information. @alignOf(T) is the address multiple the value must sit on. Odd widths are not a curiosity: they are how you say "this field is a 3-bit rank" and have the compiler refuse an 8.

29.2 The bit operators

Six operators work on the individual bits of an integer: & (and), | (or), ^ (exclusive or), ~ (not), << (shift left) and >> (shift right). Alongside them Zig offers builtins that count and rearrange bits. The {b:0>8} format prints an integer in binary, padded with zeros to eight places, which is the best way to see what is happening.

bitops.zig

const std = @import("std");

pub fn main() void {
    const x: u8 = 0b1011_0010;
    const y: u8 = 0b0110_0110;
    std.debug.print("x     = {b:0>8}\n", .{x});
    std.debug.print("y     = {b:0>8}\n", .{y});
    std.debug.print("x & y = {b:0>8}\n", .{x & y});
    std.debug.print("x | y = {b:0>8}\n", .{x | y});
    std.debug.print("x ^ y = {b:0>8}\n", .{x ^ y});
    std.debug.print("~x    = {b:0>8}\n", .{~x});
    std.debug.print("x >> 2 = {b:0>8}\n", .{x >> 2});
    std.debug.print("x << 1 = {b:0>8}  (top bit falls off)\n", .{x << 1});
    std.debug.print("popCount(x) = {d}\n", .{@popCount(x)});
    std.debug.print("clz(x) = {d}, ctz(x) = {d}\n", .{ @clz(x), @ctz(x) });
    std.debug.print("clz(1) = {d}, ctz(0b1000) = {d}\n", .{ @clz(@as(u8, 1)), @ctz(@as(u8, 0b1000)) });
    std.debug.print("byteSwap(0x1234) = 0x{x}\n", .{@byteSwap(@as(u16, 0x1234))});
    std.debug.print("bitReverse(x) = {b:0>8}\n", .{@bitReverse(x)});
    std.debug.print("x as hex {x}, as octal {o}\n", .{ x, x });
    const bit3 = (x >> 3) & 1;
    std.debug.print("bit 3 of x is {d}\n", .{bit3});
    const set = x | (1 << 2);
    const cleared = x & ~@as(u8, 1 << 4);
    std.debug.print("set bit 2: {b:0>8}, clear bit 4: {b:0>8}\n", .{ set, cleared });
}

The three idioms at the bottom are the ones you will write most: test a bit with (x >> n) & 1, set a bit with x | (1 << n), clear a bit with x & ~(1 << n). The counting builtins are @popCount (how many ones), @clz (leading zeros, counted from the top) and @ctz (trailing zeros, from the bottom). @byteSwap reverses the bytes of a multi-byte integer, which section 29.7 will connect to endianness, and @bitReverse reverses all the bits.

Why ~@as(u8, 1 << 4) and not ~(1 << 4)? The literal 1 << 4 is a comptime_int, and "not" of an untyped integer has no defined width. Give it a type first so the compiler knows how many bits to flip.

29.3 Shifts and their rules

Shifting is where Zig's strictness surprises people coming from C. The shift amount for a u8 must be a u3, because shifting an 8-bit value by 8 or more is meaningless; for a u32 it must be a u5. The compiler enforces this at the type level: pass a u8 as the amount and it will not compile.

shift_bad.zig

pub fn main() void {
    const n: u8 = 1;
    var s: u8 = 3;
    s += 1;
    _ = n << s;
}
shift_bad.zig:5:14: error: expected type 'u3', found 'u8'
    _ = n << s;
             ^
shift_bad.zig:5:14: note: unsigned 3-bit int cannot represent all possible unsigned 8-bit values

The fix is @intCast(s) to a u3 (a checked narrowing) or @truncate(s) (keep the low three bits). The second rule concerns bits that fall off the left: a plain << discards them silently, exactly like C, but @shlExact asserts that nothing is lost and @shlWithOverflow reports whether something was.

shifts.zig

const std = @import("std");

pub fn main() void {
    const one: u8 = 1;
    std.debug.print("1 << 7 = {d}\n", .{one << 7});
    std.debug.print("@shlExact(1, 3) = {d}\n", .{@shlExact(one, 3)});
    std.debug.print("@shlWithOverflow(0xF0, 2) = {any}\n", .{@shlWithOverflow(@as(u8, 0xF0), 2)});
    const n: u8 = 200;
    const shift: u3 = 2;
    std.debug.print("200 >> {d} = {d}\n", .{ shift, n >> shift });
    std.debug.print("@shrExact(200, 3) = {d}\n", .{@shrExact(n, 3)});
    const wide: u32 = 1;
    const s: u5 = 31;
    std.debug.print("1 << 31 = {d}\n", .{wide << s});
}
1 << 7 = 128
@shlExact(1, 3) = 8
@shlWithOverflow(0xF0, 2) = .{ 192, 1 }
200 >> 2 = 50
@shrExact(200, 3) = 25
1 << 31 = 2147483648

@shlWithOverflow returns a tuple: the wrapped result and a u1 that is 1 when bits were lost. @shrExact is the right-shift twin: it asserts that no one-bits were shifted out, so it is a way of dividing by a power of two and insisting the division was exact. In Debug and ReleaseSafe a violated @shlExact panics; in ReleaseFast it is undefined behaviour, so use it only where you have already proved the property.

29.4 Packed structs: fields that are bits

A normal struct lets the compiler decide where fields go. A packed struct takes that freedom away: fields are laid out in declaration order, first field in the lowest bits, with no padding, and the whole thing is backed by one integer whose width you write after the keyword. packed struct(u8) must add up to exactly eight bits or it will not compile.

packed1.zig

const std = @import("std");

const Flags = packed struct(u8) {
    armed: bool = false,
    wounded: bool = false,
    veteran: bool = false,
    rank: u3 = 0,
    _pad: u2 = 0,
};

pub fn main() void {
    var f = Flags{ .armed = true, .rank = 5 };
    std.debug.print("size {d} byte(s), bits {d}\n", .{ @sizeOf(Flags), @bitSizeOf(Flags) });
    const byte: u8 = @bitCast(f);
    std.debug.print("as byte: {b:0>8} = 0x{x:0>2}\n", .{ byte, byte });
    f.wounded = true;
    const byte2: u8 = @bitCast(f);
    std.debug.print("after wound: {b:0>8}\n", .{byte2});
    const back: Flags = @bitCast(@as(u8, 0b0010_0110));
    std.debug.print("from 0b00100110: armed={} wounded={} veteran={} rank={d}\n", .{ back.armed, back.wounded, back.veteran, back.rank });
    std.debug.print("offset of rank: {d} bits\n", .{@bitOffsetOf(Flags, "rank")});
}
size 1 byte(s), bits 8
as byte: 00101001 = 0x29
after wound: 00101011
from 0b00100110: armed=false wounded=true veteran=true rank=4
offset of rank: 3 bits

Read the first binary line from the right. Bit 0 is armed (1). Bit 1 is wounded (0). Bit 2 is veteran (0). Bits 3 to 5 are rank, which is 5, or 101. Bits 6 and 7 are padding. Put together, right to left: 00 101 0 0 1, which is 0x29. Field access reads and writes just the right bits; the compiler emits the masks and shifts for you, and a u3 rank cannot be assigned an 8.

Conversion between the struct and its backing integer is @bitCast, in both directions, and it costs nothing: the bits do not move. That is what makes packed structs the natural way to describe a byte of flags in a file format, a hardware register, or a network header.

packed2.zig

const std = @import("std");

const Rgb565 = packed struct(u16) { b: u5, g: u6, r: u5 };
const Ip = packed struct(u32) { d: u8, c: u8, b: u8, a: u8 };

pub fn main() void {
    const c: Rgb565 = .{ .r = 31, .g = 0, .b = 31 };
    std.debug.print("magenta = 0x{x:0>4}\n", .{@as(u16, @bitCast(c))});
    const raw: u16 = 0x07E0;
    const g: Rgb565 = @bitCast(raw);
    std.debug.print("0x07E0 -> r={d} g={d} b={d}\n", .{ g.r, g.g, g.b });
    const ip: Ip = @bitCast(@as(u32, 0xC0A80001));
    std.debug.print("{d}.{d}.{d}.{d}\n", .{ ip.a, ip.b, ip.c, ip.d });
}
magenta = 0xf81f
0x07E0 -> r=0 g=63 b=0
192.168.0.1

RGB565 is a real pixel format (5 bits red, 6 green, 5 blue in 16 bits) and the Ip struct shows a subtlety: because the first field lands in the lowest bits and this machine stores the low byte first, the field order is reversed relative to the dotted notation. Section 29.7 makes that precise.

Packed is not the default, and it is not free of rules. Do not reach for packed for ordinary data; it can make field access slower and forbids some field types. Use it when the bit layout is the specification. For talking to C you want extern, covered next.

29.5 @bitCast: the same bits, another type

@bitCast reinterprets a value as another type of the same size. No conversion happens; the bit pattern is simply relabelled. It is how you look at a float's binary representation, turn a negative number into its two's-complement bytes, or split a word into an array.

bitcast.zig

const std = @import("std");

pub fn main() void {
    const f: f32 = 1.0;
    const bits: u32 = @bitCast(f);
    std.debug.print("1.0f32 is 0x{x:0>8}\n", .{bits});
    const neg: i8 = -1;
    const as_u8: u8 = @bitCast(neg);
    std.debug.print("-1 as u8 is {d}\n", .{as_u8});
    const bytes: [4]u8 = @bitCast(@as(u32, 0x11223344));
    std.debug.print("0x11223344 in memory: {x:0>2} {x:0>2} {x:0>2} {x:0>2}\n", .{ bytes[0], bytes[1], bytes[2], bytes[3] });
    std.debug.print("this machine is {s}-endian\n", .{@tagName(@import("builtin").cpu.arch.endian())});
}
1.0f32 is 0x3f800000
-1 as u8 is 255
0x11223344 in memory: 44 33 22 11
this machine is little-endian

Contrast this with the casts you know. @intCast changes width and checks the value fits; @floatFromInt computes a float with the same mathematical value; @bitCast keeps the bits and changes only the label. The result type must be the same size as the source, and the compiler refuses otherwise. The third line reveals something about your machine: the bytes of 0x11223344 sit in memory lowest byte first. That is little-endian, and it is the subject of section 29.7.

29.6 Three layouts: auto, extern, packed

A struct with no layout keyword is auto: the compiler may reorder fields to reduce padding, and you must not assume where anything is. An extern struct keeps declaration order and uses the C ABI's padding rules, which is what a C library expects. A packed struct has no padding at all. The measuring builtins show the difference, and @offsetOf reports where a field sits in bytes.

layout.zig

const std = @import("std");

const Auto = struct { a: u8, b: u32, c: u8 };
const Extern = extern struct { a: u8, b: u32, c: u8 };
const Reordered = extern struct { b: u32, a: u8, c: u8 };
const Packed = packed struct { a: u8, b: u32, c: u8 };

pub fn main() void {
    std.debug.print("Auto:      size {d} align {d}\n", .{ @sizeOf(Auto), @alignOf(Auto) });
    std.debug.print("Extern:    size {d} align {d}  offsets a={d} b={d} c={d}\n", .{ @sizeOf(Extern), @alignOf(Extern), @offsetOf(Extern, "a"), @offsetOf(Extern, "b"), @offsetOf(Extern, "c") });
    std.debug.print("Reordered: size {d} align {d}\n", .{ @sizeOf(Reordered), @alignOf(Reordered) });
    std.debug.print("Packed:    size {d} bits {d}\n", .{ @sizeOf(Packed), @bitSizeOf(Packed) });
}
Auto:      size 8 align 4
Extern:    size 12 align 4  offsets a=0 b=4 c=8
Reordered: size 8 align 4
Packed:    size 8 bits 48

The same three fields cost 8 bytes as an auto struct (the compiler moved b first), 12 bytes as an extern struct in the written order (three bytes of padding after a and three after c, so the u32 stays 4-aligned), and 8 bytes again when you reorder the extern struct by hand. The packed version holds 48 bits of information but still occupies 8 bytes when stored alone, because its backing integer is rounded up. This table is the whole story of "why is my struct bigger than the sum of its fields", and of why the game's SQLite binding uses extern only where it meets C.

29.7 Endianness: which byte comes first

A u32 is four bytes. When it is written to memory, a file or a network packet, something has to decide whether the most significant byte goes first (big-endian, the convention in most file formats and all of networking) or last (little-endian, the convention of x86 and ARM processors). Your program's memory uses the CPU's order; a file uses whatever its specification says. Getting this wrong does not crash: it silently produces a number like 65536 where you expected 256.

Never convert with arithmetic by hand. std.mem.readInt and std.mem.writeInt take the integer type, a pointer to exactly the right number of bytes, and the endianness, and do the right thing on every machine.

endian.zig

const std = @import("std");

pub fn main() void {
    var buf: [4]u8 = undefined;
    std.mem.writeInt(u32, &buf, 0x01020304, .big);
    std.debug.print("big:    {x:0>2} {x:0>2} {x:0>2} {x:0>2}\n", .{ buf[0], buf[1], buf[2], buf[3] });
    std.mem.writeInt(u32, &buf, 0x01020304, .little);
    std.debug.print("little: {x:0>2} {x:0>2} {x:0>2} {x:0>2}\n", .{ buf[0], buf[1], buf[2], buf[3] });

    const png_ihdr = [_]u8{ 0x00, 0x00, 0x01, 0x00, 0x00, 0x00, 0x00, 0xC0 };
    const width = std.mem.readInt(u32, png_ihdr[0..4], .big);
    const height = std.mem.readInt(u32, png_ihdr[4..8], .big);
    std.debug.print("PNG {d} x {d}\n", .{ width, height });

    const wrong = std.mem.readInt(u32, png_ihdr[0..4], .little);
    std.debug.print("same bytes read little-endian: {d}\n", .{wrong});
    const n = std.mem.nativeToBig(u16, 0xABCD);
    std.debug.print("nativeToBig(0xABCD) stored as {x}\n", .{n});
}
big:    01 02 03 04
little: 04 03 02 01
PNG 256 x 192
same bytes read little-endian: 65536
nativeToBig(0xABCD) stored as cdab

The PNG example is real: the image header stores width and height as big-endian 32-bit integers, and bytes[0..4] with a comptime-known range gives the *const [4]u8 that readInt wants. Reading the same bytes little-endian gives nonsense, which is the bug you will meet if you ever cast a byte pointer to *u32 the way C code does. std.mem.nativeToBig and its relatives convert a value in a register; @byteSwap from section 29.2 is the primitive under them.

29.8 Bit sets

When you need a set of small integers, "is unit 12 deployed?", a bit per member is the most compact possible representation, and std.bit_set gives it a proper interface so you do not hand-roll masks. IntegerBitSet(N) is backed by one integer for N up to a machine word; StaticBitSet(N) picks the right implementation for any N; DynamicBitSet allocates.

bitset.zig

const std = @import("std");

pub fn main() void {
    var seen = std.bit_set.IntegerBitSet(16).initEmpty();
    seen.set(3);
    seen.set(7);
    seen.set(12);
    std.debug.print("count {d}, has 7? {}, has 8? {}\n", .{ seen.count(), seen.isSet(7), seen.isSet(8) });
    seen.unset(7);
    seen.toggle(0);
    var it = seen.iterator(.{});
    std.debug.print("set bits:", .{});
    while (it.next()) |i| std.debug.print(" {d}", .{i});
    std.debug.print("\nmask = {b:0>16}\n", .{seen.mask});

    var a = std.bit_set.StaticBitSet(200).initEmpty();
    var b = std.bit_set.StaticBitSet(200).initFull();
    a.set(150);
    b.unset(150);
    const both = a.intersectWith(b);
    std.debug.print("200-bit set: a has {d}, b has {d}, a&b has {d}\n", .{ a.count(), b.count(), both.count() });
    std.debug.print("first set in b: {?d}\n", .{b.findFirstSet()});
}
count 3, has 7? true, has 8? false
set bits: 0 3 12
mask = 0001000000001001
200-bit set: a has 1, b has 199, a&b has 0
first set in b: 0

The operations read like a set: set, unset, toggle, isSet, count, findFirstSet, the set algebra unionWith, intersectWith, differenceWith, and an iterator over the members. For the integer-backed version the mask field is the raw integer, which is what you store in a save file. Exercise 29.3 keeps a lance roster this way.

29.9 Vectors: several numbers at once

Modern CPUs can add four or eight numbers in one instruction. Zig exposes that directly: @Vector(4, i32) is a type holding four i32 values, and the ordinary operators +, *, > work on it element by element. Arrays convert to vectors and back by assignment when the lengths match.

vectors.zig

const std = @import("std");

pub fn main() void {
    const a: @Vector(4, i32) = .{ 1, 2, 3, 4 };
    const b: @Vector(4, i32) = .{ 10, 20, 30, 40 };
    const sum = a + b;
    const prod = a * b;
    std.debug.print("a + b = {any}\n", .{sum});
    std.debug.print("a * b = {any}\n", .{prod});
    std.debug.print("reduce add = {d}, reduce max = {d}\n", .{ @reduce(.Add, prod), @reduce(.Max, prod) });
    const twos: @Vector(4, i32) = @splat(2);
    std.debug.print("a * 2 = {any}\n", .{a * twos});
    const mask = a > twos;
    std.debug.print("a > 2 = {any}\n", .{mask});
    const picked = @select(i32, mask, a, b);
    std.debug.print("select = {any}\n", .{picked});
    const arr: [4]i32 = sum;
    std.debug.print("back to array: {any}, element 2 = {d}\n", .{ arr, sum[2] });
    const f: @Vector(3, f32) = .{ 1.5, 2.5, 3.0 };
    std.debug.print("float sum {d:.1}\n", .{@reduce(.Add, f)});
    const any_big = @reduce(.Or, a > @as(@Vector(4, i32), @splat(3)));
    std.debug.print("any element > 3? {}\n", .{any_big});
}
a + b = { 11, 22, 33, 44 }
a * b = { 10, 40, 90, 160 }
reduce add = 300, reduce max = 160
a * 2 = { 2, 4, 6, 8 }
a > 2 = { false, false, true, true }
select = { 10, 20, 3, 4 }
back to array: { 11, 22, 33, 44 }, element 2 = 33
float sum 7.0
any element > 3? true

Four builtins complete the toolkit. @splat(x) makes a vector with every lane equal to x (the length comes from the expected type). @reduce(op, v) folds a vector to one value with .Add, .Mul, .Min, .Max, .And, .Or or .Xor. Comparing two vectors gives a vector of bool, and @select(T, mask, a, b) picks lanes from a where the mask is true and from b elsewhere; this is how you write "if" without a branch. Indexing with v[2] reads one lane.

Here is the classic use: summing a long slice eight at a time, with a scalar loop for the tail.

vecsum.zig

const std = @import("std");

fn sumScalar(xs: []const u32) u32 {
    var t: u32 = 0;
    for (xs) |x| t += x;
    return t;
}

fn sumVector(xs: []const u32) u32 {
    const N = 8;
    var acc: @Vector(N, u32) = @splat(0);
    var i: usize = 0;
    while (i + N <= xs.len) : (i += N) {
        const chunk: @Vector(N, u32) = xs[i..][0..N].*;
        acc += chunk;
    }
    var t = @reduce(.Add, acc);
    while (i < xs.len) : (i += 1) t += xs[i];
    return t;
}

test "both sums agree" {
    var data: [1003]u32 = undefined;
    for (&data, 0..) |*d, i| d.* = @intCast(i);
    try std.testing.expectEqual(sumScalar(&data), sumVector(&data));
    try std.testing.expectEqual(@as(u32, 1002 * 1003 / 2), sumVector(&data));
}
$ zig test vecsum.zig
1/1 vecsum.test.both sums agree...OK
All 1 tests passed.

The expression xs[i..][0..N].* deserves a look: slicing with a comptime-known length gives a pointer to an array, and .* dereferences it into an array value, which then coerces to the vector. That is the idiom for "load the next N elements".

Should you vectorise? Usually not by hand. Compilers auto-vectorise simple loops in release modes, and a game simulation is rarely bound by arithmetic. Reach for @Vector when you have measured, or when the data is naturally a fixed small tuple: a colour, a position, a set of eight armour locations, as in Exercise 29.4.
In IRON LEDGER. The clearest use of this chapter is the hand-written PNG decoder in game/src/tui/png.zig, which reads emblem images for the terminal client. PNG stores every chunk length and every dimension big-endian, and the decoder walks the chunks exactly as section 29.7 described:

        width = std.mem.readInt(u32, data[0..4], .big);

The file's signature check, std.mem.eql(u8, bytes[0..8], "\x89PNG\r\n\x1a\n"), is the same test Exercise 29.2 asks you to write, and the decoder's test image is baked in with @embedFile("testdata/rgb4x3.png"). Elsewhere the game deliberately avoids clever bit tricks: money is a plain i64, IDs are enums, and the tuning tables are structs, because the day-to-day code is easier to read that way. Bits are for the edges of the program, where bytes arrive from outside.

//! Chapter 29, exercise 1: a status byte as a packed struct.
//! Run with:  zig test ex1_flags.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

/// One byte of pilot status, low bit first. Must fit exactly in a u8.
pub const Status = packed struct(u8) {
    active: bool = false,
    wounded: bool = false,
    veteran: bool = false,
    rank: u3 = 0, // 0..7
    morale: u2 = 1, // 0 = broken, 3 = fanatical

    pub fn toByte(self: Status) u8 {
        return @bitCast(self);
    }
    pub fn fromByte(b: u8) Status {
        return @bitCast(b);
    }
    /// How many of the three boolean flags are set.
    pub fn flagCount(self: Status) u4 {
        const low: u3 = @truncate(self.toByte());
        return @popCount(low);
    }
};

    try std.testing.expectEqual(@as(usize, 6), @bitOffsetOf(Status, "morale"));

Exercise 29.2 · Parse a PNG header practice

Write parseHeader(bytes): check the 8-byte signature, then the IHDR chunk (length 13, big-endian width and height, depth, colour type, interlace flag). Reject bad input with NotPng, Corrupt or Unsupported. File: exercises/29-bits/ex2_png.zig.

Solution 
//! Chapter 29, exercise 2: parse a PNG header by hand.
//! Run with:  zig test ex2_png.zig
//! Goal: make every test pass without changing the tests.
//! Compare with the real decoder in game/src/tui/png.zig.
const std = @import("std");

pub const Error = error{ NotPng, Corrupt, Unsupported };

pub const ColorType = enum(u8) { grey = 0, rgb = 2, palette = 3, grey_alpha = 4, rgba = 6 };

pub const Header = struct {
    width: u32,
    height: u32,
    bit_depth: u8,
    color: ColorType,
    interlaced: bool,

    /// Bytes per pixel for 8-bit images.
    pub fn channels(self: Header) u8 {
        return switch (self.color) {
            .grey, .palette => 1,
            .grey_alpha => 2,
            .rgb => 3,
            .rgba => 4,
        };
    }
};

const signature = "\x89PNG\r\n\x1a\n";

pub fn isPng(bytes: []const u8) bool {
    return bytes.len >= 8 and std.mem.eql(u8, bytes[0..8], signature);
}

/// Parse the 8-byte signature and the IHDR chunk that must follow it:
///   4 bytes length (big-endian, must be 13)
///   4 bytes type ("IHDR")
///   13 bytes data: width u32, height u32, depth u8, color u8, compression u8,
///                  filter u8, interlace u8
///   4 bytes CRC (ignored here)
pub fn parseHeader(bytes: []const u8) Error!Header {
    if (!isPng(bytes)) return error.NotPng;
    if (bytes.len < 8 + 8 + 13 + 4) return error.Corrupt;
    const len = std.mem.readInt(u32, bytes[8..12], .big);
    if (len != 13) return error.Corrupt;
    if (!std.mem.eql(u8, bytes[12..16], "IHDR")) return error.Corrupt;
    const d = bytes[16..29];
    const color_raw = d[9];
    const color: ColorType = switch (color_raw) {
        0 => .grey,
        2 => .rgb,
        3 => .palette,
        4 => .grey_alpha,
        6 => .rgba,
        else => return error.Corrupt,
    };
    const depth = d[8];
    if (depth != 8) return error.Unsupported;
    if (d[10] != 0 or d[11] != 0) return error.Corrupt;
    return .{
        .width = std.mem.readInt(u32, d[0..4], .big),
        .height = std.mem.readInt(u32, d[4..8], .big),
        .bit_depth = depth,
        .color = color,
        .interlaced = d[12] == 1,
    };
}

/// Build a header blob for tests: signature + IHDR chunk with a fake CRC.
fn makePng(w: u32, h: u32, depth: u8, color: u8, interlace: u8) [33]u8 {
    var out: [33]u8 = undefined;
    @memcpy(out[0..8], signature);
    std.mem.writeInt(u32, out[8..12], 13, .big);
    @memcpy(out[12..16], "IHDR");
    std.mem.writeInt(u32, out[16..20], w, .big);
    std.mem.writeInt(u32, out[20..24], h, .big);
    out[24] = depth;
    out[25] = color;
    out[26] = 0;
    out[27] = 0;
    out[28] = interlace;
    @memset(out[29..33], 0);
    return out;
}

test "a 4x3 RGB image" {
    const png = makePng(4, 3, 8, 2, 0);
    const hdr = try parseHeader(&png);
    try std.testing.expectEqual(@as(u32, 4), hdr.width);
    try std.testing.expectEqual(@as(u32, 3), hdr.height);
    try std.testing.expectEqual(ColorType.rgb, hdr.color);
    try std.testing.expectEqual(@as(u8, 3), hdr.channels());
    try std.testing.expect(!hdr.interlaced);
}

test "big-endian really matters" {
    const png = makePng(256, 1, 8, 6, 1);
    const hdr = try parseHeader(&png);
    try std.testing.expectEqual(@as(u32, 256), hdr.width);
    try std.testing.expectEqual(@as(u8, 4), hdr.channels());
    try std.testing.expect(hdr.interlaced);
}

test "rejections" {
    try std.testing.expectError(error.NotPng, parseHeader("hello"));
    var bad = makePng(1, 1, 8, 2, 0);
    bad[13] = 'X';
    try std.testing.expectError(error.Corrupt, parseHeader(&bad));
    try std.testing.expectError(error.Unsupported, parseHeader(&makePng(1, 1, 16, 2, 0)));
    try std.testing.expectError(error.Corrupt, parseHeader(&makePng(1, 1, 8, 5, 0)));
}

Every multi-byte number goes through readInt(…, .big). The test helper makePng builds headers with writeInt, so the tests never depend on a file on disk. Note that std.meta.intToEnum no longer exists in 0.16; a switch on the raw byte is clearer anyway.

Exercise 29.3 · A lance roster as a bit set practice

Using std.bit_set.IntegerBitSet(64), write idle(available, deployed), firstIdle, and toBits/fromBits for saving. File: exercises/29-bits/ex3_bitset.zig.

Solution 
//! Chapter 29, exercise 3: a lance roster as a bit set.
//! Run with:  zig test ex3_bitset.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

pub const max_units = 64;
pub const Roster = std.bit_set.IntegerBitSet(max_units);

/// Units that are in `available` but not in `deployed`.
pub fn idle(available: Roster, deployed: Roster) Roster {
    return available.differenceWith(deployed);
}

/// The lowest-numbered idle unit, if any.
pub fn firstIdle(available: Roster, deployed: Roster) ?usize {
    return idle(available, deployed).findFirstSet();
}

/// Pack the roster into a u64 for a save file, and back.
pub fn toBits(r: Roster) u64 {
    return r.mask;
}
pub fn fromBits(bits: u64) Roster {
    return .{ .mask = bits };
}

test "idle units" {
    var avail = Roster.initEmpty();
    avail.setRangeValue(.{ .start = 0, .end = 8 }, true);
    var dep = Roster.initEmpty();
    dep.set(1);
    dep.set(2);
    dep.set(5);
    const free = idle(avail, dep);
    try std.testing.expectEqual(@as(usize, 5), free.count());
    try std.testing.expect(free.isSet(0) and !free.isSet(1) and free.isSet(7));
    try std.testing.expectEqual(@as(?usize, 0), firstIdle(avail, dep));
    dep.set(0);
    try std.testing.expectEqual(@as(?usize, 3), firstIdle(avail, dep));
}

test "nobody idle" {
    const avail = Roster.initFull();
    const dep = Roster.initFull();
    try std.testing.expectEqual(@as(?usize, null), firstIdle(avail, dep));
}

test "round trip through u64" {
    var r = Roster.initEmpty();
    r.set(0);
    r.set(63);
    const bits = toBits(r);
    try std.testing.expectEqual(@as(u64, 1) | (@as(u64, 1) << 63), bits);
    try std.testing.expect(fromBits(bits).eql(r));
}

differenceWith is "in a but not in b". The backing mask field is a plain u64, so saving is a field read.

Exercise 29.4 · Armour with @Vector practice

Eight armour locations as @Vector(8, u16). Write applyDamage (never below zero), anyBreached, total and weakest. File: exercises/29-bits/ex4_vector.zig.

Solution 
//! Chapter 29, exercise 4: damage rolls with @Vector.
//! Run with:  zig test ex4_vector.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

pub const V = @Vector(8, u16);

/// Armor after damage, per location, never below zero.
pub fn applyDamage(armor: V, damage: V) V {
    // `-|` is saturating subtraction and works element-wise on vectors,
    // so no lane can wrap below zero. @select then shows the same idea
    // spelled out with a mask.
    const zero: V = @splat(0);
    const would_break = damage >= armor;
    return @select(u16, would_break, zero, armor -| damage);
}

/// True if any location was reduced to zero.
pub fn anyBreached(armor: V) bool {
    const zero: V = @splat(0);
    return @reduce(.Or, armor == zero);
}

/// Total armor remaining.
pub fn total(armor: V) u32 {
    var t: u32 = 0;
    const arr: [8]u16 = armor;
    for (arr) |a| t += a;
    return t;
}

/// Index of the weakest location (first one on ties).
pub fn weakest(armor: V) usize {
    const min = @reduce(.Min, armor);
    const arr: [8]u16 = armor;
    for (arr, 0..) |a, i| if (a == min) return i;
    unreachable;
}

test "damage saturates at zero" {
    const armor: V = .{ 10, 10, 10, 10, 10, 10, 10, 10 };
    const dmg: V = .{ 3, 0, 12, 10, 0, 0, 0, 1 };
    const after = applyDamage(armor, dmg);
    const expected: [8]u16 = .{ 7, 10, 0, 0, 10, 10, 10, 9 };
    try std.testing.expectEqual(expected, @as([8]u16, after));
    try std.testing.expect(anyBreached(after));
    try std.testing.expect(!anyBreached(armor));
}

test "totals and weakest" {
    const armor: V = .{ 8, 6, 9, 6, 7, 7, 7, 7 };
    try std.testing.expectEqual(@as(u32, 57), total(armor));
    try std.testing.expectEqual(@as(usize, 1), weakest(armor));
}

Plain armor - damage panics in Debug when a lane would go negative, even if @select would discard that lane. The saturating operator -| works lane by lane and solves it; the mask and @select are kept to show the branch-free idiom.

Exercise 29.5 · RGB565 pixels challenge

Pack 8-bit colour channels into 16 bits both with a packed struct and with shifts and masks, unpack them again with the top bits replicated, and store/load pixels little-endian in a byte buffer. File: exercises/29-bits/ex5_rgb.zig.

Solution 
//! Chapter 29, exercise 5: RGB565 pixels with masks and packed structs.
//! Run with:  zig test ex5_rgb.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

pub const Rgb565 = packed struct(u16) { b: u5, g: u6, r: u5 };

/// Pack 8-bit channels into 16 bits by dropping the low bits.
pub fn pack(r: u8, g: u8, b: u8) u16 {
    const px = Rgb565{ .r = @truncate(r >> 3), .g = @truncate(g >> 2), .b = @truncate(b >> 3) };
    return @bitCast(px);
}

/// Same thing with shifts and masks only, no struct.
pub fn packManual(r: u8, g: u8, b: u8) u16 {
    const r5: u16 = r >> 3;
    const g6: u16 = g >> 2;
    const b5: u16 = b >> 3;
    return (r5 << 11) | (g6 << 5) | b5;
}

/// Expand back to 8-bit channels (top bits replicated so 31 becomes 255).
pub fn unpack(px: u16) [3]u8 {
    const s: Rgb565 = @bitCast(px);
    const r: u8 = (@as(u8, s.r) << 3) | (s.r >> 2);
    const g: u8 = (@as(u8, s.g) << 2) | (s.g >> 4);
    const b: u8 = (@as(u8, s.b) << 3) | (s.b >> 2);
    return .{ r, g, b };
}

/// Write a pixel little-endian into a byte buffer at index i (2 bytes).
pub fn store(buf: []u8, i: usize, px: u16) void {
    std.mem.writeInt(u16, buf[i * 2 ..][0..2], px, .little);
}
pub fn load(buf: []const u8, i: usize) u16 {
    return std.mem.readInt(u16, buf[i * 2 ..][0..2], .little);
}

test "known colours" {
    try std.testing.expectEqual(@as(u16, 0xF800), pack(255, 0, 0));
    try std.testing.expectEqual(@as(u16, 0x07E0), pack(0, 255, 0));
    try std.testing.expectEqual(@as(u16, 0x001F), pack(0, 0, 255));
    try std.testing.expectEqual(@as(u16, 0xFFFF), pack(255, 255, 255));
}

test "both packers agree" {
    var r: u16 = 0;
    while (r < 256) : (r += 37) {
        const c: u8 = @intCast(r);
        try std.testing.expectEqual(packManual(c, 255 - c, c / 2), pack(c, 255 - c, c / 2));
    }
}

test "unpack expands full scale" {
    try std.testing.expectEqual([3]u8{ 255, 0, 0 }, unpack(0xF800));
    try std.testing.expectEqual([3]u8{ 255, 255, 255 }, unpack(0xFFFF));
    try std.testing.expectEqual([3]u8{ 0, 0, 0 }, unpack(0));
}

test "store and load bytes" {
    var buf: [4]u8 = undefined;
    store(&buf, 0, 0xF800);
    store(&buf, 1, 0x001F);
    try std.testing.expectEqual([4]u8{ 0x00, 0xF8, 0x1F, 0x00 }, buf);
    try std.testing.expectEqual(@as(u16, 0x001F), load(&buf, 1));
}

The two packers must agree bit for bit, which is a good test that you understand the packed layout: first field in the lowest bits. Replicating the top bits on unpack is what makes 31 map back to 255 rather than 248.

Check your understanding

  1. What is @sizeOf(u3) and what is @bitSizeOf(u3)?
    Answer1 byte and 3 bits. Stored alone a u3 takes a byte; inside a packed struct it takes three bits.
  2. Why does n << s fail to compile when n is a u8 and s is a u8?
    AnswerThe shift amount for a u8 must be a u3, because shifting by 8 or more is meaningless. Convert with @intCast or @truncate.
  3. In a packed struct(u8), which field occupies bit 0?
    AnswerThe first declared field. Fields fill from the least significant bit upward, with no padding.
  4. What does @bitCast require of its source and destination types?
    AnswerThe same size in bits. It does not convert values; it relabels the bits.
  5. Which layout should a struct passed to a C library use?
    Answerextern struct: declaration order with C padding rules. Auto structs may be reordered and packed structs have no padding.
  6. A PNG width field holds bytes 00 00 01 00. What is the width, and what would readInt(u32, …, .little) give?
    Answer256, because PNG is big-endian. Little-endian reading gives 65536.
  7. What does @reduce(.Or, v > @as(@TypeOf(v), @splat(3))) compute?
    AnswerWhether any lane of v is greater than 3: the comparison yields a vector of booleans and .Or folds them.
  8. Why did armor - damage panic in Exercise 29.4 even though @select discarded the bad lanes?
    AnswerThe subtraction is evaluated for every lane before @select runs, and unsigned underflow is a safety panic. Use saturating -| or wrapping -% when a lane may go out of range.
What you learned.
  • uN/iN exist for any width; @sizeOf, @bitSizeOf and @alignOf measure types.
  • Bit operators plus @popCount, @clz, @ctz, @byteSwap and @bitReverse; print with {b:0>8}.
  • Shift amounts are typed (u3 for a u8); @shlExact asserts nothing is lost, @shlWithOverflow reports it.
  • packed struct(uN) lays fields out bit by bit from the least significant end; @bitCast converts to and from the backing integer for free.
  • Auto structs may be reordered, extern follows C, packed has no padding; @offsetOf shows where fields sit.
  • Use std.mem.readInt/writeInt with an explicit endianness for every multi-byte number that crosses a file or wire.
  • std.bit_set gives sets of small integers with set algebra and iteration.
  • @Vector types support element-wise operators, @splat, @reduce and @select; convert to and from arrays by assignment.
