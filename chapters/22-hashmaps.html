22. Hash maps

In this chapter you will use Zig's hash maps to look things up by key: AutoHashMapUnmanaged for integers and structs, StringHashMapUnmanaged for strings, and the ArrayHashMap family that remembers insertion order. You will learn put, get, getPtr, getOrPut, remove and the iterators, why string keys must outlive the map, which key types work automatically and which do not, and why IRON LEDGER keeps every entity in an ordered map.

22.1 Lookup by key

An ArrayList answers "what is the fifth element". A hash map answers "what is the value for this key", where the key can be a number, a string or a small struct. Python calls it a dict, JavaScript a Map or object, C++ an unordered_map. Internally the map computes a hash of the key, uses it to pick a slot in a table, and stores the key and value there. Lookups take about the same time whether the map holds ten entries or ten million.

Like ArrayList, Zig's maps are unmanaged in 0.16. They start as .empty, every call that might allocate takes the allocator, and deinit(gpa) frees the table. The map stores its keys and values by value, in its own table. What it does not own is anything those values point to, which is the whole subject of 22.5.

22.2 AutoHashMapUnmanaged: integers in, values out

a_auto.zig

const std = @import("std");

pub fn main() !void {
    var gpa_state: std.heap.DebugAllocator(.{}) = .init;
    defer _ = gpa_state.deinit();
    const gpa = gpa_state.allocator();

    // key: unit id, value: tonnage
    var tons: std.AutoHashMapUnmanaged(u32, u32) = .empty;
    defer tons.deinit(gpa);

    try tons.put(gpa, 7, 100); // Atlas
    try tons.put(gpa, 3, 20); // Locust
    try tons.put(gpa, 12, 75); // Marauder

    std.debug.print("count: {d}\n", .{tons.count()});
    std.debug.print("unit 7 weighs {?d}\n", .{tons.get(7)});
    std.debug.print("unit 99 weighs {?d}\n", .{tons.get(99)});
    std.debug.print("has 3? {}  has 4? {}\n", .{ tons.contains(3), tons.contains(4) });

    try tons.put(gpa, 3, 25); // put on an existing key overwrites
    std.debug.print("unit 3 now {?d}\n", .{tons.get(3)});

    const removed = tons.remove(12);
    const removed_again = tons.remove(12);
    std.debug.print("removed: {} then {}, count {d}\n", .{ removed, removed_again, tons.count() });
}
count: 3
unit 7 weighs 100
unit 99 weighs null
has 3? true  has 4? false
unit 3 now 25
removed: true then false, count 2

The name AutoHashMapUnmanaged(K, V) means "a hash map whose hashing and equality for K are worked out automatically". The five calls you will use most:

  • put(gpa, key, value) inserts, or overwrites if the key is already there. It takes the allocator because the table may need to grow.
  • get(key) returns ?V: a copy of the value, or null. Because it is an optional you print it with {?d} and unwrap it with if, orelse or .?, as in Chapter 15.
  • contains(key) is a bool, for when you do not need the value.
  • remove(key) deletes the entry and returns whether there was one. It never allocates.
  • count() is the number of entries.

The map does not preserve any order, and you must not assume one. We will make this visible in 22.4.

22.3 getPtr and getOrPut: changing what is inside

Because get hands back a copy, changing that copy does nothing to the map. To modify a stored value in place you ask for a pointer.

b_getptr.zig

const std = @import("std");

const Unit = struct { name: []const u8, armor: u32 };

pub fn main() !void {
    var gpa_state: std.heap.DebugAllocator(.{}) = .init;
    defer _ = gpa_state.deinit();
    const gpa = gpa_state.allocator();

    var units: std.AutoHashMapUnmanaged(u32, Unit) = .empty;
    defer units.deinit(gpa);
    try units.put(gpa, 1, .{ .name = "Atlas", .armor = 300 });

    // get() returns a COPY of the value.
    if (units.get(1)) |u| {
        var copy = u;
        copy.armor -= 50;
    }
    std.debug.print("after get:    {d}\n", .{units.get(1).?.armor});

    // getPtr() returns a pointer to the value inside the map.
    if (units.getPtr(1)) |u| u.armor -= 50;
    std.debug.print("after getPtr: {d}\n", .{units.get(1).?.armor});

    // getOrPut: one lookup, insert if missing.
    const gop = try units.getOrPut(gpa, 2);
    if (!gop.found_existing) gop.value_ptr.* = .{ .name = "Locust", .armor = 64 };
    gop.value_ptr.armor += 1;
    std.debug.print("unit 2: {s} {d} (existed before? {})\n", .{ gop.value_ptr.name, gop.value_ptr.armor, gop.found_existing });

    const again = try units.getOrPut(gpa, 2);
    std.debug.print("second getOrPut found_existing = {}\n", .{again.found_existing});
}
after get:    300
after getPtr: 250
unit 2: Locust 65 (existed before? false)
second getOrPut found_existing = true

getPtr(key) returns ?*V, a pointer into the table. Write through it and the map changes. The same warning as for lists applies: the pointer is valid only until the next put or getOrPut, because those can rehash and move every entry.

getOrPut(gpa, key) is the workhorse for "insert if missing, then update". It does one hash lookup and returns a small struct with found_existing: bool, key_ptr and value_ptr. If the key was not there, the slot has been reserved but the value is undefined: you must write to value_ptr.* before reading it, which is what the if (!gop.found_existing) line does. Compare the alternative, if (map.get(k)) |v| put(k, v+1) else put(k, 1): two lookups and twice the code. Every counter, tally and index you build will use getOrPut.

22.4 Iterating, and why order matters

There are three iterators, and one important difference between the two map families. Let's put the same five people into an AutoHashMapUnmanaged and an AutoArrayHashMapUnmanaged.

c_iter.zig

const std = @import("std");

pub fn main() !void {
    var gpa_state: std.heap.DebugAllocator(.{}) = .init;
    defer _ = gpa_state.deinit();
    const gpa = gpa_state.allocator();

    var hashed: std.AutoHashMapUnmanaged(u32, []const u8) = .empty;
    defer hashed.deinit(gpa);
    var ordered: std.AutoArrayHashMapUnmanaged(u32, []const u8) = .empty;
    defer ordered.deinit(gpa);

    const names = [_][]const u8{ "Kell", "Natasha", "Grayson", "Morgan", "Jaime" };
    for (names, 0..) |n, i| {
        const id: u32 = @intCast(100 + i * 37);
        try hashed.put(gpa, id, n);
        try ordered.put(gpa, id, n);
    }

    std.debug.print("AutoHashMap iterator:      ", .{});
    var it = hashed.iterator();
    while (it.next()) |e| std.debug.print("{d}={s} ", .{ e.key_ptr.*, e.value_ptr.* });
    std.debug.print("\n", .{});

    std.debug.print("AutoArrayHashMap iterator: ", .{});
    var oit = ordered.iterator();
    while (oit.next()) |e| std.debug.print("{d}={s} ", .{ e.key_ptr.*, e.value_ptr.* });
    std.debug.print("\n", .{});

    std.debug.print("keys() slice:              {any}\n", .{ordered.keys()});
    std.debug.print("keyIterator on hashed:     ", .{});
    var kit = hashed.keyIterator();
    while (kit.next()) |k| std.debug.print("{d} ", .{k.*});
    std.debug.print("\nvalueIterator on hashed:   ", .{});
    var vit = hashed.valueIterator();
    while (vit.next()) |v| std.debug.print("{s} ", .{v.*});
    std.debug.print("\n", .{});
}
AutoHashMap iterator:      211=Morgan 174=Grayson 248=Jaime 137=Natasha 100=Kell 
AutoArrayHashMap iterator: 100=Kell 137=Natasha 174=Grayson 211=Morgan 248=Jaime 
keys() slice:              { 100, 137, 174, 211, 248 }
keyIterator on hashed:     211 174 248 137 100 
valueIterator on hashed:   Morgan Grayson Jaime Natasha Kell

iterator() yields entries with key_ptr and value_ptr (pointers, so dereference with .* or write through them). keyIterator() and valueIterator() yield pointers to just one side. All three work the same on both map types.

Now look at the order. The plain hash map walked the entries in the order of their hash slots, which looks random and will change when the table grows or when the standard library changes its hash function. The array hash map walked them in the order we inserted them. That is its defining feature: it keeps keys and values in two dense arrays, with a hash index on the side pointing into them. Because of that it also offers keys() and values() as plain slices, which you can loop over directly, sort, or hand to any function that takes a slice.

Use AutoArrayHashMapUnmanaged (or the string flavour, StringArrayHashMapUnmanaged) whenever the order of iteration can affect output, and reach for the plain AutoHashMapUnmanaged only when you know you will never iterate, or genuinely do not care. The ordered map costs a little more memory and its remove is slower, but "a program whose output depends on the hash function" is a bug factory. This is not a stylistic preference in IRON LEDGER; the whole determinism story of the game rests on it.

Removing from an array hash map comes in two flavours that mirror the list: swapRemove(key) is fast and moves the last entry into the hole; orderedRemove(key) shifts everything down and keeps the order. There is also orderedRemoveAt(index) when you already have the position, for instance while walking values().

22.5 String keys and who owns them

StringHashMapUnmanaged(V) is a map whose keys are []const u8, hashed by content. The map stores the slice (a pointer and a length), not a copy of the characters. If the bytes the slice points at change or disappear, the map's key silently changes or becomes garbage, and lookups start failing in ways that are very hard to debug.

d_strkeys.zig

const std = @import("std");

pub fn main() !void {
    var gpa_state: std.heap.DebugAllocator(.{}) = .init;
    defer _ = gpa_state.deinit();
    const gpa = gpa_state.allocator();

    var stock: std.StringHashMapUnmanaged(u32) = .empty;
    defer stock.deinit(gpa);

    // Literal keys live in the binary forever: safe to use directly.
    try stock.put(gpa, "medium laser", 4);
    try stock.put(gpa, "LRM-10 ammo", 2);

    // Keys built at runtime must outlive the map. This one is on the stack...
    var buf: [32]u8 = undefined;
    const temp = try std.fmt.bufPrint(&buf, "{s} {d}", .{ "SRM", 6 });
    // ...so we copy it to the heap and let the MAP own the copy.
    try stock.put(gpa, try gpa.dupe(u8, temp), 9);
    @memset(&buf, 'x'); // scribble on the stack buffer; the map does not care

    std.debug.print("SRM 6: {?d}\n", .{stock.get("SRM 6")});
    std.debug.print("medium laser: {?d}\n", .{stock.get("medium laser")});

    // Free the keys we duped before the map goes away.
    var kit = stock.keyIterator();
    while (kit.next()) |k| {
        if (std.mem.startsWith(u8, k.*, "SRM")) gpa.free(k.*);
    }
}
SRM 6: 9
medium laser: 4

The literal keys are fine: string literals live in the executable for the whole run. The third key was built into a stack buffer with bufPrint, and that buffer is reused and overwritten a few lines later. Had we stored temp directly, the key would now read "xxxxx". Instead we store gpa.dupe(u8, temp), a heap copy that lives until we free it, and since the map is now the only thing that knows about that copy, we free it by walking the keys before deinit.

Rule. A string key must outlive the map. Three safe sources: a string literal; a slice into a buffer that you know lives longer than the map (a file's contents you read once, for example); or a copy made with allocator.dupe that you free when the entry goes. When in doubt, dupe, and use an arena so the frees take care of themselves.

The same rule applies to string values, and to any pointer or slice inside a value struct. The map copies the struct; it does not copy what the struct points at.

22.6 Which keys work automatically

"Auto" hashing looks at the bytes of the key. That works for integers, enums, bools and for structs and arrays built from those, so a coordinate struct is a fine key:

e_structkey.zig

const std = @import("std");

const Hex = struct { q: i16, r: i16 };

pub fn main() !void {
    var gpa_state: std.heap.DebugAllocator(.{}) = .init;
    defer _ = gpa_state.deinit();
    const gpa = gpa_state.allocator();

    var terrain: std.AutoHashMapUnmanaged(Hex, []const u8) = .empty;
    defer terrain.deinit(gpa);

    try terrain.put(gpa, .{ .q = 0, .r = 0 }, "clear");
    try terrain.put(gpa, .{ .q = 1, .r = -1 }, "woods");

    std.debug.print("{?s} {?s} {?s}\n", .{
        terrain.get(.{ .q = 1, .r = -1 }),
        terrain.get(.{ .q = 0, .r = 0 }),
        terrain.get(.{ .q = 5, .r = 5 }),
    });
}
woods clear null

What it refuses is a key that contains a slice. Hashing a slice by its bytes would hash the pointer and length, not the contents, so two equal strings at different addresses would be different keys. Rather than guess, the compiler stops you:

The message tells you the fix: for []const u8 keys use StringHashMapUnmanaged. For anything more exotic (a struct with a string inside it, case-insensitive matching, floats) you write your own context type with hash and eql functions and use std.HashMapUnmanaged(K, V, Context, load_percentage) directly. You will rarely need that; in IRON LEDGER, every key is either an integer-backed enum ID or a string.

22.7 An ID to entity registry

Here is the pattern that the whole game is built on: entities live in an ordered map keyed by a typed ID (a non-exhaustive enum, from Chapter 13), and every other part of the program refers to them by ID, never by pointer.

f_registry.zig

const std = @import("std");

const UnitId = enum(u32) { _ };
const Unit = struct { name: []const u8, armor: u32, destroyed: bool = false };

const Hangar = struct {
    units: std.AutoArrayHashMapUnmanaged(UnitId, Unit) = .empty,
    next_id: u32 = 1,

    fn deinit(self: *Hangar, gpa: std.mem.Allocator) void {
        self.units.deinit(gpa);
    }

    fn add(self: *Hangar, gpa: std.mem.Allocator, name: []const u8, armor: u32) !UnitId {
        const id: UnitId = @enumFromInt(self.next_id);
        self.next_id += 1;
        try self.units.putNoClobber(gpa, id, .{ .name = name, .armor = armor });
        return id;
    }

    fn unit(self: *Hangar, id: UnitId) ?*Unit {
        return self.units.getPtr(id);
    }

    fn scrap(self: *Hangar, id: UnitId) bool {
        return self.units.orderedRemove(id);
    }
};

pub fn main() !void {
    var gpa_state: std.heap.DebugAllocator(.{}) = .init;
    defer _ = gpa_state.deinit();
    const gpa = gpa_state.allocator();

    var h: Hangar = .{};
    defer h.deinit(gpa);

    const atlas = try h.add(gpa, "Atlas", 300);
    const locust = try h.add(gpa, "Locust", 64);
    _ = try h.add(gpa, "Marauder", 230);

    if (h.unit(locust)) |u| u.armor = 0;
    if (h.unit(locust)) |u| u.destroyed = u.armor == 0;
    std.debug.print("scrapped locust? {}\n", .{h.scrap(locust)});
    std.debug.print("scrapped again?  {}\n", .{h.scrap(locust)});
    std.debug.print("atlas still there? {}\n", .{h.unit(atlas) != null});

    // Deterministic order: insertion order, minus what was removed.
    for (h.units.keys(), h.units.values()) |id, u| {
        std.debug.print("  #{d} {s: <9} armor {d}\n", .{ @intFromEnum(id), u.name, u.armor });
    }
}
scrapped locust? true
scrapped again?  false
atlas still there? true
  #1 Atlas     armor 300
  #3 Marauder  armor 230

Why IDs rather than pointers? Because the map can move its entries. Store a *Unit somewhere and it is stale after the next add. Store a UnitId and you can always ask the hangar for a fresh pointer with unit(id), use it briefly, and let it go. The ?*Unit return type also handles the case where the unit has been scrapped: you get null, not a crash. putNoClobber is put that asserts the key is new, which documents the intent that IDs are never reused.

The final loop uses keys() and values() together in one for: both are slices of the same length, so the multi-object for from Chapter 6 walks them in lockstep. That only works because this is an array hash map.

Exercise 22.1 · Inventory warm-up

Complete an Inventory wrapping AutoHashMapUnmanaged(u32, u32): stock adds (creating the entry with getOrPut), take removes if there is enough and deletes the key when the count reaches zero, onHand returns zero for unknown parts. Name the file: exercises/22-hashmaps/ex1_inventory.zig.

Solution 
//! Chapter 22, exercise 1: a parts inventory keyed by part number.
//! Run with:  zig test ex1_inventory.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Inventory = struct {
    parts: std.AutoHashMapUnmanaged(u32, u32) = .empty,

    fn deinit(self: *Inventory, gpa: std.mem.Allocator) void {
        self.parts.deinit(gpa);
    }

    /// Add `n` of part `id` (creating the entry if needed).
    fn stock(self: *Inventory, gpa: std.mem.Allocator, id: u32, n: u32) !void {
        const gop = try self.parts.getOrPut(gpa, id);
        if (!gop.found_existing) gop.value_ptr.* = 0;
        gop.value_ptr.* += n;
    }

    /// Take `n` of part `id`. Returns false (and changes nothing) if there are not enough.
    /// When the count hits zero the entry is removed.
    fn take(self: *Inventory, id: u32, n: u32) bool {
        const p = self.parts.getPtr(id) orelse return false;
        if (p.* < n) return false;
        p.* -= n;
        if (p.* == 0) _ = self.parts.remove(id);
        return true;
    }

    fn onHand(self: Inventory, id: u32) u32 {
        return self.parts.get(id) orelse 0;
    }
};

test "stock and take" {
    const a = std.testing.allocator;
    var inv: Inventory = .{};
    defer inv.deinit(a);
    try inv.stock(a, 100, 3);
    try inv.stock(a, 100, 2);
    try inv.stock(a, 200, 1);
    try std.testing.expectEqual(@as(u32, 5), inv.onHand(100));
    try std.testing.expect(inv.take(100, 4));
    try std.testing.expect(!inv.take(100, 4));
    try std.testing.expectEqual(@as(u32, 1), inv.onHand(100));
    try std.testing.expectEqual(@as(u32, 0), inv.onHand(999));
}

test "taking the last one removes the key" {
    const a = std.testing.allocator;
    var inv: Inventory = .{};
    defer inv.deinit(a);
    try inv.stock(a, 7, 1);
    try std.testing.expect(inv.take(7, 1));
    try std.testing.expect(!inv.parts.contains(7));
    try std.testing.expectEqual(@as(u32, 0), inv.parts.count());
}

take uses getPtr so it can decrement in place, and orelse return false handles the missing key. Note onHand takes self by value: it only reads, and get does not need a pointer to the map.

Exercise 22.2 · Word count practice

Write wordCounts(gpa, text): tokenize on spaces, tabs and newlines, count each word in a StringHashMapUnmanaged(u32), then return an owned slice of { word, n } sorted by count descending and word ascending. The words are slices into text, so no duping is needed here; say in a comment why that is safe. Name the file: exercises/22-hashmaps/ex2_wordcount.zig.

Solution 
//! Chapter 22, exercise 2: count words.
//! Run with:  zig test ex2_wordcount.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Count = struct { word: []const u8, n: u32 };

/// Count each whitespace-separated word in `text`. The words are slices into `text`,
/// so the returned array is valid as long as `text` is.
/// Results are sorted by count descending, then word ascending.
fn wordCounts(gpa: std.mem.Allocator, text: []const u8) ![]Count {
    var map: std.StringHashMapUnmanaged(u32) = .empty;
    defer map.deinit(gpa);

    var it = std.mem.tokenizeAny(u8, text, " \t\n");
    while (it.next()) |w| {
        const gop = try map.getOrPut(gpa, w);
        if (!gop.found_existing) gop.value_ptr.* = 0;
        gop.value_ptr.* += 1;
    }

    var out: std.ArrayList(Count) = .empty;
    errdefer out.deinit(gpa);
    var mit = map.iterator();
    while (mit.next()) |e| try out.append(gpa, .{ .word = e.key_ptr.*, .n = e.value_ptr.* });

    std.mem.sort(Count, out.items, {}, struct {
        fn lt(_: void, a: Count, b: Count) bool {
            if (a.n != b.n) return a.n > b.n;
            return std.mem.lessThan(u8, a.word, b.word);
        }
    }.lt);
    return out.toOwnedSlice(gpa);
}

test "counts" {
    const text = "the mech the pilot the lance\nmech pilot";
    const counts = try wordCounts(std.testing.allocator, text);
    defer std.testing.allocator.free(counts);
    try std.testing.expectEqual(@as(usize, 4), counts.len);
    try std.testing.expectEqualStrings("the", counts[0].word);
    try std.testing.expectEqual(@as(u32, 3), counts[0].n);
    try std.testing.expectEqualStrings("mech", counts[1].word);
    try std.testing.expectEqualStrings("pilot", counts[2].word);
    try std.testing.expectEqualStrings("lance", counts[3].word);
}

test "empty text" {
    const counts = try wordCounts(std.testing.allocator, "   \n ");
    defer std.testing.allocator.free(counts);
    try std.testing.expectEqual(@as(usize, 0), counts.len);
}

The keys point into text, which the caller keeps alive, so the map never owns anything and a plain deinit is enough. The map is only a scratch structure; the ordered result comes from copying into a list and sorting with a custom lessThan, which Chapter 24 covers in depth.

Exercise 22.3 · Invert practice

Given an AutoArrayHashMapUnmanaged(u32, []const u8) from pilot ID to callsign, build the reverse StringArrayHashMapUnmanaged(u32). Return error.Duplicate if two pilots share a callsign, without leaking. Name the file: exercises/22-hashmaps/ex3_invert.zig.

Solution 
//! Chapter 22, exercise 3: invert a map.
//! Run with:  zig test ex3_invert.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Callsigns = std.AutoArrayHashMapUnmanaged(u32, []const u8); // pilot id -> callsign
const ByCallsign = std.StringArrayHashMapUnmanaged(u32); // callsign -> pilot id

/// Build the reverse map. If two pilots share a callsign, return error.Duplicate.
/// The callsign strings are shared with the input map, not copied.
fn invert(gpa: std.mem.Allocator, in: Callsigns) !ByCallsign {
    var out: ByCallsign = .empty;
    errdefer out.deinit(gpa);
    var it = in.iterator();
    while (it.next()) |e| {
        const gop = try out.getOrPut(gpa, e.value_ptr.*);
        if (gop.found_existing) return error.Duplicate;
        gop.value_ptr.* = e.key_ptr.*;
    }
    return out;
}

Exercise 22.4 · Registry challenge

Build a Registry like the game's: AutoArrayHashMapUnmanaged(PersonId, Person) with hire (fresh ID, putNoClobber), person(id) ?*Person, mission() which increments every active person's mission count in place, and bury() which removes every kia entry while keeping the order of the rest. Name the file: exercises/22-hashmaps/ex4_registry.zig.

Solution 
//! Chapter 22, exercise 4: an ID -> entity registry, like GameState.people.
//! Run with:  zig test ex4_registry.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const PersonId = enum(u32) { _ };
const Status = enum { active, wounded, kia };
const Person = struct { name: []const u8, status: Status = .active, missions: u32 = 0 };

const Registry = struct {
    people: std.AutoArrayHashMapUnmanaged(PersonId, Person) = .empty,
    next: u32 = 1,

    fn deinit(self: *Registry, gpa: std.mem.Allocator) void {
        self.people.deinit(gpa);
    }

    fn hire(self: *Registry, gpa: std.mem.Allocator, name: []const u8) !PersonId {
        const id: PersonId = @enumFromInt(self.next);
        self.next += 1;
        try self.people.putNoClobber(gpa, id, .{ .name = name });
        return id;
    }

    fn person(self: *Registry, id: PersonId) ?*Person {
        return self.people.getPtr(id);
    }

    /// Every active person flies one mission. Returns how many flew.
    fn mission(self: *Registry) u32 {
        var flew: u32 = 0;
        for (self.people.values()) |*p| {
            if (p.status != .active) continue;
            p.missions += 1;
            flew += 1;
        }
        return flew;
    }

    /// Remove everyone with status kia, keeping the order of the rest.
    /// Returns how many were removed.
    fn bury(self: *Registry) u32 {
        var removed: u32 = 0;
        var i: usize = 0;
        while (i < self.people.count()) {
            if (self.people.values()[i].status == .kia) {
                self.people.orderedRemoveAt(i);
                removed += 1;
            } else i += 1;
        }
        return removed;
    }
};

test "hire, look up, mutate" {
    const a = std.testing.allocator;
    var r: Registry = .{};
    defer r.deinit(a);
    const kell = try r.hire(a, "Kell");
    const nat = try r.hire(a, "Natasha");
    try std.testing.expect(r.person(kell) != null);
    try std.testing.expect(r.person(@enumFromInt(999)) == null);
    r.person(nat).?.status = .wounded;
    try std.testing.expectEqual(@as(u32, 1), r.mission());
    try std.testing.expectEqual(@as(u32, 1), r.person(kell).?.missions);

}

    const p2 = try r.hire(a, "two");

Exercise 22.5 · Group by, owning the keys challenge

Build Groups: a StringArrayHashMapUnmanaged from role to an ArrayList([]const u8) of names. The role passed to add is a temporary buffer that will be overwritten, so the map must dupe the key on first insert and free every key and list in deinit. Name the file: exercises/22-hashmaps/ex5_groupby.zig.

Solution 
//! Chapter 22, exercise 5: group names by role, owning the keys.
//! Run with:  zig test ex5_groupby.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Groups = struct {
    map: std.StringArrayHashMapUnmanaged(std.ArrayList([]const u8)) = .empty,

    /// Free every duped key and every list, then the map.
    fn deinit(self: *Groups, gpa: std.mem.Allocator) void {
        for (self.map.keys(), self.map.values()) |k, *list| {
            gpa.free(k);
            list.deinit(gpa);
        }
        self.map.deinit(gpa);
    }

    /// `role` may be a temporary; the map must own its own copy of the key.
    fn add(self: *Groups, gpa: std.mem.Allocator, role: []const u8, name: []const u8) !void {
        const gop = try self.map.getOrPut(gpa, role);
        if (!gop.found_existing) {
            gop.key_ptr.* = try gpa.dupe(u8, role);
            gop.value_ptr.* = .empty;
        }
        try gop.value_ptr.append(gpa, name);
    }

    fn members(self: Groups, role: []const u8) []const []const u8 {
        const list = self.map.get(role) orelse return &.{};
        return list.items;
    }
};

test "group by role with temporary keys" {
    const a = std.testing.allocator;
    var g: Groups = .{};
    defer g.deinit(a);

    var buf: [16]u8 = undefined;
    const rows = [_]struct { role: []const u8, name: []const u8 }{
        .{ .role = "pilot", .name = "Kell" },
        .{ .role = "tech", .name = "Sato" },
        .{ .role = "pilot", .name = "Natasha" },
    };
    for (rows) |r| {
        // Build the key in a reused buffer so it is definitely temporary.
        const key = try std.fmt.bufPrint(&buf, "{s}", .{r.role});
        try g.add(a, key, r.name);
        @memset(&buf, 0);
    }
    try std.testing.expectEqual(@as(usize, 2), g.members("pilot").len);
    try std.testing.expectEqualStrings("Natasha", g.members("pilot")[1]);
    try std.testing.expectEqual(@as(usize, 1), g.members("tech").len);
    try std.testing.expectEqual(@as(usize, 0), g.members("medic").len);
    try std.testing.expectEqualStrings("pilot", g.map.keys()[0]);
}

The trick is gop.key_ptr.* = try gpa.dupe(u8, role): getOrPut looked the key up using the temporary, and now we replace the stored key with a copy we own. The test scribbles over the buffer after each insert to prove the map is not looking at it any more.

Check your understanding

  1. What does get return, and what does that mean for changing the value?
    Answer?V, a copy of the value or null. Changing the copy does not change the map; use getPtr for that.
  2. After const gop = try map.getOrPut(gpa, k); with found_existing == false, what is in gop.value_ptr.*?
    AnswerUndefined memory. You must assign to it before reading it.
  3. When would you pick AutoArrayHashMapUnmanaged over AutoHashMapUnmanaged?
    AnswerWhenever you iterate and the order can affect anything observable (output, event order, determinism), or when you want keys()/values() as slices. The plain map is for pure lookup tables.
  4. Why can't AutoHashMapUnmanaged([]const u8, V) compile?
    AnswerAuto hashing works on the key's bytes, and for a slice that is the pointer and length, not the characters. The compiler rejects it and points you to StringHashMapUnmanaged, which hashes contents.
  5. You build a key with bufPrint into a stack buffer and put it into a string map that outlives the function. What goes wrong and how do you fix it?
    AnswerThe map stores a slice pointing at the stack buffer, which is gone (or reused) after the function returns; lookups become garbage. Fix: gpa.dupe(u8, key) and free the copies when the entries go (or use an arena).
  6. Is a pointer from getPtr still valid after a put of a different key?
    AnswerNot necessarily. The insert may grow and rehash the table, moving every entry. Re-fetch the pointer after any insert.
  7. Why does IRON LEDGER pass around PersonId values instead of *Person?
    AnswerEntries in the map can move when it grows and can be removed; an ID is always safe to hold and can be turned into a fresh ?*Person on demand, with null when the person is gone.
What you learned.
  • Maps are unmanaged: .empty, allocator on every inserting call, deinit(gpa) frees the table only.
  • put, get (copy, optional), getPtr (pointer, optional), getOrPut (one lookup, found_existing, undefined value when new), remove, contains, count.
  • iterator, keyIterator, valueIterator give pointers; array maps also give keys() and values() slices and iterate in insertion order.
  • Plain hash maps iterate in an order you must not rely on; use the array flavour whenever order matters.
  • String keys are slices: they must outlive the map, so dupe anything temporary and free it yourself.
  • Auto hashing handles integers, enums and plain structs; slices need StringHashMapUnmanaged or a custom context.
  • Keep entities in a map keyed by a typed ID, and hand out IDs, not pointers.
