12. Structs and methods

In this chapter you will group related values into a struct, give fields default values, attach functions to the type and call them with dot syntax, and learn the one decision that matters most about a method: whether it takes self by value or by pointer. You will also nest structs, compare them, meet tuples, and teach a struct how to print itself.

12.1 Grouping values

A pilot has a name and two skill numbers. Passing those around as three separate values gets old fast; a struct bundles them under one name.

basics.zig

const std = @import("std");

const Pilot = struct {
    name: []const u8,
    gunnery: u8,
    piloting: u8,
};

pub fn main() void {
    const kai = Pilot{ .name = "Kai Allard", .gunnery = 2, .piloting = 3 };
    std.debug.print("{s}: {d}/{d}\n", .{ kai.name, kai.gunnery, kai.piloting });

    var rookie: Pilot = .{ .name = "Rookie", .gunnery = 5, .piloting = 6 };
    rookie.gunnery -= 1; // fields of a var struct can change
    std.debug.print("{s}: {d}/{d}\n", .{ rookie.name, rookie.gunnery, rookie.piloting });
}
Kai Allard: 2/3
Rookie: 4/6

The declaration const Pilot = struct { ... }; makes a new type. Each line inside is a field: a name, a colon, a type. Zig types are values, so a type is declared with const like anything else, and by convention type names are capitalised.

To make a value, write the type name followed by braces and every field with a leading dot: Pilot{ .name = ..., .gunnery = ..., .piloting = ... }. You read fields with a dot, kai.name, and if the variable is a var you can assign to them.

The second value uses the form you will see most: a type on the left of the colon and an anonymous literal .{ ... } on the right. The dot-brace literal has no type of its own; it takes whatever type the context expects. You have been using it since Chapter 2, where the arguments to print are a .{ ... } that becomes a tuple.

Every field must be given a value. Leave one out and the compiler tells you which:

12.2 Default values

A field can carry a default, written after = in the declaration. Then it may be omitted from the literal.

defaults.zig

const std = @import("std");

const Pilot = struct {
    name: []const u8,
    gunnery: u8 = 4, // the "green" defaults
    piloting: u8 = 5,
    injured: bool = false,
};

pub fn main() void {
    const a = Pilot{ .name = "Kai" };
    const b = Pilot{ .name = "Nat", .gunnery = 2 };
    std.debug.print("{s}: {d}/{d} injured={}\n", .{ a.name, a.gunnery, a.piloting, a.injured });
    std.debug.print("{s}: {d}/{d} injured={}\n", .{ b.name, b.gunnery, b.piloting, b.injured });
    std.debug.print("{any}\n", .{a});
}
Kai: 4/5 injured=false
Nat: 2/5 injured=false
.{ .name = { 75, 97, 105 }, .gunnery = 4, .piloting = 5, .injured = false }

name has no default and must be supplied; the other three are optional in the literal. When every field has a default, Pilot{} is a complete value. IRON LEDGER's GameState has about forty fields, most with defaults, so that init only has to set the few that depend on the configuration.

The last line prints the whole struct with {any}. Handy for debugging, with one surprise: the name came out as { 75, 97, 105 }. A []const u8 is a slice of bytes, and {any} does not know it is text. Section 12.9 fixes that.

12.3 Methods

A struct can contain functions as well as fields. A function whose first parameter is the struct type can be called with dot syntax, and that is all a "method" is in Zig: a namespaced function with a convenient call form.

methods.zig

const std = @import("std");

const Pilot = struct {
    name: []const u8,
    gunnery: u8 = 4,
    piloting: u8 = 5,
    xp: u32 = 0,

    /// Reads only: self is a copy.
    pub fn skillTotal(self: Pilot) u8 {
        return self.gunnery + self.piloting;
    }

    /// Mutates: self is a pointer to the caller's value.
    pub fn train(self: *Pilot, points: u32) void {
        self.xp += points;
        if (self.xp >= 10 and self.gunnery > 0) {
            self.gunnery -= 1;
            self.xp -= 10;
        }
    }
};

pub fn main() void {
    var kai = Pilot{ .name = "Kai", .gunnery = 3 };
    std.debug.print("total {d}\n", .{kai.skillTotal()});
    kai.train(6);
    kai.train(6);
    std.debug.print("gunnery {d}, xp {d}\n", .{ kai.gunnery, kai.xp });
    std.debug.print("total {d}\n", .{Pilot.skillTotal(kai)}); // the same call, spelled out
}
total 8
gunnery 2, xp 2
total 7

Two methods, two different first parameters, and the difference is the heart of this chapter.

skillTotal(self: Pilot) takes the struct by value. self is a copy of kai. The function can read it, and it could even modify its copy (after copying into a var), but the caller's kai is untouched. This is the right choice for anything that only reads.

train(self: *Pilot, ...) takes a pointer to the struct. self is the address of kai, and self.xp += points writes into the caller's value. Zig lets you write self.xp rather than self.*.xp; field access through a pointer follows the pointer automatically (there is no -> as in C).

The last line shows there is no magic: kai.skillTotal() is exactly Pilot.skillTotal(kai). The dot form passes the thing before the dot as the first argument. For kai.train(6) Zig passes &kai, because the parameter is a pointer.

12.4 @This() and namespaced declarations

Besides fields and methods, a struct can hold constants and plain functions. They live in the struct's namespace and are reached with Type.name.

this.zig

const std = @import("std");

const Money = struct {
    cbills: i64,

    const Self = @This();

    pub const zero: Self = .{ .cbills = 0 };
    pub const bp_scale: i64 = 10_000;

    pub fn fromThousands(k: i64) Self {
        return .{ .cbills = k * 1000 };
    }

    pub fn applyBp(self: Self, bp: i64) Self {
        return .{ .cbills = @divTrunc(self.cbills * bp, bp_scale) };
    }

    pub fn add(self: *Self, other: Self) void {
        self.cbills += other.cbills;
    }
};

pub fn main() void {
    var funds = Money.fromThousands(500);
    funds.add(Money.zero);
    funds.add(.{ .cbills = 250 });
    const with_bonus = funds.applyBp(12_500); // times 1.25
    std.debug.print("{d} -> {d}\n", .{ funds.cbills, with_bonus.cbills });
}
500250 -> 625312

@This() returns the type currently being defined. Writing const Self = @This(); at the top of a struct lets the methods say Self instead of repeating the type's name, which pays off when the name is long or when the struct is anonymous or generated (Chapter 26). Money.zero is a constant of the type stored inside the type. fromThousands has no self; it is a plain function that happens to live in Money, and it plays the role a constructor plays elsewhere. Note the call funds.add(.{ .cbills = 250 }): the anonymous literal becomes a Money because that is the parameter type.

The @divTrunc is Zig insisting you say which kind of integer division you mean (Chapter 4); IRON LEDGER's applyBp in src/domain/types.zig is this exact function.

12.5 Nested structs

A field's type can be another struct, named or written inline:

nested.zig

const std = @import("std");

const Date = struct { year: u16, month: u8, day: u8 };

const Contract = struct {
    name: []const u8,
    start: Date,
    end: Date,
    pay: struct { advance: i64, monthly: i64 }, // an inline anonymous struct type
};

pub fn main() void {
    const c = Contract{
        .name = "Garrison duty",
        .start = .{ .year = 3025, .month = 1, .day = 1 },
        .end = .{ .year = 3025, .month = 7, .day = 1 },
        .pay = .{ .advance = 100_000, .monthly = 45_000 },
    };
    std.debug.print("{s}: {d}/{d} to {d}/{d}, {d}/month\n", .{
        c.name, c.start.month, c.start.year, c.end.month, c.end.year, c.pay.monthly,
    });
}
Garrison duty: 1/3025 to 7/3025, 45000/month

Nested literals stay anonymous: .start = .{ .year = 3025, ... } becomes a Date because the field is a Date. The pay field uses an inline struct type, which is fine for a one-off grouping; give it a name the moment a second place needs it. Access chains with dots: c.pay.monthly.

12.6 Structs are values; pointers reach in

Like arrays, structs copy on assignment:

copy.zig

const std = @import("std");

const Pilot = struct { name: []const u8, hp: u8 };

pub fn main() void {
    const a = Pilot{ .name = "Kai", .hp = 10 };
    var b = a; // a copy of both fields
    b.hp = 0;
    std.debug.print("a.hp={d} b.hp={d}\n", .{ a.hp, b.hp });
}
a.hp=10 b.hp=0

Note that copying the struct copied the slice name, not the bytes it points at; both values still point at the same "Kai". A struct holding slices or pointers is a shallow copy, the same as in C or Go.

To share a struct rather than copy it, pass a pointer, and read fields through it without any extra syntax:

ptr_access.zig

const std = @import("std");

const Pilot = struct { name: []const u8, hp: u8 };

fn wound(p: *Pilot, dmg: u8) void {
    p.hp -|= dmg; // no arrow, no explicit deref: Zig follows the pointer for you
    std.debug.print("{s} now at {d}\n", .{ p.name, p.hp });
}

pub fn main() void {
    var kai = Pilot{ .name = "Kai", .hp = 10 };
    const ptr = &kai;
    wound(ptr, 3);
    wound(&kai, 30);
    std.debug.print("{d} {d}\n", .{ kai.hp, ptr.*.hp }); // ptr.*.hp is the long form
}
Kai now at 7
Kai now at 0
0 0

p.hp on a *Pilot reads the caller's hp; ptr.*.hp is the same thing spelled out. -|= is saturating subtraction so the second wound stops at zero instead of panicking on underflow.

12.8 Tuples, briefly

A tuple is a struct whose fields are numbered instead of named. You have been making them all along: .{ 1, "x" } is a tuple literal. They are the natural way to return two values.

tuples.zig

const std = @import("std");

fn minMax(xs: []const i32) struct { i32, i32 } {
    var lo = xs[0];
    var hi = xs[0];
    for (xs) |x| {
        if (x < lo) lo = x;
        if (x > hi) hi = x;
    }
    return .{ lo, hi };
}

pub fn main() void {
    const pair = minMax(&[_]i32{ 4, -2, 9, 0 });
    std.debug.print("min {d}, max {d}\n", .{ pair[0], pair[1] });
    const lo, const hi = minMax(&[_]i32{ 7, 3 }); // destructuring
    std.debug.print("{d} {d}\n", .{ lo, hi });
    std.debug.print("{any}\n", .{pair});
}
min -2, max 9
3 7
.{ -2, 9 }

struct { i32, i32 } declares a tuple type with two i32 fields; you index it with [0] and [1], and you can pull it apart into two names in one const lo, const hi = ... statement. If the two values have different meanings, prefer a named struct: struct { lo: i32, hi: i32 } costs nothing more and reads better six months later.

12.9 Printing a struct: {any} and a format method

{any} prints every field, which is fine for debugging and wrong for users. A struct can define how it prints by providing a method named format. In Zig 0.16 the signature is fixed:

pub fn format(self: T, w: *std.Io.Writer) std.Io.Writer.Error!void

It receives a writer, the same interface as stdout and fixed buffers, and prints whatever it likes to it. You then ask for it with the {f} specifier:

format.zig

const std = @import("std");

const Date = struct {
    year: u16,
    month: u8,
    day: u8,

    pub fn format(self: Date, w: *std.Io.Writer) std.Io.Writer.Error!void {
        try w.print("{d:0>4}-{d:0>2}-{d:0>2}", .{ self.year, self.month, self.day });
    }
};

const Plain = struct { year: u16, month: u8, day: u8 };

pub fn main() !void {
    const d = Date{ .year = 3025, .month = 3, .day = 7 };
    const p = Plain{ .year = 3025, .month = 3, .day = 7 };
    std.debug.print("{any}\n", .{p});
    std.debug.print("{f}\n", .{d});
    var buf: [32]u8 = undefined;
    const s = try std.fmt.bufPrint(&buf, "start {f}", .{d});
    std.debug.print("{s}\n", .{s});
}
.{ .year = 3025, .month = 3, .day = 7 }
3025-03-07
start 3025-03-07

{f} works anywhere a format string does: std.debug.print, bufPrint, a file writer. This is how a Date can print as 3025-03-07 in one place and be a plain three-field struct everywhere else.

{any} ignores your format. In 0.16, {any} (and a bare {}) always print the raw fields, even when the type has a format method: 
const std = @import("std");

const Date = struct {
    year: u16,
    month: u8,
    day: u8,
    pub fn format(self: Date, w: *std.Io.Writer) std.Io.Writer.Error!void {
        try w.print("{d}-{d}-{d}", .{ self.year, self.month, self.day });
    }
};

pub fn main() void {
    const d = Date{ .year = 3025, .month = 3, .day = 7 };
    std.debug.print("{any}\n", .{d});
}
.{ .year = 3025, .month = 3, .day = 7 }

Only {f} calls your method. Older Zig picked the method up automatically, so older code and tutorials write {} and expect the custom output; in 0.16 that prints fields. If your nicely formatted struct comes out as .{ .year = ... }, change the specifier to {f}.

In IRON LEDGER. The campaign calendar is a small, complete struct: fields, a namespaced constant, plain functions, a by-value method that returns a new value, and a predicate. It is the shape you should copy for your own small value types: 
// src/sim/clock.zig
pub const Date = struct {
    year: u16,
    month: u8, // 1-12
    day: u8, // 1-31

    pub const campaign_default: Date = .{ .year = 3025, .month = 1, .day = 1 };

    pub fn isLeapYear(year: u16) bool {
        return (year % 4 == 0 and year % 100 != 0) or year % 400 == 0;
    }

    pub fn next(self: Date) Date {
        var d = self;
        d.day += 1;
        if (d.day > daysInMonth(d.year, d.month)) {
            d.day = 1;
            d.month += 1;
            if (d.month > 12) {
                d.month = 1;
                d.year += 1;
            }
        }
        return d;
    }

    pub fn isPayday(self: Date) bool {
        return self.day == 1;
    }
};

next copies self into a var, changes the copy and returns it; nothing is mutated in place, by choice. The other style lives in src/sim/state.zig, where GameState has forty-odd fields, most with defaults, and every method takes self: *GameState because a game state is far too large to copy and is meant to change. Both are correct; the size and the intent decide.

Exercise 12.1 · A Date with methods warm-up

Complete IRON LEDGER's Date: isLeapYear, daysInMonth, a by-value next and a by-pointer advance that reuses it. The tests are the game's own, plus one for advance. Name the file: exercises/12-structs/ex1_date.zig.

Solution 
//! Chapter 12, exercise 1: a Date struct with methods.
//! Run with:  zig test ex1_date.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Date = struct {
    year: u16,
    month: u8, // 1..12
    day: u8, // 1..31

    pub const campaign_default: Date = .{ .year = 3025, .month = 1, .day = 1 };

    pub fn isLeapYear(year: u16) bool {
        return (year % 4 == 0 and year % 100 != 0) or year % 400 == 0;
    }

    pub fn daysInMonth(year: u16, month: u8) u8 {
        return switch (month) {
            1, 3, 5, 7, 8, 10, 12 => 31,
            4, 6, 9, 11 => 30,
            2 => if (isLeapYear(year)) @as(u8, 29) else 28,
            else => unreachable,
        };
    }

    /// The day after self, as a new value.
    pub fn next(self: Date) Date {
        var d = self;
        d.day += 1;
        if (d.day > daysInMonth(d.year, d.month)) {
            d.day = 1;
            d.month += 1;
            if (d.month > 12) {
                d.month = 1;
                d.year += 1;
            }
        }
        return d;
    }

    /// Advance self in place by n days.
    pub fn advance(self: *Date, n: u32) void {
        var i: u32 = 0;
        while (i < n) : (i += 1) self.* = self.next();
    }

    pub fn isPayday(self: Date) bool {
        return self.day == 1;
    }
};

test "leap years" {
    try std.testing.expect(Date.isLeapYear(3024));
    try std.testing.expect(!Date.isLeapYear(3025));
    try std.testing.expect(!Date.isLeapYear(3100));
    try std.testing.expect(Date.isLeapYear(3200));
}

test "next rolls over months and years" {
    var d: Date = .{ .year = 3024, .month = 2, .day = 28 };
    d = d.next();
    try std.testing.expectEqual(Date{ .year = 3024, .month = 2, .day = 29 }, d);
    d = .{ .year = 3025, .month = 12, .day = 31 };
    try std.testing.expectEqual(Date{ .year = 3026, .month = 1, .day = 1 }, d.next());
}

test "advance mutates in place" {
    var d = Date.campaign_default;
    d.advance(31);
    try std.testing.expectEqual(Date{ .year = 3025, .month = 2, .day = 1 }, d);
    try std.testing.expect(d.isPayday());
    d.advance(1);
    try std.testing.expect(!d.isPayday());
}

advance shows the two styles cooperating: it takes *Date so it can change the caller's value, and does so by assigning self.* = self.next(), the by-value method's result. The @as(u8, 29) inside the switch gives the if expression a concrete type so that both branches agree.

Exercise 12.2 · Defaults, nesting and format practice

Add three defaulted fields to Unit (an Armor struct, an optional pilot name, a destroyed flag), implement totalArmor and hitFront, and write a format method that prints Atlas (100t, 47/14) piloted by Kai [DESTROYED] style output, checked through bufPrint with {f}. Name the file: exercises/12-structs/ex2_unit.zig.

Solution 
//! Chapter 12, exercise 2: defaults, nesting and a format method.
//! Run with:  zig test ex2_unit.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Armor = struct { front: u16, rear: u16 };

const Unit = struct {
    name: []const u8,
    tons: u8,
    armor: Armor = .{ .front = 0, .rear = 0 },
    pilot: ?[]const u8 = null,
    destroyed: bool = false,

    pub fn totalArmor(self: Unit) u32 {
        return @as(u32, self.armor.front) + self.armor.rear;
    }

    /// Apply damage to the front armor; anything left over destroys the unit.
    pub fn hitFront(self: *Unit, dmg: u16) void {
        if (dmg >= self.armor.front) {
            self.armor.front = 0;
            self.destroyed = true;
        } else {
            self.armor.front -= dmg;
        }
    }

    pub fn format(self: Unit, w: *std.Io.Writer) std.Io.Writer.Error!void {
        const a = self.armor;
        try w.print("{s} ({d}t, {d}/{d})", .{ self.name, self.tons, a.front, a.rear });
        if (self.pilot) |p| try w.print(" piloted by {s}", .{p});
        if (self.destroyed) try w.writeAll(" [DESTROYED]");
    }
};

test "defaults" {
    const u = Unit{ .name = "Locust", .tons = 20 };
    try std.testing.expectEqual(@as(u32, 0), u.totalArmor());
    try std.testing.expectEqual(@as(?[]const u8, null), u.pilot);
    try std.testing.expect(!u.destroyed);
}

test "damage" {
    var u = Unit{ .name = "Atlas", .tons = 100, .armor = .{ .front = 47, .rear = 14 } };
    u.hitFront(10);
    try std.testing.expectEqual(@as(u32, 51), u.totalArmor());
    try std.testing.expect(!u.destroyed);
    u.hitFront(40);
    try std.testing.expect(u.destroyed);
    try std.testing.expectEqual(@as(u16, 0), u.armor.front);
}

test "format" {
    var buf: [96]u8 = undefined;
    var u = Unit{
        .name = "Atlas",
        .tons = 100,
        .armor = .{ .front = 47, .rear = 14 },
        .pilot = "Kai",
    };
    try std.testing.expectEqualStrings(
        "Atlas (100t, 47/14) piloted by Kai",
        try std.fmt.bufPrint(&buf, "{f}", .{u}),
    );
    u.hitFront(99);
    try std.testing.expectEqualStrings(

}

totalArmor widens to u32 before adding, since two u16 can overflow a u16. The optional pilot is unwrapped with if (self.pilot) |p|, a preview of Chapter 15. The format method uses w.print and w.writeAll, the same calls as any writer.

Exercise 12.3 · A lance of meks practice

A Lance holds a [4]Mek. Implement tonnage, readyCount, a pointer-receiver damage that marks one mek by name, and heaviestReady, which returns a pointer into the lance or null. Name the file: exercises/12-structs/ex3_lance.zig.

Solution 
//! Chapter 12, exercise 3: a struct that holds an array of structs.
//! Run with:  zig test ex3_lance.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Mek = struct {
    name: []const u8,
    tons: u8,
    ready: bool = true,
};

const Lance = struct {
    name: []const u8,
    meks: [4]Mek,

    const Self = @This();

    pub fn tonnage(self: Self) u32 {
        var t: u32 = 0;
        for (self.meks) |m| t += m.tons;
        return t;
    }

    pub fn readyCount(self: Self) usize {
        var n: usize = 0;
        for (self.meks) |m| {
            if (m.ready) n += 1;
        }
        return n;
    }

    /// Mark the mek called `name` as not ready. Returns false if no such mek.
    pub fn damage(self: *Self, name: []const u8) bool {
        for (&self.meks) |*m| {
            if (std.mem.eql(u8, m.name, name)) {
                m.ready = false;
                return true;
            }
        }
        return false;
    }

    /// The heaviest ready mek, or null if none is ready.
    pub fn heaviestReady(self: *const Self) ?*const Mek {
        var best: ?*const Mek = null;
        for (&self.meks) |*m| {
            if (!m.ready) continue;
            if (best == null or m.tons > best.?.tons) best = m;
        }
        return best;
    }
};

fn sampleLance() Lance {
    return .{
        .name = "Alpha",
        .meks = .{
            .{ .name = "Atlas", .tons = 100 },
            .{ .name = "Locust", .tons = 20 },
            .{ .name = "Marauder", .tons = 75 },
            .{ .name = "Shadow Hawk", .tons = 55 },
        },
    };
}

test "tonnage and readiness" {
    const l = sampleLance();
    try std.testing.expectEqual(@as(u32, 250), l.tonnage());
    try std.testing.expectEqual(@as(usize, 4), l.readyCount());
}

test "damage through a pointer" {
    var l = sampleLance();
    try std.testing.expect(l.damage("Atlas"));
    try std.testing.expect(!l.damage("Urbanmech"));
    try std.testing.expectEqual(@as(usize, 3), l.readyCount());
    try std.testing.expectEqual(@as(u32, 250), l.tonnage()); // tonnage unchanged
}

test "heaviest ready" {
    var l = sampleLance();
    try std.testing.expectEqualStrings("Atlas", l.heaviestReady().?.name);
    _ = l.damage("Atlas");
    try std.testing.expectEqualStrings("Marauder", l.heaviestReady().?.name);
    for (&l.meks) |*m| m.ready = false;
    try std.testing.expect(l.heaviestReady() == null);
}

damage loops over &self.meks with |*m| so the write to m.ready lands in the struct, not in a copy. heaviestReady takes *const Self because it returns a pointer into the struct; with a by-value self the pointer would refer to a copy that no longer exists.

Exercise 12.4 · A tiny ledger challenge

A Ledger keeps up to eight Entry values in a fixed array with a len counter. Implement post (returning error.Full when out of room), balance, balanceOn(day) and biggestExpense. Only entries[0..len] are meaningful; the rest is undefined. Name the file: exercises/12-structs/ex4_ledger.zig.

Solution 
//! Chapter 12, exercise 4: a tiny ledger (challenge).
//! Run with:  zig test ex4_ledger.zig
//! Goal: make every test pass without changing the tests.
const std = @import("std");

const Entry = struct {
    day: u32,
    label: []const u8,
    amount: i64, // positive = income, negative = expense
};

const Ledger = struct {
    entries: [8]Entry = undefined,
    len: usize = 0,
    opening: i64,

    const Self = @This();

    /// Record an entry. Returns error.Full when the fixed array is used up.
    pub fn post(self: *Self, day: u32, label: []const u8, amount: i64) !void {
        if (self.len == self.entries.len) return error.Full;
        self.entries[self.len] = .{ .day = day, .label = label, .amount = amount };
        self.len += 1;
    }

    pub fn balance(self: Self) i64 {
        var b = self.opening;
        for (self.entries[0..self.len]) |e| b += e.amount;
        return b;
    }

    /// Balance as it stood at the end of `day`.
    pub fn balanceOn(self: Self, day: u32) i64 {
        var b = self.opening;
        for (self.entries[0..self.len]) |e| {
            if (e.day <= day) b += e.amount;
        }
        return b;
    }

    /// The largest single expense (most negative amount), or null.
    pub fn biggestExpense(self: *const Self) ?Entry {
        var best: ?Entry = null;
        for (self.entries[0..self.len]) |e| {
            if (e.amount >= 0) continue;
            if (best == null or e.amount < best.?.amount) best = e;
        }
        return best;
    }
};

test "post and balance" {
    var l = Ledger{ .opening = 1_000_000 };
    try l.post(1, "contract advance", 250_000);
    try l.post(1, "salaries", -60_000);
    try l.post(15, "spare parts", -12_500);
    try std.testing.expectEqual(@as(i64, 1_177_500), l.balance());
    try std.testing.expectEqual(@as(i64, 1_190_000), l.balanceOn(1));
    try std.testing.expectEqual(@as(i64, 1_000_000), l.balanceOn(0));
}

test "biggest expense" {
    var l = Ledger{ .opening = 0 };
    try std.testing.expect(l.biggestExpense() == null);
    try l.post(1, "income", 500);
    try l.post(2, "salaries", -60_000);
    try l.post(3, "repairs", -75_000);
    try std.testing.expectEqualStrings("repairs", l.biggestExpense().?.label);
}

test "full ledger" {
    var l = Ledger{ .opening = 0 };
    var i: u32 = 0;
    while (i < 8) : (i += 1) try l.post(i, "x", 1);
    try std.testing.expectError(error.Full, l.post(9, "one too many", 1));
    try std.testing.expectEqual(@as(i64, 8), l.balance());
}

Every reader slices self.entries[0..self.len] so it never looks at the undefined tail. This array-plus-length pattern is what ArrayList does for you with a growable buffer in Chapter 21; building it by hand once makes the real thing obvious.

Check your understanding

  1. What happens if you omit a field without a default from a struct literal?
    AnswerA compile error naming the missing field. Zig never leaves a field silently uninitialised; write .f = undefined if that is what you mean.
  2. What is the difference between fn f(self: T) and fn f(self: *T)?
    AnswerBy value, self is a copy and the method cannot change the caller's struct. By pointer, it can. Calling a pointer method on a const value is a compile error.
  3. Is kai.train(6) different from Pilot.train(&kai, 6)?
    AnswerNo. Method-call syntax passes the value before the dot (or its address, for pointer parameters) as the first argument.
  4. How do you read a field through a pointer to a struct?
    AnswerWith a plain dot: p.hp. Zig follows the pointer; p.*.hp is the explicit form and there is no ->.
  5. How do you compare two structs for equality?
    Answerstd.meta.eql(a, b), or field by field. == is not defined for structs. Slice fields are compared by pointer and length.
  6. What does @This() return?
    AnswerThe type being defined at that point, usually stored as const Self = @This();. At file scope it is the file's own struct type.
  7. You wrote a format method and print("{}", .{d}) still shows raw fields. Why?
    AnswerIn 0.16 only the {f} specifier calls a type's format method; {} and {any} print the fields.
What you learned.
  • const T = struct { field: Type, ... }; declares a type; T{ .field = v } or a typed .{ ... } builds a value. Every non-defaulted field is required.
  • Defaults (field: Type = value) make fields optional in literals.
  • Methods are functions in the struct whose first parameter is the type; v.method() is T.method(v).
  • self: T reads a copy; self: *T mutates the original; self: *const T reads without copying.
  • Field access through a pointer needs no special syntax. Structs copy on assignment (shallowly).
  • @This() names the current type; constants and plain functions can live inside a struct.
  • Compare with std.meta.eql. Tuples are structs with numbered fields.
  • pub fn format(self: T, w: *std.Io.Writer) std.Io.Writer.Error!void plus the {f} specifier gives custom printing; {any} shows raw fields.
