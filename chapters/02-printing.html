2. Printing to the screen

In this chapter you will learn the two ways a Zig program writes text to the terminal and when to use each, how format strings and their placeholders work, how to line values up in columns, and how to write strings that contain quotes, braces, and line breaks.

2.1 Two streams

Every program started from a terminal has two output channels. Standard output (stdout) is for the program's real product: the thing a user would save to a file or pipe into another program. Standard error (stderr) is for messages about the program: progress, diagnostics, complaints. Both appear on your screen by default, which is why beginners rarely notice the difference, but the shell can redirect them separately, and tools that consume output only read stdout.

Zig gives you a different function for each, and they look very different.

two_streams.zig
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    std.debug.print("this goes to stderr\n", .{});

    var buf: [1024]u8 = undefined;
    var w = std.Io.File.stdout().writer(init.io, &buf);
    const out = &w.interface;
    try out.print("this goes to stdout\n", .{});
    try out.flush();
}
$ zig run two_streams.zig
this goes to stdout

On screen the two lines look the same. Ask the shell to hide stderr and only one survives:

$ zig run two_streams.zig 2>/dev/null
this goes to stdout
$ zig run two_streams.zig >out.txt
this goes to stderr
$ cat out.txt
this goes to stdout

2>/dev/null throws away stderr; >out.txt sends stdout to a file. This is how you will confirm, in the exercises, that your program is writing where you think it is.

2.2 std.debug.print

std.debug.print(fmt, args) writes to stderr, immediately, with no buffer and no possibility of failure. It needs no setup and no init parameter, which is why it works from a main() void. Its name says what it is for: debugging, progress messages, and, in this book, every example whose output is meant for your eyes rather than for another program. Its cost is that each call is a separate write to the operating system, which is slow if you print ten thousand lines, and that its output is on the wrong stream for a tool whose text someone wants to capture.

2.3 The stdout writer, and flush

Writing to stdout takes four lines, and each one is there for a reason.

    var buf: [1024]u8 = undefined;
    var w = std.Io.File.stdout().writer(init.io, &buf);
    const out = &w.interface;
    try out.print("this goes to stdout\n", .{});
    try out.flush();

var buf: [1024]u8 = undefined; declares an array of 1024 bytes and leaves its contents unset. This is the buffer: text you print is collected here and sent to the operating system in one piece instead of one call per line. You choose the size; 1024 is fine for a few lines and 4096 is common.

std.Io.File.stdout() is the file handle for standard output. Calling .writer(init.io, &buf) on it makes a writer, an object that knows how to push bytes into that file, using your buffer and the I/O context that came in through init. The & means "the address of": the writer keeps a pointer to your buffer rather than a copy. Pointers are Chapter 18; for now, &buf is simply how you lend the buffer out.

const out = &w.interface; takes the generic writer interface out of the file-specific writer. It is the interface field that has the print method, and taking its address once saves writing w.interface.print every time.

try out.print(…) formats into the buffer. It can fail (the disk could be full, the pipe could be closed), so it returns an error union and you must try it, which is why this main returns !void.

try out.flush(); pushes whatever is in the buffer to the file. Forget it and your program prints nothing:

noflush.zig
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buf: [1024]u8 = undefined;
    var w = std.Io.File.stdout().writer(init.io, &buf);
    const out = &w.interface;
    try out.print("you will never see this\n", .{});
    // no flush!
}
$ zig run noflush.zig

The transcript is empty on purpose. The text went into buf, main returned, and the buffer was discarded with the rest of the stack frame. Nothing in Zig runs at scope exit unless you write it, so nothing flushed. This is the "no hidden control flow" rule in action, and it is the single most common mistake in Zig printing.

Why so much ceremony? Python's print hides a buffer, a stream, an encoding, and an implicit flush at exit. Zig shows you all of them because each is a decision: the buffer is memory you own, the stream is chosen explicitly, and flushing is a moment you pick. When a program writes a million lines, the buffer size and flush points are where its speed lives. Until then, the recipe above is fixed and you can copy it.

For the rest of Part 0 the examples use std.debug.print, because it is shorter and the output is for you. Everything said below about format strings applies identically to out.print.

2.4 Placeholders

The first argument to print is a format string. Inside it, each pair of braces is a placeholder that will be replaced by the next value from the bundle. The letter inside the braces says how to render the value.

placeholders.zig
const std = @import("std");

pub fn main() void {
    const name = "Atlas";
    const tonnage: u32 = 100;
    const grade: u8 = 'A';
    const price: i64 = 9_626_000;

    std.debug.print("{s} weighs {d} tons\n", .{ name, tonnage });
    std.debug.print("rating {c}\n", .{grade});
    std.debug.print("price {d} C-bills\n", .{price});
    std.debug.print("hex {x}, HEX {X}, binary {b}\n", .{ tonnage, tonnage, tonnage });
    std.debug.print("octal {o}\n", .{tonnage});
}
$ zig run placeholders.zig
Atlas weighs 100 tons
rating A
price 9626000 C-bills
hex 64, HEX 64, binary 1100100
octal 144
PlaceholderRendersWorks on
{s}textstrings (byte slices and string literals)
{d}decimal numberintegers and floats
{c}a single charactera u8
{x} / {X}hexadecimal, lower / upper caseintegers
{b}binaryintegers
{o}octalintegers
{e}scientific notationfloats
{any}whatever the type's default looks likeanything
{}the default for simple typesnumbers, booleans

The values come from the bundle in order. .{ name, tonnage } feeds name to the first placeholder and tonnage to the second. When there is one value you can write .{grade} without spaces; zig fmt adds the spaces inside the braces when there are two or more.

{any} is the escape hatch. It prints any value in a debugging-friendly form and is what you reach for when you do not know or care about the exact type, such as an array or a struct:

any.zig
const std = @import("std");

pub fn main() void {
    const tonnage: u32 = 100;
    const ratio: f64 = 2.5;
    const flag = true;
    const point = .{ 3, 4 };
    std.debug.print("{any} {any} {any} {any}\n", .{ tonnage, ratio, flag, point });
    std.debug.print("{d} {d} {}\n", .{ tonnage, ratio, flag });
}
$ zig run any.zig
100 2.5 true .{ 3, 4 }
100 2.5 true

The second line shows that {d} also works on floats, and that a bare {} is fine for a boolean. You will see {} used for numbers in other people's code; it means the same as {d} for integers. This book prefers the explicit letter.

The compiler checks the format string against the bundle at compile time. Use the wrong letter for a type and the program does not build:

wrongspec.zig
const std = @import("std");

pub fn main() void {
    const tonnage: u32 = 100;
    std.debug.print("{s}\n", .{tonnage});
}
$ zig run wrongspec.zig
<zig>/lib/std/Io/Writer.zig:1803:5: error: invalid format string 's' for type 'u32'
    @compileError("invalid format string '" ++ fmt ++ "' for type '" ++ @typeName(@TypeOf(value)) ++ "'");
    ^~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The error is reported inside the standard library's Writer.zig, because that is where the check runs, but the message names your mistake exactly: {s} on a u32. Give it too few values and you get a similarly blunt message:

$ zig run toomany.zig
<zig>/lib/std/Io/Writer.zig:717:13: error: too few arguments
            @compileError("too few arguments");
            ^~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

This is worth pausing on. In C, a wrong printf specifier is a runtime crash or silent garbage. In Python it is a runtime exception. In Zig it is a compile error, because the format string is a compile-time constant and print is checked against it while the program is built. Your first encounter with comptime is a printf that cannot be wrong.

2.5 Width, alignment and precision

After the letter, a colon introduces options. The most useful three are a fill-and-alignment, a width, and a precision.

width.zig
const std = @import("std");

pub fn main() void {
    const pi: f64 = 3.14159265;
    std.debug.print("[{d:.2}]\n", .{pi});
    std.debug.print("[{d:8.3}]\n", .{pi});
    std.debug.print("[{d:>6}]\n", .{42});
    std.debug.print("[{d:<6}]\n", .{42});
    std.debug.print("[{d:^6}]\n", .{42});
    std.debug.print("[{d:0>6}]\n", .{42});
    std.debug.print("[{s:<10}]|\n", .{"Atlas"});
    std.debug.print("[{s:>10}]|\n", .{"Atlas"});
    std.debug.print("[{x:0>4}]\n", .{255});
}
$ zig run width.zig
[3.14]
[   3.142]
[    42]
[42    ]
[  42  ]
[000042]
[Atlas     ]|
[     Atlas]|
[00ff]

Read {d:0>6} from left to right: render as decimal, then pad with 0, aligned to the right (>), in a field 6 wide. The alignment characters are < for left, > for right, and ^ for centred. If you give a width without an alignment, numbers align right and strings align left. The fill character goes just before the alignment character and defaults to a space.

A precision comes after a dot: {d:.2} shows two digits after the decimal point, rounding. Width and precision combine as {d:8.3}, meaning width 8, three decimals. Chapter 23 and Appendix A2 have the complete grammar; these five forms cover nearly all real use.

Put together, they make tables:

table.zig
const std = @import("std");

pub fn main() void {
    std.debug.print("{s:<12}{s:>6}{s:>12}\n", .{ "Unit", "Tons", "Price" });
    std.debug.print("{s:<12}{d:>6}{d:>12}\n", .{ "Locust", 20, 1_512_000 });
    std.debug.print("{s:<12}{d:>6}{d:>12}\n", .{ "Shadow Hawk", 55, 4_701_000 });
    std.debug.print("{s:<12}{d:>6}{d:>12}\n", .{ "Atlas", 100, 9_626_000 });
}
$ zig run table.zig
Unit          Tons       Price
Locust          20     1512000
Shadow Hawk     55     4701000
Atlas          100     9626000
Trap: a plus sign appears. When you give a width to a signed integer, 0.16 prints positive values with a leading +: {d:8} on an i64 holding 75000 gives   +75000. Unsigned types never do this, and a signed value with no width does not either. If you want a padded column of signed numbers without the sign, cast to an unsigned type when you know the value is not negative, or format into a buffer first (Chapter 23).

2.6 Escapes and literal braces

A string literal is written between double quotes. Some characters cannot be typed directly inside it, so a backslash introduces an escape:

EscapeMeaning
\nnewline
\ttab
\"a double quote
\\one backslash
\rcarriage return (Windows line endings are \r\n)
\x41the byte with hex value 41 (the letter A)
\u{2588}the Unicode character with that code point, encoded as UTF-8

Braces are special in a format string, so to print one you double it: {{ and }}.

escapes.zig
const std = @import("std");

pub fn main() void {
    std.debug.print("tab:\there\n", .{});
    std.debug.print("quote: \"IRON LEDGER\"\n", .{});
    std.debug.print("backslash: C:\\games\\ledger\n", .{});
    std.debug.print("unicode: \u{2588}\u{2588} 100%\n", .{});
    std.debug.print("braces: {{d}} prints literally, {d} does not\n", .{7});
}
$ zig run escapes.zig
tab:	here
quote: "IRON LEDGER"
backslash: C:\games\ledger
unicode: ██ 100%
braces: {d} prints literally, 7 does not

Strings in Zig are sequences of bytes, not characters, and the source file is UTF-8, so you can also type █ directly into the literal and it prints correctly. The \u{…} form is for when you want the code to be readable on any keyboard. Chapter 11 goes into what a string really is.

2.7 Multi-line strings

For text with several lines, escapes get tiresome. Zig has a second string syntax: each line starts with \\, and the string is everything after the two backslashes on each line, joined with newlines. Nothing inside is escaped, so quotes and backslashes are literal.

multiline.zig
const std = @import("std");

pub fn main() void {
    const banner =
        \\==============================
        \\   IRON LEDGER   day {d}
        \\   "no plan survives contact"
        \\==============================
        \\
    ;
    std.debug.print(banner, .{1});
}
$ zig run multiline.zig
==============================
   IRON LEDGER   day 1
   "no plan survives contact"
==============================

Three details. There is no newline after the last line unless you add an empty \\ line, which the example does. The string is still a format string when you pass it to print, so {d} inside it is a placeholder and braces must still be doubled. And the closing semicolon goes on its own line after the last \\, because anything on a \\ line is part of the string.

Try it. Remove the final empty \\ line and run the program; the shell prompt lands on the same line as the bottom border. Then change {d} to {d:0>3} to get day 001.
In IRON LEDGER. The game uses both streams for exactly the reasons above. Diagnostic messages and the scripted demo go through std.debug.print, as in game/src/main.zig where the saved-campaign list is reported (three of the messages, trimmed): 
std.debug.print("could not read the campaign registry\n", .{});
// …
std.debug.print("no saved campaigns.\n", .{});
// …
std.debug.print("campaigns (most recently saved first):\n", .{});
The terminal client, on the other hand, draws the whole screen into a large buffer and writes it to stdout in one flush per frame, because a screen redraw is one product, not a series of messages (see game/src/tui/term.zig and Chapter 48). Every {s}, {d} and column width you learn here is used there, many thousands of times.

Exercises

Exercise 2.1 · Five placeholders warm-up

The starter declares a name, a grade character, and a tonnage. Produce the single line shown in its header with one print call, using {s}, {c}, {d}, {x} and {b}. The tonnage appears three times, in three bases. Name the file: exercises/02-printing/ex1_placeholders.zig.

Solution 
//! Chapter 02, exercise 1: one line, five placeholders.
//! Run with:  zig run ex1_placeholders.zig
//! Expected output (on stderr):
//!   Atlas (grade A) weighs 100 tons, hex 64, binary 1100100
const std = @import("std");

pub fn main() void {
    const name = "Atlas";
    const grade: u8 = 'A';
    const tonnage: u32 = 100;
    std.debug.print("{s} (grade {c}) weighs {d} tons, hex {x}, binary {b}\n", .{
        name, grade, tonnage, tonnage, tonnage,
    });
}

A value can be passed more than once; the bundle just lists it again. When the bundle gets long, zig fmt breaks it one item per line if you leave a trailing comma after the last item, which is what the solution does.

Exercise 2.2 · An aligned table practice

Print the four-row unit table shown in the starter's header. The name column is 12 wide and left-aligned, tons is 4 wide and right-aligned, price is 7 wide and right-aligned, with one space between columns. The header row is strings; the others mix strings and numbers. Name the file: exercises/02-printing/ex2_table.zig.

Solution 
//! Chapter 02, exercise 2: an aligned table.
//! Run with:  zig run ex2_table.zig
//! Expected output (on stderr):
//!   Unit         Tons   Price
//!   Locust         20 1512000
//!   Shadow Hawk    55 4701000
//!   Atlas         100 9626000
const std = @import("std");

pub fn main() void {
    std.debug.print("{s:<12} {s:>4} {s:>7}\n", .{ "Unit", "Tons", "Price" });
    std.debug.print("{s:<12} {d:>4} {d:>7}\n", .{ "Locust", 20, 1_512_000 });
    std.debug.print("{s:<12} {d:>4} {d:>7}\n", .{ "Shadow Hawk", 55, 4_701_000 });
    std.debug.print("{s:<12} {d:>4} {d:>7}\n", .{ "Atlas", 100, 9_626_000 });
}

The header row uses {s:>4} to right-align the word Tons over a numeric column; the same width spec works for strings and numbers. The number literals with underscores are just readable integers; underscores are ignored by the compiler.

Exercise 2.3 · A banner practice

Build the five-line box in the starter's header as one multi-line string literal, with the day number substituted through a {d} placeholder, then print it. The third line contains braces that must print literally and the fourth contains double quotes. Name the file: exercises/02-printing/ex3_banner.zig.

Solution 
//! Chapter 02, exercise 3: a multi-line banner with a placeholder inside.
//! Run with:  zig run ex3_banner.zig
//! Expected output (on stderr):
//!   +----------------------+
//!   | IRON LEDGER   day 12 |
//!   | funds: {not a hole}  |
//!   | "trust the ledger"   |
//!   +----------------------+
const std = @import("std");

pub fn main() void {
    const day: u32 = 12;
    const banner =
        \\+----------------------+
        \\| IRON LEDGER   day {d} |
        \\| funds: {{not a hole}}  |
        \\| "trust the ledger"   |
        \\+----------------------+
        \\
    ;
    std.debug.print(banner, .{day});
}

Inside a \\ string nothing is escaped, so the quotes are typed as they are. But the string is still a format string when handed to print, so the literal braces are doubled. Note the trailing empty \\ line for the final newline.

Exercise 2.4 · One number, six ways warm-up

Print the value 255 as plain decimal, zero-padded to five places, space-padded to five places, lowercase hex, uppercase hex with a 0x prefix, and binary, each in square brackets, all on one line. Name the file: exercises/02-printing/ex4_padding.zig.

Solution 
//! Chapter 02, exercise 4: the same number, five ways.
//! Run with:  zig run ex4_padding.zig
//! Expected output (on stderr):
//!   [255] [00255] [  255] [ff] [0xFF] [11111111]
const std = @import("std");

pub fn main() void {
    const n: u8 = 255;
    std.debug.print("[{d}] [{d:0>5}] [{d:>5}] [{x}] [0x{X}] [{b}]\n", .{ n, n, n, n, n, n });
}

The 0x is ordinary text in the format string, not part of the specifier. {d:0>5} reads: decimal, fill with zeros, right-aligned, width five.

Check your understanding

  1. Which stream does std.debug.print write to, and does it buffer?
    AnswerStandard error, and no: each call writes immediately and cannot fail.
  2. A stdout program prints nothing at all. What is the most likely cause?
    AnswerA missing try out.flush(); before main returns. The text is still in the buffer when the program exits.
  3. What happens if you write {s} for an integer?
    AnswerA compile error: invalid format string 's' for type 'u32'. Format strings are checked at compile time.
  4. What does {d:0>6} mean, piece by piece?
    AnswerDecimal; fill character 0; right-aligned; width 6.
  5. How do you print a literal { in a format string?
    AnswerDouble it: {{. Likewise }} for a closing brace.
  6. In a multi-line string, how do you get a newline after the last line?
    AnswerAdd an empty \\ line at the end. Without it the string ends right after the last character.
  7. Why does {d:8} on a positive i64 show a plus sign?
    AnswerIn 0.16 a width on a signed integer renders an explicit sign for positive values. Unsigned types and unpadded signed values do not show it.
What you learned.
  • stderr is for messages, stdout is for output; std.debug.print writes to stderr with no setup, the stdout writer needs a buffer, init.io, and a flush.
  • Placeholders: {s} text, {d} number, {c} character, {x}/{X} hex, {b} binary, {any} anything.
  • Options after a colon: fill, alignment (< > ^), width, and .precision.
  • Format strings are checked at compile time; a wrong specifier or a missing value is a compile error.
  • Escapes use a backslash; literal braces are doubled; multi-line strings start each line with \\.
